## Decisions (all `[default sicuro]`; no open `[BLOCCA]`)

- **D1 — the removal is total.** No `SolverKind` variant, no importable
  shim, no "this solver was removed" branch. `--solver=resolvo` exits 2 with
  the ordinary unknown-value message naming `portage` and `pubgrub`.
  Rationale: the owner's word is *disappears*; a bespoke refusal would keep
  the value in the CLI contract and in every future reader's head.
- **D2 — the message shape is kept, only its value list shrinks.** Two
  static strings (`args.rs:1158`, `:1165`) lose a word:
  `emerge: option '--solver' requires a value (portage or pubgrub)` and
  `emerge: --solver: "sat" is not "portage" or "pubgrub"`. The `--help`
  line (`help.txt:117`) reads `portage (default) or pubgrub`. No other
  wording change. **[review] NIT**: the first draft claimed a dynamic
  grammar "decided by the count"; both strings are literal, so they are
  edited directly.
- **D3 — `3rdparty/` is annotated, never deleted.** One line each in
  `3rdparty/README.md` and `repos.toml` saying the reference checkout's
  `portage-atom-resolvo` is upstream-only and never a build input here.
- **D4 — proof of no collateral damage, scoped so it cannot stop itself.**
  **[review] B3** The fingerprint comparison covers every output *except*
  the sites this slice is defined to change (the enumerated pmtest pins and
  tests below, the error/help text, the comment sweep). Concretely: for
  every contract-suite case and every Rust test, the per-test pass/fail set
  must be unchanged; for the fixed `--solver=pubgrub`/default probe set
  (fixtures plus the L0 pubgrub bed's probe list) every stdout/stderr/rc
  must be byte-identical. A change *inside* the enumerated exception list is
  expected and is reviewed as a diff, not waved through; a change outside it
  is STOP-1.
- **D5 — `Cargo.lock` may only lose entries, and the orphan set is
  whatever the audit proves.** A *version change* of a surviving crate — or
  the disappearance of a crate with another user, per version — is a STOP,
  because it would move behaviour for a slice whose whole claim is "nothing
  but resolvo changes". **Corrected after execution:** the first draft
  enumerated 7 packages (2 direct + 5 orphans) as if the count were the
  contract; the removal in fact deleted **11** — the same 7 plus
  `hashbrown 0.15.5` (`petgraph`'s), `foldhash 0.1.5` (its), `getrandom
  0.3.4` (resolvo was the sole `runtime-rng` enabler for a surviving
  `ahash 0.8.12`), `r-efi 5.3.0` (its). Every one was proven a sole-user
  orphan per version, zero versions moved, and the two survivals named
  above held, so the rule was never violated and the slice proceeded. A
  whole solver's transitive tail is expected to go; a number in a plan is
  not a promise a later reader should enforce.
- **D6 — the recorded reason survives its comment.** The dependency-block
  prose at `Cargo.toml:38-47` explains the exact pins of two engines; the
  resolvo half goes and the block is **rewritten** to say what is true of
  pubgrub alone (not "delete the waiver comment"). The substance of the
  waiver is restated in the #755 close-out.
- **D7 — `seeds_first` stays a parameter, and its comments stop lying.**
  **[review] B6** `resolve_resolvo` (`solver_bridge.rs:5923`) is the only
  production `LazyRepo::build(…, false)` caller. After the removal the
  parameter is constant-true, but deleting it is exactly the kind of
  behaviour-risk refactor D4 forbids this slice to attempt: keep it, and
  reword `:248-252` and `:315-317` so they describe pubgrub's use rather
  than "resolvo keeps the old order". A follow-up may delete it with its own
  fingerprint; #755 does not.
