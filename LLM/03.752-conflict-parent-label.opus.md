## 1. The defect, and what correct looks like

#738 fixed the *instance* line: a surviving merge-bound instance reads its
binary/ebuild label from its own settled merge row
(`conflict_instance_kind`, threaded `entries`). The *parent* line in
`show_selected_parents` still hardcodes the ebuild form for every
non-installed parent (`problem_reports.rs:1096`):

```rust
format!("{}, ebuild scheduled for merge", p.parent_cpv)
```

So in the #738 capture's `ffmpeg:0` block
(`docs/evidence/2026-11-14-738/conflict-blocks.txt:18-21`) the binary
`ffmpeg-9.0.2` instance pulls parents that render `..., ebuild scheduled
for merge` even where the merge list shows those same parents as
`[binary ...]` rows. Charter property 5: the message misleads about which
package pulls the conflict and what the user would rebuild or exclude.

Grounding: charter property 5 (the message must not mislead); the PMS
(EAPI slot semantics) says nothing about display text, so the text follows
Portage's `str(Package)` shape only as a hint
(`slot_collision.py`, `_prepare_conflict_msg_and_check_for_specificity`).
No fixture demonstrates a binary parent yet: the #738 pins cover bare
`(Argument)` parents and binary *instances* only.
