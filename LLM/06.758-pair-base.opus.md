# 06.758 — `pair_check.sh` bases itself on the branch's fork point, not on `main`

Status: proposed

## 0. What this fixes

`pair_check.sh` defaults `BASE` to `merge-base HEAD main`. On a branch cut
from the integration branch (`opencode`), that range includes everything
`opencode` carries over `main`, so the checker inherits obligations that
belong to the integration branch, not to the slice:

- it demands `LLM/evidence/merge-gate-<branch>.md` naming `sys-libs/glibc`
  and `app-shells/bash` whenever the *ancestry* touched the merge path — on
  #756, a slice touching only `LLM/tools/`, the file it wanted was
  `merge-gate-backlog-756-inode-preflight.md`;
- the "quotes no pmtest short sha" warning fires for every commit older than
  the branch, so on a mature integration branch the output is mostly noise
  exactly where it should be signal.

Observed end to end: `sh LLM/tools/pair_check.sh` → `rc=1` with the missing
evidence file; `BASE=$(git rev-parse refs/heads/opencode) sh
LLM/tools/pair_check.sh` → `pair-check: OK`.

## 1. Decisions `[default sicuro]`

- **D1 — the base is the fork point against the integration branch.**
  `PAIR_INTEGRATION` names it; when unset, `opencode` if
  `refs/heads/opencode` exists, else `main`. `base_of` becomes
  `git merge-base --fork-point refs/heads/<integration> HEAD`, falling back to
  `git merge-base HEAD <integration>` when the reflog cannot answer
  (`--fork-point` needs the branch's reflog; a freshly cloned repo may lack
  it). On `main` itself the current `HEAD^1` rule stands.
- **D2 — the same base is used for both repos.** `PMTEST_BASE` is computed the
  same way, so the pairing warnings cover the slice's commits only.
- **D3 — an explicit `BASE`/`PMTEST_BASE` still wins.** The env overrides keep
  their meaning; the change is only the default.
- **D4 — the behaviour is visible.** The script prints the base it chose (one
  line, `pair-check: base <sha> (<reason>)`), because a checker whose range
  the reader cannot see is how this defect stayed invisible: the failure named
  a missing file, never the range that made it required.
- **D5 — no weakening.** Everything the checker protects still applies to the
  slice's own diff: a merge-path change *in the slice* still requires the
  evidence file, and the branch-name/`corpus bless`/sha-quoting rules are
  untouched. Only the inherited-range false positives go.

## 2. The pin

A scratch-repo test in `pytests-contract-suite/test_harness_guards.py`
(same file, same theme: the harness's own guards):

1. build `scratch/portuale` (git init): commit on `main` touching
   `crates/portuale/src/emerge_build/x.rs`; branch `opencode` there; branch
   `slice` on top with one commit touching only `docs/note.md`;
2. build `scratch/pmtest` the same way (a commit on `main`, branch `opencode`,
   branch `slice` on top), so `PMTEST_DIR` resolves and the branch names match;
3. copy `LLM/tools/pair_check.sh` into `scratch/portuale/LLM/tools/` and run
   it from `scratch/portuale` on `slice`:
   - **green**: with no override it prints `pair-check: OK` and names the
     `opencode` base (the fix);
   - **red**: with `PAIR_INTEGRATION=main` it fails on the missing
     `merge-gate-slice.md` (the old behaviour, still available and still
     correct for a branch genuinely cut from `main`);
   - **still protected**: add a commit on `slice` touching
     `crates/portuale/src/emerge_build/x.rs` and the checker fails again with
     the same message — the fix must not have disabled the gate.
4. no network, no fixtures, git identity pinned in the test
   (`GIT_AUTHOR_*`/`GIT_COMMITTER_*` via env) so it works in any environment.

Red-first: today the first assertion fails (the checker demands the evidence
file and exits 1 on `slice`), and the third passes — that pairing is what
proves the pin tests the change and not the checker's absence.

5. S4 — close: #758 `DONE`; the script header's comment rewritten (it
   currently says "default: merge-base HEAD main"); one short
   `LLM/what-this-proves.md` paragraph (a gate that fails on inherited history
   teaches the reader to ignore it); plan Status flipped.

## 4. STOP rules

- **STOP-0**: the fork point cannot be determined in this repo (no reflog) and
  the fallback changes an existing branch's result → STOP and report; a
  checker that silently re-ranges is worse than one that over-reports.
- **STOP-1**: the change makes a *slice's own* merge-path commit pass without
  evidence → STOP; that is the protection, not the noise.
- **STOP-2**: `--fork-point` returns a base that is not an ancestor of `HEAD`
  → STOP (it can happen after a rebase; the fallback must be `merge-base`,
  never the returned ref blindly).

## Global constraints

- Both repos on `backlog/758-pair-base`. The code change is portuale-only

  declared: pmtest commit quotes the portuale sha, or stands as a paired test
  commit. No product code, no fixtures, no corpus.
- The scratch repos live under `tmp_path`; nothing outside it is written.
