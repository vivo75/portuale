### Task 3: Doc-status checker (§2 stale plan headers, §4 duplicate numbers and wrong premises)

**Files:**
- Create: `LLM/tools/doc_status_check.py`, `LLM/tools/test_doc_status_check.py`
- Modify: `LLM/tools/gate.sh`

**Inputs:** a list of backlog files, default glob `LLM/backlog-tasks*.md` (both files);
plan files `LLM/[0-9]*.opus.md`.

**Parsing:** item line `^(\d+)\. \*\*(DONE|OPEN|WITHDRAWN|CLOSED|SPLIT)?`; "Re-ranked …
closed" and entries with no status word map to `UNKNOWN`. A line `^\d+\. \d+\.` is a
**malformed item** violation (`backlog-tasks.md:107`, `147. 147.`). Plan header: first line
matching `^Status:\s*(?:\*\*)?(done|proposed|in progress)` (scan past the preamble; 02.341's
is at line 18).

**Rules** (exit 1, one line per violation):
(a) plan `done` ⇒ entry status ∈ {DONE, CLOSED, WITHDRAWN}; plan `proposed`/`in progress` ⇒
entry is not DONE unless the header names the open residues; a plan whose item number has no
entry is a violation; `UNKNOWN` is a violation unless allowed;
(b) a number defined twice, **within or across** the files;
(c) entries numbered above `FIRST_ENFORCED` (493) need an `Oracle:` or `Premise:` token, or
`Premise: n/a — <reason>` (this proves the line exists, not that the premise is right);
(d) tier prefix: plan `<tier>.<n>-…` must sit in tier `<tier>` of the entry (the two real
cases today: `06.443`, `06.452`, whose items sit in Tier 1).
Legacy violations live in an `ALLOW` table (keyed by rule + number, one reason each). **Shrink
only is enforced:** a unit test pins `len(ALLOW)` to the number written by the first run, and
`gate.sh` fails if `ALLOW` grew versus `git show main:LLM/tools/doc_status_check.py`.
