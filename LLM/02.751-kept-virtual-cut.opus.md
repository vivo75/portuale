## 1. What the user gains, and the mechanism

| Entry | Property | Gain |
|---|---|---|
| #751 | 2 | Either confidence the kept-virtual cut is sound (pinned probe, no code churn) or consumers ordered after the rebuilds they actually build against |

The mechanism is one filter in `crates/portage-world/src/order.rs:277-283`: `build_time_used` collects the targets of `DEPEND`/`BDEPEND`/`IDEPEND` edges **except `virtual/*` targets**. Because a `virtual/*` source therefore never confers build-time status, `is_cuttable_runtime_edge` (L289-295) lets the virtual's provider edge cut, and a whole rebuild cluster can be ordered before the rebuilds it is for. That is right when the installed provider is usable (the bed FAST plan is fully checker-clean with the exclusion in place), but if the installed provider were unusable — a stale slot-operator binding of the #741 shape, or an unusable `RDEPEND` closure — the consumers would build against a broken provider. No live shape shows this today (host and bed have none); the checker would flag it if it appeared. This plan builds that shape on purpose and lets the checker judge it.

Trap the executor must not fall into: the existing `w743`/`w745` fixture models name their virtual `dev-libs/w74Xvirt`, which does **not** start with `virtual/` and so never exercises the exclusion. The S0 probe must use the real `virtual/` category (e.g. `virtual/w751virt`), or it probes a different rule and proves nothing.

## 2. The rule (S1 only — skipped entirely if S0 is clean)

Two narrowing candidates. S1 builds **(b) first** (implementable with inputs already present); **(a) only if (b) leaves the probe flagged**. S2's bed comparison adjudicates which ships — the plan does not assume (a).

### Candidate (b): a virtual confers build-time status only when its provider is a plan row

A `virtual/*` target of a build-kind edge confers build-time status (like any other build input, PMS 8.1) **iff the provider edge's target is in `rows`** — the merge-bound slots. When the provider is not rebuilt, the installed copy's usability is pre-existing breakage that both the planner's walk (`chain_unmet`, `order.rs:452-483`) and the checker's `_Moment.gap` already excuse, so behaviour changes exactly where it matters (provider rebuilt) and nowhere else.

Plumbing, stated so the executor does not invent it: `rows: BTreeSet<String>` is already built in `ordered` (`order.rs:86-92`) and already threaded into `close_usability_gaps` via `Usability` (`order.rs:414-420`). Thread the same set one step further — `ordered` passes `&rows` into `depend_order` (new parameter), which passes it into `build_time_used(kinds, rows)`; the filter is one membership test (a `virtual/*` target is excluded from the set only when it is **not** in `rows`). Sorted sets throughout, no hash iteration, no new cross-crate input.

### Candidate (a): a virtual confers build-time status unless every installed provider is usable

A `virtual/*` target confers build-time status **unless every installed provider of that virtual is usable**: installed, with recorded `:=` bindings satisfiable against the plan's chosen provider versions (the #741 staleness judgment) and a satisfiable `RDEPEND` closure at name level (the `close_usability_gaps` approximation — say so in the commit, and note R1).

Plumbing, stated because `World` does not carry what (a) needs: `World` (`lib.rs:496-525`) has no VDB recorded RDEPEND/USE bindings, and `SlotSet.installed` is version-only (`reorder.rs:23-25`); the #741 staleness judgment lives in `portage-repo`'s rebuild scan, not in `portage-world`. So (a) needs a **new input**: `unusable_installed: &BTreeSet<String>` (node names whose installed copy's recorded bindings are unsatisfiable against the plan), filled by the `mrg --plan-world` caller from the rebuild scan's staleness output — the same scan that already feeds `World.rebuilds`/`World.refused` (`lib.rs:511-517`) — threaded `ordered → depend_order → build_time_used` as a sorted set (determinism preserved). Do not re-resolve staleness inside `portage-world`, and do not invent a second definition of "stale binding": reuse the scan's verdict. Cost: cross-crate plumbing versus (b)'s one-filter change; that cost is why (b) goes first.

Candidate the plan rejects unless both (a) and (b) fail the probe while the bed stays clean: dropping the exclusion outright and accepting the perl-cluster churn. Its measured cost is already on record (10 new `build-order` findings on a 176-row bed plan, code note `## fn runtime_cut`); re-measure on the current bed before even considering it, and take the owner's call.

Grounding: charter property 2 (order is legal) and PMS 8.1 (usability); Portage is a hint, not the oracle — do not copy a Portage quirk (`LLM/portage-quirks.md`).
