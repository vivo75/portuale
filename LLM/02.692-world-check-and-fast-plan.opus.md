## 2. What the PMS says, and where it is silent

Sources: `3rdparty/gentoo/proj/pms/`.

- **Order (`dependencies.tex`, `sec:dependency-classes`).** `DEPEND` (and
  `BDEPEND`) "must be installed and usable before the `pkg_setup` phase";
  `RDEPEND` "before the results of an ebuild merging are treated as usable";
  `PDEPEND` "at some point before the package manager finishes the batch of
  installs". So a `PDEPEND`-only edge puts no constraint on order. This
  settles #693's open question: `--sort depend` must leave `PDEPEND` out.
  `World::edge_kinds` has carried the kind of every edge since `2f00eccd`, so
  the sentence "the edges do not tell `RDEPEND` from `PDEPEND`" in `order.rs`
  and in #693 is stale.
- **An unchanged installed package contributes only `RDEPEND` and `PDEPEND`**
  (the library's rule): consistent with the same section, build dependencies
  bind only a build.
- **Slot operators (`dependencies.tex`, `sec:slot-dep`).** With `:=` the
  package "will break unless a matching package with slot and sub-slot equal
  to the slot and sub-slot of the best version installed as a build-time
  dependency is available". A plan that upgrades a provider across a sub-slot
  and does not rebuild its `:=` consumers breaks property 1. The `R` rows for
  this case are required by the PMS, not copied from Portage. `:=` is invalid
  in `PDEPEND` and inside `||`, so only `DEPEND`/`RDEPEND`/`BDEPEND`/`IDEPEND`
  edges count.
- **Metadata cache (`metadata-cache.tex`).** "The metadata cache may be
  incomplete or non-existent, and may contain additional bogus entries." A
  missing entry is therefore a normal state, not a missing package; dropping
  such an ebuild's dependencies in silence (#692 d) is the defect.
- **USE dependencies (`dependencies.tex`, `sec:use-dep`).** A flag named by a
  use dependency without a `(+)`/`(-)` default must be in the target's
  `IUSE_EFFECTIVE`. The library's known cut ("an implicit-IUSE flag that is
  off is judged undeclared") can therefore produce a false `NO MATCH`. S0
  checks whether it does on this host; if so it gets backlog #737.
- **Silent:** `@world`, `--update`, `--deep`, `--emptytree`, `--newuse`, the
  world file, and which visible version is "best". These are the package
  manager's own. The charter's property 3 covers "best"; the rest is the
  owner's (Q1, Q4, Q5). Nothing here may be justified with "Portage does it".

### A2 — `mrg --check-world --json` (#692 b)

- Shape: one JSON object per line, the fields of `health_checker.Finding`
  (`property`, `package`, `atom`, `reason`, `pre_existing`), so
  `health-report.py` groups them unchanged. Properties: `world-invalid`,
  `world-no-match` (failures), `checker-limitation` for A1's rows,
  `world-unneeded` only under the future option. Then one summary object
  `{"atoms":…, "slots":…, "unsatisfiable":…, "not_read":…}`.
- Red tests in `check_world.rs`: a clean world prints only the summary and
  exits 0; a missing package gives one `world-no-match` line whose `package`
  is the asker and `atom` the atom. Exit codes are those of the text form.
- pmtest: add `world-invalid`, `world-no-match`, `world-unneeded` to the
  report's known names; `world-unneeded` joins `NOT_FAILURES`. One test in
  `test_health_checker.py` that the report reads a `--check-world --json`
  file.
- Text and JSON are produced from one list of findings, not two loops.

### B2 — `mrg --plan-world --json`, judged by `health_checker.py` (#693)

- Shape: what `emerge -pv --json` prints and `load_plan` reads: `entries`

  `required_use`, `source`) and `kept`. First step of the slice: read the

- Red test (pmtest, `test_health_checker.py`): plan the fixture world with

- Rust test in `plan_world.rs`: the JSON rows equal the text rows, in order.
- Fold the shared option setup of `check_world::run` and `plan_world::run`

  `check-world-threads` too.

### A3 — mutation test for `--check-world` (#692 c)

- New `../pmtest/differential-test-bed/compare/check-world-mutants.py`, in
  the style of `health-mutants.py`. It copies the fixture config root and
  repositories (`symlinks=True`), asserts the clean copy exits 0, then per
  operator applies one change and requires exit 1 and a finding that names
  the mutated package:
  `mask_best` (a line in the profile's `package.mask`), `drop_keyword`
  (ebuild and its md5-cache entry, `_md5_` recomputed), `raise_bound` (a
  `>=` atom of a consumer raised above every version), `remove_package`
  (a package `@world` names deleted, cache included), `unreadable` (cache
  entry deleted, no provider: A1's finding). Control `harmless`: a mask on a
  package nobody reaches; the report must stay identical.
- Exit 1 when a mutant survives or the control changes. Each mutant prints
  the diff of the tree it made, so a no-op mutation is visible.
- `pytests-contract-suite/test_check_world_mutants.py` runs it on the
  fixtures; it is part of the suite.

### B3a — rebuild rows for slot operators (#693)

- Ground: §2, `sec:slot-dep`. An installed package whose recorded
  `:slot/sub-slot=` no longer matches the version the plan chooses gets
  `[ebuild   R    ]` and its build-time edges (it is rebuilt, so the
  library's "rebuilt follows every edge" rule applies).
- Reuse the `@changed-subslot` computation in `sets.rs` (tested in #701 g)
  instead of a second reader of the VDB; if it cannot take a chosen version
  as input, extend it, do not copy it.
- Red tests: `plan_world.rs`, a provider upgraded across a sub-slot lists its
  `:=` consumer as `R` after it; a `:*` consumer is not listed. pmtest: the
  `bump_sub_slot`/`drop_slot_rebuild` operators of `health-mutants.py`
  already cover the checker side; B2's fixture test gains this case and must
  go from a `runtime-deps` failure (red) to clean (green).
- Measure after: the `resolver-only` reinstalls of A4 that remain.

### B3b — rebuild rows for changed USE (Q4 = yes)

Installed `USE` restricted to `IUSE` against the configured one, per
installed package in the reached set; `R` with no claim about order. Alpha
future option `plan-world-newuse`.

### B4 — `--plan-world=emptytree` (Q1 accepted)

Every reached slot is a row (`N`, `U`, `D` or `R`), `with_bdeps` forced on
(everything is built, so every build edge binds, §2). Test: row count equals
`world.reached` minus invalid slots on the fixture world. `-up`: not built
(Q5), recorded in #693.

### B5 — the command says what it did not check (property 5)

The stderr summary of `--plan-world` becomes two lines: the count and order,
then `not checked: blockers, REQUIRED_USE, slot conflicts[, USE rebuilds];
run 'mrg -puDN @world' for the full plan`. Pinned in pmtest
(`test_future_options.py` neighbour or a new `test_plan_world.py`), docstring
source: charter property 5. `docs/` gets a short section for both actions
