### C2 — critical — portuale drops argument atoms from the conflict atoms; Portage counts them (proven for the divergence, likely for each count)

**Evidence.**
- `slot_conflict_mask_choices` skips every puller with an empty category,
  that is the top-level argument (`backtrack_params.rs:66-79`). The comment
  says they "match every version and never discriminate".
- That is false for versioned arguments. In Portage the argument is an
  `AtomArg` parent in `_parent_atoms` and joins `slot_parent_atoms`
  (D:2161-2166). `s0b.md` §1, cgp VER `>=cgp1x-2`: "choice[1] masks {cgp1x-1
  ebuild, cgp1x-0.1, cgp1x-1 installed} … Its atom is the argument
  `>=cgp1x-2`". VER-down: choice[0]'s atom is the argument `<cgp1x-1`.

**Divergence.** On the five keeper cells whose merge version only the
argument wants (k3 `=paired-2.0`, igw `>=igw0x-2` / `<igw0x-1`, cgp VER both
forms; #54 K3, #222, #223):
- the "mask installed" choice gets 0 parents in portuale where Portage has 1.
  It sorts first instead of being tied, so the pop order flips. Portage
  explores "mask installed" first; portuale would explore "mask merge"
  first;
- with 0 parents, the similar-package loop is skipped altogether
  (`backtrack_params.rs:98`). On VER-down, Portage's choice {2, 1e, 1i}
  becomes portuale's {1, 1[installed]}: version 2 is not masked, so the
  consumer `>=cgp1x-1` can be met by 2 in that pass. The dead-end shape, and
  maybe the count and the residual, then differ.

This holds whether 10a feeds the arguments in through `slot_pullers` or
through the record's `instances[*].parents`. The plan's "Conflict atoms =
union of the parents of every slot node" never says that the empty-category
filter has to go.

**Fix.** Add to the 10a "Conflict atoms" rule:
- argument atoms (`(Argument)` parents) are conflict atoms like any other
  (D:2161-2166);
- they are never "masked" for `check_runtime_pkg_mask`, because an `AtomArg`
  is never in `runtime_pkg_mask` (B:162);
- remove or narrow the empty-category skip at `backtrack_params.rs:71`.

The skip is shared with walker conflicts, so a global change can move other
cells. Either scope it to records that carry consumer parents, or extend the
S0e count list with every CASES row whose slot conflict has a versioned
argument parent. Add a RED on the cgp VER-down shape that asserts Portage's
try-by-try mask sets from `s0b.md` §1.

### M9 — major — 10b's per-pass view rule does not map onto where portuale evaluates the consumer (likely)

**Evidence.**

   forced by a slot conflict while backtracking at D:9473-9480. "PostMerge

### M10 — major — the Q19 sibling-virtual rule is not implementable as written (likely)

**Evidence.**

  virtuals**, for example `dev-perl/List-MoreUtils-XS`.
  `_select_atoms_highest_available` builds `chosen_atom_ids` from that
  parent's `mycheck[1]` and filters each virtual's `atom_graph` children

1. which parent's dep string is evaluated (an installed or merge-bound
   package with several `virtual/*` deps, reached in the pass);
2. that each virtual reached through that parent gets, as parent atoms,
   those of its dep-string atoms equal (text **and** declaring EAPI, plus
   the unevaluated form) to an atom chosen anywhere in that parent's
   dep_check;
3. one RED on a two-virtual fixture whose virtuals have different arm
   orders, plus one with differing EAPI, so the "same EAPI" leg is pinned.

Also fix the quirk entry: Q19 "Portuale: copied" should read "to be copied
by plan 02.589 10b". Nothing copies it yet.
