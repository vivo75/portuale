# 06.757 — the volatile-name filter at the four sites that copy the vdb

Status: proposed

## 0. What this fixes

`fixtures_copytree_ignore()` (`pytests-contract-suite/conftest.py:580`) exists
precisely because a copy of the shared fixture tree can list
`var/db/.pkg.portage_lockfile` a microsecond before its owner deletes it, and
then die with `ENOENT`/`shutil.Error`. Its docstring says so; #754 put the
same idea into the mutant harness. Almost every site in the pytest suite
uses the pattern. Four do not, and they are the ones that copy the vdb.

**Scope of the claim: the pytest suite (`pytests-contract-suite/`).** Not
whole-repo: `differential-test-bed/compare/health-state-mutants.py:83,124`
also copies bare, but its sources are `var/db/pkg/*` while the lock lives in
`var/db/`, one level up and unreachable by path — stated here so a reader
does not go looking for a fifth site there.

| Site | What it copies |
|---|---|
| `test_emerge_pretend_contract.py:39048` (`test_skipped_update_block_names_every_installed_consumer`) | `<ROOT>/var` |
| `test_emerge_pretend_contract.py:39886` (`_698_root`) | `<ROOT>/var` |
| `test_emerge_pretend_contract.py:40041` (`test_715_the_provider_is_merged_before_the_holders_rebuilt_for_it`) | `<ROOT>/var` |
| `test_health_checker.py:1230` | the whole `<ROOT>` |

Observed, not theorised: `/var/tmp/755-after.log` has `test_733…[pubgrub]`
failing with `shutil.Error` naming that lockfile, and the #755 bless run had
`test_698_a_holder_without_a_route_still_withholds_the_upgrade[portage]`
fail the same way (both pass solo, 2/2).

## 1. Decisions `[default sicuro]`

- **D1 — widen the predicate, not the call sites.** `fixtures_copytree_ignore`
  currently drops three literals. The shape #754 and portuale's `vdb_rw.rs`
  both guard is wider: the lock, its hardlink siblings
  (`.portage_lockfile.hardlock-*`) and the inode-test probes (`*-inode-test`),
  plus the seeder's files. The suite creates none of those today — so this is
  not a live hole — but a predicate that fixes one filename does not fix the
  class, and the next writer who hardlinks will not remember. Mirror
  `is_volatile_name` (`differential-test-bed/compare/check-world-mutants.py:71-74`)
  in the conftest predicate, with the same names, and keep the docstring
  saying why.
- **D2 — apply it to the four sites; convert nothing else.**
  ~111 callers already pass `ignore=fixtures_copytree_ignore(...)` and are
  correct. Rewriting them buys no protection and each edit can silently lose
  a site-specific `extra=` (the two `extra=("mtimedb")` sites,
  `test_portuale.py:5014` and `:12300`, need it: a copy must start
  record-free) or flip a `symlinks=` default. Four edits, four risks.
- **D3 — no new helper.** A `copy_fixture_tree(...)` used at four sites out of
  115 is a second way to copy plus a new parameter to get wrong (a caller
  passing `ignore=` would have to be given merge-never-replace semantics to
  stay safe). The seam that matters is the predicate, and it is already
  shared. `shutil.copytree(..., ignore=fixtures_copytree_ignore())` at the
  four sites, exactly as the other 111 do it.

## 2. The pin (the half that matters)

A test in `pytests-contract-suite/test_emerge_pretend_contract.py`:

1. scratch source tree with `var/db/pkg/<cpv>/…`,
   `var/db/.pkg.portage_lockfile`, `var/db/.portage_lockfile.hardlock-1`,
   `var/db/pkg/.pkg.portage_lockfile-inode-test`, `var/lib/portage/.mtimedb.tmp.123`,
   `var/lib/portage/.mtimedb.seed.lock`;
2. `shutil.copytree(src, dst, symlinks=True, ignore=fixtures_copytree_ignore())`;
3. assert the package entry is present and **no volatile name travelled** —
   every one of the six is absent from `dst`;
4. assert a non-volatile sibling *does* travel (so the filter is not "skip
   everything").

Red-first: against a bare `shutil.copytree` step 3 fails (the lock travels).
The planting is deterministic; no race is needed, and the race is only the
reason the names must not travel — a *copied* lock is both useless and, when
its owner deletes it mid-listing, fatal. The hardlink and inode-test names
make the pin cover D1's widened predicate, not just today's three strings.

## 4. STOP rules

- **STOP-0**: a converted site's test starts failing for a reason other than
  the volatile names (e.g. it needed the lock present) → STOP and report; the
  filter is right, the site's expectation is not.
- **STOP-1**: `pytest-parallel.sh` totals move by anything other than the
  added pin → STOP; a harness change must not silently drop a test.
- **STOP-2**: the widened predicate hides a name some test needs (check
  `mtimedb`: it must keep riding along — only `.mtimedb.seed.lock` and
  `.mtimedb.tmp.*` are transient) → STOP and narrow it with the reason
  recorded.
