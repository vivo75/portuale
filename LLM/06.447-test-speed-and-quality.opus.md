# Plan 06.447 — faster, leaner tests (backlog #447–#451; #443 unscheduled)

Status: in progress (2026-10-20, branch tests-speed). #447, #448, #449 done;
#450/#451 optional after re-measuring; #443 unscheduled. Results (same host):

| | before | after |
|---|---|---|
| contract suite | 632 s serial | ~90 s with `pmtest/scripts/pytest-parallel.sh` (8 workers), 4206 passed; serial about 475 s by subtraction (metamorphic 171 -> 12 s), not re-run serially |
| `cargo test --release` | ~258 s | 19.6 s (warm build) |

Findings that changed the plan: the 171 s metamorphic test was vacuous (it
compared identical `resolving profile` errors, `copytree` without
`symlinks=True`); one Rust test held 183 s of 196 s; xdist is the biggest
lever, not de-duplication.
 Owner goal: tests are the product's proof, but
they now take a large share of development time; improve their quality while
cutting the time. Portage is updated every few months, so comparisons against
Portage should be paid for once per Portage version, not on every run.

Scope: the contract suite (`../pmtest/pytests-contract-suite`), the Rust
workspace tests, the corpus and the bed atomlists. Plans, backlog and numbers
live here (see `pmtest/AGENTS.md`); fixtures and pins ride in pmtest commits.

## 1. Slices (order = value/risk)

- **S1 (#447) — Rust per-test time profile.** Get per-test durations for the
  `portuale` crate (nightly `--report-time`, or `cargo nextest` if the owner
  accepts installing it, or a tiny wrapper timing each test binary filter);
  write the ranking to `LLM/evidence/`. Decides S5. Mechanical; Haiku.
- **S2 (#448) — Portage-answer cache keyed on the Portage version + repo
  pins.** Cache the answers of Portage's Python harnesses (atom/use_reduce/
  versions `*_between_implementations`, 95 s + parts of others) in a file
  keyed by `emerge --version` and `differential-test-bed/repo-pins.txt`
  (pmtest, already committed with this plan). A miss, or `PMTEST_REFRESH_PORTAGE=1`,
  re-runs Portage and rewrites the cache; a Portage or repo bump invalidates it
  by key. Record Portage's version in every bed run's `pm.json` and call
  `scripts/repo-pins.sh --check` at bed start. Rule 4 of AGENTS.md still holds:
  the cache stores Portage's answer, never portuale's.
- **S3 (#449) — metamorphic + invariants budget (171 s + 44 s).** Measure which
  transforms/cases ever caught anything (mutation check: break the Rust on
  purpose for each transform), then shrink the subset to the cases that matter
  and run the 5 transforms in one pass per case where the process cost is
  startup. Property tests keep their guarantee; the choice is evidence-based.
- **S4 (#450) — collapse duplicate tests and checks.** (a) the 72 identical-body
  groups and the pg34/pg367 matrix become table-driven tests (same expected
  data, same Portage-capture docstrings); (b) a `CASES` row whose argv has a
  dedicated pinned test stops running a separate rc assertion; (c) corpus
  `contract.json.xz` entries that duplicate pinned tests are dropped with a
  reviewed `PORTUALE_CORPUS_BLESS=1`; (d) merge the `l0-fixture-oracle-*`
  sub-lists. Gate: the set of covered argv shrinks only where another check
  pins the same bytes; list removed items in the commit.
- **S5 (#451) — Rust `portuale` crate slow tests.** From S1: share fixtures/
  builds between tests, move end-to-end cases that duplicate a contract-suite
  pin to the suite, and mark the few heavy merge/sandbox tests so the default
  run skips them while CI/close-out runs them (`cargo test -- --ignored`).
  `test_portuale.py` (150 s) gets the same review.
- **S6 (#443) — asciinema recording and comparison**, as filed; the owner
  does not mind when (or whether) it is done, so it is not scheduled against
  S2–S5. Short/pretend cells only; timing is
  a report, never a gate (owner answers 2026-10-20).
- **S7 — measure again** (same two commands, same host), write the before/after
  table into this file and `LLM/what-this-proves.md`, flip this plan to done
  in the commit that closes #451 (AGENTS.md rule 11).

## 3. Rules for this plan

1. A test is removed only if another test pins the same bytes — name it in the
   commit. Time saved is reported next to what was removed.
2. Baseline by test name before and after each slice (not counts).
3. The full verification pass of AGENTS.md step 8 runs at the end of each slice;
   a merge-path change still needs the glibc/bash test merge.
4. Pins for Portage-version-dependent expectations cite the Portage version
   and `repo-pins.txt` values they were taken under.
