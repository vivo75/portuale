## 2. New findings

### Critical

**N-C1 (D, proven by scratch run). `extract_block.py` cannot put the new function in the host file. Rule 5's sibling file only works for `mod.rs` hosts.**

- **Mechanism.** `render()` writes SRC (the cut text), then writes TARGET_RS from `self.orig_target`, the target as read at `__init__` (`extract_block.py:477-484`). When TARGET_RS is SRC, the second write restores the uncut host and appends the new function.
- **Reproduced** with `Cut('host.rs',3,3,'step_b','host.rs',…).render(False)`: the host still contained line 3, and `step_b` was appended.
- **Sibling files.** A new TARGET_RS is declared (`mod x; pub(crate) use x::*;`) only when SRC is a `mod.rs` (`:238-240`). Every host in this plan except `pretend/mod.rs` (D6 `run`) is a plain `x.rs`: `pretend.rs`, `assemble.rs`, `select_nodes.rs`, `entry_line.rs`, …. For those, a sibling file is never wired in, the call site cannot resolve, and the tool exits with "no type for …".
- **Impact.** Method §0.4 step 2 plus rule 5 cannot be executed for any slice. Slice 3 ended with its steps in the host files, so its worker did something by hand that the plan does not describe.
- **Fix (tool change in Task 0, a tool not product code).** In `render()`, when `os.path.abspath(self.target) == os.path.abspath(self.src)`, set `base = "\n".join(new_src)` and write the file once. Add a regression check to Task 0 (the two-line scratch case above). Then rewrite rule 5 as: new functions go in the host file. This is slice 3's precedent and also answers muse I3. Use a new file only when the host already is a `mod.rs` directory module.

**N-C2 (D, proven by scratch run). In `--loop` mode, an assignment to a Copy local declared outside the range is lost when the helper exits through `continue`. R5 hits this three times.**

- **Mechanism.** A written Copy parameter becomes `x_out: &mut T`, with `let mut x = *x_out;` on entry and `*x_out = x;` only in the fall-through tail (`:410`, `:421`, `:461`). A host `continue` becomes `return ControlFlow::Break(())` with no write-back (`:268-270`); `flatten_flow.py` turns it into `return;`, still with no write-back.
- **Reproduced:** `flag = false; return ControlFlow::Break(());` ends up in the helper and `*flag_out` is never written.
- **Hits in R5** (`select_nodes.rs`; `prefer_asap` and `drop_satisfied` are declared at `:14-15`, outside the `while` at `:74`):
  - second rung: `prefer_asap = false; continue;` at `:246-247`;
  - stuck branch: `prefer_asap = true; drop_satisfied = false; continue;` at `:283-285`;
  - admission: the same assignments at `:298-300`.
- **Effect.** After the cut, the next iteration sees the old flags. Merge order changes, or the loop spins. rustc emits an `unused_assignments` warning, which the tool does not print. A worker "fixing the clippy warning" by deleting the assignment makes the bug permanent. Slice 2 hit this class and worked around it by moving the loop locals into `PassState` (commit `79026688` body). That is a non-verbatim change the plan's own constraints forbid.
- **Fix, choose one and write it into the plan:**
  - (a) Tool: emit the write-back lines before every `return ControlFlow::Break(..)` / `return;` the tool generates. This is a ~3-line change at `:268-270` and `flatten_flow.py:31`.
  - (b) Allow, in §0.4, the slice-2 move of loop-carried Copy locals into a small `struct` the helper takes `&mut`. Name it as an allowed edit, and list R5's `prefer_asap` / `drop_satisfied`.
  - Either way, add a Task 0 test (the scratch case above) and add to R5: "MO_SEL trace identical", using a real capture (N-I9).

**N-C3 (D, proven by scratch run). A bare `return;` in a non-loop cut of a `()`-returning host silently becomes a return from the helper. R4 hits this.**

- **Mechanism.** `wrap_returns` skips `return;` by design ("a closure's or loop helper's", `:144-148`), so `self.returns` stays `False`. The helper gets `return;` and the host continues.
- **Reproduced:** `if n == 0 { return; }` was cut into `guard(n)`, and `tail()` then ran for `n == 0`.
- **R4 hit.** `expand_resolved_slot_with_flipped_use` returns `()`. Cut `481–547 → enqueue_new_tokens` contains `if new_toks.is_empty() { return; }` (`slot_expand.rs:489-491`) and `if kept_toks.is_empty() { return; }` (`:513-515`). After the cut, the host goes on to `new_targets` (559) and the test-deps block (573–633) when it used to return. That is a resolver change that compiles cleanly.
- **Same class**, failing loudly instead (see N-I5): the let-else cuts `314–412` (`else { return; }` at `:410-412`) and `enqueue.rs 196–283` (`:281-283`).
- **Fix.**
  - Tool: in non-loop mode, when the host returns `()` and the range contains a top-level bare `return;` (outside closures), treat it like `--ret`, giving `ControlFlow<()>` plus `if f(..).is_break() { return; }`. Or refuse with a message.
  - Plan: split R4's `enqueue_new_tokens` at the two guards, or keep the guards in the host. Add an explicit §0.4 rule: "a bare `return;` in a `()` host must become `ControlFlow::Break(())` and `if …is_break() { return; }`" (slice 3's convention, which is what the plan names but the tool does not do).
