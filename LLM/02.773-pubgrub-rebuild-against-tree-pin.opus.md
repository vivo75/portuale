## 0. Premise and what grounding found

Root `a10` (`LLM/evidence/02.766/mkroots.sh` style): world gains `dev-libs/p569prov`;
installed `dev-libs/p573virt-1` records `RDEPEND="dev-libs/p569prov:0/5.42="` and is in no
world. Its tree ebuild has `RDEPEND="=dev-libs/p569prov-5.42* dev-libs/p569prov:="`. The
installed provider is `p569prov-5.42`; the tree's best is `5.44` (`0/5.44`). The shared
fixture VDB also holds `p569virt-1`, recorded `|| ( =…5.42* … ) dev-libs/p569prov:0/5.42=`.

Captured on 2026-11-22 with the binary of `466b1a2e`,
`emerge --pretend --verbose --update --deep --newuse --getbinpkg=n @world` (all rc 0):

| Planner | Rows | Messages |
|---|---|---|
| default solver | `[ebuild  rR    ] dev-libs/p573virt-1`; no row for `p569prov` | `WARNING: One or more updates/rebuilds have been skipped due to a dependency conflict:` `dev-libs/p569prov:0` … `=dev-libs/p569prov-5.42* required by (dev-libs/p573virt-1 …)` |
| `--solver=pubgrub` | `[ebuild     U  ] dev-libs/p569prov-5.44 [5.42]` **and** `[ebuild  rR    ] dev-libs/p573virt-1` | the stale-binding NOTE names `p569virt-1` only; "`p569prov-5.44` … causes rebuilds for: `p573virt-1`" |
| `mrg --plan-world` (before runbook 1) | `U p569prov-5.44` | `2 stale slot-operator binding(s) not rebuilt: dev-libs/p569virt (…, no visible ebuild), dev-libs/p573virt (…, no visible ebuild)` |

After runbook 1 the fast plan is expected to print `R p573virt-1`, `R p569virt-1`,
`N p569core-1.0` and no `U p569prov` (runbook 1 Task 5 Step 7). `p573virt` comes from the
Q-C side effect, as in the default solver's outcome. `p569virt` (the shared VDB's,
stale outside the walk in iteration 1) is rebuilt through its recorded `||`'s
`~p569core-1.0` arm by the owner decision of 2026-11-22. It stays a rebuild after the
seeded `p573virt` keeps the provider at 5.42, because the rebuild set never shrinks
(needless work, residue #777).

**The defect:** the pubgrub plan merges `p569prov-5.44` and then rebuilds `p573virt-1`,
whose ebuild requires `=dev-libs/p569prov-5.42*`. That rebuild cannot have its
dependencies met. Property 1 is broken, and nothing says so (property 5).

**The cause, by source (not traced; S0 confirms it):** the rebuild is scheduled by the
stale-pin arm of the shared scan (`stale_pin_for_consumer`,
`crates/portage-repo/src/slot_operator/rebuild_scan.rs`). Its `repairable` check asks the
consumer's tree ebuild twice, and both questions miss the pin:

1. `replacement_accepts` (`slot_operator/force_scan.rs`, the `.filter_map` near `:462`)
   drops every tree atom that matches the *installed* provider
   (`!atom_matches_installed_instance`). `=dev-libs/p569prov-5.42*` matches the installed
   5.42, so it is dropped and constrains nothing. That is right while the provider stays;
   it is wrong once the plan has moved it.
2. `replacement_parent_accepts` (`slot_operator/abi_probe.rs`, near `:983`) returns true
   as soon as **one** tree atom on the provider accepts the candidate.
   `dev-libs/p569prov:=` accepts 5.44, so the versioned pin is never judged.

On the default solver the scheduled rebuild becomes a walked node of the next pass; its
tree pin then conflicts with the upgrade and the upgrade is skipped with the WARNING. The
pubgrub bridge re-drives no pass (`slot_operator_rebuild_entries`,
`slot_operator/eliminate.rs`: "the engine re-drives no pass, so it keeps the post-pass
synthesiser"), so the rebuild row is added to a plan that was already solved with the
provider at 5.44.

**Two observations, not part of this item:**

- The default solver's own plan on `a10` rebuilds `p573virt-1` although it keeps
  `p569prov` at 5.42, where the recorded `:0/5.42=` binding is not stale. A rebuild that
  repairs nothing is a property-3 question (needless work). Residue #790 if the owner
  wants it looked at.
- Backlog #769 says of this shape (its class A10) "rebuilt by the fast plan, silent in the
  resolver". Both halves are false; runbook 1 corrects that entry.

## 1. Questions

- **[OWNER, blocks S1] Q1 — what should the pubgrub plan do on this shape?**
  - **(A) Refuse the rebuild and name the consumer (recommended).** The plan keeps
    `U p569prov-5.44`; `p573virt-1` is not rebuilt and joins the stale-binding NOTE:
    `dev-libs/p573virt-1: its dependency =dev-libs/p569prov-5.42* is not satisfied by dev-libs/p569prov-5.44`.
    This is how the same plan already treats `p569virt-1`, whose *recorded* text carries
    the pin; here the pin is in the tree text. Small (about 30 lines in the shared scan,
    behind a flag only the bridge sets), no new text. Cost: pubgrub then differs from the
    default solver and from the fast plan, which both hold the provider back.
  - **(B) Hold the provider back, like the default solver.** The three planners agree.
    The bridge has to re-solve with the provider pinned; the code that does this kind of
    thing is `holder_fix`, which has an open defect of its own on a neighbouring shape
    (residue #781 of plan 02.770: it ignores an `||` arm on another package). Larger,
    needs its own plan from a stronger model after #781; S1 below does not cover it.
  - **(C) Leave it and document it** as a pubgrub limitation (CUT entry). Property 1 says
    no; listed for completeness.
- **[default sicuro] Q2 — where the check lives (option A).** In the shared scan, behind a
  new argument `tree_pin_refuses: bool`. The bridge passes `true`. The default solver's
  callers pass `false`: there the next pass walks the rebuild and judges the pin itself,
  and changing its answer would move L0 rows nobody asked to move.
- **[default sicuro] Q3 — which tree atoms count (option A).** The atoms of the consumer's
  tree ebuild at its installed version, read with `selected_parent_atoms` (each `||` group
  gives only its chosen arm), on the provider's package, non-blockers. Any one that does
  not match the provider version the run leaves behind refuses. This is
  `replacement_accepts` without the installed-instance filter. It deliberately does not
  use `provider_atoms`, which flattens every `||` arm (the #781 trap).
  Known limit (review F11, 2026-11-22): `selected_parent_atoms` picks an arm in-graph
  first, then installed. When the arm that would accept the new provider names a package
  the pubgrub plan does not merge, the check refuses, although the default solver would
  pull that package in and rebuild. The witnesses are safe (on `pull`, pubgrub's plan has
  `N p569core-1.0`, captured 2026-11-22). Write this limit into the code note (Step 6)
  and add it to residue #781's text at close-out; do not widen the check.
- **[default sicuro] Q4 — no new message text.** The existing NOTE row is used; the atom
  shown is the tree atom.

```rust
    /// The atom of the consumer's tree ebuild that rejects the provider
    /// version the run leaves behind on one of `edges`, as a refusal. Each
    /// `||` group counts through its chosen arm only.
    fn tree_held_back(
        &self,
        pkg: &InstalledPackage,
        stale_keys: &[&str],
        edges: &[StaleEdge],
    ) -> Option<StalePinRefusal> {
        let live = live_metadata_for_installed(
            self.gate.repos,
            self.root,
            &pkg.category,
            &pkg.package,
            &pkg.version,
        )?;
        let use_flags =
            read_vdb_flag_set(self.root, &pkg.category, &pkg.package, &pkg.version, "USE");
        for edge in edges {
            for tok in stale_keys.iter().flat_map(|key| {
                selected_parent_atoms(
                    live.get(*key).map(String::as_str).unwrap_or_default(),
                    self.root,
                    self.entries,
                    &use_flags,
                )
            }) {
                let Some(atom) = parse_dep_atom(&tok, "rebuild_scan_tree_pin") else {
                    continue;
                };
                if atom.blocker != portage_dep::Blocker::None
                    || (atom.category.clone(), atom.package.clone()) != edge.provider_cp
                {
                    continue;
                }
                if portage_dep::match_from_list(portage_dep::without_use(&tok), &[edge.cand.as_str()])
                    .is_none_or(|m| m.is_empty())
                {
                    return Some(StalePinRefusal {
                        consumer: pkg.cpv(),
                        atom: tok,
                        provider: format!(
                            "{}/{}-{}",
                            edge.provider_cp.0, edge.provider_cp.1, edge.final_version
                        ),
                        no_ebuild: false,
                    });
                }
            }
        }
        None
    }
```
