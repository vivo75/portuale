"a slot with `change() == Some(Change::Rebuild)` exists" cannot hold: `SlotSet::change`
(`reorder.rs:57-67`) never returns `Rebuild`. Only `World::change` (`order.rs:32-38`) does. To close the

needs `reached`).

### G2. Q-C's side effects are not predicted. Not blocking. **Likely** (source); the resolver half is proven.
Seeding brings the consumer's **tree** dependencies into the walk. That can change other slots, not just
the consumer's own version:
- On `a10`, the seeded `p573virt` adds the requester `=dev-libs/p569prov-5.42*`. `reorder`
  (`reorder.rs:117-140`) then chooses `5.42`, the provider stops moving, and the fixpoint returns
  `rebuilds = {p573virt}`, because `rebuilds` never shrinks. The result is an `R p573virt-1` row and no
  `U p569prov`.
- That matches the default solver (captured, D6), but only by accident. In general a seed can also
  hold back a world package's upgrade with no message, which is charter property 5.

S1 should state the expected `a10` outcome. Add a Rust case for "a seeded consumer's tree pins the
provider", asserting both the row and the unmoved provider, and record the decision.

### G3. Q-C's requester check greps the wrong thing. Not blocking.

(`wants {atom}  <- {by}`). Neither path runs with `opts.rebuilds` (`check_world` never sets it), so
seeding renders nothing today. Replace STOP-2's "rendered requester string" with this concrete
statement, or with a test that `check-world` output is unchanged.

### G4. Q-B's signature does not compile as written. Not blocking.
`best_visible_in_slot(…) -> Option<&Candidate>` cannot borrow from `list_candidates`, which returns a
fresh `Arc<Vec<Candidate>>` (`candidates.rs:150-154`). The existing caller also filters by `a.slot:
Option` (no slot means any slot, `lib.rs:322-326`). Use `Option<&str>` for the slot and return an owned
`Candidate` (or the `Arc` plus an index).
