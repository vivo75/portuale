## D — defects (in the plan's verification design)

### D1 — blocking — the vdb-expand probes, the trace and L0 never reach the changed function (proven, source read)

- Where: plan §3 S0.2 (the three appended argv and their `PORTUALE_PG_TRACE=1`
  reruns), S0.4 and S2 (L0), §1 Q4, and STOP-1/STOP-3.
- Facts: `build_relaxed` is reached only through `resolve_pubgrub_at`
  (`solver_bridge.rs:5494`) ← `resolve_pubgrub` (`:5315`) ← `PubGrubResolver::resolve`
  (`:4058-4060`). That resolver is selected only for `SolverKind::PubGrub`
  (`crates/portage-repo/src/resolve/resolver.rs:73-77`). The default is
  `SolverKind::Portage` → `BacktrackingResolver` (`resolver.rs:13-14`).
  `pg_trace` / `pg-closure` lines (`:323-329`) are printed only inside
  `build_relaxed`.
- Divergence shape:
  - The input `emerge --pretend --update --deep dev-libs/p698upg` (and the
    `--emptytree diamond` and `--deep @world` ones), with or without
    `PORTUALE_PG_TRACE=1`, runs on the default solver. `build_relaxed` is never
    called, so the stdout/stderr hashes cannot move and the trace hash is the hash
    of nothing.
  - `l0-resolver.sh` without `L0_PORTUALE_OPTS=--solver=pubgrub`
    (`../pmtest/differential-test-bed/README.md:153-166`) runs the default solver,
    so the L0 before/after pair is equally non-discriminating, at the cost of two
    full bed runs.
  - In the inherited 13-argv set, only the 9 `--solver=pubgrub` argv touch the
    function, and none of them passes `--deep`/`--emptytree`, so the `vdb_expand`
    factor the slice rewrites is exercised by no probe at all.
- Fix direction:
  - Add `--solver=pubgrub` to every appended argv and to its trace rerun.
  - If L0 is kept, run it as `L0_PORTUALE_OPTS=--solver=pubgrub` (the bed's
    `l0-pubgrub` mode). Otherwise drop L0 by owner decision, since the default
    resolver is untouched (see P1).
  - Add a check to S0 that each trace capture contains at least one
    `pg-closure … expanded` line and at least one `… shallow` line, so an empty
    trace cannot pass.

### D2 — not blocking — `dev-libs/p698upg` is not installed in the shared fixture root (proven)

- `fixtures/var/db/pkg/dev-libs/` has no `p698*` entry. The p698 tests synthesize
  their own root (`crates/portage-repo/src/tests/tests_p698.rs:13`, `p698_root`).
- On the plain fixture root, `--update --deep dev-libs/p698upg` therefore exercises
  no installed-cone expansion of p698.
- The fixtures built for exactly this code path are the #34 `pg34-*` ones:
  `pg34-arg` (installed and named, so seed-and-installed; contract rows at
  `../pmtest/pytests-contract-suite/test_emerge_pretend_contract.py:453-456`) and
  `pg34-gapp` → `pg34-gone` → `pg34-gextra` (vdb-only dep chain; unit test at
  `solver_bridge.rs:6947-6960`).
- `--deep @world` with pubgrub does reach `vdb_expand`, because the shared vdb holds
  223 cpvs.
- Fix direction: replace the p698upg probe with
  `--pretend -v --solver=pubgrub --update --deep dev-libs/pg34-gapp` and
  `--pretend -v --solver=pubgrub dev-libs/pg34-arg`, each also run with
  `PORTUALE_PG_TRACE=1`.
