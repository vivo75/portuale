## 3. Commits

The owner allowed commits for these runbooks (2026-11-22). **No push. No merge.**

- pmtest commits first. The portuale commit quotes the pmtest short sha in its body.
- A pmtest commit names the portuale branch and the backlog number.
- Title: `<what changed>: <short description> (#NNN)`. Plain English, no jargon.
- Body: why, and what the change is grounded in (charter property, PMS section).
- Last line: `Co-Authored-By: <the model that did the work> <noreply@anthropic.com>`,
  for example `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`.
- One commit per task that says "Commit". Never squash. Never amend a commit of another task.
- `git add` names files explicitly. Never `git add -A`: the working tree holds untracked
  files of other plans.
- The first portuale commit of runbook 1 also carries the uncommitted edit of
  `LLM/backlog-tasks.md` (owner decisions on #768/#769 and the new entry #773) and the
  plan, review and runbook files of that runbook.

## 5. Long jobs, disk space, test beds

- Before any long job: `sh LLM/tools/check-work-space.sh` (must exit 0).
- Start a long job only through a named scope, in the background:

```bash
sh LLM/tools/scope/scoperun.sh <slug> <log> <cmd> [args...]
sh LLM/tools/scope/scopewait.sh <slug> [secs]     # wait for it
sh LLM/tools/scope/ocstatus.sh <slug> <log>       # STOPPED / HUNG / RUNNING
```

- Never use `ps`, `pgrep` or `pkill` to check or stop a job.
- Never run the contract suite and a bed at the same time.
- Never run `cargo build` while a bed runs: the bed mounts `target/release` live. Probes
  use a frozen copy of the binary, made once per runbook.
- `/var/tmp` and `/tmp` are tmpfs and share RAM. Never write to `/dev/shm`. Delete your
  scratch directories (`/var/tmp/768*`, `/var/tmp/770`, `/var/tmp/771`, `/var/tmp/773`)
  when the runbook closes, and a finished suite directory (about 10 GB) before starting
  the next suite.
- Do not install programs. If a tool is missing, stop and report.

## 6. Rules for tests, fixtures and code

- **Red before green.** Write the test, run it, see it fail by assertion (not by a compile
  error), save the failing output to the runbook's `after/red*.txt`, then write the code.
- **Never change an expected value to make a test pass.** The expected values in the
  runbooks come from the plans and the owner's decisions. If the program gives another
  value after a correct implementation, that is a STOP (§7), not an edit.
- The code blocks in the runbooks were written by reading `466b1a2e`; they were not
  compiled. If a block does not compile, fix the code (a borrow, a type, a renamed
  helper). The behaviour is fixed by the tests.
- Expected behaviour comes from the charter (`docs/charter.md`), the PMS
  (`3rdparty/gentoo/proj/pms/`) and the owner's decisions, not from Portage's output. A
  test's docstring names its source.
- Fixtures: before using a new package name run
  `ls ../pmtest/fixtures/repo/*/ | grep -c <prefix>` (must print 0). Every new fixture
  ebuild needs a real md5-cache entry. Scratch ROOTs built inside a test need none.
- Call the reference package manager "Portage", never "real".
- Code comments stay short: a `///` summary and, at most, one line of why. **No backlog
  numbers, dates or history in comments.** That context goes to
  `LLM/code-notes/<crate>/<path without src/ and .rs>.md` under `## <kind> <symbol>`.
- New CASES rows in pmtest go at the END of the list.
- `LLM/what-this-proves.md` is append-only: add a paragraph at the end, never edit one.
- Backlog numbers are never reused. Reserved residue numbers: #774-#779 and #793 (runbook 1),
  #780-#784 (runbook 2), #785-#789 (runbook 4), #790-#792 (runbook 3). Before filing one,
  run `grep -nE '^[0-9]+\. \*\*' LLM/backlog-tasks*.md` and check it is still free.
  Used, as of the close-outs of 2026-11-22: #774-#778, #780, #781, #783 and #793 (runbooks
  1 and 2), #790 and #791 (runbook 3), #787 and #788 (runbook 4). The reserved numbers

## 7. STOP protocol

Each runbook lists its STOP rules. When one fires:

1. Do not fix, adapt or work around it. Do not edit a pin, a test or an allowlist.
2. Write `LLM/evidence/<runbook dir>/STOP-<rule>.md` with: the rule, the command, the
   expected output, the actual output (verbatim), and what you had changed so far.
3. Leave the working tree as it is (no `git stash`, no `git reset`).
4. End your turn with status `BLOCKED` and the path of that file.

A STOP is a correct result. Guessing past one is the failure.

## 8. Report format

End every task with: status (`DONE`, `DONE_WITH_CONCERNS`, `BLOCKED`), the commands run
and their one-line results, the files changed, the commit shas, and any difference you
saw between a document and the code.
