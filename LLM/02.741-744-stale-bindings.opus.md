## 2. The rule

1. **Which packages are scanned.** A kept installed package means "installed and not replaced by the plan" — the same set `plan_json` prints as `kept` (`plan_world.rs:143-158`, every non-replaced installed package at its main slot). `rebuild::kept` (`rebuild.rs:14-24`) filters on `World::reached` and is a second implementation of that set: **share the one source** (a `World::kept_installed()` helper used by both `plan_json` and `rebuild.rs`), so the two cannot drift. That is the bug behind #741: 20 bdep-only consumers are in `kept` but not in `reached`.
2. **What makes it stale, and the helper shape.** For each non-blocker atom of the installed copy's five `*DEPEND` variables with `SlotOperator::Equals`, resolve the provider to its **final** version: `s.chosen()` when the plan changes that slot (`reorder.rs:44-52`), else the installed VDB version (`portage_vdb::for_root(root)`). Compare the atom's recorded sub-slot with the provider's final sub-slot; `:*` never counts. Change the helper's signature to make the refusal explicit:
   ```rust
   pub(crate) fn slot_operator(world: &World, root: &Path) -> StaleBindings;
   pub(crate) struct StaleBindings { pub rebuild: BTreeSet<String>, pub refused: Vec<RefusedBinding> }
   pub(crate) struct RefusedBinding { pub consumer: String, pub atom: String, pub provider: Option<String> }
   ```
   `World` gains `refused: Vec<RefusedBinding>` so `plan_world` can print it. The final provider version a rebuild would use must exist: a consumer with no visible tree candidate (`s.chosen().is_none()`) is refused too, not rebuilt (the `every_kept` filter at `rebuild.rs:64-69` is the precedent).
3. **No rebuild may hold a package back.** A consumer is rebuilt only if every atom of its installed `*DEPEND` that names a cp the plan *changes* is satisfied by the plan's chosen version of that cp. The tool for that is `Memos::atom_matches` (`lib.rs:212-228`) against the chosen `Candidate`'s match string; a version operator (`=`, `~`, `<`, `>=`) must be judged by that matcher, not by a sub-slot compare. `||` groups in recorded VDB text are **not** pre-reduced (see #746's dump and `fixtures/var/db/pkg/dev-libs/p569virt-1/RDEPEND`, whose `~dev-libs/p569core-1.0` sits inside a group): evaluate them with the same `use_reduce_flat_disjunctive` the planner already uses, or refuse the consumer with a `RefusedBinding` rather than mis-judging it. The shape this must exclude, from `tests_p698.rs:13-28,178-193`: `p573virt`'s installed `RDEPEND` is `=dev-libs/p569prov-5.42* dev-libs/p569prov:0/5.42=`, the plan chooses `5.44`, so the `=5.42*` atom refuses it — that is why the p698 co-upgrade survives, and the plan must say so in the test. (`p569virt`/`p569core` is **not** the example: `p569core` has one ebuild and no upgrade exists.)
4. **The message (property 5).** A stale binding that is *not* repaired is named once on stderr, with the atom and the reason:
   `plan-world: N stale slot-operator binding(s) not rebuilt: cat/pkg (<atom> not satisfied by <final version>)`
   and, for a consumer with no visible candidate, `cat/pkg (<atom>, no visible ebuild)`. The same rows go to `--json` as `checker-limitation` entries so `world-crosscheck.py` sees them. No message when the list is empty (byte-identical output otherwise).

Grounding: charter property 1 (the final state has a `:=` binding naming a gone sub-slot) and 5; PMS slot dependencies; the #737 review. Determinism: the scan is a `BTreeSet`; a `HashMap` for the final sub-slot is allowed only if it is read, never iterated — collect the result into a `BTreeSet`.
