## 0. Premise and what grounding found

#755 D7 kept `seeds_first` as a parameter because deleting it was a behaviour-risk refactor that slice could not afford. The backlog entry and D7 both say "`LazyRepo::build` … the tests passing `false`". Grounding (`grep -rn seeds_first crates/`, `grep -rn "LazyRepo::build" crates/`) disagrees on three points. Fix the entry's wording at close-out.

1. **There is no `LazyRepo::build`.** The function is `LazyRepo::build_relaxed` (`crates/portage-repo/src/solver_bridge.rs:~255`, parameters `(req, repos, (seeds, shallow), seeds_first, opts)`). The only `seeds_first` hits are in that file: doc comment (`:250`), parameter (`:257`), `vdb_expand` (`:299`), queue comment (`:301-302`), the `if seeds_first` queue (`:303`).
2. **There are no `false` callers and no tests passing `false` left.** Two call sites remain, both `true`: production `:5516` and the test helper `lazy_closure` (`:5905`). #755 B4 deleted `s6_closure_skips_vdb_expansion_for_resolvo_order`, the only test of the `false` path. "The tests passing `false` to remove" is the empty set. S0 proves it again; if the grep finds one, STOP-1.
3. **The `false` arm is dead code.** Deleting the parameter removes the `else` queue arm (seeds pushed first, so `pop` drains shallow entries before the seeds) and the `seeds_first &&` factor in `vdb_expand`. Both are unreachable in every build. It also deletes comments that now misdescribe the code.

Pure dead-branch deletion; charter: "prefer changes that remove code". Tier 2.
