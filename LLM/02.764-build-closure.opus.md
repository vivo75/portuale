### 0.1 What the code does (read, HEAD `46215c09`)

- `build_time_used` (`order.rs:159-169`) collects the target of every edge in `kinds` whose mask has a `BUILD_KIND_MASK` bit (`DEPEND`/`BDEPEND`/`IDEPEND`, `order.rs:150-152`), minus `virtual/*` targets. It iterates `kinds`, so an edge with no kind entry (unit tests only) confers nothing.
- `is_cuttable_runtime_edge` (`order.rs:171-179`): an edge is cuttable when it is runtime-only (`is_runtime_edge`, `:155-157`) **and its source** is not in that set. So `T -R-> M` is protected when T is a direct build dependency. `M -R-> U` is not.
- `depend_order` (`order.rs:96-110`) loops `runtime_cut` (`:184-220`) and removes one edge per pass. `cycle_cut` (`:228-243`) takes the first cuttable edge in cycle order, starting at the ancestor the back edge points at. If a cycle has no cuttable edge, `cycle_cut` returns `None`, the scan goes on, and the cycle stays in `working`. `unordered` (`:114-141`) then breaks it implicitly at whatever back edge the name-ordered DFS meets.
- `build_time_cycles` (`order.rs:249-333`) is an SCC over **build-kind edges only**. It feeds the `plan-world: build cycle with no serial order` line (`plan_world.rs:70-85`) and the bootstrap (`bootstrap.rs:75-77`).
- Only one production path reaches `depend_order`: `mrg --plan-world --sort depend`. The call chain is `plan_world.rs:69` → `World::build_plan` (`bootstrap.rs:75`) → `World::ordered` (`order.rs:55-64`). The default sort is `alpha` (`plan_world.rs:39-41`), so every probe must pass `--sort depend`. `--sort alpha` is the control that does not reach the code. `emerge` never reaches it.
- Existing pins of the one-level rule: `lib.rs:1497` `a_build_tool_makes_its_runtime_closure_build_time` (its name says "closure" but it checks one edge) and `lib.rs:1518` `a_runtime_dependency_of_a_runtime_dependency_is_not_build_time` (the `loc -> get` edge is cuttable). These pin the **edge**. No test pins the **order** consequence, i.e. a tool's depth-2 runtime dependency merged after the consumer.

### 0.3 Wording drift in #764 (fix at close-out)

- (a) "although PMS 8.1 asks for a usable tool": true of PMS (`dependencies.tex:63-68`). But charter 2a, as ruled by the owner in #749, is literal: a tool's runtime closure need only be present by the end. So #764 is a **PMS-vs-charter gap the owner accepted**, not a property-2 violation, and the literal checker cannot see it. `build_time_used` itself already goes beyond the literal charter (it is a #746 heuristic).
- (b) "Propagating along RDEPEND would make almost every cycle uncuttable": the real consequence is narrower and worse. An uncuttable cycle that contains a runtime edge is **neither cut by rule nor reported** (`build_time_cycles` ignores runtime edges). The implicit DFS cut can then fall on a **build** edge and produce a literal `build-order` failure with no report line (shape V1/V3 below). This plan measures it.
- (c) The one-level rule already produces that silent failure on a depth-1 shape (V3, §1). This is a defect of today's rule, not only of a deeper propagation.
- (d) "`virtual/*` excluded on the same grounds": the recorded ground was different, namely the perl/libcrypt cluster (10 `build-order` findings on a 176-row bed plan; `LLM/code-notes/portage-world/order.md:63-71`).

## 2. Options and decision

- **(a1) bounded propagation, depth k (or along "hard" RDEPEND edges only).** It changes which edges are cuttable. Its cost is shown on the fixtures (§1: V1 turns into a silent literal failure at k=2 and k=∞, V2 is only pushed one level deeper at k=2); the whole-plan measurement of k=2/k=∞ is run only if S0.9 gives D1 (C1). It reopens the owner ruling of 2026-11-15 and changes plan order. Expected verdict: rejected on V1/V2 alone.
- **(a2) cut preference.** Among the cuttable edges of a cycle, cut the one whose target is nearest (in RDEPEND distance) to a build-used node. If several tie, take the first in cycle order. No edge becomes uncuttable, so the owner's objection does not apply. About 25 lines (a BFS depth map plus a key in `cycle_cut`). It changes plan order where it fires, so it needs the owner.
- **(b1) a stderr line in `--plan-world`** naming the late package, e.g. `plan-world: dev-libs/w764at is used to build dev-libs/w764ab before its runtime dependency dev-libs/w764au is merged`. This is new user-visible text, and it also needs the closure walk inside `portage-world`.
- **(b2) a checker or crosscheck note**, e.g. `[note] fast-tool-closure-late` in `world-crosscheck.py`, or a non-failing kind in `health_checker.py`. It brings back about 40 lines of the `_Moment.gap` walk that #749 deleted on purpose ("recorded, not a reason to keep depth 1"). In `health_checker.py` it would also fire on resolver plans, so `world-crosscheck.py` (FAST-only) is the only sensible home.
- **(c+) status quo order, documented and pinned, measured by an evidence script.** Fixtures V1/V2/V3 go into pmtest, pins go into `order.rs` (unit) and pytest, docs and comments say "one level, by owner ruling", and `LLM/evidence/02.764/` keeps the re-runnable strict-closure measurement.
