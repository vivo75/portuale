## 0. Owner ruling (this inverts the previous design — read first)

Owner's decision, verbatim: *"option 1 — the literal charter. A build dependency must be installed before the build; its runtime dependencies need only be present by the end."* The checker's transitive "usability closure at build start" is therefore too strict, and the #745 "unserializable" shape is a checker artifact, not a cycle: `[prov, virt, user]`, one build each, no finding, no duplicate.

Owner's counter-example, which is a real cycle and needs a rebuild, verbatim: *"pkgnew depends on `usefoo? ( otherpkg[useblah])`; otherpkg depends on `useboh? ( pkgnew[use3])`. If otherpkg has useboh and pkgnew has usefoo the cycle exists. It can be serialized: 1) build USE=\"-useboh\" otherpkg (temporary), 2) build pkgnew, 3) build otherpkg (definitive)."* (Step 2 is `pkgnew`.) That is the **only** legal 2a: a first build with a different USE, the last build with the declared USE. It needs a capability we do not have (choose a reduced-USE variant for the boot build), so it becomes residue **#753** (owner files it; this plan references it by number only, never writes its entry).
