## 1. Slices

- **K1 — long cells runner.** Extend `cast_cells.py`: a second cell list
  (`LONG_CELLS`) of real-execution cells run under `sudo --preserve-env`
  with a per-run scratch `PORTAGE_TMPDIR`/`PKGDIR`, chosen with
  `--cells pretend|long|all` (default `pretend`, so the old behaviour is
  unchanged). Cells: keep-going (schedbad+schedok), no-keep-going stop
  (schedbad then schedok), keep-going with a dependent (schedbaddep), a
  clean multi-package merge (schedparent with its leaves), and a resume
  (`emerge --resume` after a failed first run, second recording).
- **K2 — cap and filter.** `cast_cap.py` (or a function in `cast_compare`):
  collapse the build-output events between two landmark lines (`>>> Emerging`
  ... `>>> Install`/`Failed to emerge`) beyond a byte budget into one marker
  event, record original and capped size in the report. Applied by default to
  long cells; `--no-cap` disables.
- **K3 — timing correlation.** In `report.md` add per cell a landmark
  timeline (`>>> Emerging`, `>>> Install`, `Failed to emerge`, `>>>
  Completed`, `*** Resuming`, the final summary) with seconds since start under
  each PM side by side. Report only.
- **K4 — `--ask`.** Find out whether an answer can be fed to a recorded
  `emerge --ask` (stdin of the headless pty). If yes, add ask cells
  (answer `n`, answer `y`); if not, document the limit and try a python `pty`
  driver around `asciinema rec`.
- **K5 — bed image.** Check whether the bed image has `app-misc/asciinema`;
  if not, add it to the image recipe and document how a bed cell records
  (no bed run needed tonight).
- **K6 — tests, docs.** Unit tests of the cap and landmark code on synthetic
  casts (mutation-checked), `USAGE.AGENTS.md` paragraph, `what-this-proves`
  paragraph with the live report, backlog #452 DONE with residues.
