### Findings

**#34-1 — Important, proven (source). S2 never names where `InstalledPolicy::Rebuild` is registered.**
- **Where the plan is silent:**
  - `KeptInstalled.rebuild` is documented as "registered `InstalledPolicy::Rebuild`", but S2's Files and Interfaces sections only list `versions_for`, `LazyRepo::build` and `graph_result_from_order`.
  - The bridge registers every installed package with a hardcoded `policy: InstalledPolicy::Favor` in the `add_installed` loop at `solver_bridge.rs:843-865` (`:862`).
- **Consequence if S2 is executed as written:**
  - S2 gets the `R` row (from `graph_result_from_order`).
  - It does not get Rebuild's dependency expansion: the crate's kept branch, `solve.rs:319`, tests the registered policy.
  - So S2 loses the "expands DEPEND/BDEPEND as Portage's ebuild node does" property it claims at plan line 163.
- **Fix:** add to S2's Files: "`resolve_pubgrub`'s `add_installed` loop (`solver_bridge.rs:843-865`): `policy = if kept.rebuild.contains(cpv) { Rebuild } else { Favor }`". Add to S2 Step 1 a Rust test that asserts `provider.installed_policy(..) == Some(Rebuild)` for the named argument.

**#34-2 — Important, proven. `graph_result_from_order` is also called by resolvo, and S2 does not say what resolvo passes.**
- **Where:** `solver_bridge.rs:1072` (inside `resolve_resolvo`, `:944`) calls it, as does pubgrub at `:923`. S2 adds a `KeptInstalled` parameter.

  - State that resolvo's output must not move.
  - Add `graph_result_from_order` to the list of shared code that triggers default-mode L0 (it is already in Global Constraints line 54 as "callees"; name the function itself).

**#34-3 — Minor, proven (source). S1's `_greedy_slots` rule is phrased on the installed version, but Portage compares the best visible version of that slot. S1's prediction then reads as if slot 1 were not a target.**
- **What Portage does:** `_greedy_slots` (`depgraph.py:5913-5923`):
  - takes the installed slots matching the **argument atom** (`vardb.match(atom)`);
  - for each other slot, runs `_select_package(root, "cp:slot")` (no version constraint from the argument);
  - adds the slot when that pick `< highest_pkg`.
- **Plan wording:** "each installed slot whose installed version is lower than that best" (line 137). That differs when the slot's best visible version is above `highest_pkg`, e.g. a `<cat/pkg-5` argument with a newer ebuild in the installed slot.
- **S1 Step 1's prediction:** "`-pvu` → slot 2, plus slot 1 only if a newer slot-1 version exists". That is right about *rows*, but `target_slots` must return both slots under `update` (pg34-multi-1 < pg34-multi-2). Slot 1 is simply up to date, so it prints no row.
- **Fix:**
  - Reword the interface: "each slot of an installed package matching the atom, other than the pick's slot, whose best visible version (slot atom, no argument version constraint) is lower than the pick".
  - Have the `target_slots` unit test expect `["2", "1"]` for `update = true`.

**#34-4 — Minor, likely. Under `-pve`, S2 registers every installed package as `Rebuild` but leaves `set_rebuild_tree` to S4. In between, `-pve` keeps old installed versions.**
- **Engine behaviour:** `Rebuild` with `!rebuild_tree && !prefer_update` keeps the installed version (`solve.rs:112-118`). Portage `-e` selects the highest visible version.
- **Effect:** S2's `-pve` measurement would show `R old` where Portage shows `U`.
- **Fix:** move `provider.set_rebuild_tree(req.empty)` into S2 with the `empty` registration, or note in S2 Step 5 that `-pve` is interim until S4.

- **Fix:**
  - Scope the rule to S1–S4 and to S5's fix tasks.
  - For S6, say "standalone: no pmtest counterpart" if pmtest is untouched (AGENTS.md "Standalone commits stay single").
