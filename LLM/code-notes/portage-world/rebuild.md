# crates/portage-world/src/rebuild.rs
Installed packages a plan keeps but must build again: slot-operator and USE
rebuilds over the kept set.

## fn slot_operator
- #741 (plan `02.741`): a kept package whose recorded `:=` binding is stale is rebuilt. Staleness is judged against the *final* provider version -- the chosen version when the plan changes the provider's slot, else the installed VDB version -- so a binding that was already stale before the plan still repairs. `:*` never counts; an atom whose provider version cannot be worked out is skipped. Charter property 1 is the spec (PMS `dependencies.tex`, `sec:slot-dep`); Portage is not run.
- `World::kept_installed` is the one source for the kept set (installed and not replaced, at the main slot), shared with `plan_json`'s `kept`, so the two cannot drift.
- The chosen tree ebuild must still name a stale provider for the rebuild to fire (`tree_names_provider`, evaluated against the chosen version's effective USE): a rebuild re-records the live dependencies, so a tree that dropped the dep has nothing stale left to repair. Unreadable tree metadata counts as naming. The resolver's arm has the same gate, with a different notion of naming (any ebuild of the consumer's slot; unreadable metadata does not count). The old `kept` filtered on `World::reached`, which dropped bdep-only consumers (the #741 bug); the judged set is every installed consumer, but reachability still enters in two places: a `DEPEND`/`BDEPEND` key counts only for a consumer the walk reaches (Q-A (i)), and the #769 holder-route waiver applies only to a walked consumer (`World::walked`). A stale consumer with no slot in `world.slots` is no longer refused for that: it is judged by its best visible ebuild, and refused with a `None` provider only when it has no visible ebuild (#768 S1 below). Replacement means `World::change`, so a kept package the plan builds again still counts as kept for the scan but leaves `plan_json`'s `kept`.
- Rule 2.3 (no rebuild may hold a package back): every recorded non-`:=` atom naming a slot the plan changes must match the chosen version there, judged by `Memos::atom_matches` (a version operator like `=5.42*` is judged by the matcher, not by a sub-slot compare). `:=` triggers are skipped in this check: `matches_slot` enforces recorded-sub equality, so the matcher would refuse every stale binding. `||` groups and `flag?` conditionals reduce against the recorded USE with the same `use_reduce_flat_disjunctive` the planner uses; a text that does not reduce refuses the consumer rather than mis-judging it.
- Returns `StaleBindings` (`rebuild` set plus `refused` list) instead of a bare set, so the refusal is explicit. `World.refused` carries the refusals to `plan_world`, which names each once on stderr (property 5) and in `--json` as `stale-bindings`. Refusals sort by `(consumer, atom)`; the scan otherwise collects into `BTreeSet`s (no hash iteration in any order).
- #766 (plan `02.766`, owner decision 2026-11-16: keep two implementations, pin their agreement, change no behaviour): the resolver applies the same PMS rule in `portage-repo/src/slot_operator/rebuild_scan.rs` over graph entries. `test_plan_world.py::test_766_*` runs `mrg --plan-world --json` and `emerge --pretend --json -uDN @world` (both solvers) on scratch ROOTs and pins the agreement at the consumer `cat/pkg` and every known difference exactly; `world-crosscheck.py` judges the same on the real tree (`stale-binding-fast-only` / `-resolver-only`). Known differences, evidence `LLM/evidence/02.766/before/classes.txt`: D1 (a consumer outside the @world walk has no slot in `world.slots`, so `slot_operator` refuses it at the `chosen` lookup with provider `None`, rendered "no visible ebuild" although its ebuild is visible; the resolver names atom and provider correctly; residue #768, the owner decides the fix), A1 and A3 (the fast plan names a consumer with no ebuild, or whose recorded text does not reduce, where the resolver is silent; #768), D-698 (the fast plan refuses what the resolver's holder route reinstalls; #769), A4 (DEPEND/BDEPEND read here, not by the resolver under `--usepkg`; #769). The pubgrub bridge schedules no rebuild for a walked stale consumer the default solver rebuilds (#770).
- The p573virt shape is the reason the check reads *recorded* atoms: its tree ebuild pins `=5.42*` too, but a consumer with no visible tree ebuild accepts vacuously in the replacement gates, so only the recorded check guards the co-upgrade.
- #768 S1 (2026-11-22; plan `02.768-769`; owner decisions Q1(a), Q3(a), Q-A (i), and F1(b) of 2026-11-22): `Scan::judge` no longer refuses a consumer for having no slot in the walk. The version a rebuild installs is the walk's choice, else `Memos::best_visible_in_slot` of the installed main slot (the loop `branch_preference` already had, extracted); only a consumer with no visible ebuild there is refused, with provider `None`. A recorded text that does not reduce is no longer a refusal: its raw stale `:=` atoms count as stale, it adds no hold-back atom, and the chosen tree ebuild decides through `tree_names_provider`. `World::walked` (the slots the first walk reaches from the world atoms alone, frozen in `analyse`) picks the keys: a consumer inside it reads all five `DEP_KEYS`, one outside it reads `OUTSIDE_WALK_KEYS` (`RDEPEND`, `PDEPEND`, `IDEPEND`, the resolver's runtime set, `rebuild_scan.rs` "walked" branch), because PMS `dependencies.tex` says a `:=` breaks a runtime binding only; the same keys go to `tree_names_provider`. A rebuild outside the walk would otherwise be a `rebuilds` member with no row, so `walk` seeds every rebuild node as the atom `cat/pkg:slot`, requested by itself; not under `emptytree`, where every kept package is already a rebuild. Side effects, expected: a seeded consumer's tree dependencies enter the walk (its tree pinning the old provider keeps the provider where it is), and `rebuilds` never shrinks, so a seeded rebuild whose binding stops being stale stays a rebuild (residue #777). `p569virt`-style records (`|| ( =..5.42* .. ~p569core-1.0 ) ..:=`) reduce in plan mode to the arm the best visible version matches, so the fast plan rebuilds them (plus `N p569core`) where the resolver refuses on the installed arm (residue #793). `Scan::provider_cpv` is gone: its only caller was the refusal of an unreduced text (it gave the `cat/pkg-ver` of the provider version the final state binds `atom_str` against, `None` when the atom names no slot or no version is left).
- #769 S2 (2026-11-22; plan `02.768-769`, owner Q4(a)): a recorded pin no longer refuses a *walked* consumer whose chosen tree ebuild accepts the new provider. `held_back` now returns every hit (one per atom, as `HoldBack`), and each is judged on its own: the tree atoms on that provider (`tree_reduced_atoms`: the chosen ebuild's text over the same keys as `tree_names_provider`, reduced with the planner's `||` reduction) go to `portage_repo::provider_atoms_accept` with the version the plan chooses; one unaccepted hit still refuses (two pins, the tree lets one go). Walked consumers only: the resolver's holder route (`holder_routes`) runs only on holders whose pin withheld an upgrade, and a consumer outside the walk has no tree dependencies in the plan, so its pin stands (the tree is not read for it). A tree that does not name the provider gives no atoms, which `provider_atoms_accept` accepts. An unreadable or unreducible tree waives nothing. The fast plan tests one candidate where the route searches all; and `tree_reduced_atoms` is used instead of `provider_atoms` because that one keeps every `||` arm (a menu), which refuses what the arm the planner prefers accepts (the misreading plan `02.770` names as #781). The `provider_atoms_accept` doc says "masked ones included" because that is what the route does.

## fn kept_installed
- See `## fn slot_operator`: `(node, InstalledPackage)` pairs in VDB order for every installed package the plan does not replace. `plan_json` renders `kept` from it, so the JSON is byte-identical to the old inline filter (verified by `json_rows_equal_text_rows_in_order` and the host kept count 1925 -> 1905, exactly the 20 new rows).

## struct Scan (#760)
- `slot_operator` is split into `Scan::{final_provider, provider_cpv, stale_atoms, held_back, judge}` plus one `refuse(...)` constructor. The installed records are read once (`all_installed_packages`, first record per `(category, package, slot)`) instead of per atom in `final_provider`/`provider_cpv`/`kept_installed`; `World::kept_of` is `kept_installed` over an already-read list.
- A4 is kept on purpose (owner Q5(c)): the fast plan reads `DEPEND`/`BDEPEND` of a consumer in the walk, the resolver under `--usepkg` does not. `--usepkg` can mix prebuilt and to-be-built packages, so a clean rule would hold only for `--usepkgonly`. The resolver now names a consumer with no ebuild too (#768, `rebuild_scan.md`), so A1 no longer differs at the consumer key.
