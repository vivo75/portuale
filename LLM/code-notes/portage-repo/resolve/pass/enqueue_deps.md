# crates/portage-repo/src/resolve/pass/enqueue_deps.rs
Folds the entry's dependency keys and queues the atoms they name.

## fn enqueue_entry_deps
- Portage `depgraph.py:4195-4247` (`_add_pkg_dep_string`): with `myparams["bdeps"]` not in `("y","auto")` (i.e. `--usepkg`/`--getbinpkg`, which leaves `bdeps` unset per `create_depgraph_params.py:100`), `DEPEND` and `BDEPEND` are emptied. A binary's recorded `BDEPEND` (e.g. libgweather's `|| ( ( python:3.14 pygobject[...] ) ... )`) must not drive a merge.
- Backlog #143 S1: Portage `depgraph.py:4176-4183` blanks runtime keys for a non-built package under `--buildpkgonly` without `--deep`, so runtime blockers never enter the graph (upstream pg1 E/F) and runtime edges never reach the merge-order digraph either.
- Backlog #194: `man emerge.1` documents the onlydeps defaults (rdeps enabled, so only explicit `=n` blanks; ideps disabled, so only explicit `=y`/bare flag keeps). An EAPI-7 root with `--onlydeps-with-rdeps=y` merges `[B, C, D]`, never `E` (oracle cell).
- Below EAPI 8 `portdb.aux_get` serves `""` for `IDEPEND` (Portage `porttree.py:644-648` defaults a missing `EAPI` to `"0"`, same as `bintree`).
- Discovery order differs from inclusion order: Portage walks `RDEPEND`, `IDEPEND`, `PDEPEND`, `DEPEND`, `BDEPEND` (`depgraph.py:4253-4289` deps tuple). `use_reduce_flat` drops `||`/`(`/`)` markers and lists every branch's atoms in written order; the unchosen branches are never an entry, so they contribute no edge once the digraph looks them up. See `GraphEntry::deps`.
- Running order: the old sidecar walk used `["DEPEND", "BDEPEND", "RDEPEND", "IDEPEND"]`, so `rdrtooldep` precedes `rdrlib`. The `cyc0z-3`/`cyc0y` cross-root `DEPEND` cycle (the #207 flip) carries a single key either way.
- Running BDEPEND cut: the `rdrcycb -> rdrcyca` bootstrap closing edge drops like the old sidecar `seen` guard dropped its second `required_by` edge (and like the `required_by` cut drops it for `find_hard_cycles`); `rdrtooldep`/`rdrlib` stay since first-visit. `DepEdge::key` numbering is `0=R,1=I,2=P,3=D,4=B`; bare and versioned atom texts alike collapse to cp.
- Self-edge exemption: Portage `_serialize_tasks` dead-ends on the kept edge (`depgraph.py:10262`, the g216 running-root self cycle). The owner's own cp is trivially "visited" (its own pulling atom resolved to it). Satisfied self-edges drop via `build_digraph`'s self-edge rule and `owner_self_loop`'s installed gate.
- Classification uses a plain (non-disjunctive) `use_reduce_flat`: only the originating key matters, and a `||` group's branch choice matches the main flatten in every case without one. Groups never span keys, so the `||` branch choice matches across the buildtime/runtime/bdepend flattens.
- Without blanking, the runtime set is the long-standing unconditional three-key set.
- Cross-root runs: each queued atom carries its group root (`QueueItem::targets_running_root`); candidates select against that root's installed db, and only same-root entries satisfy the in-graph preference. Siblings share one owner and one cp, so the group root is homogeneous in practice. Mixed-key same text falls target (the queue tag's target-wins rule).
- `--root-deps` limitation (documented in `LLM/agent-context.md`'s `--root-deps` backlog entry, the "recursive second-root graph" gap): portuale's single-unified-graph architecture merges the five dep keys into one string before flattening, so the closure can't tell which key an atom came from while Portage applies `--root-deps` only to `DEPEND`/`BDEPEND`.
- Backlog #221: `disjunction_preference` takes `slot_constraints` itself (not a lookup closure); it holds this pass's recorded cycle edges -- empty on the first attempt, populated on the restart after a stranded walk (see `collect_feedback`). Backlog #249 adds a virtual's pullers to that view.
- Backlog #216: `dev-lang/go`'s BDEPEND `|| ( >=dev-lang/go-<min> dev-lang/go-bootstrap-<min> )` with in-graph `go` ranks the first branch `preferred_in_graph` (bin 0), so the cycle forms and the `circular_dependency` map re-resolves it; see `disjunction_preference`'s circular-self-dep check.
- Review 2026-09-11 F1/F2: the `dep_zapdeps` choice-bin classification used to be two hand-maintained copies (this closure and `enqueue_dependencies`'s); only this one got the fine `unsat_use_*` bins, so they were unified into `disjunction_preference`.
- Backlog #133: `buildtime_atoms`/`runtime_atoms` are raw-keyed flattens and `enqueue_flat_deps` runs its own post-pass over whatever survives.
- Backlog #90 (S1): backtracking slices 3/4 record pullers; slice 4 renders the `pulled in by` lines from the kept atom text.
- `--with-test-deps` gating (depth == 0, "test" a valid, not-already-enabled, not-masked IUSE flag) and the reason for `use_reduce_flat_subset` over a plain pass: see `resolve_pretend_graph`. The subset filter drops the group structure, so `test?`-gated deps are plain atoms (empty universe); `DepPriority.optional` never contributes to hard cycles.
