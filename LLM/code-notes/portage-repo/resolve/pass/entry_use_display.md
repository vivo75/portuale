# crates/portage-repo/src/resolve/pass/entry_use_display.rs
Records the entry's USE display: changed flags, IUSE and USE_EXPAND groups.

## fn record_entry_use_display
- IUSE `+flag`/`-flag` default markers were already consumed where `use_flags` came from; the USE display is about the package's own metadata, unrelated to whether its deps are walked (shown by `--pretend -v` regardless of `nodeps`).
- Portage `depgraph.py` "NOTE: REQUIRED_USE checks are delayed until after package selection": a genuine post-selection check, no part of matching/visibility. A violation eventually fails the whole run wherever reached, but not immediately: Portage's `_add_pkg` (~line 3600) sets `_dynamic_config._required_use_unsatisfied = True` and returns 0, which does not stop the walk (unlike a top-level atom's `NoVisibleCandidate`, which aborts). Every violation is collected into `required_use_violations` and turned into this call's `Err` at the end of the pass.
- An invalid REQUIRED_USE (e.g. referencing a flag that is not valid IUSE) stays immediately fatal: Portage's `check_required_use` itself raises there, outside the `if not required_use_is_sat:` branch.
- Installed (`built`) packages skip the check: Portage's gate is `not pkg.built` (`depgraph.py:3629-3632`); an installed package's REQUIRED_USE was satisfied at build time. History (backlog #74 S1): re-validating once turned the whole run into a bogus "ebuild selected ... has unmet requirements" failure when the `||` selection picked an installed instance whose current-profile USE no longer enables a REQUIRED_USE flag (`dev-lang/rust-1.94.1`'s `llvm_slot_21`, built with it, `LLVM_SLOT=22` now).
- `check_required_use` validates against `pkg.iuse.is_valid_flag`, i.e. effective IUSE including `PORTAGE_ARCHLIST` (profiles/arch.list), `use.mask`/`use.force` and literal `build`/`bootstrap` -- without this, a REQUIRED_USE referencing an implicit flag never in the package's own IUSE (e.g. media-libs/mesa referencing "x86") spuriously fails. See `portage_profile::Config::archlist` for the full grounding and the deliberate USE_EXPAND_HIDDEN (elibc_*/kernel_*/userland_*) simplification.
- The violation block mirrors Portage `_show_unsatisfied_dep`'s REQUIRED_USE block: the failing atom as `xinfo` (Portage's `atom.unevaluated_atom`), the candidate + `pkg_use_display`, the minimal unsatisfied sub-expression (`check_required_use(...).tounicode()`), the complete expression when it differs, then the `(dependency required by …)` chain.
- Dedup example: gnome-extra/gnome-color-manager's `IUSE="test test"` (eclass + ebuild); Portage renders `sorted(pkg.iuse.all)`, a `frozenset`.
- `New`/`AlreadyInstalled`/`NoVisibleCandidate` have no installed side to diff.
- `Upgrade`/`Downgrade`/`New` carry no `reinst_flags`; their changed flags already render via the `*`/`%` markers.
- `use_expand_display` is the `-pv` (`all_flags = verbosity == 3`) form, `use_expand_display_p` the plain `-p` one; for a `New` (no installed diff) they are identical.
