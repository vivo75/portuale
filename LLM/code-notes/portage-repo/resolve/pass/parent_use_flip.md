# crates/portage-repo/src/resolve/pass/parent_use_flip.rs
Records a parent USE flip that alone can satisfy a failed dependency, then re-walks.

## fn parent_use_flip
- Ports Portage `--autounmask-use` PART B (`_apply_parent_use_changes` -> `_show_unsatisfied_dep(collect_use_changes=True)`, `depgraph.py:5820`/`6768`): a dependency's use-dep was conditional on the requesting parent's USE (`opt?`/`opt=` forms) and no candidate satisfies the evaluated form. Portage flips the parent's flag (`suggested_parent_use_candidate`), folds it into `_needed_use_config_changes`, and FAILS the resolve (`_success_without_autounmask`); with `--autounmask-backtrack=y` (Slice 4) the flip is folded into `autounmask_use_config` (a `package.use` entry) and the driver's `autounmask_grew` restart re-walks. A probe re-resolution of the freed atom gates both arms, so only a helping flip is recorded; `--autounmask-use=n` suppresses via `autounmask_suggest_use`.
- Default arm: Portage `_apply_parent_use_changes` runs only after `_create_graph` already failed (`depgraph.py:5677`), and the `_success_without_autounmask` tail (`:5793`) returns False (rc 1). The abort renderer skips the rescued dep's row (see the `pretend` NVC loop's gate); `nvc_dep_atoms` is still kept since `abort_outcome` needs the atom.
- Dep-chain fill: a parent-flip rescue names the flipped parent, not the failed dep. When the change's package is itself a top-level argument, Portage's chain is just the argument line (`_get_dep_chain` never prints the start node, `elif node is not start_node`, `depgraph.py:6357`); the failed graph walks straight to the argument (oracles: the aup0b container probe prints a single `# required by =dev-libs/aup0b-1 (argument)`; `abort-au-plain`'s parent-plus-argument rows for the generic case). The post-loop fill leaves non-empty chains alone.
- Backlog #217: Portage collects `_apply_parent_use_changes` post-failure.
- Backtrack arm: without the `newly`-against-effective check the same flip would re-fire every pass and eat the backtrack budget. The driver at the bottom of `'backtrack` does the `continue`, not here; with `--autounmask-backtrack` off the change is recorded and displayed but the graph is not re-driven (a post-loop pass refreshes the package's own USE line).
- The flip serves an already-resolved slot and the current dep's owner is often not the forcing parent (e.g. the bare-depending top package).
