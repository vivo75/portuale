# crates/portage-repo/src/resolve/pass/parent_use_flip.rs
Records a parent USE flip that alone can satisfy a failed dependency, then re-walks.

## fn parent_use_flip
- Ports Portage `--autounmask-use` PART B (`_apply_parent_use_changes` -> `_show_unsatisfied_dep(collect_use_changes=True)`, `depgraph.py:5820`/`6768`): a dependency's use-dep was conditional on the requesting parent's USE (`opt?`/`opt=` forms) and no candidate satisfies the evaluated form. Portage flips the parent's flag (`suggested_parent_use_candidate`), folds it into `_needed_use_config_changes`, and FAILS the resolve (`_success_without_autounmask`); with `--autounmask-backtrack=y` (Slice 4) the flip is folded into `autounmask_use_config` (a `package.use` entry) and the driver's `autounmask_grew` restart re-walks. A probe re-resolution of the freed atom gates both arms, so only a helping flip is recorded; `--autounmask-use=n` suppresses via `autounmask_suggest_use`.
- Default arm: Portage `_apply_parent_use_changes` runs only after `_create_graph` already failed (`depgraph.py:5677`), and the `_success_without_autounmask` tail (`:5793`) returns False (rc 1). The rescued dep's own key is latched in `parent_flip_recorded` so its masked/use-unsat/plain-miss disclosure is suppressed (Portage drops the collected item from `_unsatisfied_deps_for_display`, `:5820` `remaining_items`) and the abort renderer skips its row (see the `pretend` NVC loop's gate); no merge rows, the change block plus the "terminated early" notice are the whole output (rc 1); `nvc_dep_atoms` is still kept since `abort_outcome` needs the atom. The dependency keeps its `NoVisibleCandidate` outcome (Portage's failed `_create_graph`).
- Dep-chain fill: a parent-flip rescue names the flipped parent, not the failed dep. When the change's package is itself a top-level argument, Portage's chain is just the argument line (`_get_dep_chain` never prints the start node, `elif node is not start_node`, `depgraph.py:6357`); the failed graph walks straight to the argument (oracles: the aup0b container probe prints a single `# required by =dev-libs/aup0b-1 (argument)`; `abort-au-plain`'s parent-plus-argument rows for the generic case). The post-loop fill leaves non-empty chains alone.
- Backlog #217: a failed dep rescued by a parent flip (Portage `_apply_parent_use_changes` collecting post-failure) pre-empts the `_success_without_autounmask` tail; the notice stays.
- A parent-flip rescue names the flipped parent, not the failed dep: no single forcing parent, legacy fill (backlog #205).
- A parent flip that contradicts an accumulated change is Portage `_autounmask_breakage` territory (Slice 3).
- A3 overlay: the opposite-flip check reads the effective (overlay-then-`bp`) value; `newly` is computed against it too; dedup spans the union (this pass's overlay plus `bp`'s committed records). Writes go to the overlay only; `collect_feedback` + driver unions them into `bp` before deciding.
- Already folded on an earlier pass yet the dep still failed this one: the ordinary NoVisibleCandidate path (with `parent_use_suggestion`) renders it.
- Backtrack arm: without the `newly`-against-effective check the same flip would re-fire every pass and eat the backtrack budget. The driver at the bottom of `'backtrack` does the `continue`, not here; with `--autounmask-backtrack` off the change is recorded and displayed but the graph is not re-driven (a post-loop pass refreshes the package's own USE line).
- Backward-cascade overlay: the flip serves an already-resolved slot and the current dep's owner is often not the forcing parent (e.g. the bare-depending top package) -- no single forcing parent, legacy fill (backlog #205).
