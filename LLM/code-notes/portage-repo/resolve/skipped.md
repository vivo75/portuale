# crates/portage-repo/src/resolve/skipped.rs
Skipped-update records (withheld upgrades, backtrack-mask rows) and their grouping.

## struct SkippedUpdate
- Backlog #90 (S2): one withheld upgrade for Portage's `WARNING: One or more updates/rebuilds have been skipped due to a dependency conflict:` block (`depgraph.py`'s `_conflict_missed_update["slot conflict"]`, rendered after the merge list, rc 0). Two producers feed it: the direct solve (a formed slot conflict whose non-forced instance is removed) and the reverse-pin withhold (an enforced holdable pin that settles the installed version while a higher visible candidate exists). Both render through the same `pretend.rs` block, suppressed under `--quiet` unless `--debug` (Portage `_show_missed_update`, `depgraph.py:1576-1581`); `--json` returns before the block and `--columns` has no gate. The rc stays 0 either way since no `SlotConflict` survives.
- `missed_targets_running_root` / `consumer_targets_running_root` (backlog #242 Slice D): whether the missed instance / a merge consumer resolves in the running root (Portage's per-node `to '<root>'` + per-root USE paint, see `skipped_update_roots`). `false` on every single-root run and on the target-walk-only withhold path; installed consumers always resolve from the walk root's own vdb (the target walk), so `false`.

## struct SkippedMissingDep
- Backlog #129 (S1): one slot Portage reports through the abbreviated `!!! The following update(s) have been skipped due to unsatisfied dependencies / !!! triggered by backtracking:` tail (`depgraph.py:1638-1649`) -- a masked version higher than the chosen one whose missing-dependency mask still bites at settle time (Portage's `check_backtrack` probe raises `_backtrack_mask`). Only the slot renders (no versions, no parents); the full per-update form Portage prints when the probe does *not* raise is out of scope (see `backtrack_missed_updates`: those records are skipped, not rendered).

## struct SkippedMissingDepFull
- Backlog #198: one update Portage reports through the full per-update form of `_show_missed_update_unsatisfied_dep` (`lib/_emerge/depgraph.py:1592-1636`) -- a masked version higher than the chosen one whose missing-dependency mask no longer bites at settle time (Portage's `check_backtrack` probe does *not* raise `_backtrack_mask`, i.e. the missing atom names no backtrack-masked version). Renders the `cat/pkg:slot` header, the `selected:` / `skipped: ... (see unsatisfied dependency below)` rows (Portage `str(Package)`, destinations omitted like every other portuale notice row), then the missing atom's own disclosure -- the masked block or the plain-miss block, with a single-parent `(dependency required by ...)` chain: the skipped package is not in the settled graph, so Portage's `_get_dep_chain` stops there (`depgraph.py:6397`, "not in the graph ... break") with no `(argument)` line.
- `selected_display`: `(cpv:slot/sub::repo, ebuild scheduled for merge)` for a merge-bound selected entry, `(cpv:slot/sub::repo, installed)` for an installed one (vdb repo, `__unknown__` fallback).
- `skipped_display`: `(cpv:slot/sub::repo, ebuild scheduled for merge)` for the masked higher version (never installed: Portage excludes `pkg.installed` from missed updates, `:1539-1542`).
- `dep`: the missing atom's disclosure: masked-only candidates, or the plain miss when the atom names nothing at all.

## enum SkippedDepDisclosure
- Reuses the settled-pass report shapes, with the chain pinned to the single skipped parent (see `SkippedMissingDepFull`).

## fn missing_dep_full_row
- Backlog #198 (Portage `_show_missed_update_unsatisfied_dep`, `depgraph.py:1592-1636`). Returns `None` when no settled entry holds the slot (Portage's `any_selected` gate) or the masked version's tree metadata cannot name the skipped node.
- `selected_pkg`: the tracker's match for the slot -- a merge-bound entry first, else the installed instance.
- Backlog #286: no settled entry holds the slot, but the vdb holds the masked version itself in it -- the dropped set-arg shape (Portage's tracker still selects the installed instance: the `@world` argument is dropped from the graph, but the installed package stays visible through the complete walk). Scoped to version equality: any other installed version has no proven graph presence (Portage's `any_selected` gate), so it stays silent like before.
- The skipped package is not in the settled graph, so the chain is the single skipped node (Portage stops there, no `(argument)` line).

## fn collapse_skipped_updates
- Backlog #129 (review): Portage `_get_missed_updates` chains `_runtime_pkg_mask` before `_conflict_missed_update` (`lib/_emerge/depgraph.py:1533-1536`) and keeps per `(root, slot_atom)` the highest missed pkg (`:1553-1562`). Portuale's two `SkippedUpdate` sources -- the backtrack-mask rows (first-seen order) and the direct-solve/withhold rows (sorted) -- collapse the same way: per `(category, package, slot)` (a single root, so root is constant) keep only the rows naming the highest `skipped_version` (`vercmp_ordering`, the same comparison the derivation uses). Equal versions all stay (the established one-row-per-parent shape -- Portage keeps one record per slot with every parent inside, portuale one row per parent, grouped into one block at render by `group_skipped_updates`); exact duplicates collapse to one. Relative order is preserved: mask rows lead, then the direct solve's rows in first-seen block order, then the pin withholds (sorted).
- Backlog #292: Portage's `missed_updates[k] = ...` overwrites the value of an existing `(root, slot_atom)` key, and a Python dict keeps the key's *first* insertion position (`_get_missed_updates`, `depgraph.py:1544-1560`): a higher pkg replacing a lower one of the same slot renders where the lower was first recorded, not where the higher row sits.

## fn group_skipped_updates
- Backlog #129 (review round 2): Portage `_get_missed_updates` keeps one entry per `(root, slot_atom)` (`lib/_emerge/depgraph.py:1553-1562`) -- the highest missed pkg with its whole `(parent, atom)` set (`:2090-2106` accumulates into a set per pkg) -- and `_show_missed_update_slot_conflicts` (`:1650+`) renders one block per entry with every parent line inside. Portuale's rows stay one per rejecting parent (the established #90 S2 shape, which `collapse_skipped_updates` also assumes). Portage itself iterates an unordered set -- `Package` keeps identity hash (`_emerge/Package.py:27`) -- so its within-block order is hash order; the `blk0b blk0c blk0a` oracle's b-then-c order is what the sorted direct rows give here.
- Mask rows arrive in first-seen mask order, direct rows in first-seen block order.

## fn backtrack_masked_match
- Backlog #129 (S1): Portage `_show_unsatisfied_dep(..., check_backtrack=True)` (`depgraph.py:6471-6484`) -- no output, just the verdict: `true` when the atom matches a version the settled backtrack state still masks (Portage raises `_backtrack_mask`, and the missed update renders in the abbreviated tail). USE-deps are stripped for the match, exactly like the missed-update recording's plain-match form (`direct_solve_atom_matches`' `for_skipped` arm, `:2083-2094`).
