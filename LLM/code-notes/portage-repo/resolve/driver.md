# crates/portage-repo/src/resolve/driver.rs
The backtracking loop: one pass per node, settle or feed back.

## fn backtracking_resolve
- Phase C2 (023): Portage `_backtrack_depgraph` -- pop a node, run one pass, settle or feed the outcome back, and when the search is exhausted re-run with the deepest terminal (config-only) params. `--backtrack=0` explores no feedback at all (Portage's `_allow_backtracking` gate): the root pass settles as-is.
- #59 S2, R6 #600: Portage `_backtrack_depgraph`'s `backtracked` counter -- one per loop pass that does not end the loop. A restart always counts (D:12414-12416), even when every child it adds is rejected (no accepted node still ends the loop through the empty stack); any other failed pass counts only while unexplored nodes remain (`elif backtracker`, D:12417-12418). The final best-run re-pass after the loop shares the value, exactly as Portage's counter is frozen before its own best-run re-pass. A grown `--autounmask-use` config Portage would not restart for (its fail-fast walk fails first, or the flip changes nothing Portage checks) is not a Portage pass and is not counted: `grow_restart_counts` replays Portage's `want_restart_for_use_change` (flattened `*DEPEND`/`LICENSE` under the new USE, or a USE dep of an existing parent the change breaks) and requires the replay to complete.
- Backlog #209: the `--backtrack=0` reverse-dependency feed loop. Portage `_resolve_conflicts` (`_emerge/depgraph.py:9444`) runs `_complete_graph()` (`:8562`) with no `_allow_backtracking` gate (that flag only gates auto-enabling `complete` mode on slot conflicts at `:9444-9450`, and the slot-op trigger at `:2131`), so a satisfiable installed-consumer pin enforces in-pass even with backtracking off. Portuale's scan runs post-pass, so its `RevDep` working copy feeds one more pass here instead of settling -- a feed loop, not a backtrack retry (`restarts` stays 0, Portage `backtrack: 0/0`). Bounded: `reverse_dep_masked` latches every enforced `(cp, atom)`, so a pass that adds nothing new falls through to `Settle`. `--nodeps` is excluded: Portage pops `recurse` there (`create_depgraph_params.py:181-183`), so its complete graph never runs.
- Backlog #244: the USE changes `replay_walk` found needed on earlier passes (see the `_feedback_config` note in the loop).
- Portage `_backtrack_depgraph`: a retry whose walk fails (a masked top-level select, backlog #198's single-version peel) is a failed iteration, not a result -- the search continues and an exhausted search falls back to the best run. Only the root pass's own failure propagates (nothing to fall back to). A feed pass has no node to adopt into, so it is just dropped.
- Failed iterations without feedback count too (`elif backtracker: backtracked += 1`) and the cap is checked first (`backtracked >= max_retries`) (#297).
- The per-pass config view: the accumulator's autounmask-use changes layered on as the top USE tier (see `Config::autounmask_use`). Cloned (not borrowed) out of the node params so the decision/assembly calls below can borrow alongside it; the clone only allocates on autounmask-growth passes.
- The clean pass after an autounmask breakage is Portage's last pass (`allow_backtracking=False`) -- reported as it stands, cut to what the fail-fast walk reached.
- Portage's own walk over this pass, with the USE changes it needs (`_needed_use_config_changes`). A flip that contradicts one already needed fails the pass right there (`depgraph.py:7714`) -- no slot-conflict or config feedback is ever computed for it (`_resolve` returns before `_process_slot_conflicts`), and the failure is an autounmask breakage (`autounmask_breakage_detected`, `:11779`): one clean pass follows (`:12262-12280`).
- With `--autounmask-backtrack` off Portage stops after the first pass that carries an autounmask change (`need_config_change`), so only that pass is replayed; later passes portuale runs for other feedback have no Portage counterpart to mirror.
- Portage `_feedback_config` (`--autounmask-backtrack=y`): the changes this walk needed carry into every later try, including the ones portuale's own pass never recorded (its walk skips the flip when the requester first lands on another instance of the slot).
- Portage `need_config_change` (`depgraph.py:11708`): with `--autounmask-backtrack` off, a pass whose graph carries an autounmask change ends the loop before any slot-conflict backtracking (`_autounmask_backtrack_disabled`) -- the pass is the report, conflict block, change block and "terminated early" notice together.
- The settle arm: backlog #286 -- a retry pass that dropped a set member and still reports a slot conflict is a failed iteration, like the abort the drop replaced -- the search goes on to masks that settle cleanly (`btnr`: masking the world-selected `btrb` ends in the very conflict the bound mask was meant to avoid). A drop on an otherwise conflict-free pass settles (#276).
- The dead-end arm: Portage's abandoned `_create_graph` attempt: the node is consumed, but it keeps the pass's merged accumulators so a best-run re-pass reports the same USE changes and dropped pins the abandoned pass saw. The search itself continues elsewhere; the report comes from the best run below. Same cap as the failed-iteration arm (#297).
- The no-search arm: report the root pass with its merged working copy, exactly like the old single pass -- except the #209 feed above, which enforces satisfiable reverse-dep pins in-pass like Portage's ungated `_complete_graph`.
- Portage `_backtrack_depgraph` breaks when `backtracked >= max_retries` before feeding back; `restarts` is the number of restarts already done (passes-1); breaking falls through to the best-run re-pass after the loop.
- Exhausted without settling: the best run (deepest terminal node) is reported, never a masked-by-backtracking graph unless nothing better exists (Portage `get_best_run`).
- Backlog #563: the best-run re-pass re-derives the pass-local settle accumulators (dropped/enforced pins) through `collect_feedback` before assembling, and only assembles with them on `Settle` -- any other decision re-runs untouched, exactly as before. The terminal node's own accumulators predate the search (mask feedback children are non-terminal, so `get_best_run` comes back to the root with empty pins), and the re-pass never ran `collect_feedback`, so without this the fallback silently drops the residual/withhold reports: a pinned-newver `=dev-libs/p563pull-2` fell back to a clean upgrade that breaks the installed pinner with zero notice, where Portage aborts rc 1 with the slot conflict. Portage recomputes the report from the best run's own walk every time, so re-deriving is the faithful shape; the re-pass walk is deterministic, so a settle here reports what the best params settle on their own pass.
- Portage re-runs the best params with `allow_backtracking=False` once any restart happened (`backtracked`): every `--backtrack=0` gate applies to that last pass (#295).
- Backlog #244: Portage's post-loop `autounmask_breakage_detected()` (`depgraph.py:12262`): with the changes the search accumulated, a dependency of the best run wants a flag the other way from a needed change -- one clean pass instead.

## fn slot_conflict_handler_stops (#597)
- Portage's `need_config_change` handler arm (`_emerge/depgraph.py:11849-11865`) with the loop break at `:12401-12418`. The handler is built once per pass, on that pass's slot conflicts, so the check runs once per pass and a stop is only ever caused by the pass that found the change.
- Portage skips the arm when blocker conflicts are accepted: `--backtrack=0` together with `--buildpkgonly` or `--nodeps` (`_accept_blocker_conflicts`, `:9302-9315`; `--fetchonly` and `--fetch-all-uri` are not known to the resolver).
- Stop on the root pass: that pass is the report (`settled_with_backtracking` set, so the generic advice's `--backtrack=30` sentence stays out when it prints). Stop on a later pass: the loop breaks and the best-run pass with backtracking off follows, which drops the suggestion (quirk Q20: `need_display_problems()` is false for the stopped pass because the arm only returns True in the call that builds the handler). The final pass's own handler runs at assembly time on its own conflicts.
- Only conflicts the walk recorded are visible here. The residual installed-instance conflicts are added at assembly (`build_residual_slot_conflicts`), so a keeper like the cgp USE break (settles on the root pass) is explained by the assembly-time search, not by this stop.

## exit count (R6 #600: the printed count is Portage's `backtracked`)
- `restarts` is bumped by every loop pass that does not end the loop: a feedback always (D:12414-12416, even with all children rejected; the grow-config arm only when Portage would restart for the flip), a failed walk or dead end only while unexplored nodes remain (D:12417-12418). The cap is checked first everywhere (D:12411). The old `passes - 1` undercounted the first restart and every dead end with nodes left, and overcounted grow flips Portage never takes.
- The same rule is why the ordinary unsolvable slot-conflict cells print one less than Portage (host 3.0.83: 6 against 5 on `slotconflictunsolvable`, `slotconfgroup`, `scuseparent`, 4 against 3 on `slotusegroup`) and the missing-dependency abort cells print 0 where Portage prints 1 (`ormissbad`): fixed here, moving the harvested rows listed in `LLM/evidence/2026-10-26-575-residues/r6/drift-after.tsv` (+1 each, count line only).
- Known gap (#613): the count follows the search, and the search still takes a single-mask reverse-dependency restart where Portage takes a two-choice slot-conflict restart (`--autounmask-backtrack=y --backtrack=2 dev-libs/abk0d` with world `abk0b`: 1/2 vs 2/2, same rows/rc). No counting rule reaches Portage's number without visiting Portage's second node; see `LLM/evidence/2026-10-26-575-residues/r6/abk0-search-gap.md`.

## the MissingDep autounmask-backtrack stop (#594)
- The `--autounmask-backtrack=n` break also covers a `MissingDep` decision when the pass recorded an autounmask change: `need_config_change` is checked before `need_restart` (`depgraph.py:11838-11885`, `:12407-12418`), so the pass is the report even though a missing dependency was filed. Unlike the slot-conflict arm, no `failure.is_none()` is required: the replay stops at the first failure, so everything it recorded came before the stop.
- "Before the stop" is what the None-first replay order is for: with target-less edges first, a fixable USE miss later in the key never precedes the missing dep (the keeper that already matched keeps matching), while a change the walk genuinely reached first (another parent, LIFO) still breaks. Keepers that record no change (`needed == needed_init`) never break. The clean-pass contradiction arm above still runs first.
