# crates/portage-repo/src/resolve/rev_dep_or.rs
Which `||` arms of an installed consumer become parent atoms (#580 10b).

## struct OrScan
- The per-pass facts of `||` evaluation: whether Portage entered complete mode (`ResolveCtx::portage_complete`), the installed packages the walk recursed into with their picks (`PassState::installed_walked`), and the post-merge set (`PostMergeSet`).

## fn consumer_or_arms
- Portage evaluates an installed consumer's `||` once per dependency key, in the `_create_graph` call that pops it (`t9/views.md`). Three cases: the walk recursed into it (`Deep::recurses_at`, D:3834): the **walker's recorded pick**, whatever the complete-mode signal says (Portage chose it in `_filtered_trees` at pop time; the scan never recomputes it). Not recursed and Portage entered complete mode: `PostMerge` selection (`installed_consumer_or_selection`). Neither: `None`, the `||` is never evaluated and adds no parent atom.
- Edge: with `--ignore-world` the `--deep` re-walk has no seeds, but `portage_complete` does not depend on them (it is `req.complete` or the auto-detection over the pass's entries), so the edge noted in `t10b/mapping.md` section 2 does not arise.

## fn consumer_or_demotions
- The arm texts of one consumer's dependency string that are no parent atoms: the arms `dep_zapdeps` did not select, every arm when the `||` is not evaluated, and, for a `PostMerge` consumer, a selected arm that matches no installed package. Portage files such a dependency as initially unsatisfied (`_complete_graph`, D:8803-8809: `vardb.match_pkgs(dep.atom)` is empty) and never adds a pin; the site is the vdb test, not "matches nothing in the post-merge set" (T3's `=5.42*` matches the vdb and keeps its pin; T1's `=5.40*` does not). The plan named D:3438-3453, which is the narrower `_create_graph` site. A walker-recursed consumer's pick is not dropped: Portage's walk pulled it in.
- An arm that a sibling virtual leaked (see `sibling_virtual_leaks`) stays a parent atom, and goes through the same vdb test.
- Not done: a plain (non-`||`) atom that matches no installed package follows the same Portage rule and still pins here. Backlog item filed by 10b.

## fn sibling_virtual_leaks
- Quirk Q19 (`LLM/portage-quirks.md`). `_expand_new_virtuals` runs one `dep_check` per virtual (DC:195-260); `_select_atoms_highest_available` then keeps a virtual's child atoms whose `id()` is in `chosen_atom_ids`, the ids of every atom chosen in the parent's call (D:6122-6133, D:6164-6167). Since atoms are interned (PD:100-130) equal atoms are one object, so a virtual keeps every atom of its own dependency string that equals an atom chosen by its parent or by a sibling virtual, whatever its own `||` picked. On the bed's `dev-perl/XML-Parser` cell nine installed perl virtuals that list `=5.44*` first still carry `=5.42*` through this.
- The pre-pass runs per evaluated parent (walked, or in scope under complete mode) and per dependency key: chosen = the parent's plain atoms and its own `||` picks, plus, for each installed virtual it names, that virtual's plain atoms and picks (recorded when the virtual was walked, `PostMerge` otherwise; a virtual nothing evaluates chooses nothing). The leak of a virtual is its atoms that are in that set.
- Intern key (PD:1577-1595): atom text, EAPI, repo, USE and the unevaluated form. Only the text is compared here. `dep_check` passes `eapi=None` for an installed declaring package (DC:870-871), so EAPI never splits the key for installed virtuals (read from the source, not probed). A merge-bound virtual of another EAPI would not leak; not modelled, because the consumers are installed virtuals read from the vdb. Backlog item filed by 10b.
- Fixture family `p590v*` (pmtest): `p590vpar-1` (installed, in world) expands `virtual/p590vva` (`=5.44*`, `=5.42*`) and `virtual/p590vvb` (`=5.42*`, `=5.38*`). Portage 3.0.83 lists both virtuals' `=5.42*` in the skip block (`t10b/captures/q19-order-portage.txt`). The test passes on HEAD too, by the installed-arm heuristic that this slice removes; it is the guard for the pre-pass.

## built-atom conflict (fix round)
- In `constraints_from_atom`: a built slot-operator atom of a PostMerge consumer (not walked, Portage complete mode) that the post-merge set cannot satisfy but an installed instance matches is a pin, verbatim with its sub-slot, so the 10a consumer-pin conflict forms (`_complete_graph`, D:8803-8834; T2). It applies only when the stripped constraint is not already broken by the merge (that case keeps its old pin text; `test_oracle_209`).
- Exception, D:8816-8832: when backtracking is allowed and `_want_installed_pkg(pkg)` is false, Portage tries `_slot_operator_update_probe` (a rebuild of the parent) instead of adding the instance, so no pin. `OrScan::want_installed_pkg` is D:7308-7330: true if `--exclude` matches the installed instance; true if `selective` is set (`--update`, `--newuse`, `--reinstall`, `--noreplace`, `--changed-deps`, `--changed-slot`, `--selective`, minus `--emptytree`: `create_depgraph_params.py:145-155`, `:175-180`, `:213-217`); otherwise true unless an argument atom matches the instance. Argument atoms are real atom matches against the installed instance's `cat/pkg-ver:slot/sub::repo`. The `force_reinstall` argument flag is not modelled (portuale has no such argument kind). `selective` is `ctx.selective && !ctx.empty` (`resolve_plan.rs` computes it from Portage's trigger flags). So with `--update` the pin forms: `--update dev-libs/p589bpull` is 4/20 like Portage.

## sibling_virtual_leaks: bed fix round
- A virtual contributes its **RDEPEND** to a parent's dep_check whatever key the parent names it in (GLEP 37, `dep_check.py:217-220`). The first version looked the virtual up under the parent's own key, so virtuals named in an installed parent's BDEPEND (`dev-perl/List-MoreUtils-XS`, `File-ShareDir`, `YAML-Tiny` on the bed; File-Path) leaked nothing.
- A **merge-bound** parent is a graph node the walk expanded in the normal view: its dependency strings are the tree's (`live_metadata_for_installed` finds the ebuild by version) and its USE the entry's. On the bed `dev-lang/perl-5.44.0` is the only parent of `virtual/perl-Data-Dumper` and `virtual/perl-CPAN`. Its own `||` is chosen with `OrView::Normal`.
- Fixtures: `p590wpar` (installed, BDEPEND only; no Portage capture possible, host Portage resolves BDEPEND against `/` when ROOT differs) and `p590xpull` (merge-bound parent naming both virtuals; Portage capture `t10b/captures/q19-merge-portage.txt`).
- Bed probe (L0, six cells): `=5.42*` rows 21/21/20/21 and `:0/5.42=` rows 48/48/47/48 against Portage's 21/21/20/21 and 48/48/47/48 on XML-Parser, mariadb, MakeMaker, ruby; gimp's hidden-row counts 67 = 67.
- The skip-block `^` marker under an `=cat/pkg-ver*` atom now includes the `*` (Portage `format_unmatched_atom`: `op == "=*"` adds `*` to the version); it surfaced once the row lists matched.
