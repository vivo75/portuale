The slot-conflict ABI probe.

## struct ProbeParent
- Built `:S/SS=` atoms already relaxed the way Portage checks them (`relax_built_slot_operator_atom`).

## fn collect_probe_parents
- Portage `_slot_operator_check_reverse_dependencies` (`lib/_emerge/depgraph.py:2472-2573`) as the update probe's refusal gate on both scan arms (the `:2622` replacement-parent gate and the `:2738` candidate-child gate inside `_slot_operator_update_probe`; the `:2310` slot-conflict-fired probe is v2 `#214`'s own `slot_conflict_abi_probe`, which reuses this map).
- The caller precollects, per provider cp, every installed package Q whose recorded deps name that cp -- Portage's `_parent_atoms[child]`. Only parents Portage could see are collected: Q must be complete-mode reachable or walked this pass (an unwalked parent registers no dep); a Q this run replaces (merge-bound entry, or already in the replace set), uninstalls (blocker-conflict removal), or excludes carries a stale pin Portage skips (`:2513-2528` elimination, `_upgrade_available`, bug 612772, `excluded_pkgs`).
- `probe_refused` answers per scheduling edge: the fresh provider candidate (`fresh_cand`, `"cat/pkg-ver:slot/sub"` -- repo-less, so a `::repo` atom passes vacuously, a documented over-match corner) must match every surviving parent atom, with the consumer itself skipped (Portage's `replacement_parent` skip: the rebuild replaces it, so its own pin is not a veto). A single mismatch refuses the whole replacement -- the caller schedules nothing for that edge.
- Consumers scheduled later in the same scan loop are skipped at check time instead (see `probe_refused`).
- Same build-time-key rule as the scheduling loop: Portage drops a built package's `DEPEND`/`BDEPEND` before any dep is registered when `bdeps` is off, and only non-optional (walked) parents register them when it is on.
- Cuts: `_too_deep` (no depths at this layer), the direct-circular escape (no digraph here), and soname atoms (the parser rejects them, same direction as Portage's `continue`). `[use]` deps are not evaluated (the candidate carries no USE state -- allows, never blocks).

## fn add_argument_probe_parents
- Backlog #288: Portage's `_add_parent_atom` records an argument (`Arg`) as a parent of the package it selects, so `_slot_operator_check_reverse_dependencies` refuses a provider candidate that fails an argument atom (`=app-misc/mmprov-1` vetoes every slot-1 candidate, `--debug`: `candidate package does not match atom`). The installed-parent collection above never sees arguments.
- Cut: only the rebuild scan's call site files arguments (the slot-conflict probe and the force scan keep installed parents only).

## fn slot_conflict_abi_probe
- Backlog #214 (v2 `#24e`): Portage `_slot_conflict_backtrack_abi` (`lib/_emerge/depgraph.py:2282-2315`), the slot-conflict-fired half of the update probe (Portage `:2310`, via `_slot_operator_update_probe_slot_conflict` `:2453`).
- Portage's `_process_slot_conflict` tries this BEFORE the masking backtrack: for every recorded conflict, for every parent edge whose atom is a built package's soname/`:=` atom, it re-probes with `_slot_operator_update_probe_slot_conflict` (the `slot_conflict=True` form -- no `want_update` gate, no complete-mode gate) and, on success, schedules the parent reinstall through `_slot_operator_update_backtrack` (the same `slot_operator_replace_installed` set + restart the #211 scan feeds) instead of reporting the conflict.
- Portuale runs this over the direct solve's surviving records, in the feedback chain before the mask arms (the same order as Portage), and the caller grows the replace set, which restarts the search -- no masks are filed for a resolved conflict, like Portage's `remaining` skip. The rebuild's display pair is recomputed at settle time (see `slot_conflict_abi_display_pairs`), mirroring Portage's settle-time `_compute_abi_rebuild_info`.
- Per parent edge (parent P with atom A filed under instance M, other instance C), P is scheduled when every check holds: P parses (an `(Argument)` edge is not a package -- Portage's `not isinstance(parent, Package)` skip) and is installed at that version (Portage's `parent.built`), but is not merge-bound this pass (a merging parent rebinds its live `:=` through its own walk), is not already scheduled, and is not eliminated; P is not `--exclude`d (Portage checks the dep's parent end); A is a built slot-operator atom (`cat/pkg:S/SS=`, Portage `Atom.slot_operator_built`) that does NOT match C (else this edge is not conflicted at all); C differs from M in sub-slot (Portage skips identical slot/sub-slot) and is not older than M (downgrades need `_downgrade_probe`, unimplemented -- the same direction as the scan); a same-version tree ebuild for P exists (the reinstall Portage forces; with no visible candidate it would dead-end) whose live atoms accept C; the R2 refusal passes for C (the same `probe_refused` gate as the scan, over the same `collect_probe_parents` map).
- Cuts, all disclosed: soname atoms (the parser rejects them -- the scan carries the same cut); the probe's per-autounmask-level retry (`_slot_operator_update_probe_slot_conflict` re-probes at each level when `_autounmask` is on); merge-bound veto parents (the refusal only sees installed parents, like the scan's); the child-side `--exclude` check (only the parent end is gated); `||` evaluation of the replacement's atoms (every branch is flattened -- USE conditionals ARE evaluated against the replacement's effective USE, #254).
- Not gated on `rebuild_if_new_slot`: Portage's conflict path never is (the scan's call-site gate is the pre-existing narrowing for its own arms, not this one).
- Portage restarts the whole search per resolution, so two edges never share one probe call; the growing set is the local equivalent (a parent scheduled by an earlier edge skips, and its veto is forgiven, exactly like the scan's `scheduled`).
- Portage probes each non-conflicting slot node in turn as a candidate child.
- The same-version reinstall Portage forces: its mere presence proves the reinstall can land.
- #254: Portage's probe evaluates the replacement's USE conditionals (`_select_atoms_probe`, `_emerge/depgraph.py:2667-2713`, with `_pkg_use_enabled(replacement_parent)`). The replacement is the same-version tree ebuild; its effective USE is the one the walk would give it.
- #254: an atom under a `flag? ( ... )` whose flag the replacement ebuild does not enable is never selected, so it cannot accept C.
- The replacement's live atoms on the provider must all accept the other instance (not just one): Portage keeps only the replacement children every atom of the replacement parent agrees on (`_slot_operator_update_probe`, D:2780-2790, the `all_candidate_pkgs` intersection), so an exact pin on the old version (`=cat/pkg-5.42*` next to `cat/pkg:=`) leaves none and the probe files nothing. A `||` arm counts like any atom: the probe cannot tell which arm `dep_zapdeps` selects, and refusing is the safe side.

## fn slot_conflict_abi_display_pairs
- Backlog #214 (v2 `#24e`): the firing pass restarts the search, so only the settled graph is left to render Portage's `causing rebuilds` block -- and the scan cannot re-derive the pair there (no `Upgrade` entry keys its same-slot arm when nothing was installed, and same-slot `New` entries never feed its new-slot arm). Recomputed here from the settled state instead, mirroring Portage's settle-time `_compute_abi_rebuild_info` (`depgraph.py:996-1090`, which derives the block from the force-reinstalled parents rather than carrying it). Unioned with the scan's pairs and deduped by the caller, so shapes the scan already covers render exactly once.
- #254: Portage `_compute_abi_rebuild_info` (`_emerge/depgraph.py:996-1090`) only pairs a provider that is a graph child of the *replacement* consumer (`digraph.child_nodes(reinst_pkg)`): a rebuild whose new build no longer pulls the provider (a USE-conditional `:=` now off) was not caused by it, and Portage prints no pair. The provider entry's `required_by` is that edge.

## the same-slot vdb scan (doc block above highest_visible_slot)
- Portage depgraph's `_slot_operator_trigger_reinstalls` (3089-3132) + `_slot_operator_replace_installed` (the `@__auto_slot_operator_replace_installed__` set), run once every merge-bound entry is resolved: an installed package whose vdb `*DEPEND` carries a *built* slot-operator atom (`cat/pkg:S/SS=` -- operator `=`, both slot and sub-slot present, Portage `Atom.slot_operator_built`) whose bound `S/SS` no longer matches how this run leaves `cat/pkg` **in that same slot** must be rebuilt -- Portage's "don't leave a broken ABI link" auto-rebuild. (The scan itself lives in `rebuild_scan.rs`; this doc block is attached to `highest_visible_slot` for lack of a nearer item.)
- #24 S3: this is the *scan* only. It returns the consumer `(cat, pkg)` set for `BacktrackParams::slot_operator_replace_installed` (Portage's `backtrack_infos["config"]["slot_operator_replace_installed"]`) plus the `(provider_cpv, consumer_cpv)` display pairs (Portage's `_forced_rebuilds`), and builds **no** `GraphEntry`: the consumer becomes a walked node on the next pass (`run_pass`'s seed + flip), which is what gives it re-evaluated deps, a re-bound `:=` and Portage merge-order edges. The old post-pass entry synthesiser -- and with it the internal `scheduled`/`new_slot` fixpoint -- is gone; the cascade now falls out of the next pass seeing the rebuilt consumer as a provider at its *tree* sub-slot. The consumer becomes a walked node on the next pass (`run_pass`'s seed + flip), which is what gives it re-evaluated deps, a re-bound `:=` and Portage merge-order edges.
- **The scan is gated on `reachable`** -- Portage only slot-op-rebuilds a consumer that is in the graph in complete mode (a member of, or a forward-installed-dep of a member of, the required sets: Portage `_complete_graph` 8677 starts from `_initial_arg_list` -- the CLI args -- and appends `@world`/`@selected`/`@system`). `reachable` empty (not complete mode) means no rebuilds at all. #24 S5: the vdb half of this scan keeps that gate; the appended `slot_operator_slot_change_probe` half does *not* (Portage 3103-3107).
- `already` is the replace set as the current search node carries it. A cp in it is *not* skipped by the in-graph test (it is in the graph precisely because this scan put it there last pass), so its `abi_rebuilds` pairs keep being reported for the whole search; every other in-graph cp is skipped, exactly as before.
- `undone` (#24 S4) is the undo latch: a cp Portage's `_eliminate_rebuilds` demoted must never be scheduled again within a search node (Portage mutates the settled graph in place and does not restart, so its scan cannot re-fire; portuale's re-runs every pass and needs the latch).
- `with_bdeps` (#65 S1) mirrors Portage's `bdeps` parameter (`_emerge/create_depgraph_params.py:97-103`): only when it is true are an *installed* consumer's `DEPEND`/`BDEPEND` read at all. `_add_pkg_deps` (`_emerge/depgraph.py:4194-4247`) empties a built package's `DEPEND`/`BDEPEND` before any dep is registered when `bdeps` is not `y`/`auto` (Portage's default under `--usepkg`/`--getbinpkg`), so no slot-operator dep can ever be registered from them and no rebuild can fire. `RDEPEND`/`PDEPEND`/`IDEPEND` are runtime/install-time keys and stay unconditional.
- #65 S2: with `with_bdeps` true, `DEPEND`/`BDEPEND` are still read only for a consumer this pass actually **walked** (`entries`), not for one only *reachable* in complete mode. Portage registers an installed parent's build-time slot-op dep with `optional=pkg.built` (`depgraph.py:4277/4287`) and `_slot_operator_trigger_reinstalls` only probes `want_update` parents (`:3114`), which complete-mode-only reachability never satisfies (`:3802-3806`) -- so a world-only build-time consumer stays untouched while the same consumer, walked (an `@world` seed or an argument), rebuilds. The runtime keys keep the `reachable` gate: the slot-conflict path rebuilds graph-node runtime consumers in both shapes.
- Cuts (v2 remainder): the `_slot_change_probe`'s `runtime_pkg_mask` check on the tree ebuild (`:2341`); the update-probe (`_slot_operator_update_backtrack`, `:2427-2431`) and unsatisfied-probe (`_slot_operator_unsatisfied_backtrack`, `:2901-2903`) `slot_operator_mask_built` arms, which have no portuale-visible diverging shape -- both steer a *parent* the graph is already replacing (update) or failing on (unsatisfied), so same-version binary-vs-ebuild steering is vacuous there. The `:2310` slot-conflict-fired probe is NOT this scan (v2 `#214` ports it as the sibling `slot_conflict_abi_probe`, fed by the surviving conflict records rather than the merge entries).

## fn greedy_pinned_cps
- Backlog #268 cut (a): Portage expands each directly-requested atom into per-slot `cat/pkg:S` args, but only when the atom spans slots: `slots` is every installed slot matching the atom plus the highest visible match's slot, and a single slot means no pins at all. An explicit slot (`mmprov:1/2`) or exact version (`=mmprov-2`) atom therefore pins nothing -- the update probe's reverse-deps gate has no `P:S` arg to refuse against and the probe fires (probed on Portage 3.0.82.2, 2026-10-01; see `test_oracle_slotop_pin_gate_explicit_request_atoms_probe`).
- `top_level_cps` (every requested cp, whatever the atom form) stays the `want_update` stand-in -- an exact-version request still selects the provider through the arg chain (`=mmprov-2` rebuilds its consumer with no upgrade row at all).
- Visibility/masking is unfiltered here, the same approximation as `highest_visible_slot` (Portage `_select_package` respects it).

## fn greedy_pin_survives_revision
- Backlog #268 cut (b): Portage re-derives the greedy args accounting for blockers between the selected packages (`depgraph.py:5421`, `_greedy_slots(..., blocker_lookahead=True)`) and discards a pin whose package conflicts with the highest one (probed on Portage 3.0.82.2, 2026-10-01; see `test_oracle_slotop_pin_gate_blocker_discard_probes`).
- Models the highest-vs-bound-slot half: `G` is the highest visible tree package in the bound slot (Portage `_select_package` of the `P:S` atom), `H` the highest visible overall, both with their effective USE (the walk's own, via `effective_use_flags_uncached` over `flat_dep_atoms` -- Portage `_select_atoms` with `_pkg_use_enabled`).
- Still cut: the pairwise lower-version discard among two or more greedy packages (needs three installed slots; no fixture spans that yet).

## fn replacement_parent_accepts
- Backlog #304: Portage `_slot_operator_update_probe` (`depgraph.py:2576`) only reports a new-slot update when some *replacement parent* -- another available package in the consumer's slot (`_iter_similar_available(dep.parent, dep.parent.slot_atom)`) -- carries an atom on the provider that **accepts** the candidate (`replacement_candidates`/`all_candidate_pkgs`, `:2667-2760`; with no agreeing candidate the loop `continue`s and the probe returns `None`). A consumer whose current dependency atom is slot-pinned (`gcr:0/1=`) therefore never rebuilds just because the provider also exists at a higher slot (`gcr:4`).
- Approximates the replacement parent with the consumer's available tree ebuilds in its slot, evaluated with their own effective USE (the same reading the slot-conflict probe's `accepts` uses).
- Deliberate narrowing (documented cut): a replacement that cannot be read stays accepted, the pre-#304 behaviour, because the bare-ebuild unit fixtures and any tree whose metadata is incomplete would otherwise lose the probe entirely.

## fn parse_conflict_parent_cpv
- `cat/pkg-ver` for a slot-conflict parent edge: [`slot_conflict_puller_cpv`] renders `` `cat/pkg-ver:slot/sub::repo` `` (empty for a top-level `(Argument)` parent). Strips the display suffixes back to the triple.
