# crates/portage-repo/src/slot_operator/installed_parent_update_probe.rs
The update probe for an installed parent (the `_slot_operator_replace_installed` seed).

## fn installed_parent_update_probe
- Backlog #491. Portage `_slot_operator_trigger_reinstalls` (`depgraph.py:3104`) runs at the end of every pass (pass 0 included): for each recorded built-parent dep with `want_update`, `_slot_operator_update_probe` (`:2591`) ranges over available (not graph-bound) replacement parents, and each hit files `_slot_operator_update_backtrack` (`:2415`): `slot_operator_replace_installed` for the installed parent and the installed child, `slot_operator_mask_built` for non-installed binary parent/child, then `_need_restart`. Portuale's `fold_rebuild_scan` only runs inside SlotConflict feedback and `built_parent_update_probe` only covers merge-bound binary parents, so a clean pass seeded nothing.
- The replacement loop, candidate-child filter, and reverse-dependency check are `child_has_slot_update` (shared with the built-parent probe): the vdb-recorded (baked `:S/SS=`) atoms identify child and bound slot; the tree replacement's atoms pick the new child; `other_consumers_accept` relaxes built pins. Same-cpv tree candidates are skipped (sub-slot move without revbump is insignificant until a rebuild needs it).
- Gates, all Portage-shaped: graph-bound (only `AlreadyInstalled` entries — Portage probes `_slot_operator_deps`, never the whole vdb); `update` only (`want_update_probe` needs `dep.want_update` for an installed parent); never for an argument-pinned parent (`arg_pins_installed`: a request atom matching the installed instance but no strictly newer replacement — portuale tracks no per-edge update-wanted flag, and the hermetic V1 cell proves Portage stays quiet there: `captures/p491-debug-v1.stderr` carries no update-probe line); masked/excluded replacements and children refused (`_iter_similar_available` + probe-top excluded checks).
- Wiring (`resolve/feedback/slot_operator_probe.rs::step_installed_parent_update_probe`, called last in `collect_feedback_inner`): files through `file_unsat_probe_results` (no binary masks — both filings name installed packages), extends `probe_replaced`, folds the rebuild scan, restarts free via Config feedback. Last position is load-bearing: an early Config restart preempts the MissingDep mask and costs @world an extra try (4/20 branch baseline vs Portage 4/20 became 5/20; back to 4/20 after the move, merge rows byte-identical).
- Limits (Task 6 residue): the seed only fires for consumers the pass graphs — live `@world`-reached installed consumers (the kdbusaddons 24-atom try-1 set) stay out of reach without complete-graph member traversal, so the live pair is unchanged (20/20 rc 1, kde-frameworks conflicts, replace-in 28). Hermetic V1 (`=con-1` pinned) stays quiet by the pin gate; its remaining divergence (Portage 6 tries + lib:6 conflict vs portuale 1 try + rR rebuild) is conflict-feedback depth, a separate slice.

## fn arg_pins_installed
- Stands in for Portage's per-dep `want_update`: `=dev-libs/p491con-1` matches the installed instance but no strictly newer replacement, so the subtree wants no update. Same-version ebuild replacements do not count (a pin on the installed version still allows a reinstall).
