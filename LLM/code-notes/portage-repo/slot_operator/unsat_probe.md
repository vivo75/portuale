The unsatisfied slot-operator dependency probe.

## fn slot_operator_unsatisfied_probe
- Backlog #215 (v2 `#24f`): Portage `_slot_operator_unsatisfied_probe` (`_emerge/depgraph.py:2817`) as a post-pass trigger. Portage fires it in-walk (`:3447-3458`) when a built slot-operator dep (`dep.atom` with `slot_operator_built`, e.g. the vdb-recorded `>=app-misc/sousatprov-1:0/1=`) goes unsatisfied: for each `replacement_parent` -- a visible, non-installed, non-excluded package in the parent's own slot (`_iter_similar_available`, `:3015`) -- every live `:=` atom (`atom.slot_operator == "="`, `:2835-2839`, not a blocker, same cp) is tried with USE deps discarded (`atom.without_use`, `:2843`) through `_select_package` (`:2845`); the first hit returns true and `_slot_operator_unsatisfied_backtrack` (`:2881`) writes `slot_operator_replace_installed` (for an installed parent, via `_replace_installed_atom`, `:2908-2911`) plus `_need_restart`.
- The non-installed-parent `slot_operator_mask_built` arm (`:2901-2903`) is a cut of its own -- deliberately not ported here, and not covered by #212 (whose slot-change probe fires on a different trigger: a merge-bound binary's shifted built dep, Portage `:2381-2398`): a non-installed built parent (a binary package whose recorded `:=` dep is unsatisfied) has no unsatisfied-probe path at all (residue #257). The installed arm below is this probe.
- Portuale has no in-walk backtrack for this shape, so the probe runs here, on a dead-end pass, next to the #211/#212 post-pass trigger, with the same `BacktrackFeedback::Config` the scan uses (Portage's `backtrack_infos["config"]` + `_need_restart`). The seed grows the set monotonically, so the search terminates; a pass that heals settles, one that finds no replacement stays a dead end.
- Gates and cuts, all Portage-grounded:
- backtrack-gated at the call site (`ctx.backtrack_max > 0`), like Portage's `_allow_backtracking` gate (`:3447`) and the scan's own bt0 gate: under `--backtrack=0` Portage fails the run (`emerge: there are no ebuilds to satisfy ...`), and so does this port.
- `dep.atom.package` (Portage `:3449`) is vacuous: parsed atoms always carry a package.
- The parent must be installed (Portage `dep.parent.installed`) and the probed installed instance must not sit in `runtime_pkg_mask` already (Portage `:3447-3448`, per package instance, else the restart would loop); an installed parent matching `--exclude` refuses (Portage `:2818-2824`).
- The replacement search is same-slot (Portage passes `dep.parent.slot_atom`), visible (`is_visible`, standing in for `_pkg_visibility_check`), non-excluded and unmasked per instance (Portage `:3036-3040` skips `pkg in _runtime_pkg_mask` then the excluded check), ebuild-only (installed instances never seed a reinstall).
- `onlydeps` (Portage `:2844-2845`, threading `dep.onlydeps` into `_select_package`) is ignored: the re-resolve passes `&[]`.
- The replacement's live dep keys are runtime keys always, `DEPEND`/`BDEPEND` only `with_bdeps` (the scan's own key discipline; Portage's `validated_atoms` spans every key).
- The replacement's atoms are reduced with every conditional branch active, Portage's `validated_atoms` (`use_reduce(..., matchall=True)`, `_emerge/Package.py:329-359`).
- No `check_reverse_dependencies` refusal: Portage's unsatisfied probe has none (unlike the #211 update probe) -- a vetoing sibling does not withhold the reinstall (S0 veto cell).
- Same-version-first seeding (`_replace_installed_atom`'s `=cpv` half) is a cp-level seed here like the scan's: with a single available parent version the two coincide; a newer-version replacement alongside the same-version reinstall is a filed cut.

## fn slot_operator_unsatisfied_probe_full
- Plus #257's binary arm: Portage `_slot_operator_unsatisfied_backtrack` (`_emerge/depgraph.py:2881-2915`) masks a *non-installed* built parent (`slot_operator_mask_built`, `:2896-2903`) instead of seeding a reinstall, and restarts, so the next pass selects the replacement ebuild. Here that parent is a merge-bound binary graph entry; the second result carries its `(category, package, version)`, filed by the caller as the same `[binary]`-marked `SlotOperatorBuilt` negative #212 uses. The firing gate is Portage's `dep.parent not in _runtime_pkg_mask` (`:3447-3448`) for that binary instance.
- Portage `_iter_similar_available` (`:3036-3040`) and the firing gate (`:3447-3448`) both skip `pkg in _runtime_pkg_mask` per package instance (Portage keys by package object); a `[binary]`-marked negative never screens the same-version ebuild (Portage still yields the ebuild there; see `is_binary_only_mask`).
- #276: an `[installed]`-marked negative screens the installed instance itself (Portage `:3447-3448` skips a masked parent).
- Portage probes one dep edge (parent -> the built atom, `:3447-3458` into the `:2817` probe); Portage restarts on the first hitting edge (`:3453-3455`), this seeds every hitting owner of the cp in one pass (residue #256).
- The puller triples pair owner and atom text; Portage's USE-evaluated view matches: a conditional built want that evaluates false is absent.
- #254's conditional shape heals only through the matchall reduction.
