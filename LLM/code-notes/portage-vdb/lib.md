# crates/portage-vdb/src/lib.rs
The installed-package database ("VDB") behind one interface.

## module
- feat#157, backlog #305. Design: `LLM/feat-157-authoritative-vdb-database.md` (authoritative) and `docs/vdb_to_db.md` sections 6-11. Plan: `LLM/02.305-vdb-backends.opus.md`.
- The method list comes from the S0 inventory (`LLM/evidence/305-s0-path-inventory.md` section 4, needs N1-N16 in section 5) and the write order from `LLM/evidence/305-s0-vartree-write-order.md` (S0.1 rows 3-16).
- `register` / `for_root` is the process-wide registry. `FilesDb` history: S1.2 moved the per-entry and `aux` reads behind it; S1.4 moved the merge's writes (item 20 below); other methods returned `Error::Unsupported` until S2+ moved them.
- Method-to-need mapping (S0 inventory): `entries` = R3, `category_entries` = R1, `aux_get` = R2, `has_entry` = N13, `read_file` (exact bytes) = R5, `reverse_dependents` = R4, `owners` = R6, `read_pending_file` = N2, `read_file_all` = N11, `vdb_dir`/`entry_path` = N9/N10, `world`/`world_sets` = N5, `preserved_libs` = N6, `config_memory` = N7, `counter`/`next_counter` = W5/N1, `insert_entry` = W1, `delete_entry` = W2, `replace_file` = W4, `put/copy_entry_file` = N3, `set_world` alone legal = N4, `delete_entry` rmdir = N14, `begin_entry` before `pkg_preinst` (killed-mid-merge invariant) = N1, `categories`/`category_entries` order = item 21, snapshot for backend caches = S3.2, `category_generation` = N8a, `entry_stat` = S7, import mark tooling = S2.6/convert, `rebuild_index` = S8.3.
- `Cpv` is `EntryKey { category, pf }` (item 1): splitting needs `ververify`, and several sites only hold the `pf`. The key is always the stored (pre-move) name; the move fallback stays in `portage-repo` (N13).
- `begin_entry(image) -> EntryId` split into steps keeping the write order (item 2): `begin_entry` runs before `pkg_preinst`; `copy_entry_file`/`put_entry_file` add files (N3); `next_counter` ticks (N1); `seal_entry` writes `metadata` with the stamp last; `finish_entry` publishes. N1 wanted the counter from `begin_entry`, but it is ticked after the build-info copy, so one call cannot do both; `next_counter` returns the value before any payload lands.
- The pending entry is named by its `EntryKey`, not an `EntryId` (item 3): it outlives a transaction (backends commit `merging` first, finish later; `files` has at most one `-MERGING-<pf>` per key).
- Replace order is delete, then publish (item 4; `vartree.py:5219-5238`): `delete_entry` for the old instance before `finish_entry` for the new one.
- `snapshot()` is not the hot read path (item 5): on `files` a whole snapshot would open ~23 files per entry for the ~1,500 of 2,130 host entries with no `metadata` file. The resolver reads via `entries`/`category_entries`/`aux_get`/`has_entry`, keeping the `openat`/`statx` counts (N8b). `snapshot` stays for the database backends' generation-keyed caches (S3.2).
- Two cache keys (item 6, N8a): `generation` (files: `vdb_fingerprint`, `0` when missing) and `category_generation` (files: one category dir mtime, 1-2 `statx` per call instead of ~30).
- Extra reads (item 7): `read_pending_file` (N2; caller composes "live, then pending"), `file_meta` (exists-tests as one `stat`), `read_file_all` (N11; every live entry with `None` where missing, so `read_all_needed_entries` keeps empty rows without a second walk).
- `reverse_dependents` returns raw records (item 8; section 0.7, N15 option b): `DepRecord` holds normalised `USE` plus the requested `*DEPEND` strings; the caller reduces and matches. `files` returns every entry, an indexed backend only entries whose reduced atoms name `cp`. The classes are a parameter because the scan reads four keys, not five (no `IDEPEND`).
- `world()`/`set_world` split into `world` + `world_sets` (item 9, N5): each file read/written alone, single-store transactions legal (N4).
- `PreservedLibs` carries `loaded` (item 10, N6): `set_preserved_libs` writes nothing when `entries == loaded`.
- Counter store access for converters (item 11): `counter` + `set_counter`. `Counter` is `i64`: missing/corrupt reads as `-1`, so the first merge gets `0`. On `files` the tick is Portage's `counter_tick_core` since #306: under the VDB lock, max of the file and every entry's `COUNTER`, plus one, written atomically.
- Whole-entry copy for converters (item 12): `entry_image` + `insert_entry` with exact bytes, modes, mtimes and stamp state. A stale stamp stays stale; no `metadata` file is ever added (S0.3 corpus).
- Paths for the `files` backend (item 13): `vdb_dir` + `entry_path` (N9: `PORTAGE_UPDATE_ENV`, saved-env phases; N10: `emerge -C /var/db/pkg/cat/pf`). `None` on database backends; callers use a scratch copy plus `replace_file`.
- `FileMeta` keeps the section 6.1 meaning (item 14); N16's `CONTENTS`-line record is not a trait type (see Rejected).
- `aux_get` serves only the 23 `METADATA_FILE_FIELDS` (item 15), normalised like Portage's `_aux_get` (`" ".join(v.split())`, invalid `SLOT` to `"0"`). Other keys (`CONTENTS`, `NEEDED.*`) are `read_file`, raw bytes. `None` means "no such entry", so the move fallback can tell it from an empty field.
- Errors are one hand-written `Error` enum (item 16): `#[non_exhaustive]`, no `thiserror`. `Error::Io` displays as `"<path>: <io error>"`.
- One copy of the `metadata` format (item 17): `METADATA_FILE_FIELDS`, `METADATA_FILE_FORMAT_VERSION`, `in_metadata_file` defined here; `portage-repo` re-exports them (S1.2).
- How `FilesDb` realises the S1.2 reads (item 18, no interface change): per-entry memo is thread-local keyed by `(vdb dir, category, pf)`, validated by the entry dir's `st_mtime_ns` (the registry hands out one `FilesDb` per root, but the memo is per thread, as before). `aux_get` costs one `statx` on a memo hit. `has_entry` is one `statx`. `read_file` is one `open` with no existence `stat` (callers needing "entry exists" call `has_entry` first). `category_generation` is one `statx`. `snapshot` unimplemented until S3.2.
- S1.3 (item 19): `FilesDb` does not implement `reverse_dependents`; the scan stays in `portage-repo` over `aux_get` (reproducing the memoised `all_installed_packages` walk would need the move-remapped set above this crate, or an uncached walk). `FilesDb::entries` serves `all_installed_packages`' uncached walk; `has_entry` the entry-exists tests and move-fallback resolution; `read_file` the contents reads and env vars.
- S1.4 merge writes on `files` (item 20, no interface change): five VDB steps call the trait in order, each its own transaction. `create_vdb_tmp` -> `begin_entry`; `populate_vdb_tmp` -> `copy_entry_file` per build-info file, `next_counter`, then `put_entry_file` for `CATEGORY`/`SLOT`/`repository`/`COUNTER`; `write_vdb_tmp_contents` -> `put_entry_file` (`CONTENTS`) then `seal_entry`; `publish_vdb_tmp` -> `finish_entry`. Replaced same-slot entries still deleted by `delete_vdb_dir` between the last two steps (S1.5 routes it to `delete_entry`), so item 4 holds. `begin_write` does no I/O. `populate_vdb_tmp` rejects non-UTF-8 build-info names (entry file names are `String`); before S1.4 it copied them -- no such name exists (fixed ASCII keys and `<PF>.ebuild`).
- S1.5 unmerge, W4 rewrites, scans (item 21, one addition): `delete_entry` is `delete_vdb_dir`; `replace_file` is the two `std::fs::write` calls of `remove_from_contents` (in place, entry mtime and stamp untouched). Unmerge reads are `read_file`/`file_meta`; saved environment and ebuild go to bash by path (`entry_path`, N9). `read_file_all` is `read_all_needed_entries` moved unchanged. `owners` is `find_owners` plus per-entry `CONTENTS` reads (`find_owners` drops entry names that don't split, and applies the package-move fallback above the crate). New: `categories`, so `blockers_from_flat_deps` keeps its order (list a category, read each entry's `SLOT`, next category); also drops the per-entry `is_dir` stat (directory-ness by `d_type` or `stat`). `unmerge_replaced_same_slot` lists its category the same way, so a stray non-directory named like a version is no longer an installed instance.
- S1.6 world/world_sets on `files` (item 22, no interface change): readers are `pretend::read_world_atoms`/`read_world_sets` moved unchanged (one `read_to_string`; only `NotFound` is empty, else `Error::Io`; caller adds its `reading ` prefix; trimmed lines, blank/`#` dropped, `world` drops `@` lines, `world_sets` keeps only `@` lines stripping every leading `@`). Writers are `pretend`'s three rewrites moved unchanged (caller sorts/de-duplicates; `create_dir_all` once per transaction; lines joined by `\n` plus trailing `\n`; empty writes empty file; plain `write`, no temp file/lock/ atomicity). Single-store transactions legal. "Recording ... in world favorites file" stays in `pretend`. Bare VDB dir: reads empty, writes `Unsupported`.
- S4.1 merge on a database backend (item 23, two additions): `finish_entry_replacing` deletes replaced same-slot entries and publishes in one transaction (default: `delete_entry` each then `finish_entry`); `replace_in_publish` is the switch (`files`: false, databases: true). `files` unchanged. Commit order on a database backend: (1) `begin_entry` before `pkg_preinst`; (2) build-info files, `CATEGORY`/`SLOT`/`repository`, `next_counter` + `COUNTER`; (3) payload merge's config memory; (4) `CONTENTS` + `seal_entry`; D4 writes per old instance (each its own commit, without deleting the old row); (F) one commit: `finish_entry_replacing` (old rows gone, new row installed, derived tables, `counter_hwm = max(hwm, COUNTER)`) plus preserved-libs registration. After: `pkg_postinst` `environment.bz2` rewrite (one commit) and post-merge prune. Until (F) every reader sees the old instance; a crash before (F) leaves old installed plus a `merging` orphan (design 9.1). Commits 2 and 4 cannot join (1)/(F): `pkg_preinst` runs between (1) and (2), and the replace loop reads pending `CONTENTS`/`NEEDED.ELF.2`. D4 writes before (F) stay separate because the next step reads them back. `world` written by `pretend` at run end (section 0.7). The replace loop tells later unmerges which earlier ones already unmerged (rows still live), so `others_in_slot` matches `files`. Paths for bash/copiers (N9): `materialize_files`/`materialize_entry` write live-entry files into scratch dirs, `absorb_file` stores back with one `replace_file` commit when bytes changed. `files` keeps `entry_path`.
- S4.2 standalone unmerge on a database backend (item 24, no interface change): uses `replace_in_publish` as the switch again; `ebuild_unmerge::retire_entry` collects D4 writes in memory and commits with the row deletion in one transaction after `pkg_postrm` (W4 `replace_file`s of other entries, `set_preserved_libs` with `loaded` = stored registry, `set_config_memory` stale prune, `delete_entry`). Exactly one generation step per unmerge. Until commit every reader still sees the entry (payload files already gone, as on `files` before `delete_vdb_dir`); `prerm`/`postrm` read the scratch copy. Steps reading what earlier steps wrote read the in-memory copy. Separate: world files (`deselect_from_world`, second transaction, as on `files`; `--deselect` has no unmerge); merge replace loop (S4.1: D4 writes precede publishing commit and are read back); failed unmerge leaves registry/config/rows as they were (on `files` the registry write would already have landed). `files` unchanged.
- S4.3 sweeping orphans (item 25, one addition): a killed merge leaves a `merging` row (`files`: `-MERGING-<pf>`) that `pending_entries` lists. Nothing removes it automatically: `mrg` warns at startup on a database backend (once, before its own merge), `portuale vdb status` lists it, `portuale vdb sweep` calls `discard_pending` (only pending entries; installed untouched; non-pending key is `Error::Invalid`).
- S7.2 read-only FUSE view (item 26, one addition): `entry_stat` is `entry_image` without bytes (needs every entry's dir mtime for category/root mtimes without reading blobs). Every backend overrides the default. The view is `portuale`'s `vdb_view.rs`; `fuser` is not a dependency of this crate.

## SqliteDb (feature `vdb-sqlite`)
- S2.3 schema + `open`/`open_readonly`; S2.4 reads; S2.5 writes. Nothing `Unsupported`.
- Reads (S2.4) return what `FilesDb` returns for the same logical content (unit tests seed both and compare every read). Only `state = 'installed'` rows live; `read_pending_file` reads the `merging` row. Lists ordered by `(category, pf)`/name, byte order. `aux_get` follows the stored stamp: `valid` serves the stored `metadata` snapshot complete (a dropped field, e.g. non-UTF-8, is `""`); `absent`/`stale` read the field file lossy/whitespace-joined; invalid `SLOT` is `"0"`. Extracted `slot`/`subslot`/`repo` columns unused by reads. `owners` reads the `owner` table (S8.2: indexed lookup of each distinct path, `/p` and `p` spellings, `claim_paths` rule, first matching input path, `(category, pf)` then `CONTENTS` order). `category_generation` is global `meta.generation`. `counter` is `meta.counter_hwm`, `-1` reading as `None`. `read_file_at` is `substr` on the blob. `snapshot` built from field files under `aux_get` rules in one read transaction. `reverse_dependents` reads `dep_atom` (S8.1): live entries with a row for `cp` or unsure `""`. Known difference: `categories` lists only categories with a live entry. `world`/`world_sets`/empty-path preserved-libs round-trip as `files` since S2.5.
- Write transactions (S2.5): one merge spans several transactions, so a pending entry is a committed `state = 'merging'` row surviving crashes (design 9.1). Each `SqliteTxn` is one SQLite transaction on its own connection, `BEGIN IMMEDIATE` in `begin_write` (second writer waits up to 5 s `busy_timeout`, then `Error::Backend`), committed by `commit`, rolled back when dropped uncommitted. Reads on `SqliteDb` during an open transaction don't block (WAL) and see committed state. Read-only handle refuses `begin_write` (`Error::Invalid`).
- Generation policy: `meta.generation` +1 per committed transaction that wrote anything (no-effect writes and unchanged `set_preserved_libs` don't bump), D4-only ones included. `files` has no counter; the portable contract needs a change only after entry-level commits, and bumping more only invalidates caches more often.
- Entry writes: `begin_entry` drops a stale `merging` row and inserts fresh (schema `UNIQUE (category, pf, state)`; installed row of same key stays). File puts store mode/mtime of the call; a new name on a `valid` stamp makes it `stale` (as a dir-mtime move on `files`). `seal_entry` stores the `metadata` bytes `FilesTxn` writes (`#dir_mtime=` carries `entry.dir_mtime_ns`), stamp `valid`. `finish_entry` in one transaction: delete same-key installed row (cascade), flip `merging` row, fill extracted columns + derived tables, raise `meta.counter_hwm` to entry `COUNTER` when larger. `insert_entry` stores the image as given, replaces live same-key row, fills derived tables, leaves `counter_hwm` (converter calls `set_counter`). `delete_entry` removes installed row only (pending replacement survives); missing entry, puts, or `finish_entry` without pending are `Error::Invalid`. `replace_file` keeps mode/other files/stamp/dir mtime, refreshes derivatives. `next_counter` is `counter_hwm + 1` in the same transaction (atomic, unlike `files`; dropped transaction consumes nothing); `set_counter` plain store.
- Derived tables exist only for installed rows, refillable from stored files. `owner`: `claim_paths` line rule; non-UTF-8 `CONTENTS` gives no rows, like `files`. `needed`: `NEEDED.ELF.2` lines with >= 5 `;` fields; no-rpath sentinel `""`. `dep_atom` prefilter (no `portage-dep`, item 8): one row per distinct `(class, cp, token)` via `dep_cp`; S8.1 unsure marker `""`; callers still reduce/match. Index assumes a `valid` snapshot agrees with the `*DEPEND` files; pre-S8.1 databases need `rebuild_index` (S8.3). Columns `slot`, `subslot` (slot when no `/`), `repo`, `counter` come from `SLOT` (as `aux_get` serves it), `repository`, `COUNTER`.
- Schema edits in S2.5 (nothing released, so `SCHEMA_VERSION` stays 1): `UNIQUE (category, pf, state)`; `preserved_lib.path` nullable; `world`/`world_sets` keyed by `pos` keeping written order.
- Schema version policy: `meta.schema_version` (1, `SCHEMA_VERSION`) independent of `METADATA_FILE_FORMAT_VERSION` (plan section 1, Q4). Another value, no `meta` table, or a non-SQLite file is `Error::Corrupt`; no silent migration. Engine failures `Error::Backend`; missing file for `open_readonly` is `Error::Io`.
- Pragmas (`open`): `journal_mode=WAL` (refused with `Error::Invalid` when the filesystem won't take it), `synchronous=FULL`, `busy_timeout=5000`, `foreign_keys=ON`. Local filesystems only; network not detected.
- Tables: `meta`, `entry` (`(category, pf)` key, `merging`|`installed`, stamp, dir mode/mtime), `entry_file` (the truth, bytes), rebuildable `owner`/`dep_atom`/`needed`, plus `preserved_lib`/`world`/`world_sets`/`config_memory`. `meta` holds `schema_version`, `generation`, `counter_hwm` (`-1` = none), `created_at`, optionally `imported_files_generation` + `imported_files_source` (converted-from-files detection).
- Import mark: `copy_all` files->database records source `generation()` and root path as `imported_files_generation`/`imported_files_source`, so tools can warn when the source changed since conversion and reconversion is needed.

## RedbDb (feature `vdb-redb`)
- S5.2 tables + `open`/`open_readonly` + reads; S5.3 writes (every `WriteTxn` method; `begin_write` `Error::Invalid` on read-only). Details in `redb_db.rs` / `redb_db/write.rs` module docs.
- One process only: redb locks the file for a read-write handle, so a second open fails with `Error::Busy`. Several read-only handles may coexist. S5.5 surfaces this in `convert` and `vdb status`.
- State model as sqlite: `entry` keyed by `(state, category, pf)` (`0` merging, `1` installed). File bytes in 64 KiB chunks (`entry_file_chunk`, `(len, mode, mtime)` in `entry_file_meta`); `read_file_at` loads only needed chunks. Fixed little-endian binary records, no serde.
- Writes follow `SqliteTxn` method by method (semantics, errors, generation, counter, stamps, derived rows). One `WriteTxn` is one `redb::WriteTransaction`; redb allows one write transaction per `Database` and `begin_write` blocks until the open one ends -- so a second `begin_write` on the thread already holding one would wait for itself and returns `Error::Invalid`. Callers hold one transaction at a time (the merge already does). Reads during a transaction don't block and see committed state. `owner`/`dep_atom` (shared `dep_cp` prefilter)/`needed` filled in the same transaction; `meta.generation` bumped on commit when anything was written.
- Reads equal sqlite's (and `FilesDb`'s): same stamp rule, same `owners` rule, `category_generation` = `generation`, `categories` only live categories. Listing + 23-field snapshot cached in-process, validated against `meta.generation` (same read transaction) per call; single-process, only this handle's commits can change the file.
- Schema version `REDB_SCHEMA_VERSION` (1) in `meta`; another value, a redb file without the tables, or a non-redb file is `Error::Corrupt`. `meta` also holds `generation` (0 at creation), `counter_hwm` (-1), `created_at`.

## Rejected from N1-N16

## trait InstalledDb
- `generation` on `files` is the `vdb_fingerprint`; database backends use `meta.generation` bumped by every commit.
- `category_generation` on `files` is the category dir mtime in nanos (the `installed_candidates` key).
- `aux_get` normalisation mirrors Portage `_aux_get`; `None` vs empty distinguishes "no such entry" for the move fallback.
- `read_file_at` serves FUSE: short at end of file.
- `entry_stat` default derives from the image; S7 needs it without blob reads.

## trait WriteTxn
- `begin_entry` creates the empty pending entry before `pkg_preinst` (the l32 C4 killed-mid-merge invariant, #183).
- `next_counter` on `files` is Portage `counter_tick_core` (VDB lock, max-over-entries, atomic write); the caller writes the entry's `COUNTER` file with `put_entry_file`.
- `seal_entry` is Portage `_write_metadata_file` + `_stamp_metadata_file` (`vartree.py:188-229`, `not delete_individual`).
- `finish_entry` is Portage `self.dbdir = self.dbpkgdir; self.delete(); _movefile(dbtmpdir, dbpkgdir)`.
- `finish_entry_replacing` default preserves the delete-then-publish replace order (design section 9, item 4).
- `begin_write` takes the write lock on database backends (sqlite `BEGIN IMMEDIATE`).
