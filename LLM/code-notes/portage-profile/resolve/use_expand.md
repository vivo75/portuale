# crates/portage-profile/src/resolve/use_expand.rs
USE_EXPAND, USE_EXPAND_UNPREFIXED and IUSE_EFFECTIVE from the folded scalars.

## fn expand_use_vars
- Each named variable's value uses the same last-wins mechanism every other non-USE/ACCEPT_KEYWORDS variable uses (see the module doc comment) -- a deliberate simplification of Portage's genuinely-incremental per-USE_EXPAND-variable behavior, extending the pre-existing "no incremental merge outside USE/ACCEPT_KEYWORDS" cut, not a new one.
- History: an earlier "`USE_EXPAND_HIDDEN`/`USE_EXPAND_IMPLICIT` are display-only" note was wrong for `USE_EXPAND_IMPLICIT`: it drives `pkg.iuse.is_valid_flag` (so a `foo[elibc_glibc]` USE-dep matches a `foo` that never lists `elibc_glibc`), not just `emerge --info` display. `USE_EXPAND_HIDDEN` genuinely is display-only for EAPI 5+ (see `Config::iuse_effective`); it is read now (`Config::use_expand_hidden`) and honoured only by `emerge --pretend -v`'s USE_EXPAND grouping in `portage_repo`.
- Env layer: Portage treats each USE_EXPAND value as its own incremental; portuale's last-wins `scalars` model lets the env value replace the profile/make.conf one.
- Per-level fold: Portage config.py (2849-2889), "In order to best accommodate the long-standing practice of setting default USE_EXPAND variables in the profile's make.defaults, we translate these variables into their equivalent USE flags". Portage then skips re-folding USE_EXPAND for the `defaults` configdict (2964); portuale mirrors that with the `profile_scalars` guard in the two global loops. The neovim `^^ ( lua_single_target_* )` REQUIRED_USE case in miniature: base `make.defaults` `LUA_SINGLE_TARGET="lua5-1"` plus base `package.use` `app-editors/neovim lua_single_target_luajit -lua_single_target_lua5-1`.
- Guard shape: per-var ("did conf/env touch it"), never per-level ("is this level's value the one that survived"), because Portage's `conf`/`env` pass with `is_not_incremental` clears every `<var>_*` flag and re-adds that tier's value wholesale (handled by the global loops).
- UNPREFIXED: Portage's companion mechanism; Gentoo's own profile sets `USE_EXPAND_UNPREFIXED="ARCH"`, which is literally how `amd64`/`x86`/`arm64` exist as USE flags at all.
- IUSE_EFFECTIVE: computed now that `use_expand`/`use_expand_unprefixed`/`use_expand_implicit`/`iuse_implicit` are all stacked and every `USE_EXPAND_VALUES_<v>` scalar read.
