# crates/portage-profile/src/resolve/package_use.rs
`package.use` from repos, profiles and the user, plus the FEATURES=test and env.d USE.

## fn fold_package_use
- package.use's three sources (the "Config depth" slice, SCOPE_BACKLOG Part 2.C; see the module doc comment's `package.use` bullet and `portage-repo::effective_use_flags`): repo-level (`<repo>/profiles/package.use`, every configured repo -- Portage `UseManager._parse_repository_files_to_dict_of_dicts` iterates `repositories.repos_with_profiles()`) into `package_use_repo` (Portage `configdict["repo"]`); every profile level's own package.use (chain order) into `package_use` (Portage `configdict["defaults"]`, `_pkgprofileuse`); user-level `/etc/portage/package.use` into `package_use_user` (Portage `configdict["pkg"]`, `_pusedict`/`getPUSE`). Overlay repo lines are `::repo`-scoped via `scope_repo_package_use_lines` (the "package.mask, widened" precedent); the main repo's stay unscoped, since Portage's own masters-chain lookup (`repos = masters + [pkg.repo]`) always includes it (every overlay here implicitly masters main, no explicit `masters =` support yet). Each source is parsed independently so only the user-level one gets the USE_EXPAND-prefix shorthand's user-only `extended_syntax` (see `parse_package_use_lines`). The `defaults`-tier profile package.use is interleaved per profile level (see `Config::profile_use_layers`, built in the make.defaults chain loop); the flat `config.package_use` built here is only the fallback for a hand-built `Config`.
- Repo `make.defaults` USE (Portage `config.py` `_repo_make_defaults`): `${VAR}` expanded against the scalars accumulated so far. An overlay's entry (its name) applies only to a candidate from that overlay; see `Config::repo_make_defaults_use`.
- FEATURES is a last-wins scalar here (make.conf / profile make.defaults / env layer, whichever set it last), a documented simplification.
- env.d USE comes from Portage `_get_env_d`; `/etc/env.d/*` doesn't set `USE`.
- The `*/*` pop: Portage's `_pusedict` is built from user files alone, never profile/repo package.use. Folded here -- after the USE_EXPAND / USE_EXPAND_UNPREFIXED loops -- so a `*/* -lua_single_target_lua5-1` really removes the value the profile's own `LUA_SINGLE_TARGET=` scalar just folded in. Popped from `package_use_user` too (Portage deletes the `*/*` key), so it is not also re-applied per-candidate in `effective_use_flags`.
