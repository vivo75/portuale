# crates/portuale/src/emerge_build/tests/buildpkgonly.rs
`--buildpkgonly` execution tests (end-to-end builds plus failure-mode pins).

## general
- Codec pinned to "bzip2" (near-universal base package) rather than Portage's default "zstd", so these tests do not depend on the test-running host actually having zstd installed; xpak/tbz2 building is codec-agnostic either way.
- The gpkg default is backlog #173 (Portage `cnf/make.globals:43`): tests asserting the default artefact follow gpkg, while the XPAK-shape tests pin `binpkg_format: "xpak"` explicitly.
- `SIZE` assertions are backlog #39: Portage's `_post_src_install_write_metadata` always writes `IUSE` (empty for a no-IUSE ebuild), the profile-computed `IUSE_EFFECTIVE`, and `_post_src_install_uid_fix`'s own `${D}`-walk `SIZE`. The size walk must record a positive `SIZE` for a package with a file; `phaseenvpkg` installs only a `keepdir` (the `.keep_*` marker lands at merge time), so its image holds no regular file and Portage's own walk writes `0`, but the member must be *present*.
- `USE`/`FEATURES`/`SLOT`/`IUSE`/`IUSE_EFFECTIVE` assertions are #37 S2: Portage's `__dyn_install` writes `USE`/`FEATURES` into `build-info` from the phase env, and `_post_src_install_write_metadata` always writes `IUSE`/`IUSE_EFFECTIVE`.
- `fetchpkg`'s fixture has a nonempty `SRC_URI` but no Manifest entry at all; see `crate::fetch::fetch_src_uri` (unverifiable content is worse than a loud failure).
- The per-entry `BINPKG_COMPRESS` test is backlog #147 S2: a `package.env` scalar match must reach the xpak tar pipe for that entry only; the observable is the archive magic (the matched entry compresses with its own codec, its unmatched neighbour in the same run keeps the run-wide one). Portage's `doebuild_environment()` reads the package's own `mysettings` (`doebuild.py:697`); S0 B-xpak proves gzip magic with a zstd run-wide. Needs no Portage checkout: the install/package phases run through the native helpers (#326 S2-S7), verified live with `PORTUALE_PORTAGE_CHECKOUT=/nonexistent`, like the multi-instance test.
- The multi-instance test is backlog #130 plus backlog #147 S1 ruling (i): the binpkg layout is run-wide-only (Portage's bintree binds its allocator once, `bintree.py:529-531`; S0 A1x/A2 prove both directions), while the `BUILD_ID` export follows the entry's own token (Portage `EbuildBinpkg.py:47-48`). With run-wide multi-instance on, a per-entry `-binpkg-multi-instance` negation still takes the multi path (layout ignores it) but exports no `BUILD_ID` (the gate honors it): S0 A2 shape.
- The portage-tmpdir test is backlog #99/#129 (Phase 2 S0 cell E): `run_buildpkgonly` re-derives the tmpdir per entry instead of only ever using the run-wide one.
- The post-clean test is backlog #42: Portage's `_buildpkgonly_success_hook_exit` runs the `clean` phase after a successful `--buildpkgonly` package (the phase itself, not a `noclean` gate, honors `keepwork`).
- The `missing matched PORTAGE_TMPDIR` message asserted is Portage's exact `_check_temp_dir` text ("The directory specified in your PORTAGE_TMPDIR variable, ..." / "does not exist. Please create this directory or correct your PORTAGE_TMPDIR setting.").
