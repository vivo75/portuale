# crates/portuale/src/helpers/gpkg.rs
Native `gpkg-helper.py compress`: builds signed/compressed gpkg binpkgs from dirs.

## module
- #326 S4, D1/D3/D4/D7: a port of `bin/gpkg-helper.py` (`main` + `command_compose`) over `lib/portage/gpkg.py` (`gpkg.compress`, `_add_metadata`, `_add_manifest`, `_add_signature`, `_record_checksum`, `_generate_metadata_from_dir`, `_check_pre_image_files`, `_get_tar_format_from_stats`, `_get_binary_cmd`, `_create_tarinfo`, `tar_stream_writer`, `checksum_helper`), routed from the `python` dispatcher when the script argument's basename is `gpkg-helper.py`. It writes what the reader in `binpkg.rs` (`read_outer_members`, `verify_gpkg_manifest`) reads.
- Behaviour is Portage's, in Portage's order: argv (no command -> argparse error rc 2; a command other than `compress` -> rc 2 `invalid command: '<cmd>'`; `compress` with argc != 4, arg 3 or 4 not a directory -> rc 1 with Portage's messages; the usage line there says `compose`, as Portage's does). The category of the first argument is dropped (`basename.split("/", 1)[-1]`). Order of work: the metadata dict (`os.walk` order of the metadata dir, first-insertion position and last value per file name, names that are not UTF-8 skipped), then the image pre-scan (a non-UTF-8 name there is an error, rc 1, and no artifact is created), then the container file, `gpkg-1`, the compressor command (resolved from the settings *after* the container exists, like Portage), the metadata member (+ `.sig`), the image member (+ `.sig`), the `Manifest`, and the two zero blocks plus padding to a 10240-byte record. Tar headers are rendered by hand as `tarfile.TarInfo.tobuf` does (the `tar` crate cannot reproduce them: USTAR directory names keep a trailing `/`, the name/prefix split is `_posix_split_name`'s, GNU `L`/`K` extension blocks are Portage's, uname/gname are looked up from the uid/gid and are empty without an entry, numbers overflow into base-256 only in GNU format). The container format (`gpkg-1`, the `.sig` members, `Manifest`) is USTAR, GNU when the basename has 154 characters or more or the image is 8000000000 bytes or more; the `metadata.tar` member header is always USTAR and the `image.tar` member header carries the image format (oracle: `long-basename` has USTAR stream members in a GNU container, `longname` the reverse). The image tar is GNU when a file name or link target is 100 bytes or more, a directory path is 155 bytes or more, or one file is 8000000000 bytes or more (`_get_tar_format_from_stats`). The image tar is `TarFile.add(root, "image")`: lstat, a sorted walk, a regular file seen again with `st_nlink > 1` becomes a type 1 hardlink to the first arcname, sockets are skipped, `st_mode` keeps its setuid/setgid/sticky bits. Compressors and the signing command are spawned from the settings in the process environment (`BINPKG_COMPRESS`, `BINPKG_COMPRESS_FLAGS[_<NAME>]`, `PORTAGE_BZIP2_COMMAND`, `MAKEOPTS`, `FEATURES`, `BINPKG_GPG_*`) over `make.globals`' defaults, with `varexpand` + `shlex.split` and `{JOBS}` from `makeopts_to_job_count`, like `_get_binary_cmd` and `checksum_helper`.

## enum Failure
- Why `compress` stopped. `Compressor` is the one exception the Portage helper catches (`CompressorOperationFailed` -> `eerror` + rc 1); everything else is an uncaught Python exception (rc 1, traceback).

## fn run
- Entry point: `script` is the `gpkg-helper.py` element (Portage's `sys.argv[0]`), `args` everything after it. Portage passes `usage="usage: ..."` and argparse prefixes `usage: ` again: the doubled prefix is Portage's.

## struct Settings
- The slice of `portage.settings` Portage reads: the process environment over the `make.globals` defaults of the keys below. (The Python helper also folds `make.conf`/profile into `settings`; here the caller, `invoke_dyn_package`, exports the resolved values into the environment, backlog #180.) Defaults pinned: `cnf/make.globals:39,47,50,105` (`BINPKG_COMPRESS=zstd`, `BINPKG_GPG_SIGNING_BASE_COMMAND`, `BINPKG_GPG_SIGNING_DIGEST=SHA512`, `PORTAGE_BZIP2_COMMAND=bzip2`).
- `has_feature`: `settings.features`, the incremental `FEATURES` stack (`-*` clears, `-x` removes, else pushes).

## fn compression_cmd / signing_command
- `_get_binary_cmd(compression, "compress")`: `BINPKG_COMPRESS_FLAGS_<NAME>` overrides the generic flags; `{JOBS}` from `makeopts_to_job_count`; empty template or missing binary is `CompressorNotFound`. The signing command of `checksum_helper(SIGNING)`: unset/empty base is `CommandNotFound`; f-strings of unset settings print `None`; `GPG_TTY` from stdout's tty when it is one.

## tar writer (Fmt, Info, itn, stn, create_header, gnu_long_header, posix_split_name, tobuf)
- `tarfile.itn` (octal, GNU base-256 overflow, USTAR overflow error), `tarfile.stn` (truncate, NUL-pad), `TarInfo._create_header` (devmajor/devminor only for `3`/`4`, chksum over spaces), `TarInfo._create_gnu_long_header`, `TarInfo._posix_split_name` (first split with prefix <= 155 and rest <= 100 wins), `TarInfo.tobuf(format)`: `get_info()` (a directory name always ends with `/`); USTAR refuses long linknames/names it cannot split; GNU prepends `K`/`L` long headers.
- `Info::new`: a fresh `tarfile.TarInfo(name)` (mode 0644, owner 0:0, no names).

## checksums (Hashes, Checksums, digest_of)
- `checksum_helper.libs` for `MANIFEST2_HASH_DEFAULTS` (BLAKE2B + SHA512 in 32768-byte blocks). `gpkg.checksums` and `_record_checksum`: keyed by file name (last component), replacing the earlier record.

## struct Gpg
- `checksum_helper.finish()`: EOF, wait, collect the output; a failed run is `GPGException("GnuPG signing failed")`, with the `Binary package is not usable (signing failed):` preamble and tabbed stderr lines.

## struct Container / Sink / stream_member / add_signature
- `container.addfile(tarinfo, fileobj)` at the end of the file; `container.close()`: two zero blocks, then pad to a record. `Sink`: the compressed (or raw) stream goes to the container file, the digests, and the signer's stdin (`tar_stream_writer` + `checksum_helper.update`). `stream_member`: `tar_stream_writer` as used by `_add_metadata` (header format USTAR) and `compress` (header format `image_tar_format`: the *container* format only governs `gpkg-1`, the `.sig` members and `Manifest`, which go through `container.addfile`). The checksum helper (and its gpg) is made before the writer. A dead compressor shows as a broken pipe in `produce`: Portage's `CompressorOperationFailed("PIPE broken")`. The reader thread keeps draining so the compressor ends on a write failure. `_add_signature`: the `.sig` member plus its Manifest record.

## image tar (name_of, Counted, ImageTar::add)
- `TarFile.add(path, arcname)` (recursive): `(dev, ino)` hardlink tracking (a repeat with `st_nlink > 1` and a different arcname becomes type 1; ino 0 never tracked); `pwd.getpwuid` KeyError -> `''` (uname/gname caches); device numbers via `major`/`minor`; sockets (`gettarinfo` returns None) add nothing. `sorted(os.listdir(name))`: the names are UTF-8 (the pre-scan refused anything else), so byte order is code-point order. `TarFile.close()`: two zero blocks, then pad to a record (`TarFile.offset`).

## fn utf8_error
- Python's `UnicodeEncodeError` text for a surrogate-escaped name (single position vs range, `\uXXXX` with surrogate code points).

## fn scan_image / tar_formats
- `os.walk(root)` + the bookkeeping of `_check_pre_image_files` (`rel` is the path of `dir` below the image root, empty for the root; `os.walk` swallows a listing error; `entry.is_dir()` follows symlinks; hardlinked files count their full path length as link length). "image/" is the arcname prefix Portage counts (`image_prefix_length`). A non-UTF-8 name prints `\n*** {msg}\n\n` and is `UnicodeEncodeError` (rc 1, no artifact). `_get_tar_format_from_stats`: container GNU at 8000000000 total bytes; image GNU at 8000000000 max file size or prefix >= 155 / name >= 100 / link >= 100; basename >= 154 chars (Python `len(str)`, one per code point/byte) forces a GNU container ("Long CPV").

## fn generate_metadata_from_dir
- `_generate_metadata_from_dir`: a Python dict in insertion order (first position kept, last value wins; non-UTF-8 skipped; symlinked dirs not walked; `os.walk` listing errors swallowed).

## fn compress
- `gpkg.__init__` (category dropped, `BINPKG_COMPRESS` none/empty/`none` means raw, `self.ext_list`); an unknown method is refused later, by `_get_compression_cmd`, once the container and `gpkg-1` exist. `os.path.join(self.basename, name)`; an empty basename joins to the bare name, and `_create_tarinfo` then refuses (checked after the compressor resolves, so the container + `gpkg-1` exist first). `_add_manifest`: `manifest.seek(0); manifest.write(gpg_output)` with the size `manifest.tell()`: the member is exactly gpg's output.

## tests: fixture plumbing
- The `portuale` binary next to the test binary (child processes). pmtest's `fixtures/helpers/gpkg/` holds oracles generated by running the Portage `bin/gpkg-helper.py compress` (see its README). pmtest's `fixtures/helpers/gpg-keyring/` is portage's own test keyring: trusted key 0x5D90EA06352177F6, untrusted 0x8812797DDF1DD192, passphrase GentooTest. Scratch space on tmpfs, never `/var/tmp` (zfs here refuses non-UTF-8 names and hands `readdir` back in hash order, which would change the metadata member order the helper sees; tmpfs order is stable for a fixed creation order). `materialise.py` ported to Rust (no python3): `%XX` unescaping (uppercase hex); entries in manifest order, then a deepest-first pass applies ownership (root only: `lchown`, else the invoker), mode (not symlinks; after chown, which clears setuid) and the pinned mtime; hardlinks share their target's inode and are skipped in the final pass (deepest first, stable like `sorted(..., reverse=True)`).

## tests: D3 field dump (dump_fields.py, format v1)
- The oracle side reads tars with its own parser (`tarfile.nti`, `_posix_split_name` with the 100/155 limits, GNU `L`-block handling) and must not share code with the writer under test. `dump_fields.py <container>`: the D3 field dump of a gpkg container, mtime never printed. Owner rewriting: the user-run oracle records the generator's own owner (uid 1000, gid 100, `vivo`, `users`, from the case README's `/etc/passwd (user run)` lines) on every image entry it owned; here those become the host owner. Container and metadata lines (uid 0, empty names, set by the writer) are never touched; only `image.member` lines carrying the generator's owner are rewritten.

## tests: run_case / check_oracle
- Stage a case like the generator did (`generate-gpkg.sh` sorted creation order) and run `portuale __helper python gpkg-helper.py <args>` as a CHILD PROCESS with the case's `env` file and the `@..@` tokens substituted. `None` = skipped (tool or tmpfs missing). `key` overrides `BINPKG_GPG_SIGNING_KEY`. As root the oracle's root run applies when it differs (owners/names), else the user run's files. `non-utf8`: Portage's refusal (rc 1, no artifact). 8 oracle cases x compressors: `plain`, `special`, `empty` (zstd/xz/bzip2/gzip); `longname`, `long-basename`, `basename-153`, `non-utf8`, `signed` (zstd).

## tests: unit tests (itn, tobuf, tar_formats, argv_errors, unknown_compression)
- `tarfile.itn`: octal, GNU base-256 overflow, USTAR overflow error. `tobuf`: GNU puts an `L` block in front only beyond 100 bytes. `_get_tar_format_from_stats`: the 100/155 thresholds are `>=`. argv errors are Portage's (`gpkg-helper.py`): argparse rc 2, the `compose` usage rc 1. An unknown `BINPKG_COMPRESS` is refused by `_get_compression_cmd`, after the container and its `gpkg-1` header exist: Portage (probed live, Portage 3.0.82.2, `BINPKG_COMPRESS=foo`) exits 1 with `InvalidCompressionMethod: foo` and leaves a 512-byte file holding only `pkg-1/gpkg-1`.

## tests: round trips and no-checkout reruns
- The native output is accepted by the container reader, its metadata reads back, the Manifest verifies, and extracting the image gives back the materialised tree (types, contents, link targets, hardlink groups; modes depend on the umask and are not compared). Build-info extracted verbatim equals the metadata dir that went in. Signed: the oracle ran with the untrusted key 0x8812... (the field dump does not depend on the key); acceptance by `verify_gpkg_manifest` needs the keyring's TRUSTED key 0x5D90EA06352177F6, so this run signs with that one. Every member has its `.sig`, the clear-signed Manifest and each detached signature verify (request-signature = nothing may be unsigned). The oracle's own key (0x8812...) is the keyring's UNTRUSTED one: valid signatures but `verify_gpkg_manifest` refuses them (`TRUST_UNDEFINED`), as Portage's `_check_gpg_status` does. `generate_metadata_from_dir`: a duplicate file name keeps its first position and its last value, a non-UTF-8 name is skipped, a symlink to a directory is not walked (top-level files first, then the subdirectory; `A` is last-wins). No-checkout reruns: one `ebuild_package` test each in a child process with no Portage checkout and no Python reachable, so the native `gpkg-helper.py` is the only thing that can build the gpkg. `MAKEOPTS` set only in `make.conf` (not in the calling env) reaches the native helper: `invoke_dyn_package` exports the file side, and `{JOBS}` of `zstd -T{JOBS}` becomes 5 (Portage: `makeopts_to_job_count` of the helper's own `portage.settings`); a logging `zstd` stands in for the compressor (child process, no checkout, no Python; config root = the fixtures' etc/ with MAKEOPTS appended and repo locations absolutized).
