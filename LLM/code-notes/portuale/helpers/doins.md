# crates/portuale/src/helpers/doins.rs
Native `doins.py`: installs files/dirs into the image with Portage's semantics.

## module
- #326 S6, D1/D3/D4/D7: a port of `3rdparty/portage/bin/doins.py` (all 619 lines: `main`, `_parse_args`, `_install_dir`, `_doins`, `_InstallRunner`, the two in-process runners, the two subprocess runners, `_parse_install_options` and `_set_attributes`/`_set_timestamps`), routed from the `python` dispatcher when the script argument's basename is `doins.py`.
- Behaviour is Portage's, in Portage's order: outer argv (`_create_arg_parser`: the long options as Portage spells them, both `--x=v` and `--x v`, unique long-option prefixes, and `--` before the sources; `-h`/`--help` and the single-dash `-h*` cluster, as argparse parses it, prints the help to stdout and exits 0, winning over any other error; any other argparse error exits 2 with Portage's usage text, probed live and pinned in tests; `--distdir` becomes its value + `/` (an empty one is `/`, so every absolute link target counts as inside it)). Install options (`_parse_install_options`): `-g/--group`, `-o/--owner`, `-m/--mode` (default 0o755) and `-p`, parsed from `shlex.split(options)` with `parse_known_args` semantics (`-m` uses `int(x, 8)` -- whitespace, sign, `0o` prefix and `_` separators accepted, failure gives `mode=None`; owner/group resolve a name first from `/etc/passwd` and `/etc/group` by parsing the files -- no NSS in a static binary -- then `int()`; an `int()` failure is an argparse type error, exit 2; remaining args, or `mode is None`: the two `!!! <helper>:` warnings, then `--strict_option` exits 1, otherwise fall back to `install(1)` from PATH). File install: `stat` (following links; failure is uncaught, rc 1), `_is_install_allowed` with its same-file warning, unlink (ENOENT is fine; anything else is uncaught), copy the contents into a newly created file (`0o666 & ~umask`), then lchown, chmod, the xattr copy, then `-p` utime (ns); any failure in that block is logged and returns False, the file stays behind. xattr (`--enable_copy_xattr`): list (ENOTSUP means none), skip `--xattr_exclude` whitespace-split globs (fnmatch semantics), set the rest; a set failure becomes Portage's `OperationNotSupported` message; the `listxattr`/`getxattr`/`setxattr` variants are used, as Portage's `portage.util._xattr` (which calls `os.listxattr`/`getxattr`/`setxattr` with `follow_symlinks=True`) does. Dirs: `makedirs`, so created parents get `0o777 & ~umask` and only the leaf gets `_set_attributes`; EEXIST on an existing dir is fine; `install_dir` re-raises only with `--helpers_can_die`, otherwise it logs `install_dir failed.`. `_doins`: the symlink branch preserves the link (unlink the dest, rmtree if it is a dir) when `--preserve_symlinks` is set and its target does not start with distdir; otherwise the file is installed. `_install_dir` walks without following symlinks: a symlinked dir is queued for `_doins`, a real dir gets an `install_dir`; a dir without `-r` is skipped (None), for `dodoc` it is a warning plus failure. `main`: create `--dest` if it is not a dir, loop over the sources, return `0 if not any_failure and any_success else 1`. D7 write guard: before every create, unlink, mkdir, symlink, chown, chmod, xattr-set or utime, the canonical parent (for mutations that follow links: the canonical path itself) must lie under the canonical `$D` (when `D` is set in the env), else under the canonical `--dest`; a violation prints an error naming the path and exits 1. Python tracebacks are not reproduced: where Portage logs an exception (`logger.exception(...)`), the first line (the message) and the final `ExceptionType: message` line are printed; uncaught exceptions print only the final line.
- Deviations from Portage, all documented where they occur: usage/help text is rendered at a fixed width of 80 columns (Portage's argparse re-wraps when `COLUMNS` is set or stdout is a wide tty). Non-UTF-8 option values are decoded lossy for parsing (paths stay raw bytes throughout). `int()`-style owner/group values beyond `i64` are type errors rather than unbounded Python ints. `copyfile` uses a plain read/write copy (no reflink/sparse acceleration): contents are identical, which is what D3 compares.

## Python repr helpers (py_bytes_repr, py_str_repr, py_str_list_repr, py_bytes_list_repr)
- Warning/exception lines quote bytes the way Python's `repr()` does, so the pinned lines match Portage's byte for byte on ASCII paths. `b'...'` uses double quotes when the value contains a single quote and no double quote.

## const OUTER_USAGE / OUTER_HELP / INSTALL_USAGE / INSTALL_HELP
- Probed live from Portage `doins.py` (Portage 3.0.82.2, pipe width 80; see the module notes for the fixed-width deviation). `doins.py` occurs exactly once in each and is the program name.

## fn warn
- `_warn`: `print(f"!!! {helper}: {msg}\n", file=sys.stderr)` -- the `print` adds a second newline, so every warning is followed by a blank line.

## fn shlex_split
- `shlex.split` (posix mode, `whitespace_split`, no comments; ASCII syntax, arbitrary bytes pass through). Probed against Portage's `shlex.split` (which is Python's): inside `"..."` a backslash escapes only `"` and `\` (`"06\44"` keeps the backslash); outside quotes it escapes any byte, a newline included (`a\<newline>b` is `a<newline>b`, no line continuation); `''`/`""` give an empty word. An unterminated quote or a trailing backslash is Portage's uncaught `ValueError`.

## fn py_int
- Python `int(x, base)`: surrounding ASCII whitespace, an optional sign, a matching `0o`/`0O` prefix for base 8, and single `_` separators between digits. Anything else fails.

## owner/group (parse_id_file, lookup_uid, lookup_gid, parse_user, parse_group, parse_mode)
- `/etc/passwd` and `/etc/group` parsed by hand (no NSS in a static binary). A name first, then `int()`; the first match wins; malformed lines skipped; the id field must be a plain decimal number. A numeric name resolves as a name first (Portage checks the name before `int()`). `_parse_mode`: `int(mode, 8)`, `None` on failure.

## fnmatch (fnmatch_inner, find_class_close, class_matches, fnmatch_glob, xattr_excluded)
- posix fnmatch: `*` matches everything including `/`; case is significant; `*` runs collapse, then every split is tried. Unterminated `[` is a literal (`fnmatch.translate`); only `!` negates, a leading `^` is a literal member (`translate` escapes it); a backslash is an ordinary character in `fnmatch` (probed: `a\*b` matches `a\xb`, not `a*b`). `find_class_close` scans as `fnmatch.translate` does: an optional `!`, then a `]` right after is a literal member. Class members are single bytes and `lo-hi` ranges (a `-` first or last is literal; an inverted range matches nothing, as `translate` drops it); backslashes are literal members. `_xattr_excluder(pattern)`: whitespace-split globs, any match excludes; `None`/empty never excludes. Shared with `helpers/xattr.rs` (#326 S7).

## outer argv (OuterOpts, outer_namespace_repr, match_long, parse_outer)
- `_create_arg_parser` + `_parse_args`. Long options as Portage spells them, in `add_argument` order (the order ambiguous-option errors list). Unique-prefix match (exact wins; none = unrecognized, several = ambiguous). Single dash: only `-h` exists; `-h` fires the help action, `-h*` (no `=`) does too, as argparse parses the `-h` prefix first (probed: `-hx`, `-help`), while `-h=x` is an explicit-argument error. With no positionals, argparse's `parse_known_args` keeps a `--` separator in extras (probed: `-- -v` gives `['--', '-v']`). `_parse_args`: `distdir` becomes its value + `/`. `outer_namespace_repr`: Python `Namespace(...)` repr of the outer options, for the `Failed to create symlink` first line (field order = Portage's `add_argument` order; bytes values use `b'...'`).

## install options (InstallParsed, parse_install_shorts, parse_install_options)
- `_parse_install_options`. `-h` help fires wherever argparse reaches it (`-hx`, `-help`, `-ph`); `-h=x` is an explicit-argument error. A leading `=` is the `--x=v` spelling (`-m=0600`). Unknown shorts put the token (or, mid-cluster, the `-tail`) in `remaining`, as argparse's extras do (`-vp` stays whole, `-pv` leaves `-v`). An ambiguous long prefix is an error even in `parse_known_args`. `InstallParsed::namespace_repr`: `Namespace(group=.., owner=.., mode=.., preserve_timestamps=..)` for the `Failed to copy file` first line (Portage's field order).

## D7 write guard (Guard, absolutize, lexical_normalise, canonical_best_effort, under_root)
- Every filesystem mutation must land under the canonical `$D` (when `D` is set and non-empty in the env), else under the canonical `--dest`. A static binary escapes libsandbox's `LD_PRELOAD`, so without this a symlink inside the dest tree could redirect writes outside it. `lexical_normalise`: `.`/`..` only, symlinks left alone (fallback when nothing exists to canonicalize). `canonical_best_effort`: the real path when it (or an ancestor) exists, else the absolutised lexical form. `check_parent` (creates/unlinks/mkdirs/symlinks): the canonical parent must be under the root; creating the root itself (or resolving to it) is allowed too -- the bootstrap for `--dest` when `D` is unset; anything else outside, including siblings of the root, is refused. `check_resolved` (chown/chmod/utime/xattr, which follow links): the canonical path must be under the root; dangling/missing falls back to the parent check and lets the operation fail naturally.

## failures (Fatal, exc_name, errno_line, errno_line2, errno_line_str, type_error_line)
- `Uncaught` prints Portage's final `ExceptionType: message` line (rc 1). `Guard` prints the D7 refusal (rc 1). Errno to Python exception-type mapping; `ExcType: [Errno n] strerror: b'path'`; two-filename `OSError` (`os.symlink`) as `b'src' -> b'dst'`; `'str-path'` form for the `install` fallback's `FileNotFoundError: ...: 'install'`. `TypeError: message` (no errno), e.g. the missing-`--dest` crash (`os.fsencode(None)`).

## xattr (xattr_list, xattr_get, xattr_set, copy_xattr)
- `movefile._copyxattr` over `portage.util._xattr`. `xattr.list(src)`: ENOTSUP/EOPNOTSUPP means "none" (`attrs = ()`). Shared with `helpers/xattr.rs` (#326 S7: one copier, not two). `_copyxattr(src, dest, exclude)`: `Err` is an errno line (list/get failures other than ENOTSUP) or the full `OperationNotSupported: ...` line (set failures: `OperationNotSupported("Filesystem containing file '%s' does not support extended attribute '%s'")`). Shared with `helpers/xattr.rs` (#326 S7: `install.py` copies through this, never its own).

## filesystem ops and runners (makedirs, set_attributes, dir_in_process, dir_subprocess, install_dir, is_install_allowed, copy_and_set, ins_in_process, ins_subprocess, place_symlink, doins_one, install_dir_tree, walk, combine_rc, main_inner)
- `makedirs` without `exist_ok`: missing parents created top-down (their own EEXIST swallowed, like the `except FileExistsError: pass` in Portage's recursion -- but only when the ancestor is reachable); a final EEXIST is reported for the caller to judge. `_set_attributes(options, path)`. `_DirInProcessInstallRunner.run` (EEXIST on an existing dir is fine); `_DirSubprocessInstallRunner.run`: `install -d <opts> <dest>` (`["install", "-d"] + split_options + [dest]`: options are `str`, `dest` is `bytes`; the message ends with a period, `CalledProcessError.__str__`); a failure is an error for `install_dir` to judge (Portage's `check_call` raises into it). `install_dir`: re-raise only with `--helpers_can_die`, otherwise log `install_dir failed.` and swallow. `_is_install_allowed`, with its same-file warning (hardlink-aware via best-effort realpaths). File copy into a newly created file (`0o666 & ~umask`, like Python's `open(dst, "wb")`), then attributes, xattrs, timestamps; failures log the `Failed to copy file` first line plus the final line and return False. `_InsInProcessInstallRunner.run` (`stat` follows links, failure uncaught; unlink first to emulate `install`: ENOENT fine, anything else uncaught via the `raise` outside Portage's `try`). `_InsSubprocessInstallRunner.run`: `install <opts> <source> <dest_dir>` from PATH, stdio inherited, True iff rc 0; a missing `install` is uncaught (Portage's `subprocess.call` has no `try` here). The symlink branch of `_doins`: unlink the dest (rmtree if it is a dir; other unlink errors swallowed, as Portage's bare `except OSError` does) and re-create the link; `os.symlink(linkto, dest)` raises with both filenames, which Python prints as `b'linkto' -> b'dest'`. `_install_dir`: `None` = skipped (no `-r`, non-`dodoc` helper); an empty `-r` dir still counts as success. One level of Portage's `os.walk` (no `followlinks`): symlinked dirs queued for `_doins`, real dirs get `install_dir` immediately, everything else queued; a listing error silently skipped, as `os.walk` does (`entry.is_dir()` follows links: a symlink to a dir walks as a dirname, anything else as a filename; the loop body runs per yielded level, top-down, then descends skipping symlinked dirs). `main`'s return rule: `0 if not any_failure and any_success else 1` -- an all-skipped run (no `-r` dirs only) is a failure. `_InstallRunner(opts)`: insoptions first, then diroptions; a strict refusal exits before `--dest` is created (Portage dies in the constructor, and the oracle's `unknown-strict` case pins the never-created dest). `isdir` follows links; a symlinked dir with `--preserve_symlinks` installs as a link. Overflow: `-1` keeps the id; anything outside `u32` cannot be passed to the syscall (Portage's `OverflowError`, caught and logged there).
- `c_lchown`/`c_chmod`/`c_utime_ns` map to `errno_line` failures; `dirname_of`/`basename_of`/`join_path` mirror `posixpath.dirname`/`basename` and `os.path.join(a, b)` for non-absolute `b`; `strip_trailing_slashes` is `source.rstrip(b"/")` exactly (all-slash input strips to empty).

## tests: install-option forms, int parsing, passwd/group, fnmatch, shlex
- Install-option forms (probed live, see the original task brief): every argparse form Portage accepts, probed with a harness importing Portage's parser logic (17-case table in the test). `-mp`: `-m` eats `p` as its value, `int('p', 8)` fails, so the mode is None and the run falls back to `install(1)`. Unknown options become `remaining`, in order (`-m 0644 -v` -> `-v`; `-pv` -> `-v`; `-vp` stays whole; `-- -v` keeps `--`); the fallback keeps the raw split tokens; with `--strict_option` they refuse instead (exit 1). `int(x, 8)` semantics (probed: `int(s, 8)` on the samples; 17-case table). `/etc/passwd` and `/etc/group` parsing (no NSS): first match wins, malformed lines skipped; a numeric name resolves as a name first. The xattr excluder: whitespace-split globs, fnmatch semantics (probed against `fnmatch.fnmatch` via Portage's cases); the `make.globals` default exclude list (a phase-defaults oracle case pins this end to end); `*` crosses `/` (posix fnmatch), `?` is one byte, classes and `!` negation work. Probed against Portage `fnmatch.fnmatchcase` (Python 3.14): a backslash is literal, only `!` negates (`^` is a member), a `]` first in a class is literal, `-` last is literal, an inverted range matches nothing, an unterminated `[` is literal. `shlex.split` as Portage runs it on `--insoptions` (each expected value probed with Python 3.14's `shlex.split`). An unterminated quote in `--insoptions` is Portage's uncaught `ValueError` from `shlex.split`, raised in `_InstallRunner` before `--dest` exists (probed live: rc 1, last traceback line `ValueError: No closing quotation`, no dest dir). The `Failed to copy file` Namespace keeps Portage's field order with each id in its own field. `0 if not any_failure and any_success else 1`. An empty run installs nothing and fails (probed: `doins.py --helper=doins --dest=...` with no sources exits 1 silently).

## tests: D7 write guard
- The guard root is `$D` when set, else `--dest`; the canonical parent must lie under it. A symlink inside the guarded tree pointing outside refuses the write through it, while creating the link itself is an inside-write and allowed (creating/replacing the link itself is fine -- its parent is inside; anything through it is outside). End to end through a child process: `doins -r` over a dest tree containing a symlink to the outside is refused (rc 1, the path is named) and the outside tree is untouched (the symlink sits where the run would write through it: `doins -r tree` installs `tree/sub/file.txt` via `<dest>/tree/sub`, which already exists here as a link to the outside).
