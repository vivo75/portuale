# crates/portuale/src/helpers/xattr.rs
Native `xattr-helper.py` + `install.py`: extended-attribute dump/restore and install wrapper.

## module
- #326 S7, D1/D3/D4: ports of `3rdparty/portage/bin/xattr-helper.py` (all 178 lines: `quote`, `unquote`, `dump_xattrs`, `restore_xattrs`, `main`) and `3rdparty/portage/bin/install.py` (all 195 lines: `parse_args`, `copy_xattrs`, `Which`, `main`), routed from the `python` dispatcher when the script argument's basename is `xattr-helper.py` / `install.py`. With these the transition table is empty (see `helpers/python.rs`): every remaining `python <script>` exits 127. The oracle is pmtest's `fixtures/helpers/xattr/` (one case dir per behaviour, generated by running the Portage helpers; Rust reads it through the `fixtures` symlink, so no checkout or Python is needed).
- Behaviour is Portage's, in Portage's order: `xattr-helper.py` argv (argparse: `-h`/`--help` prints the help to stdout and exits 0; `--dump` / `--restore` with unique long prefixes, `--x=v` on a flag is an explicit-argument error; anything else starting with `-` (except `-` alone and `--`) is `unrecognized arguments` (exit 2); `--` ends the options. Neither action exits 2 with `missing action!`. Both actions: the dump branch wins). `--dump`: argv paths win, else stdin split on NUL (a `\n`-joined pair is ONE path), empty parts dropped. Files without attrs are skipped silently. The `# file:` + `name="value"` text uses the getfattr-style octal escapes (`\ooo` for NUL, `"`, newline, CR, backslash in values, plus `=` in names, plus backslash/newline/CR in paths); every other byte (0xff, UTF-8) passes through raw. `xattr.list`/`get` follow symlinks, as Portage's `portage.util._xattr` (plain `os.listxattr`/`getxattr`, `follow_symlinks=True`) does. `--restore`: lines split on `\n`; `# file: ` headers set the path (unquoted); `name=value` lines split on the FIRST `=` (values may hold `=`), strip one trailing newline and the surrounding quotes, and unquote (`\` + 3 octal digits only). Blank lines are skipped; anything else is `ValueError: line N: malformed entry'; an attr before any header is `ValueError: line N: missing pathname'. `xattr.set` follows symlinks, as Portage's does. `install.py`: chdir(`__PORTAGE_HELPER_CWD`) first (bug #469338), then `Which("install")` over `PATH` skipping the helper itself by (ino, dev), `install: command not found` + 127 when absent. The original argv runs verbatim through the real `install(1)` (stdio inherited); a non-zero rc returns as is (no xattr copy). Else xattrs copy through doins.rs's shared `copy_xattr` (S6's copier, not a second one) with `PORTAGE_XATTR_EXCLUDE`: `-d`/no-files returns early; `-t dir` (else: last arg when it is a dir) lands each source by basename; otherwise `files[0]` -> target. The files are the `parse_known_args` extras, so an option's value (`-m 0644`, `-t dir`) is never one. An `OperationNotSupported` copy failure prints its line plus Portage's `!!! install: copy_xattrs failed ...` note and exits 71 (`EX_OSERR`); any other failure is uncaught in Portage: its line, rc 1, no note. Python tracebacks are not reproduced: uncaught failures print only the final `ExceptionType: message` line (the doins.rs convention).
- Deviations from Portage, all documented where they occur: usage/help text is pinned at the capture width (80 columns): Portage's argparse re-wraps when `COLUMNS` is set or stdout is a tty. A missing `__PORTAGE_HELPER_CWD`/`__PORTAGE_HELPER_PATH`, a failed chdir, or a failed `Which` stat prints the final line only (`KeyError:` / `FileNotFoundError: ...`, rc 1), not a traceback. A signal-killed `install(1)` reports rc 1 (Portage reports `-N`). D7: deliberately NO write guard here. Unlike `doins` (anchored at `--dest`/`$D`), `--restore` and `install.py` write exactly the caller-named paths -- the path IS the operation, as with `install(1)` itself -- so there is no anchor to check against. The callers (estrip's dump/restore, the xattr `install` wrapper) are Portage's own scripts passing image paths; sandboxing stays the phase's job, as it was for the Python helpers.

## fn quote
- `quote(s, quote_chars)`: every byte in `quote_chars` becomes its octal escape; all other bytes pass through raw (0xff and UTF-8 are NOT escaped -- pinned by the `dump-escapes` oracle case). NOTE in Portage: always quote backslashes.

## fn unquote
- `unquote(s)`: `\\[0-7]{3}` becomes the byte; anything else (a `\` with fewer/different followers included) stays literal. Leftmost match wins (`_UNQUOTE_RE.search(s, pos=pos)`).

## const XATTR_USAGE / XATTR_HELP_BODY
- Probed live from Portage `xattr-helper.py --help` (Portage 3.0.82.2, piped: 80 columns; see the module notes for the fixed-width deviation). `xattr-helper.py` occurs in the usage line only.

## fn dump_xattrs
- `dump_xattrs(pathnames)`: each file's section is written as it is produced, so a later failure leaves Portage's partial stdout (not an empty one). `Err` is Portage's final `ExceptionType: message` line (rc 1).

## fn restore_xattrs
- `restore_xattrs(file_in)`: `data` is the raw stdin bytes. File iteration splits on `\n`; a trailing empty chunk is skipped by the blank-line rule, so `split` is equivalent (line numbers match: the phantom chunk is never an error). `[8:]` drops the `# file: ` tag (`rstrip(b"\n")` is a no-op on a chunk); the value is `[1:-1]` saturating.

## fn parse_install_args
- `parse_args`: argparse (`add_help=False`, `parse_known_args`) for the known options, then Portage's files loop over the EXTRAS that `parse_known_args` returned. A known option's value is consumed by the parse and so is never a file (`-m 0644 src dest` gives `[src, dest]`; `-t dest a b` gives `[a, b]`; probed against Portage's `parse_args`). The extras are, in order: unknown option tokens, positionals, and everything from a `--` on (the `--` itself kept, as Portage's 3.14 argparse keeps it). Only `--directory` and `--target-directory` matter downstream. Long options in `add_argument` order with `action="store"` noted; a short cluster holds flags then possibly one valued option taking the rest of the token or the next token; an unknown first short is an extra; the files loop skips dash tokens either way. Portage's files loop, verbatim, over the extras: non-dash args before a `--`, everything after it.

## fn shlex_join
- `shlex.join(args)`: quote for the `copy_xattrs failed` note.

## const EX_OSERR
- `os.EX_OSERR` (Portage's `return os.EX_OSERR` on xattr-copy failure).

## fn which_install
- `Which(filename, exclude)`: the first `PATH` entry with an executable regular file that is not the helper itself ((ino, dev) comparison, `stat` following links, as Portage's does).

## fn copy_xattrs_after_install
- `copy_xattrs(opts, files)`: 0 on success, else the rc. `PORTAGE_XATTR_EXCLUDE`: missing means empty (Portage's `os.environ.get(..., "")`). Only `OperationNotSupported` is caught (`traceback.print_exc()`, `EX_OSERR`, then `main`'s `!!! install:` note, via `portage.util.writemsg(..., noiselevel=-1)` plain stderr). Any other error (e.g. a missing source for `xattr.list`) escapes `main` uncaught: rc 1, and the note is never printed.

## fn run_install
- `os.chdir(os.environ["__PORTAGE_HELPER_CWD"])` first (bug #469338: after the imports -- here there are none, so first). `cmdline = [install_binary] + args`, verbatim, stdio inherited. Portage's `subprocess.call` has no `try` here either; the final line stands in for the traceback.

## tests: install_parse_args_matches_portages
- `parse_args` against Portage's: each expected files list, `target_directory` and `directory` was probed by calling Portage `install.py`'s `parse_args` (Python 3.14). A known option's value never becomes a file (16-case table in the test).

## tests: quote_escapes_only_the_getfattr_set / unquote_processes_only_three_digit_octal_escapes
- `quote` escapes exactly NUL, `"`, newline, CR and backslash in values (plus `=` in names, plus path chars in paths); 0xff and UTF-8 pass through raw. `unquote` turns `\` + 3 octal digits into the byte and leaves everything else (short escapes included) literal; `\\101` is a literal backslash + `A` (leftmost match wins). Round trip with `quote` pinned.
