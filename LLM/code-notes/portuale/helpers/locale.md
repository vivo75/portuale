# crates/portuale/src/helpers/locale.rs
Native answer for the QA locale probe (`has_utf8_ctype`).

## module
- Answers what Portage's `bin/install-qa-check.d/90config-impl-decl:98-102` asks: it runs `$PORTAGE_PYTHON -c 'import locale; print(locale.getlocale()[1])'` and passes iff it prints exactly `UTF-8`.
- Portage's answer depends on the interpreter's effective C locale (PEP 538/540 coercion) and on which locales are installed. The D4 oracle (`fixtures/helpers/locale/table.tsv`, generated by running the Portage probe) is the law; row by row it says: `LC_ALL` set and non-empty means NO coercion (`C`/`POSIX` print `None`, an installed locale prints its own codeset (`en_US` -> `ISO8859-1`, `*.UTF-8` -> `UTF-8`), a non-installed one prints `None`); otherwise (`LC_ALL` unset or empty) the effective locale is `LC_CTYPE`, else `LANG`, else the C default (`C`/`POSIX`/unset/empty print `UTF-8` via PEP 538 coercion to `C.UTF-8`; a non-installed locale falls back to C and likewise prints `UTF-8`; an installed one prints its own codeset). A phase never sees `LC_ALL` (`phase_env_vars` splits it into the `LC_*` categories), but the helper answers for any environment it is run in, since the QA check only compares with `UTF-8`.
- Implemented with libc (`setlocale(LC_CTYPE, ...)`, `nl_langinfo(CODESET)`), never by running `locale(1)` (musl hosts lack it). The only Python spellings the table contains are `UTF-8`, `ISO8859-1` and `None`; other codesets are printed as libc reports them.

## fn present_var
- A set-but-empty variable counts as unset (glibc/Python treat `""` as "no selection", so the next lower-precedence variable wins).

## fn codeset_of
- The `LC_CTYPE` codeset of the named locale, or `None` when it does not resolve on this host (`setlocale` returns null).

## fn map_codeset
- Python's `locale.getlocale()[1]` spellings for the codesets the oracle contains; anything else is printed as libc reports it (the QA check only tests `== UTF-8`, and the unit test only requires the `is_utf8` bit to match).

## tests: the_native_locale_answer_matches_every_oracle_row
- #326 S2.4/D3: every row of `fixtures/helpers/locale/table.tsv` (the D4 oracle, generated by running the Portage probe). The native answer runs as a child process with `env_clear()` + exactly that row's variables (+ PATH): the `is_utf8` bit must match every row, and the printed string matches Portage's where the table records it. Rows whose locale resolves differently on the machine running the test are skipped with a printed reason: `locale charmap` in the row's own environment is compared against the table's `locale_charmap` column (which records what Portage saw on the generating host).
