# crates/portuale/src/helpers/xpak.rs
Native `xpak-helper.py recompose`: packs metadata dirs into tbz2 XPAK segments.

## module
- #326 S5, D1/D3/D4/D7: a byte-level port of `bin/xpak-helper.py` (`main` + `command_recompose`) over `lib/portage/xpak.py` (`addtolist`, `xpak`, `xpak_mem`, `encodeint`, `tbz2.scan`, `tbz2.recompose_mem`), routed from the `python` dispatcher when the script argument's basename is `xpak-helper.py`. It is the inverse of the reader in `binpkg.rs` (`read_xpak_segment`/`parse_xpak_members`).
- Behaviour is Portage's, in Portage's order: argv: no command -> argparse error (usage + `<prog>: error: missing command argument`, rc 2); a command other than `recompose` -> rc 2 `invalid command: '<cmd>'`; `recompose` with argc != 2, arg 1 not a regular file, arg 2 not a directory -> rc 1 with Portage's messages (stderr is raw argv bytes, like Python's surrogateescape). `xpak(dir)`: `addtolist` walks the tree (a real subdirectory is listed as `sub/`, a symlink to a directory is skipped). Portage's UTF-8 checks there only fire on `bytes`, and its `os.walk` yields `str`, so a non-UTF-8 name is NOT skipped: it is a surrogateescape `str`, sorted by code point, and packed by `xpak_mem` with `backslashreplace`. The invalid byte 0xff becomes the six bytes `\udcff` (probed live 2026-10-08 on tmpfs). `CONTENTS` is skipped and every other entry is read as raw bytes. Reading a `sub/` entry dies in Portage with `IsADirectoryError` (traceback, rc 1, binpkg untouched): reproduced as rc 1, the binpkg untouched and a one-line message (the traceback text is not reproduced). `xpak_mem`: `XPAKPACK be32(indexlen) be32(datalen) index data XPAKSTOP`, index records `be32(len(name)) name be32(datapos) be32(size)`. `recompose_mem`: `scan()` (last 16 bytes `XPAKSTOP be32(infosize) STOP` -> `xpaksize = infosize + 8`, else 0); when `st_nlink > 1` the hardlink is broken by a content-only copy (Portage `util.file_copy.copyfile`) to a new file in the same directory, renamed over. Portage's `apply_stat_permissions(self.file, ...)` targets the original path before the rename, so it changes nothing. The new file ends up with mode `0o666 & ~umask` and the caller's owner, not the old file's (probed live: a 0600 binpkg comes out 0644 under umask 022). Then `xpaksize` bytes are truncated from the end and `segment + be32(len(segment)) + "STOP"` appended.

## fn run
- Portage passes `usage="usage: ..."` and argparse prefixes `usage: ` again: the doubled prefix is Portage's (checked against Portage).

## fn addtolist
- Portage `addtolist`: the relative names under `root`, as raw bytes (`sub/` for a real subdirectory, then its contents). A symlink to a directory is in Portage's `os.walk` `dirs`, not recursed into (followlinks=False), never listed.

## fn py_code_points
- A name as the code points of Python's surrogateescape `str`: each byte of an invalid UTF-8 sequence becomes U+DC80+byte. Portage sorts these `str`s, so this is the sort key.

## fn py_name_bytes
- Portage `xpak_mem`'s `k.encode("utf-8", "backslashreplace")` of a surrogateescape name: valid UTF-8 kept, each invalid byte written as the text `\udcXX`.

## fn scan_xpaksize
- Portage `tbz2.scan()`'s `xpaksize`: `infosize + 8` when the last 16 bytes are `XPAKSTOP be32(infosize) STOP`, else 0.

## fn break_hardlink
- Portage `recompose_mem`'s hardlink break: a content-only copy into a new file in the same directory (mode `0o666 & ~umask`, the caller's owner, as Portage's `copyfile` leaves it), renamed over. Content only: `std::fs::copy` would also copy the permissions.

## tests
- The oracle cases live in pmtest `fixtures/helpers/xpak/<case>`, generated by running the Portage `bin/xpak-helper.py`. `check_case` asserts rc, stderr and the resulting bytes; the `nested` error case only asserts a message on stderr; `nested_leaves_the_binpkg_unchanged` also asserts the binpkg bytes are untouched. `argparse_errors_exit_2` pins the doubled-`usage:` prefix. `recompose_round_trips_through_the_binpkg_reader`: the writer is the inverse of `binpkg.rs`'s reader. `non_utf8_names_are_packed_like_portage_surrogateescape`: a non-UTF-8 name is packed, not skipped (surrogateescape `str` from `os.walk`, sorted by code point -- U+DCFF before U+E000, the reverse of byte order -- encoded with backslashreplace); expected bytes are Portage `xpak-helper.py`'s on this input (probed live 2026-10-08, tmpfs; /var/tmp is utf8only zfs here and refuses the name). `broken_hardlink_gets_the_creation_mode_like_portage`: breaking the hardlink leaves the caller's creation mode, not the old one (probed live: 0600 in, 0644 out under umask 022). The two `real_package` reruns run in a child process with no Portage checkout and no Python reachable, so the native `xpak-helper.py` is the only thing that can pack the metadata.
