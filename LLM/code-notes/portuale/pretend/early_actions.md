# crates/portuale/src/pretend/early_actions.rs
Option checks that end the run early, and the actions that need no resolve.

## fn validate_and_early_actions
- `--tree` + `--columns`: Portage prints to stdout with `return 1` (`actions.py`: "if '--tree' in emerge_config.opts and '--columns' in emerge_config.opts"); portuale instead follows its own CLI-usage-error convention (exit 2, stderr, per the contract suite), matching every other CLI-usage error portuale reports (`--exclude` requires an argument, an invalid `--deep` value) rather than Portage's inconsistent mix of exit codes for different usage errors. Checked once parsing finishes, order-independent, before any other validation, matching Portage's own placement.
- `--pretend` silently drops `--ask` first, and only then is `--ask` checked against `stdin.isatty()` (`actions.py:3917-3926`): `--ask --pretend` on a non-terminal stdin is fine (ask is already `false` by the time the isatty check runs), but a bare `--ask` piped from a non-terminal is a hard immediate exit.
- Privilege gate (`actions.py:3964-4012`): an action writing into a root-owned filesystem -- any merge, `--unmerge`/`-C`, `--depclean`/`-c`, `--prune`/`-P`, `--deselect`/`-W` (world-file rewrite), `--config`, `--clean` -- requires `secpass == 2` (`uid == 0`, or non-root ownership of the target root; see `privileges::is_privileged`).
- Backlog #246: with `--ask`, a non-privileged caller is offered `Would you like to add --pretend to options?` (`_emerge/actions.py:3983-4006`) instead of being refused. Portage prints `This action requires {access_desc} access...` to stdout first; portuale has a single privilege tier (no portage-group tier -- see `privileges.rs`), so `access_desc` is always `superuser` here. The prompt goes through the shared `UserQuery.query` port (`ask_yes_no`, backlog #240): "No" exits `128 + SIGINT` with nothing else printed, EOF/SIGINT prints `Interrupted.` and exits the same way; "Yes" sets `--pretend`, drops `--ask`, and the run continues as a pretend run. Host probe 2026-09-29, `/usr/sbin/emerge` 3.0.82.2 as uid 1000, secpass 0: exact bytes in the pin docstrings below.
- Without `--ask` (`actions.py:4007-4012`): `emerge: superuser access is required` on stderr, exit 1, no hint line (host probe 2026-09-29). This no longer goes through `privileges::deny_superuser` (kept for `ebuild`, whose refusal is unprobed).
- `config`, `metadata`, `regen` reject `--pretend` outright (`actions.py:4106-4111`).
- `--unmerge`/`--depclean`/`--prune`/`--deselect` without `--pretend` really execute after the display: `run_unmerge_pretend` / `run_depclean_pretend` / `run_prune_pretend` / the `--nodeps` variant each run `execute_unmerge` after the display when `pretend` is `false`, and `run_deselect` rewrites the `world` / `world_sets` files (Portage `action_deselect`'s `world_set.replace(remaining)`).
- Non-pretend `emerge` itself builds/merges (`--buildpkgonly`, `--getbinpkgonly`, or a plain source build); dispatched from the `!pretend` block after resolution.
- `--deselect` becomes a standalone action only when `myaction is None` (`main.py`); under `--depclean`/`--prune`/`--unmerge` it is a modifier (Portage `action_depclean`'s `deselect`; see `run_depclean_pretend`).
- Real non-dry-run execution paths portuale implements for `emerge` itself: `--buildpkgonly` (builds a binary package, never merges -- `emerge_build.rs`), `--getbinpkgonly` (downloads remote binpkgs and merges them -- `emerge_getbinpkg.rs`), and a plain `emerge <atom>` (Portage source build + merge -- `emerge_build::run_source_merge`).
- Portage `main.py`: `--deselect` becomes a standalone action only when `myaction is None` -- `--depclean`/`--prune`/`--unmerge` each set their own action first, and then `--deselect=y|n` is just a modifier on it (Portage `action_depclean`'s `deselect` -- see `run_depclean_pretend`).
- `--list-sets`: a standalone action needing nothing from the resolved config -- dispatch before the "expected a package atom" guard and all the repos.conf/profile machinery.
- `--jobs` / `--load-average` thread straight through (Portage `action_regen(settings, portdb, max_jobs, max_load)`).
