## struct EmergeOpts

## fn parse_emerge_args
- `Err` carries the exit code of an option error, already reported.
- --columns: display-only, same "entirely independent of resolution" shape as --tree above (Portage output_helpers.py's own MergeListItem.conf.columns is a display-layer flag, never consulted anywhere in depgraph.py) -- mutually exclusive with --tree, checked once parsing finishes (see the "can't specify both" check below).
- --depclean-lib-check y|n: Portage `main.py:442` (`_DEPCLEAN_LIB_CHECK_ DEFAULT = True`). Only consulted by `--depclean`/`--prune`. `n` disables the `NEEDED.ELF.2` soname-consumer scan (and, no-args, adds the `Depclean may break link level dependencies` advisory paragraph).
- `--binpkg-changed-deps[=y|n]` (Portage `true_y_or_n`): `None` = auto (Portage `create_depgraph_params.py`'s "enabled unless `--usepkgonly`"), `Some(true|false)` = explicit force on/off. `--use-ebuild-visibility[=y|n]` (Portage `true_y_or_n`, default off).
- --complete-graph (Portage `true_y_or_n`, `main.py:155`/`878-881`, OFF by default -- only a `y`-ish value turns it on). "completely account for all known dependencies": Portage `create_depgraph_params.py:169-175` sets `myparams["complete"]`, which `depgraph.py::_complete_graph` turns into a forced deep walk (see `resolve_pretend_graph`'s `complete` param). `--rebuild-if-{unbuilt,new-rev,new-ver}` imply it too (same `create_depgraph_params.py` block); `--nodeps` pops it.
- --dynamic-deps (Portage `y_or_n`; Portage default is "y" for a source install -- see create_depgraph_params.py). ON is portuale's own long-standing behaviour (an AlreadyInstalled package's `--deep` walk reads the current ebuild); only `=n` flips it to the vdb snapshot. `--nodeps` forces it off (Portage `create_depgraph_params.py:122`).
- --implicit-system-deps (Portage `y_or_n`, `main.py:490`, default "y"): whether `@system` members are assumed to be implicit dependencies. Only `=n` disables -- Portage `create_depgraph_params.py:120` (`myopts.get("--implicit-system-deps", "y") != "n"`), and for a `--pretend` merge list that only shows up in `_merge_order_bias` (depgraph.py:9279 early-returns): with `=n`, the @system-first / reference-count sort is skipped and the list stays in discovery order. Threaded into the resolver.
- --fuzzy-search (Portage `true_y_or_n`): `emerge --search`'s own `difflib.SequenceMatcher` fuzzy matching. Portage `action_search`: `fuzzy = myopts.get("--fuzzy-search") != "n"` -- ON by default, only `--fuzzy-search=n` disables it.
- --regex-search-auto (Portage `y_or_n`, `"default": "y"`): auto-detect a regular-expression search key. Portage `action_search`: `regex_auto = myopts.get("--regex-search-auto") != "n"`.
- --search-similarity (Portage: a float 0..100, default 80): the minimum `SequenceMatcher.ratio()` percentage a fuzzy hit needs. Portage `search.py`: `self.search_similarity = 80 if search_similarity is None else search_similarity`.
- --regen (Portage `action_regen`): regenerate every repo's `metadata/md5-cache` by running each ebuild's `depend` phase. A Portage write action -- rejects `--pretend`. --metadata (Portage `action_metadata`) transfers a repo's pre-generated cache into portage's own `depcachedir`; portuale reads `metadata/md5-cache` directly and has no `depcachedir`, so the transfer is a no-op. --sync is a permanent non-goal -- `emerge --sync` prints "Functionality has moved to `emaint sync`." and exits 1.
- --jobs[=N] / -j[N] (Portage `main.py`, `valid_integers`): the maximum number of concurrent jobs -- package *builds* for a plain source `emerge <atom>` (Portage `_emerge/Scheduler.py`'s `_max_jobs`), `depend` phases for `emerge --regen` (Portage `MetadataRegen`'s `max_jobs` -- see `regen.rs`). Default 1 = portuale's long-standing strictly-serial build+merge loop; a bare `--jobs`/`-j` means "as many as the work allows" (`usize::MAX`, capped by the scheduler); an explicit `0` means the CPU count (Portage `main.py:1036-1039`). The vdb merge step is always serialized regardless -- only the `install` phase runs in parallel, matching Portage. Only consulted for a plain source `emerge <atom>` and `--regen`; `--buildpkgonly` and the binary-merge paths stay serial (nothing to build in parallel).
- --root-deps: Portage main.py's own `choices: ("True", "rdeps")`, plus a bare form (no `=value` at all). Portuale doesn't distinguish "True" (fold DEPEND/BDEPEND/IDEPEND into RDEPEND) from "rdeps" -- and for this EAPI-7+-only fork it never needs to: at EAPI 7+ (`eapi_attrs.bdepend`, `depgraph.py:4218-4238`) the `--root-deps == "rdeps"` `ignore_depend_deps` branch is inside `else: if eapi_attrs.bdepend`, so `=rdeps` is a **complete no-op**. Every accepted form just enables the one behavior portuale implements: Portage running-root satisfiability for DEPEND/BDEPEND/IDEPEND atoms (which at EAPI 7+ genuinely target `/` for BDEPEND/IDEPEND and `ESYSROOT` ≈ ROOT for DEPEND). See `root_deps_satisfied_atoms`'s own doc comment.
- --solver=<portage|pubgrub|resolvo>: portuale-only (Portage `emerge` has no `--solver`), same "special-cased, not in emerge_options.rs" treatment `--shell`/`--json` get. Picks the dependency-solving algorithm: the backtracking walk (default, the one Portage runs) or lu-zero's PubGrub / resolvo bridges over the same repo facts (see `solver_bridge.rs`).
- --autounmask-continue (Portage `true_y_or_n`, `main.py:345`/`810`) and --autounmask-backtrack (Portage `choices: ("y", "n")`, a REQUIRED value, `main.py:338`, **disabled by default** -- `man emerge`). `--autounmask-continue`'s "write the changes and keep merging" path is gated on `"--pretend" not in myopts` (`depgraph.py:5796`), so under `--pretend` its only observable is the `actions.py:3772` warning against `--autounmask=n` -- but it also *implies* `--autounmask-backtrack=y` (`man emerge`), and that half IS observable here: it gates the `'backtrack` loop's autounmask re-drive (`Config::autounmask_backtrack`). `None` = flag not given.
- `None` until an explicit `--selective`/`--selective=y`/`--selective=n` is given, so `n` can override whatever `update`/`newuse`/ `changed_use`/`changed_deps`/`changed_slot`/`noreplace` computed -- matching Portage `create_depgraph_params.py`'s own unconditional `if myopts.get("--selective") == "n": myparams.pop("selective", None)`, checked after every other trigger. See `selective`'s own computation just before the `resolve_pretend_graph` call below.
- Portage `main.py:1036-1039`: an explicit `--jobs=0` means the CPU count (not "one job"). Shared by every `--jobs` spelling below.

## value-shape conventions (Portage grounding for the whole parse loop)
- Optional-value flags (`--ask`, `--verbose`, `--changed-deps`, `--selective`, …): Portage's `true_y_or_n` choices -- a bare flag means true (Portage's `insert_optional_args` inserts `"True"`), a separate `y`/`n` word is consumed, and a separate `True` stays a positional atom (only `y`/`n` are in the insert `y_or_n` set). `=y`/`=True`/`=n` forms are argparse's own `=` handling. Per-flag insert-set membership this was verified against: `--ask`, `--read-news`, `--onlydeps-with-rdeps`/`--onlydeps-with-ideps`, `--verbose`/`-v`, `--quiet`/`-q`, `--deselect`/`-W` (`:158`), `--changed-deps` (`:152`), `--changed-deps-report` (`:154`), `--changed-slot` (`:153`), `--selective` (`:183`), `--with-test-deps` (`:191`), `--autounmask-keep-keywords` (`:146`), `--autounmask-keep-masks` (`:147`). Normalization is `in true_y` at the matching `main.py` site (`--verbose`, `--quiet` at `:939-941`; `--deselect` at `:869-870`; `--changed-deps` at `:848-851`; `--changed-deps-report` at `:854-857`; `--changed-slot` at `:860-863`; `--selective` at `:988-989`; `--with-test-deps` at `:1133-1136`; `--autounmask-keep-keywords` at `:821-822`; `--autounmask-keep-masks` at `:824-825`).
- `--deep`/`--backtrack`/`--jobs` peeking: Portage's `valid_integers` `__contains__`, checked by `insert_optional_args` before optparse ever sees the value. A bare flag, or one followed by anything non-numeric, means unlimited depth (`myoptions.deep == "True"` for `--deep`). The `=` forms are argparse's native mechanism instead, so a non-numeric value there is an immediate parse error (Portage's `parser.error("Invalid --deep parameter: ...")`).
- Append flags (`--exclude`, `--reinstall-atoms`, `--useoldpkg-atoms`, `--rebuild-exclude`/`--rebuild-ignore`, `--usepkg-exclude`/`--usepkg-include`, `--buildpkg-exclude`): Portage's `action: "append"` -- repeatable, each occurrence's own value itself a space-separated atom list (Portage `bin/emerge` help text: "A space separated list of package names or slot atoms"). A missing value is an immediate usage error.
- REQUIRED-value flags (`--with-bdeps`, `--autounmask-backtrack`, `--quickpkg-direct`, …): Portage's `argument_options` with `choices` -- a missing or out-of-choice value is an immediate usage error with no default to fall back to.
- Short-flag bundles (`-pv`): decomposed one character at a time, left to right. This differs from Portage `emerge`'s own recycling-based algorithm (same outcomes, different internal order). A bundled `-v`/`-D`/`-W`/`-a` never consumes a value -- same "no ambiguity with another bundled flag character" reasoning (the standalone `-a`/`--ask` handler still accepts `-a y` / `-a n`).

## flags: prompts and resume
- `--ask`/`-a`: after the merge/removal list, before anything executes, prompt `Would you like to ...? [Yes/No]` (Portage's `UserQuery.query`, `_emerge/actions.py:525` / `unmerge.py:621`). "No" prints `Quitting.` and exits 130, while EOF/SIGINT prints only `Interrupted.` and exits 130 (Portage exits from inside `query`, so its `Quitting.` never runs -- backlog #240). (`128 + SIGINT`.)
- `--read-news`: Portage's `y_or_n` insert default (`main.py:175`), `choices: true_y_or_n` (`main.py:625`), normalized to `True`/`None` at `main.py:950-953`. Offers `eselect news read` while calculating dependencies (Portage `actions.py:4266-4281`, backlog #231).
- `--resume`/`-r` + `--skipfirst`: Portage's `_emerge/Scheduler.py` resume handling -- `--resume` replays `mtimedb["resume"]["mergelist"]`; `--skipfirst` drops the first (failed) entry. Portuale writes that list when a source merge fails (see `mtimedb::write_resume_list`).

## flags: display-only
- `--tree`/`-t`, `--unordered-display`, `--columns`, `--alphabetical`: display-only, independent of resolution (Portage's `_tree_display` / `MergeListItem.conf.columns` / `conf.alphabetical` all live in `output_helpers.py`'s display layer, never `depgraph.py`'s core resolution). `--columns` and `--tree` are mutually exclusive, checked once parsing finishes. `--alphabetical` only affects `_create_use_string`'s `USE="…"` ordering (one combined bare-name-sorted list instead of enabled-first).
- `--color y|n`: Portage's `main.py` `argument_options` entry (`"choices": ("y", "n")`, `main.py:421`) -- the explicit override winning over `NO_COLOR`/`NOCOLOR`/isatty (see `color::resolve_havecolor`).
- `--verbose-conflicts`: Portage's bare boolean (`main.py`'s `y_or_n` group). Portage's `_prepare_conflict_msg_and_check_for_specificity` shows *every* parent atom of a slot conflict instead of one representative per collision reason, and drops the "(and N more ...)" / "NOTE: Use the '--verbose-conflicts' option" trailer.
- `--verbose-slot-rebuilds`: Portage's `y_or_n`, default `"y"`. Only `=n` suppresses the "The following packages are causing rebuilds:" block (`_show_abi_rebuild_info`).

## flags: builds and actions
- `--shell bash|brush` (default `bash`): see `ebuild_phases::ShellBackend` (including why bash is the default). Special-cased in the parse loop rather than routed through `emerge_options.rs`, like `--json`. Threaded into the removal-hook (`pkg_prerm`/`pkg_postrm` under `-C`/`--unmerge`/`--depclean`/`--prune`/`--clean`/`--rage-clean`, plus the `FEATURES=unmerge-backup` `quickpkg`) and `--config` (`pkg_config`) paths -- every non-`--pretend` phase chain `emerge` can drive picks up the same backend.
- `--json`: NOT a Portage `emerge` option at all -- Portage has no structured-output mode for `--pretend`. Deliberately not routed through `emerge_options.rs`'s CLI-surface tables (unlike every other flag here), and given no short alias (nothing to bundle).
- `--buildpkgonly`/`-B`: plain-boolean shape like `--newrepo`.
- `--quiet-build[=y|n]` (Portage `true_y_or_n`, `main.py`): Portage's `Scheduler._background_mode` -- `n` never *disables* capture under `-j` >1 (`parallel_jobs` still forces it); it only matters for a single-job build.
- `--debug`/`-d` (Portage `main.py:1235`): `PORTAGE_DEBUG=1` (Portage's `bin/ebuild.sh` then runs `set -x` in every phase -- portuale threads it into the phase env, same as `ebuild --debug`) and `initialize_logger(logging.DEBUG)` (Portage's internal `logging.DEBUG` trace -- Python-implementation noise with no portuale equivalent and not part of the "same behaviour" contract, a documented no-op here). So `emerge --pretend --debug` is byte-identical to `emerge --pretend`.
- `--jobs[=N]`/`-j[N]` (Portage `main.py`, `valid_integers`): package *builds* for a plain source `emerge <atom>` (Portage's `_emerge/Scheduler.py` `_max_jobs`), `depend` phases for `emerge --regen` (Portage's `MetadataRegen` `max_jobs`, see `regen.rs`). Default 1 = portuale's long-standing strictly-serial build+merge loop; bare means "as many as the work allows" (`usize::MAX`, capped by the scheduler). Only the `install` phase runs in parallel, matching Portage; `--buildpkgonly` and the binary-merge paths stay serial (nothing to build in parallel). `--jobs=0` (Portage `main.py:1036-1039): means the CPU count.
- `--load-average[=LA]`/`-l[LA]` (Portage `main.py`, `type=float`): Portage's `_emerge/Scheduler.py` `_is_work_scheduled` / `JobStatusDisplay` load gate -- never deadlocks because one build is always allowed.
- `--search-similarity` (Portage `main.py:1088-1099`): Portage's `search.py` (`self.search_similarity = 80 if search_similarity is None else search_similarity`).
- `--fuzzy-search`: Portage's `action_search` (`fuzzy = myopts.get("--fuzzy-search") != "n"`). `--regex-search-auto`: Portage's `action_search` (`regex_auto = myopts.get("--regex-search-auto") != "n"`).
- Standalone actions (Portage `main.py` `myaction`): `--unmerge`/`-C` (`_UnmergeAction`, `myaction = "unmerge"`, dispatched to `run_unmerge_pretend`, not a modifier on ordinary resolution); `--depclean`/`-c` (`myaction = "depclean"`, to `run_depclean_pretend`); `--prune`/`-P` (`myaction = "prune"`, routed through the same `action_depclean` as `--depclean`, to `run_prune_pretend`); `--config` (`myaction = "config"`, `action_config` -- run `pkg_config` for one installed package, no short alias, to `run_config_action`, ignoring `--pretend` entirely since Portage's `action_config` never checks it); `--list-sets` (`myaction = "list-sets"`, print every defined package set name, sorted, one per line, `actions.py:3839`); `--search`/`-s` and `--searchdesc`/`-S` (`action_search`, `searchdesc`); `--check-news` (`actions.py:3844`, unread relevant GLEP 42 news items per repo); `--regen` (`action_regen` -> `MetadataRegen`, running each ebuild's `depend` phase; a write action that rejects `--pretend`); `--metadata` (`action_metadata`, the post-`--sync` cache transfer into Portage's `depcachedir`); `--sync` (prints "Functionality has moved to `emaint sync`." and exits 1); `--clean` (`action_uninstall` -> `unmerge` `unmerge_action="clean"` -- per slot, remove every version older than the newest); `--rage-clean` (fast `--unmerge`: same selection but skips `CLEAN_DELAY` + prerm/postrm -- invisible at `--pretend`); `--info` (`action_info`, no short alias).
- `--ask-enter-invalid`: Portage boolean flag (no value) -- `UserQuery.query`'s `enter_invalid` gate, reset at `run` entry.
- `--ignore-default-opts` (Portage `main.py:1352`).
- `--deselect`/`-W`: unlike `--verbose`, a bare flag turns the invocation into the standalone deselect action (Portage `main.py`'s "if myaction is None and myoptions.deselect is True: myaction = 'deselect'"; see `run_deselect`).
