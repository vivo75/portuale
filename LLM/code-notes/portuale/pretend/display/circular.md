## fn circular_node_text
- Backlog #206 S1: ports Portage's `_emerge/Package.py::Package.__str__` for a merge-bound package — the `(cpv:slot/sub_slot::repo, <type> scheduled for merge)` node text — which `circular_dependency_handler._prepare_circular_dep_message` (`resolver/circular_dependency.py:76`) prints for each cycle member (the digraph f-string renders `str(Package)`). The `cpv:slot/sub::repo` head is wrapped in Portage's per-operation colour (`PKG_MERGE` for an ebuild merge, `PKG_BINARY_MERGE` for a binary one -- a no-op unless the caller's `Colorizer` is enabled).
- Deliberate cuts, both grounded on live Portage: the ` to '<ROOT>'` arm never fires (eight unanimous `LLM/evidence/2026-09-27-181-circular-text/real/` captures plus the six-case n206 container probe, all `ROOT=$FX`, show no suffix -- and backlog #242 Slice D's S0 (`LLM/evidence/2026-10-02-242-display-sites.md` §1d) settles why: every pinned cycle forms in the running root `/`, so Portage's own per-node gate stays shut on every pinned shape; portuale's root is non-`/` in every test, so the literal gate would inject tmp paths; same rationale as `root_suffix`'s pre-D form), and the `installed` / `uninstall` variants are unreachable here (cycle members are merge-bound by construction -- `find_hard_cycles` only considers merge-bound entries; a member missing from `entries` falls back to the bare cpv at the call site).
- Each node is Portage's `str(Package)` (`circular_node_text`); each label is Portage's `DepPriority.__str__` of the edge into that line's package. The slot-conflict renderers below keep their own local closures (their unknown-member fallbacks differ from each other and carry no colour, so sharing this helper would move their pins).

- Backlog #228: `edge_labels[i]` is the edge into line `i + 1`'s package (`cycle[i] -> cycle[i + 1]`), and the closing line's label is the wrap-around edge (`cycle[last] -> cycle[0]`).
