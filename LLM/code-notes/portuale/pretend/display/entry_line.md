- `plain_miss_deps` (#135 (d)): Portage's `emerge: there are no ebuilds to satisfy "<atom>"` + chain block. The staging `for <root>.` suffix stays absent (the `fixture-miss-message-unsuffixed` class), matching the top-level miss and the two sibling blocks above.
- `force_sizes` (backlog #206 S2): Portage's `_show_circular_deps` forces `--verbose` for the stuck-remainder display, so every row carries its fetch size (`verbose_size`, `0 KiB` for an ebuild whose distfiles are already present) -- while plain `-pv` rows keep portuale's established cut of omitting that bare `0 KiB`.
- `circular` (backlog #221, I5): the settling pass's recorded cycle edges.

## fn print_entry_line
- One `GraphEntry`'s own display line, factored out so flat and `--tree` modes share one implementation rather than drifting apart (`indent` prepended right before the category/package text -- empty for flat mode, `print_tree`'s own growing prefix for `--tree`). `onlydeps`/`top_level_pkgs` decide suppression exactly as before: a directly-requested top-level atom's own line (not its dependencies) is hidden under `--onlydeps`, whatever its outcome. `columns`/`columnwidth` switch the New/Upgrade/Downgrade/Reinstall arms below to `columns_line`'s own layout instead of the default inline `"...-version (upgrade from X)"` format -- see its own doc comment. Never both `columns` and a non-empty `indent` at once: the CLI layer refuses `--tree`+`--columns` together (the only source of a non-empty `indent`), so `columns_line`'s own `indent` parameter is always `""` in practice here, still threaded through for symmetry with the non-columns arms. `entries`/`index`/`root` are what the #68/#72 B2 blocker disposition needs (see `blocker_row_disposition`): the entry's own trailing blocker rows are filtered here, the inline ones are printed by the caller right after this line.
- Verbosity: Portage's `_DisplayConfig` is `--quiet and 1 or --verbose and 3 or 2`.
- `classify` ports Portage's `Display.check_system_world` (`output.py`): `world` when this package already matches an atom in `var/lib/portage/world`, OR when it's a directly-requested target (a "favorite") that `create_world_atom` would actually add -- i.e. NOT `--oneshot`/`--onlydeps` (Portage's `_DisplayConfig.oneshot`), and not an unslotted `@system` member (Portage "unslotted system packages will not be stored in world"). `system` = matches a `@system` atom; slot-qualified `@system` atoms are matched version-only -- a cosmetic-only miss, colour only. The full `create_world_atom` slot/repo/virtual logic is cut (see `update_world_file`).
- `root_annotation` order: Portage's `pkg_str + " " + oldbest + "to " + pkg.root`, with the USE display coming later on the same line -- backlog #242 Slice D repaints a running-rooted row's USE from the running profile, so the order matters there too.
- `bracket`: `CandidateSource` mirrors the exact two strings `"ebuild"`/`"binary"` of Portage's `lib/_emerge/RootConfig.py` `pkg_tree_map`.
- `force_reinstall` is Portage's `PkgAttrDisplay.force_reinstall`, the `@__auto_slot_operator_replace_installed__` set yielded with `force_reinstall=True`. `remote_binary` (the `g` column) is Portage's `attr_display.remote_binary = pkg.remote` for a `--getbinpkg` binary not yet in `$PKGDIR`.
- `show_slot` is Portage's `_append_slot` gate. `disp_version`: Portage's `output.py::_append_build_id` runs first (before `_append_slot`/`_append_repository`); `GraphEntry::build_id` is `Some` only for such a binary. `oldbest_str`: a brand-new `New`, or a `Reinstall` whose version, slot, sub-slot and repo all match the installed instance, has none.
- `convert_myoldbest`'s non-`new_slot` branch appends the old instance's sub-slot on a *second* disjunct the entry's own `_append_slot` does not have: `old.slot == pkg.slot and old.sub_slot != pkg.sub_slot`. Only reachable for an `oldbest` whose slot matches but whose sub-slot moved -- a `--changed-slot` / slot-operator reinstall (#24 S3 made `Reinstall` carry an `oldbest` at all).
- `emit` ports Portage's `_set_no_columns` (`f"[{type} {attr}] {indent}{pkg_str} {oldbest}"`; `print_messages`' `" " + verboseadd`). `verbose_size` (`conf.verbosity == 3` only): `verboseadd += localized_size(mysize)`, the bytes still to fetch. The one case ever non-zero here is a `--getbinpkg` remote binary -- an ebuild's distfiles / a local `$PKGDIR` binary are already present, so Portage would show a bare ` 0 KiB` that portuale's `-pv` lines have always omitted; closing that wider gap would re-pin every `-pv` assertion and is left out. Backlog #206 S2: the circular re-display runs forced-verbose, so its rows carry Portage's `0 KiB` like the live oracle. Backlog #272: Portage's `verbose_size` concatenates directly onto the trailing-spaced USE string (`verboseadd += localized_size(mysize)`), so the size carries no leading space of its own when a USE display precedes it (`USE="x" 0 KiB`, one space).
- Nomerge arm (#75 C1): Portage's `_set_no_columns` non-merge arm (`[<operation ljust 13><empty_space_in_brackets>] <indent><cpv> <oldbest>`); `verbose_size` is merge-gated, but the `USE="…"` display IS appended: Portage's `Display.__call__` runs `_display_use` for every package with no ordered/merge gate, and `print_messages` appends `" " + verboseadd` to the row (#154). The running-root suffix is appended like every other row. Portage pastes `pkg_str + " " + oldbest + suffix` (the space after the version is unconditional -- else the version glues to `to`, e.g. `diamond-1.0to <root>`).
- `New` arm, Portage's `_get_installed_best`: brand-new -> `attr.new`; into a fresh slot while another slot is installed -> `attr.new` *and* `attr.new_slot` (`GraphEntry::new_slot`). No oldbest for a brand-new package; the other-slot version list Portage shows for a new-slot install (`myoldbest = installed_versions`) is deferred to a follow-up increment (portuale doesn't carry the other-slot versions on the entry yet).
- `Upgrade` arm: the exact new cpv isn't installed, so `attr.replace` stays clear; oldbest = the in-slot installed version(s) (`myinslotlist`), from `entry.oldbest`.
- `Reinstall` arm: `myoldbest` stays empty for a same-slot/same-repo reinstall (no `[from]`). Portage's `-pv` shows no inline "why" for a reinstall at all -- portuale's former `(reinstall for changed …)` prose is dropped here (the USE diff still shows in the `USE="…"` section for `--changed-use`; `--changed-deps`/`--changed-slot` reasons are genuinely invisible in Portage `-pv` too).
- `AlreadyInstalled` arm: Portage's `emerge -p` / `-pu` never prints a per-package "is already installed" notice, whether reached as a dependency or requested directly, and whether or not `@world`/`@system` pulled it in. Portuale used to print one for a top-level atom; it polluted `emerge -puD @world` (one line per up-to-date world member) and matched nothing in Portage, so it was dropped. Blocker owners (#73): an installed `bparent` kept out of the merge list still gets `[blocks B]` (cells g/g3/g4); the satisfied `b` rows of such an owner are not part of the group (Portage appends those inline on a *scheduled uninstall*, #72). `resolve_blockers` writes `satisfied_by: None` whenever `unsolvable` (#84 context).
- `Uninstall` arm: Portage's `_set_no_columns` non-merge bracket arm (`output.py:514-529`) with `PKG_UNINSTALL` (`:285-286`): `[uninstall     ] <cpv> `, one fewer pad space under `-q` (verbosity 1 -> `empty_space_in_brackets()` is empty, u5b), skipped entirely under `--columns` (`output.py:869`, u5a). `-pv` decorates the cpv like every other row (`_append_slot`/`_append_repository`, `:523-524`); a non-`/`-rooted entry carries Portage's `to <root>` like every other row (`root_suffix`).
- `NoVisibleCandidate` arm: the USE-unsatisfied disclosure is Portage's `_show_unsatisfied_dep` "no ebuilds built with USE flags to satisfy" block.
- Keyword suggestion: previously only a top-level atom's own fatal NoVisibleCandidate got this note (as part of the `Err` message that aborts the whole call); now extended to a dependency's own NoVisibleCandidate.
- Parent flip: when that flip resolves the dep, `resolve_pretend_graph` applies it and the entry is no longer NoVisibleCandidate, so this arm is a fallback hint for the (currently unreachable) case where the suggestion exists but wasn't applied.
- Portage `output.py:841-862`'s own `to <root>` annotation for a non-`/`-rooted entry -- empty for every `/`-rooted one (see `root_suffix`'s own doc comment). Placed right before `use_suffix` in each arm below, matching Portage's own ordering (`pkg_str + " " + oldbest + "to " + pkg.root`, with the USE display coming later on the same line -- backlog #242 Slice D repaints a running-rooted row's USE from the running profile, so the order matters there too).
- `emerge -pv` (verbosity 3) decorates the bracket cpv *and* every `[old-ver]` with `:slot`/`::repo` (Portage `_append_slot` / `_append_repository` / `convert_myoldbest`). `show_slot` is Portage `_append_slot`'s own gate, computed once for the whole line.
- The version as displayed in the bracket line: bare at `-p`, `:slot::repo`-decorated at `-pv`. Portage `output.py::_append_build_id` runs first (before `_append_slot`/`_append_repository`): a `type_name == "binary"` entry whose `Packages` index carried `BUILD_ID` shows `<cpv>-<build_id>` (`GraphEntry::build_id`, `Some` only for such a binary).
- Portage `convert_myoldbest`: `blue("[" + ", ".join(versions) + "]")`, each version `-r0`-stripped and (at `-pv`) `:slot::repo`-decorated with *its own* slot/sub_slot/repo. Empty string when there's no `oldbest` (a brand-new `New`, or a `Reinstall` whose version, slot, sub-slot and repo all match the installed instance).
- Portage `output.py:856-861`: `darkgreen("to " + pkg.root)`, shared by the merge, `nomerge` and uninstall arms.
- One merge line, shared by `New`/`Upgrade`/`Downgrade`/`Reinstall`. Portage `_set_no_columns`: `f"[{type} {attr}] {indent}{pkg_str} {oldbest}"` -- the space before `oldbest` is always there even when `oldbest` is empty. The running-root `to <root>` suffix (Portage `output.py:856-861`) and the `USE="…"` display (Portage `print_messages`' own `" " + verboseadd`) follow, each already carrying its own leading space via `root_suffix`/`use_suffix`.
- Portage `output.py::verbose_size` (`conf.verbosity == 3` only): `verboseadd += localized_size(mysize)` -- the bytes still to fetch, appended after the USE string. Portuale renders it only for a `--getbinpkg` remote binary (the one case that's ever non-zero here -- an ebuild's distfiles / a local `$PKGDIR` binary are already present, so Portage would show a bare ` 0 KiB` that portuale's `-pv` lines have always omitted; closing that wider gap would re-pin every `-pv` assertion and is left out) or under `force_sizes` (backlog #206 S2: the circular re-display runs forced-verbose, so its rows carry Portage's `0 KiB` like the live oracle).
