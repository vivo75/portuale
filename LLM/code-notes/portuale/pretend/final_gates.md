# crates/portuale/src/pretend/final_gates.rs
The last gates before execution: ABI rebuilds, changed-deps report, buildpkgonly deps, circular dependencies.

## fn final_gates
- The ABI-rebuild report ports `_show_abi_rebuild_info` (`depgraph.py:1210`): `_forced_rebuilds[root][child] = {parents}`; rendered right after the merge list / autounmask blocks, before the changed-deps report; `writemsg_stdout`, so stdout. Each package prints as `str(Package)` (`Package.__str__`): `(cpv:slot/sub_slot::repo, ebuild scheduled for merge[ to '<root>'])`.
- The changed-deps gating (empty unless `changed_deps_report` was given AND `changed_deps` was NOT) lives in `resolve_pretend_graph`; see its doc comment.
- The `buildpkgonly` gate ports `display_problems()` after `_show_merge_list()`; see `GraphResult::buildpkgonly_deps_unsatisfied` for the exact check.
- The cycle gate ports `_serialize_tasks` -> `_show_circular_deps` (`depgraph.py:10425`): every edge in the cycle is one Portage's `_ignore_runtime` scan cannot linearize (an unsatisfied `DEPEND`/`BDEPEND` with no run-time alternative, or since backlog #228 an unsatisfied slot-operator edge).
- Faithful transcription of `_show_circular_deps`'s `writemsg` sequence: the reduced cycle-only re-display (`self.display(handler.merge_list)`, flat portuale lines since portuale's tree model dedups shared nodes and never abandons the list) and the `large_cycle_count` "a lot of cycles" trailer (shown only with a concrete suggestion, like Portage). The suggestion branch ports `circular_dependency_handler._find_suggestions`: `gpcyclec` is a hard grandparent clash (disqualifies), `fucyclec` a conditional one (kept with `followup_change`). The shortest cycle drives `_prepare_circular_dep_message`; every line after `depends on` carries its own edge's `priorities[-1]` label (backlog #228 -- `(buildtime)` on every line for all-buildtime cycles, `slopcyca` pins the mixed shape).
- Slice 5 routing for the legacy site: a cycle abort printed above, before the autounmask section; a masked/unsat abort prints no circular block at all -- the pre-Slice-5 print-and-exit-1 shape, byte-identical.
- Backlog #19 abort-path outcome mapping: `not success` -> `display_problems()`, `return 1` (`_emerge/actions.py:460-462`); gated on `portage_repo::abort_path_enabled` (`PORTUALE_ABORT_PATH=0` keeps the legacy "report, don't enforce" list + exit 0 -- Gate G0.4). Since Slice 3 the resolver produces `Aborted` (see `portage_repo::abort_outcome`); Slice 4 moves the partial-list rendering here.
- Already empty unless `changed_deps_report` was given AND `changed_deps` was NOT (see `resolve_pretend_graph`'s own doc comment for that gating), so no extra condition needed here beyond "is there anything to report at all".
- The `Change USE:` suggestion branch itself is shipped (`portage_repo::circular_dep_solutions`, Portage `circular_dependency_handler._find_suggestions`): fixtures `usecyclea` (bare suggestion), `gpcyclec` (hard grandparent clash disqualifies it), and `fucyclec` (conditional grandparent clash keeps it with `followup_change`) pin all three outcomes.
- Since Slice 3 the resolver produces `Aborted` (see `portage_repo::abort_outcome`), so this fires for a masked-only or otherwise unsatisfiable dependency of a merge-bound package and for an unserializable cycle; it sits *after* the circular block above because Portage's `display_problems()` prints `_show_circular_deps` first (`depgraph.py:11113`) and only then returns 1. Slice 4 moves the partial-list rendering here. `mrg` needs no separate wiring: `to_emerge_argv` hands its argv to this same `pretend::run` (`mrg.rs`), so resolution output and exit codes are literally `emerge`'s by construction.

## fn print_resolver_debug
- Ports `_compute_abi_rebuild_info`'s DEBUG dump (`depgraph.py:1011-1206`). Portage's `_slot_operator_deps` / `_forced_rebuilds` are richer dicts than portuale's flat `abi_rebuilds` `(provider-cpv, consumer-cpv)` list -- portuale emits the same shapes from what it has. Both ends of each abi-rebuild edge are Reinstall/Upgrade; same shape the "causing rebuilds" block builds.
- `emerge --pretend --debug` Stage 5: Portage `_compute_abi_rebuild_info`'s own DEBUG-level dump (Portage `depgraph.py:1011-1206`), on stdout, right before the `_show_abi_rebuild_info` "causing rebuilds" block.
- Group abi-rebuild pairs by the provider's `cp:slot` slot-atom.

## fn failure_gates
- The blocker gate ports `_show_unsatisfied_blockers` + `show_blocker_docs_link` (`depgraph.py:10496`); the per-parent `pulled in by` detail needs Portage's `_parent_atoms` / complete graph. Backlog #80: `file_blocker_conflicts` only orphans `unsolvable` rows; Portage prints the same `* Error` block for the n1b shape. The `Conflict: N blocks (M unsatisfied)` line depends on the sentence and exit code.
- Backlog #62: a recorded slot conflict fails the whole action with rc 1, matching Portage 3.0.82.2. The rule was verified against the source and host-side oracles before coding (the obvious "notice printed => rc 1" formulation is wrong in the escape cases, and the first draft of the plan had it wrong too). The notice itself is unconditional on the conflict existing (`display_problems` prints it whenever `any(_package_tracker.slot_conflicts())`, `depgraph.py:11117-11120`); it says nothing about the exit code. The exit code comes from `action_build`'s `if not success: display_problems(); return 1` (`actions.py:460-462`), and `success` is False exactly when a conflict is recorded and not tolerated (`_resolve` tail, `depgraph.py:5685-5691`). Escape 1 -- `--autounmask-only` returns 0 first (`actions.py:456-458`), notice printed and all; preserved for free since this gate sits after that early return. Host oracle: the needer/othermod triangle with `--autounmask-only` prints the notice and exits 0. Escape 2 -- `_accept_blocker_conflicts()` (`depgraph.py:9259-9271`): backtracking disabled plus one of `--buildpkgonly`, `--fetchonly`, `--fetch-all-uri`, `--nodeps`. Host oracles: `--backtrack=0 --nodeps` and `--backtrack=0 --buildpkgonly` on the triangle exit 0 (in fact Portage records no conflict at all there -- `--nodeps` never walks the deps that would pull it in, `--buildpkgonly` resolves the shape without the upgrade -- so no "notice with rc 0" shape was reproducible; the gate still matters because portuale's resolver does record the conflict there). `--fetchonly` / `--fetch-all-uri` are still portuale-unimplemented options (rc 2 before reaching here), so they need no parsed flag yet -- extend this condition when that surface lands. `--fetchonly` shapes could not be oracled hermetically anyway: Portage attempts the fetch phase past resolution and fails on the fixture's unexpanded `file://${PORTAGE_CONFIGROOT}` binhost URL (rc 1 even with no conflict anywhere). `--json` has no Portage counterpart (Portage rejects it, rc 2) and follows the same rule for consistency. The blocker path is untouched: its `all satisfied` -> rc 0 / `unsolvable` -> rc 1 split already matches Portage.
- Backlog #295: the best-run re-pass could not take the `prune_rebuilds` restart Portage wants (`depgraph.py:5763-5775`).
- Portage `_serialize_tasks` -> `_show_unsatisfied_blockers` + `show_blocker_docs_link` (`depgraph.py:10496`): a blocked installed package the resolver could neither replace nor unmerge is an unresolved conflict -- Portage prints the `* Error: The above package list …` block and `actions.py` returns 1. Portuale's per-parent `pulled in by` detail is a documented cut (it needs Portage's `_parent_atoms` / complete graph); the sentence, the docs link and the exit code are what a `$?` check and the `Conflict: N blocks (M unsatisfied)` line depend on.

## fn final_gates (ignored-user-patches block, backlog #509)
- Prints `GraphResult::ignored_user_patch_binaries` between the ABI rebuilds and the changed-deps report (Portage `display()` order: merge list, abi rebuilds, ignored binaries, changed-deps report). Suppressed under `--quiet` and under an explicit `--binpkg-respect-user-patches=y|n` (`opts.binpkg_respect_user_patches.is_some()`); the `--verbose` tail comes from `opts.verbose`.
