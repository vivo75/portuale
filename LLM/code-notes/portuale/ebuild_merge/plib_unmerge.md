# crates/portuale/src/ebuild_merge/plib_unmerge.rs
Unmerge-side preserved-library handling: the prune-registry step, the unused-library computation and the prune that deletes files and rewrites owners.

## module
- Ports Portage's `dblink._prune_plib_registry` (with `unmerge=True`), `dblink._find_unused_preserved_libs` (incl. `_find_unneeded_preserved_nodes`) and `_remove_preserved_libs` (vartree.py).

## fn preserve_libs_on_unmerge
- Ports `dblink._prune_plib_registry`, called from Portage's `unmerge()` with `unmerge=True` right before `_unmerge_pkgfiles()` runs. Portage's `preserve_paths` (a `_prune_plib_registry` parameter, not this function's return value) is only ever non-`None` when a depgraph-driven upgrade transaction already computed it via a companion `merge()` call in the *same* transaction: `None` on the standalone path (portuale's `merge`/`unmerge` are always separate, independent CLI invocations), the merge-side set on the replace loop. An instance that owns no files still unregisters (Portage's `instance_owns_files` gates only the rebuild and the scans).
- Order: rebuilds the system-wide `LinkageMap` from every installed package's vdb-stored `NEEDED.ELF.2` (`linkage_owner_entries` + `rebuild` -- Portage's `exclude_pkgs=None` on the standalone path, since the package being unmerged hasn't left the vdb yet, so its own data is still part of the map, matching Portage exactly). Computes `needed_elf::find_libs_to_preserve` with `new_owner_is_owner` always `false` (matching what Portage's `not unmerge and self.isowner(f)` collapses to when `unmerge` is `true`) and `old_owner_is_owner` as Portage's `self.isowner` (`owns_path_pf`, this exact package's own `CONTENTS`). Unconditionally unregisters this package's own prior registry entry first (Portage's `plib_registry.unregister`); if anything is actually preserved, registers this package -- the one being removed -- as the new keeper of those paths (Portage's `plib_registry.register`).
- `is_replacement` is Portage's `unmerge_with_replacement` (`preserve_paths is not None`, set exactly when `treewalk()`'s replace loop drives this unmerge): Portage then skips the `_find_libs_to_preserve(unmerge=True)` re-registration entirely and only unregisters the old entry -- the preserved set was already computed merge-side (`find_preserve_paths_for_merge`) and injected into the replacing package's own `CONTENTS`, so the files survive removal through same-slot ownership (`remove_contents`' `is_owned` skip) and the record lands under the merging package via `register_merge_preserved_libs`. Returns an empty set in that mode; the standalone (`emerge -C`) mode returns the preserved paths for the caller to exclude from its file-removal loop.
- Returns the set of preserved paths (already `ROOT`-relative absolute paths, portuale's `CONTENTS` convention) -- the caller is responsible for excluding them from its file-removal loop (Portage's "remove the preserved files from our contents so that they won't be unmerged"; portuale's vdb entry directory gets deleted wholesale moments later regardless, so there is no separate `CONTENTS`-file rewrite to also perform here).

## fn preserve_libs_on_unmerge_into
- The `retire` variant (feat#157 S4.2): keeps the registry in `retire` instead of writing it.
- In-function facts: Portage's `_prune_plib_registry` still runs `unregister()` for an instance that owns no files (`instance_owns_files` gates only the linkmap rebuild and the preserve/prune scans); only the preserve-set computation is skipped. The orphan scan must see the registry *before* this package's own entry is unregistered: Portage rebuilds the `LinkageMap` (whose orphan `scanelf` branch reads the registry) before `unregister()` runs, so a previously-preserved library this instance no longer ships in its own `NEEDED.ELF.2` is still indexed for the computation.

## fn preserved_lib_paths
- Every currently-registered preserved-library path, keyed by the cpv that owns it (Portage's `PreservedLibsRegistry.getPreservedLibs()`). A thin `pub(crate)` reader for the resolver-side `@preserved-rebuild` set and the `display_preserved_libs` advisory, both living outside this module.

## fn find_unused_preserved_libs
- Ports `dblink._find_unused_preserved_libs`: the registered preserved libraries that no installed package links against any more, keyed by the cpv that owns them (so the caller can prune each owner's `CONTENTS`). Rebuilds the system-wide `LinkageMap` from every installed `NEEDED.ELF.2` **plus** the registry orphans no `NEEDED.ELF.2` indexes (`linkage_owner_entries`, `LinkageMap.rebuild`'s preserved-libs branch) -- without the orphans a just-preserved library is invisible here -- and, for each registered path that still exists on disk, collects its consumers -- from the linkage map when the path is still an indexed object, otherwise via a basename==soname reverse lookup (`needed_elf::soname_consumers`) for a library whose owning package has already left the vdb. The consumer/preserved graph is then reduced by `needed_elf::find_unneeded_preserved` (Portage's `_find_unneeded_preserved_nodes`, cycle-aware).
- `unmerge_no_replacement` + `being_unmerged`: Portage's "also eliminate consumers that are going to be unmerged if unmerge_no_replacement is True" (Portage's `unmerge_no_replacement = unmerge and not unmerge_with_replacement`): on a plain unmerge with no replacement, a consumer that is itself entirely owned by the package now being removed does not keep a library alive; in replacement mode those consumers survive through the replacing package, so they still count. `being_unmerged` returns true for such a path.
- `exclude_cpvs` + `replacement_preserved`: Portage's `exclude_pkgs` + `preserve_paths` (see `linkage_owner_entries` in plib_merge notes): in replacement mode the unmerged instance's own linkmap data is excluded while the merge-side just-preserved set is scanned in, so a preserved library whose only linkmap consumer is a just-preserved file is kept. Both are empty/`None` on every other path.
- `replacement_needed`: Portage's `include_file` (see `linkage_owner_entries` in plib_merge notes): the replacing package's own `NEEDED.ELF.2` lines, so a preserved library whose only remaining consumer is the replacing package itself survives the replace-loop prune. Empty on every other path (standalone `emerge -C` has no replacing package; the merge-end prune runs after the rename into place, when the new entry is enumerated).
- Deliberate narrowing vs. Portage: the per-consumer "an alternative, non-preserved provider of the same soname is installed" edge removal (Portage's "erroneously preserved due to a move from one directory to another") is not reproduced -- portuale has never had a preserved-lib directory-move path, and the collision-protect takeover (`unregister_preserved_libs`) already covers the same-path case.

## fn find_unused_preserved_libs_in
- `find_unused_preserved_libs` over an explicit registry (the one an unmerge in progress holds in memory, feat#157 S4.2).
- Fallback when the path is not an indexed object (owning package gone): "does any installed object still need this soname".

## fn prune_unused_preserved_libs
- Ports `dblink._prune_plib_registry`'s tail (`_remove_preserved_libs` + the `removeFromContents` loop + `pruneNonExisting`), which Portage runs at the end of **both** a merge (`treewalk` -- "For gcc upgrades, preserved libs have to be removed after the library path has been updated") and an unmerge.
- Deletes every preserved-library file `find_unused_preserved_libs` reports as unneeded (tolerating an already-gone file), removes empty parent directories, strips the paths from each still-installed owner's `CONTENTS`/`NEEDED.ELF.2` (`remove_from_contents`), rewrites the registry with those paths gone (and drops any entry whose paths no longer exist on disk -- Portage's `pruneNonExisting`). Prints Portage's `<<< !needed  {obj|sym} <path>` per removed file. Returns the removed `ROOT`-relative paths.
- `unmerge_no_replacement` / `being_unmerged` / `exclude_cpvs` / `replacement_preserved` / `replacement_needed` pass straight through to `find_unused_preserved_libs` (see its section for the grounding); every caller except the replace-loop unmerge passes `exclude_cpvs=&[]` and empty feeds.

## fn prune_unused_preserved_libs_into
- The `retire` variant (feat#157 S4.2): reads the registry from `retire` and leaves its writes (the registry, the W4 rewrites) there instead of committing them. The files it removes are removed at once either way.
- In-function facts: "Remove empty parent directories if possible" -- walks upward from each removed file's parent, stopping at the first non-empty one. Only still-installed owners get the `CONTENTS`/`NEEDED.ELF.2` strip; every matching registry entry loses the paths regardless. Tail is Portage's `_remove_preserved_libs` (vartree.py:3995): `self.vartree.dbapi._plib_registry.pruneNonExisting()` -- drops a registry entry once none of its recorded paths exist on disk any more (rebuilding survivors file-then-symlink, not just retaining).
