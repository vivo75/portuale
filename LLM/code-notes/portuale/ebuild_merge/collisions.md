# crates/portuale/src/ebuild_merge/collisions.rs
Blockers against installed packages and file collisions.

## fn blocked_installed_packages
- Ports Portage's `dblink.merge()` blocker half (`mypkglist = others_in_slot + blockers`; `others_in_slot` is already `find_collisions`' `own_versions`). Portage's `dblink._blockers` is never computed by `dblink` itself but injected by the depgraph resolver, which knows the full graph by merge time. Portuale's standalone `ebuild <file> merge` has no depgraph (unlike `emerge --pretend`), so this is new self-contained machinery: resolves `repos.conf`/profile/USE config for the merging package's repo (`portage_repo::find_repos` + `portage_profile::resolve_config`, the same machinery `pretend.rs` uses, including its `masters =` resolution), computes effective USE the way `portage_repo`'s (now `pub`) `effective_use_flags` always has, flattens the real `DEPEND`+`RDEPEND`+`BDEPEND`+`PDEPEND`+`IDEPEND` (`portage_use_reduce::use_reduce_flat`), and matches every blocker atom found (`!atom`/`!!atom`, `portage_dep::parse_atom`'s `.blocker`) against every installed package (`portage_dep::match_from_list`, which ignores an atom's blocker marker when matching -- verified behaviour relied on elsewhere -- so the blocker string passes through as-is). Weak vs. strong blockers are not distinguished (Portage's `mypkglist` construction doesn't either). Returns matched packages as bare `(category, pf)` pairs.
- Degrades gracefully to an empty set on any resolution failure (missing `repos.conf`, unreadable md5-cache, ebuild path outside any repo): config resolution isn't guaranteed in every context `ebuild <file> merge` runs from (unlike `emerge --pretend`, the real-execution CLI never required it before this slice), and a missed exclusion only reports an ordinary collision instead -- never a false negative toward silent corruption.

## fn blockers_from_flat_deps
- The installed-package scan plus blocker-atom match half of `blocked_installed_packages` (Portage's `mypkglist` `blockers` term). Category by category, like the old walk: list the category, read each entry's `SLOT`, then the next. Slot handling goes through the vdb seam (#116), so the scan sees the same normalised `SLOT` every other consumer does (a missing field is `""`, split into `("", "")` here).

## fn find_collisions
- Portage's `os.walk(srcroot)` (building `filelist`/`linklist`, `vartree.py:4625-4681`) puts a directory-target symlink into `dirs`, not `files`, so it never reaches the checked lists and is never collision-checked (verified: `link_to_dir` lands in `dirs`, `link_to_file`/dangling land in `files`). A directory-target symlink colliding with a directory (e.g. linux-firmware's `nvidia/ad10x` symlinks over installed directories) is therefore ignored here, matching Portage. `metadata` follows the link exactly like `os.walk`'s own `is_dir()` (image-relative for relative targets); a dangling link errors here and falls through to the check, like Portage.
- `FEATURES=protect-owned` is decided by the caller (`run_merge`) from this function's `collisions` plus `find_owners`, not inside this function itself.

## fn find_owners
- The scan is `portage_vdb::InstalledDb::owners` (S1.5: the old two-level walk and per-entry `CONTENTS` read moved into `FilesDb` unchanged). Two things the old loop did stay here because they live above `portage-vdb`: an entry whose directory name does not split as `<package>-<version>` (`portage_repo::split_pf`) claims nothing (the old walk skipped it before reading `CONTENTS`; it is now read and its claims dropped), and the result is regrouped as `category/pf` -> the matched collision strings (the same absolute strings the old direct read pushed).

## fn collision_message
- Narrowed to what portuale cheaply computes (see the module doc): every colliding path with whichever other installed packages `find_owners` found claiming it, `(unclaimed)` when none did (Portage's own "None of the installed packages claim the file(s)" case).
