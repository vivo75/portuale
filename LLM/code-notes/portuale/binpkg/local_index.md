# crates/portuale/src/binpkg/local_index.rs
The local `$PKGDIR` scan: per-file entries with index fast-path, stale vouching, and orphan re-injection.

## fn populate_local_pkgdir
- Ports Portage's `bintree._populate_local`, both halves: walk `pkgdir` for binpkg files and synthesize one `Packages`-style entry per file from its own embedded metadata (`read_xpak_metadata` / `read_gpkg_metadata`), fast-pathed against any already-parsed `<pkgdir>/Packages` entries first. A candidate entry (matched by basename) whose own `_mtime_`/`SIZE` still agree with the live file's `stat(2)` and which carries Portage's own `minimum_keys` (`PKGINDEX_MINIMUM_KEYS`) is reused verbatim. The fast path is Portage's `bintree.py:1108-1136` "Validate data from the package index and try to avoid reading the xpak if possible" optimization; `PATH` refresh is Portage's `if oldpath != mypath: d["PATH"] = mypath`.
- A basename-matched entry whose `_mtime_`/`SIZE` no longer agree is still reused verbatim (backlog #174): that is Portage's own default, so only `CPV` is required of the vouched stanza, not the reindex fast path's `minimum_keys`. Only a file no stanza vouches for is freshly parsed. Entries are `CPV`-sorted for a deterministic pool order.
- The stale-vouch arm is Portage's default: `FEATURES=pkgdir-index-trusted` (in Portage's `make.globals` default `FEATURES`, `cnf/make.globals:81`) runs `_populate_local` with `reindex=False`, which never stats or reads the file at scan and leaves verification to merge-time `BinpkgVerifier`. Only `CPV` is required (Portage injects stanzas unconditionally on this path; notably a portuale-written `--buildpkg` stanza may carry no `SLOT`). The category guard exists because the same `PF` can exist in two categories with the same basename, and the first same-basename stanza would vouch for the wrong file.
- Error split ports Portage's caller (`bintree.py:1185-1199`): `Invalid` is Portage's `PortagePackageException`/`SignatureException` family, reported with Portage's own `!!! Invalid binary package: '<path>', <reason>` (noiselevel=-1, unconditional); `Fatal` is Portage's uncaught `KeyError`/`AttributeError`/`RecursionError`. Portage's `<e>` is the bare exception text.
- Multi-instance layout ports Portage's `bintree._allocate_filename_multi` (a `<cat>/<pn>` subdir, a `-<build_id>` suffix, the `.xpak` extension); A `.xpak` file is byte-format-identical to a `.tbz2` (`[image tarball][XPAK …STOP]` -- Portage `bin/misc-functions.sh` builds the same archive either way), so `read_xpak_metadata` reads it unchanged; the multi-instance `BUILD_ID` comes from the filename, validated against the archive's own embedded `PF`. `CPV` is `<category>/<pf>` (embedded `PF` for multi-instance, filename otherwise), `SIZE` the file's byte size (Portage `bintree`'s `st_size`), `REPO` the embedded `repository`, `PATH` the relative path.
- Orphan re-injection (backlog #187): Portage's `reindex=False` `cpv_inject`s every stanza without stating any file (`bintree.py:1057-1064`), so the resolver still selects the binary and the merge aborts with Portage's `!!! Tried to use non-existent binary` pair instead of silently falling back to the ebuild. Only stanzas whose `PATH` names no live file inject; a `CPV` is required (Portage's own `_pkg_str` needs it too). A PATH-less stanza defaults to `<cpv>.tbz2` (`bintree.py:1047-1055`).
- `trust_index` selects Portage's two `_populate_local` modes (backlog #199, `bintree.py:936-938`'s `reindex = "pkgdir-index-trusted" not in features or force_reindex`): `false` (`FEATURES=-pkgdir-index-trusted`) is `_populate_local(reindex=True)` (only the `_mtime_`/`SIZE` fast path is trusted; changed files re-parsed, `bintree.py:1179-1351`; stanzas with no live file dropped, `bintree.py:1353-1356`). In trusted mode Portage never walks at all, but this scan always walks so a `Packages`-less `$PKGDIR` still resolves (pre-#199 behavior the flag must not change). Portage rewrites a changed `Packages` back under lock (`populate`'s second `_populate_local()` + `_pkgindex_write`); portuale never writes it back.
- Replaced portuale's former "present `Packages` is always trusted outright, no scan at all" stance (`portage_repo::read_packages_index`'s doc); the caller (`pretend.rs`'s `--usepkg` CLI-boundary setup) now uses this function unconditionally.
- v1 cut: the old flat `<pkgdir>/All/<pf>.tbz2` layout (Portage's `mydir != "All"` fallback) is not walked. A misnamed multi-instance file (one whose `<pf>-<id>` stem disagrees with its embedded `PF`, or whose subdir isn't `<pn>`) is skipped, matching Portage's `invalid_name`/`name_split` `continue`; the subdir check is Portage's `tuple(catsplit(mydir)) == name_split[:2]`.

## const PKGINDEX_MINIMUM_KEYS
- Ports Portage's `minimum_keys` (`bintree.py:1018`: `self._pkgindex_keys.difference(self._pkgindex_hashes)`; see also `bintree.py:1014-1018`): the `_aux_cache_keys` (`bintree.py:96-120`) plus `CPV`/`SIZE` (`bintree.py:550-551`, with `bintree.py:548-551`), minus the `_pkgindex_hashes` digests (`MD5`, `SHA1`, `bintree.py:548`; Portage never computes digests at scan, `bintree.py:1014-1017`). `MD5` is the one hash that is also an aux key, hence the only name dropped; `SHA1` was never in it. A stanza missing only digests must still hit the fast path. `CPV`/`SIZE`/`SLOT`/`_mtime_` ride along (Portage checks presence of the whole set, values only for `_mtime_`/`SIZE`).

## fn scan_binpkg_file
- Fast-path gate ports `bintree.py:1115-1126`: the live `lstat(2)` mtime seconds and byte size must agree with the stanza's `_mtime_`/`SIZE`, and the stanza must carry every one of Portage's `minimum_keys`, so a stat-matching but key-incomplete stanza is re-parsed, not vouched; minimum-keys presence is `bintree.py:1124`'s `if not minimum_keys.difference(d)`. Under `FEATURES=-pkgdir-index-trusted` a stat-matching but key-incomplete stanza falls through to the fresh parse, exactly like Portage.
- Multi-instance naming ports Portage's `_parse_build_id` + `myfile != f"{mypf}-{build_id}.<ext>"`; single-instance ports `myfile != mypf + ".<ext>"` -> `invalid_name`.
- The stale-vouch arm: Portage's own default `_populate_local(reindex=False)` never walks `$PKGDIR` at all -- every `<pkgdir>/Packages` stanza is injected verbatim and the file's own bytes are first touched at merge, by `BinpkgVerifier` (backlog #174). So an index stanza for this basename vouches for the file even when its `_mtime_`/`SIZE` no longer agree with the live file (a truncated or otherwise corrupted binpkg): reuse it verbatim -- stale `SIZE`/digests included, since the merge-time verification (`verify_binpkg_against_index`) checks the file against exactly those index values -- instead of re-parsing the container and pre-rejecting it with `!!! Invalid binary package`. A file no stanza vouches for keeps the reindex behavior: parse the container now, rejecting it at scan when its metadata can't be read (Portage's `PortagePackageException` / `SignatureException` arm, `bintree.py:1185-1199`). With `trust_index == false` (backlog #199) this whole arm is off.
