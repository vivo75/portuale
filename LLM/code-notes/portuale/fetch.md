# crates/portuale/src/fetch.rs
Network fetch of a package's distfiles via `wget` (locking, mirrors, resume, digest verification).

## module
- The second half of "actually fetch a package's sources": `portage_fetch`'s module doc covers the pure-logic half (SRC_URI flattening, Manifest parsing, digest verification, all offline and 100% unit-testable); this module shells out to the genuine `wget` using `make.globals`'s default `FETCHCOMMAND` template verbatim (`cnf/make.globals`), rather than an in-process HTTP client -- matching portuale's "run the same genuine external process Portage would" precedent (`bin/*.sh`, `xpak-helper.py`, ...).
- `FEATURES=distlocks` is genuine too (`lib/portage/locks.py:175-`'s `lockfile(mypath, wantnewlockfile=1)`, called at `fetch.py:1315-1330` / unlocked at `:2032-2033`, wrapping the entire per-file fetch-and-verify sequence, not just the download): a genuine blocking `flock(2)` exclusive lock (Portage's `fcntl.flock`) on a genuine separate sibling lockfile (`'.' + basename + '.portage_lockfile'`) -- guards against two concurrent Portage processes racing the same distfile. Confirmed via `cnf/make.globals` (lines 77-84) that `distlocks` is one of Portage's own default `FEATURES` tokens (`PortageLockfile::acquire`'s callers default to locking accordingly). Released by closing the lock file's fd (`PortageLockfile`'s `Drop`), the same effect Portage's `unlockfile()` explicit `flock(fd, LOCK_UN)` has -- POSIX releases all of a process's `flock` locks on an fd when it closes. Portage `unlinkfile=0` (portuale's default too, matching `fetch.py`'s own call): the lockfile persists on disk after release, just unlocked, ready for reuse.
- Known, documented gaps (v1 scope, portuale's own "narrow v1, document the cut" pattern): see the bullets below.
- Resume IS modelled (the candidate loop passes Portage's fresh-vs-resume bit through the `mrg_director::FetchRequest` seam, `resume: true` running `make.globals`'s own default `RESUMECOMMAND`, `FETCHCOMMAND` + `-c`): once a non-empty partial file is on disk (a dropped connection, a mirror that closed mid-transfer), the candidate loop switches to `wget -c` to continue it rather than restarting, matching Portage `fetch.py`. A complete-but-corrupt file (digest mismatch after a full download) is still dropped -- it can't be resumed. Not modelled: Portage's `PORTAGE_FETCH_RESUME_MIN_SIZE` threshold (it only resumes a partial past 350000 bytes) -- portuale resumes any non-empty one.
- `mirror://` resolution is genuine (`portage_fetch::resolve_mirror_candidates` + `mirror_url`'s `layout.conf` negotiation and `.mirror-cache.json`; covers Portage `custommirrors`, an admin-configured `${PORTAGE_CONFIGROOT}/etc/portage/mirrors` file, `RESTRICT=mirror` (`FetchOptions::restrict_mirror` -- the public `GENTOO_MIRRORS` fallback is skipped), `RESTRICT=primaryuri` (`FetchOptions::restrict_primaryuri` -- the file's literal URIs move to the front), `FEATURES=force-mirror` (`FetchOptions::force_mirror` -- plain URIs never enter the list), and the genuine candidate order itself (`assemble_candidates`: local mirrors, then public `GENTOO_MIRRORS`, then `mirror://` expansions, then literals -- rather than portuale's old most-specific-first). On-filesystem mirrors (Portage `fsmirrors`) are copied from before any download (`copy_from_fsmirrors`). The one Portage behaviour deliberately not attempted: third-party shuffle (portuale stays deterministic). The `mirror+`/`fetch+` SRC_URI prefixes ARE parsed (`portage_fetch::SrcUriEntry::override_mirror`/`override_fetch`): `mirror+` re-permits the public `GENTOO_MIRRORS` fallback even under `RESTRICT=mirror`, and `override_fetch` (from either prefix) re-permits a plain URI under `RESTRICT=fetch` -- which IS modelled (`FetchOptions::restrict_fetch`): a plain (non-`mirror://`) URI is barred from the candidate list, and the public mirrors too, so a `RESTRICT=fetch` package fetches OK only from an already-verified `DISTDIR` copy (or `custommirrors`/a `mirror://`-named mirror). Running the ebuild's own `pkg_nofetch` phase for a missing file IS modelled -- `fetch_src_uri` fails, and its caller `ebuild_phases::fetch_sources` then runs `run_one_phase(env, "nofetch")` so the ebuild's custom "download it from ... and place it in DISTDIR" instructions print, before the fetch error propagates.
- No `FEATURES=verify-sig` GPG check -- this backlog item was mis-scoped when first written: genuine `verify-sig`/signature verification is a `gpkg` (the newer GPG-signed binary package format, `lib/portage/gpkg.py`) and repo-sync concept (Portage `lib/portage/sync/modules/webrsync`'s own gemato-based Manifest signing), not a `SRC_URI`/distfile-fetch one at all -- confirmed by grepping `fetch.py` directly and finding zero hits for either term. Neither `gpkg` nor repo syncing are in portuale's scope at all yet, so there is nothing to port here.

## fn gentoo_mirrors_from_env
- Portage `make.globals`'s own `GENTOO_MIRRORS="http://distfiles.gentoo.org"` default. Used only by `ebuild_phases::fetch_sources`'s own `FetchOptions` construction, NOT read inside `fetch_src_uri` itself -- unlike `DISTDIR`/`ROOT`/`PORTAGE_TMPDIR`, `GENTOO_MIRRORS` has no dedicated CLI flag of its own yet, but the same "explicit parameter, not an ambient env read inside library code" reasoning still applies here: `FetchOptions.gentoo_mirrors` lets each test control it directly (most tests set it to `vec![]`, so a deliberately-failing fetch doesn't silently reach out to the real `distfiles.gentoo.org` as an unintended fallback) without needing `std::env::set_var`'s own unsoundness under parallel test execution.

## struct FetchOptions
- `distdir` is env-var-sourced at the `ebuild.rs`/`pretend.rs` CLI boundary (`DISTDIR`, same "env var/hardcoded default" shortcut `PKGDIR`/`CONFIG_PROTECT` use); `Default` matches Portage `make.globals`'s `DISTDIR="/var/cache/distfiles"` exactly.
- `gentoo_mirrors`: Portage `make.globals` default; a field rather than read inside `fetch_src_uri` per `gentoo_mirrors_from_env`.
- `config_root` (Portage `PORTAGE_CONFIGROOT`) is consulted only for `custommirrors` (`${config_root}/etc/portage/mirrors`) -- deliberately a field, not an ambient env read, mirroring `ebuild_merge::MergeOptions::config_root` exactly (portuale's dev/test machine is a genuine Gentoo system with a genuine populated `/etc/portage/mirrors`-shaped tree, so a silent `/`-style default here would make every test that doesn't override this field read host config); `Default` uses the same deliberately impossible path `MergeOptions::config_root` does.
- `distlocks` (Portage `"distlocks" in self.settings.features`) defaults to `true`: Portage `distlocks` is one of `make.globals`'s own default `FEATURES` tokens (`cnf/make.globals:77-84`, confirmed by reading it directly) -- unlike, say, `collision-protect`, which genuinely isn't.

## struct FetchOptions: more fields
- `use_flags`: the package's resolved `USE` (Portage `PORTAGE_USE`, the phase env's `USE`) that `SRC_URI`'s `flag?` groups reduce against. Empty (every `flag?` off, every `!flag?` on) when no resolved `USE` was threaded (standalone `ebuild <file>` with no graph).
- `mirror_cache_now`: Portage `time.time()` for the `.mirror-cache.json` day-long freshness check (`mirror_url`); `None` reads the system clock. Tests pin it.
- `portage_ssh_opts`: Portage `mysettings.get("PORTAGE_SSH_OPTS")` (`fetch.py:1806-1810`): the `FETCHCOMMAND_SSH`/`_SFTP` templates' `"${PORTAGE_SSH_OPTS}"` argument; `None` (the unset setting) expands to empty, same as Portage. Built from the resolved config via `portage_ssh_opts_from_config`.

## fn FetchOptions::restrict_mirror
- Ports Portage `fetch.py:880` (`restrict_mirror = "mirror" in restrict or "nomirror" in restrict`): when set, the public `GENTOO_MIRRORS` fallback (`Candidate::Mirror` roots) is NOT tried for this package (`file_restrict_mirror` gates `location_lists.append(public_mirrors)` at `fetch.py:1126`, `fetch.py:1117-1127`). Only the public mirror list is dropped: a `mirror://` URI's own `thirdpartymirrors`/`custommirrors` expansion and any explicit `SRC_URI` URI are still tried. Sourced from the ebuild's own `RESTRICT` md5-cache field by `ebuild_phases::fetch_sources`. Portage's `mirror+` `SRC_URI` prefix (`portage_fetch::SrcUriEntry::override_mirror`) re-permits the public `GENTOO_MIRRORS` fallback for that one file even when this is set -- `fetch_src_uri` checks `entry.override_mirror` per-entry, matching `file_restrict_mirror = ... and not override_mirror` (`fetch.py:1117-1119`).

## fn FetchOptions::restrict_fetch
- Ports Portage `fetch.py:1061` (`restrict_fetch = "fetch" in restrict`): a *plain* (non-`mirror://`) `SRC_URI` URI is barred from the fetchable-candidate list at `fetch.py:1167` (`if (restrict_fetch and not override_fetch) ...: continue`), and the public `GENTOO_MIRRORS` fallback is barred too (via `(restrict_fetch or restrict_mirror)`). A `fetch+`/`mirror+` `SRC_URI` prefix (`portage_fetch::SrcUriEntry::override_fetch`) re-permits the URI. So a `RESTRICT=fetch` package only fetches OK when its distfile is already verified in `DISTDIR` (or comes from `custommirrors` / a `mirror://`-named mirror). Sourced from the ebuild's own `RESTRICT` md5-cache field by `ebuild_phases::fetch_sources`. NOTE: the old field doc claimed portuale does NOT run `pkg_nofetch` for a missing file (failing with a generic pointer instead) -- stale since the caller runs the `nofetch` phase; the code keeps the current behaviour. (The stale claim read: portuale does NOT run the ebuild's own `pkg_nofetch` phase for a missing file, a documented cut -- `fetch_src_uri` fails with a generic "place it in DISTDIR by hand" pointer instead.)

## fn wget_fetch
- Ports `make.globals`'s default `FETCHCOMMAND` verbatim: `wget -t 3 -T 60 --passive-ftp -U "Portage (Gentoo, gentoo.org) distfile-fetch" -O "${DISTDIR}/${FILE}" "${URI}"`. Invoked as a genuine subprocess with the exact same arguments, not reimplemented as an in-process HTTP client. A failed fetch removes whatever partial file `wget` left behind, same "don't leave broken state around" reasoning `emerge_build.rs`'s build-failure handling applies elsewhere.
- The transport itself is `portage_fetch::download_via_wget` (shared with the `mrg-director` `Fetcher` seam); this wrapper names the non-resume `FETCHCOMMAND` for its own callers (the standalone mirror `layout.conf` read and the remote-`Packages` fetches in `emerge_getbinpkg`), while `fetch_src_uri`'s candidate loop dispatches Portage's fresh-vs-resume split through the seam.

## fn wget_fetch_quiet
- Quiet sibling of `wget_fetch`: the same default-`FETCHCOMMAND` wget, but output-captured (`download_via_wget_quiet`) -- for the binhost index refresh (`emerge_getbinpkg::refresh_binhost_indexes`), whose failure message is shaped from the transcript (Portage `bintree._populate_remote`'s `!!! [repo] ...` pair), never inherited onto stdout/stderr.

## fn assemble_candidates
- Ports `fetch()`'s `filedict[myfile]` build (`fetch.py:1099-1192`). Details: `local_mirrors` always tried, even under `RESTRICT=fetch`/`mirror` (`location_lists = [local_mirrors] + ...`); third-party half unshuffled (Portage shuffles for load-balancing; portuale deterministic); literals in reverse order per Portage `uris.reverse()` (as `fetch(..., listonly=1)` shows, tried last-listed first); repeated third-party URLs attempted once (Portage `tried_locations`); plain literal barred by `RESTRICT=fetch`/`force-mirror` never enters (`fetch.py:1167` `continue` -- `force-mirror` skips even a re-permitted literal); primary-uri group appended last normally, prepended first under `RESTRICT=primaryuri` (`fetch.py:1186-1192`); mirror roots resolved lazily via `functools.partial(async_mirror_url, ...)`.
- Portage `local_mirrors` keep their spelling (no `rstrip`), Portage `public_mirrors` are `x.rstrip("/")` -- both are also the `.mirror-cache.json` keys, so the spelling matters.
- `/`-rooted entries are Portage `fsmirrors` (`copy_from_fsmirrors`), never download candidates.
- The primary-uri group is Portage `filedict[myfile] = primaryuri_dict.get(myfile, []) + uris`.
- The plain-URI filter ports `fetch.py:1166-1174`: `if (restrict_fetch and not override_fetch) or force_mirror: continue` -- a *plain* (non-`mirror://`) `SRC_URI` URI is NOT a fetchable candidate under `RESTRICT=fetch` (only `mirror://`-named mirrors + `custommirrors` are). A `fetch+`/`mirror+` prefix (`entry.override_fetch`) re-permits it under `RESTRICT=fetch` (but not under `force-mirror`). A `mirror://` URI's own candidates already come only from the expansions, never the raw token, so nothing to strip there.
- `custommirrors["local"]` `/` entries come before `/`-rooted `GENTOO_MIRRORS`; `local_mirrors` stay in `location_lists` regardless of restrict, `fetch.py:1125`.

## fn checksum_failure_max_tries
- Ports Portage `fetch.py:896-934`: `PORTAGE_FETCH_CHECKSUM_TRY_MIRRORS` as an integer, default 5; non-integer or below-1 warns (the returned lines are Portage's `writemsg` text) and uses the default.

## fn mirror_url
- Portage `async_mirror_url(mirror_url, filename, mysettings, cache_path)` (`fetch.py:731-785`): the URL (or, for a `/`-rooted mirror, the local path) of `filename` under `mirror`, laid out per the mirror's own `layout.conf`. `cache_path` holds each mirror's `[structure]` with the time it was read; an entry younger than a day is used as is.
- Only a successful read is cached; a failed download or an unparseable file silently means "flat, nothing cached".
- `now` is Portage `time.time()`, passed in so the day-long freshness window is testable.
- `cache_path` is `${DISTDIR}/.mirror-cache.json` when `DISTDIR` is writable, else `None`. Otherwise the `layout.conf` is read from `<mirror>/layout.conf` for a `/`-rooted mirror (missing reads as empty -- Portage `read_configs` swallows `OSError`), else downloaded from `<mirror>/distfiles/layout.conf` into `${DISTDIR}/.layout.conf.<host>` (Portage `async_fetch(..., force=1, try_mirrors=0)`; left in place like Portage).

## fn fsmirrors
- Portage `fsmirrors` (`fetch.py:1019-1030`): the `/`-rooted `custommirrors["local"]` entries (as written), then the `/`-rooted `GENTOO_MIRRORS` entries (`rstrip("/")`).

## fn copy_from_fsmirrors
- Portage `fetch.py:1503-1513`: try each on-filesystem mirror in order, resolving the file's path through that directory's own `layout.conf`, copy the first one that exists to `dest`, and print Portage's `Local mirror has file: <file>`. A missing file (`ENOENT`/`ESTALE`) moves on to the next mirror; any other copy error is fatal, as Portage re-raises it. Returns whether a copy was made.
- Resolves through the directory's own `layout.conf` via `async_mirror_url(mydir, myfile, mysettings)` with no cache path, so it is re-read every time.

## fn distdir_writable
- Portage `os.access(DISTDIR, os.W_OK)` (`fetch.py:991`), which decides whether `.mirror-cache.json` is used at all.

## fn has_enough_space
- Portage `fetch.py:1503`: check if there's enough free space on the filesystem holding `distdir` to accommodate a file of size `bytes`. Uses `os.statvfs` (Portage `_emerge/main.py:1063`) to get filesystem stats.

## fn fetch_src_uri
- For every file `src_uri` (this ebuild's own md5-cache-sourced `SRC_URI` string) names for the current USE set, fetches it into `options.distdir` unless a Manifest-verified copy is already there. `flag?` groups reduce against `options.use_flags` (Portage `use_reduce(..., uselist=PORTAGE_USE)`, #37 S4).
- Returns the filename list Portage `A` should be set to (the caller exports it -- this module has no opinion on shell environment setup). A file with no `Manifest` entry at all is refused outright rather than fetched-but-unverified: unverifiable content is worse than a loud failure.
- Custommirrors read: `.unwrap_or_default()`, not `?`: `options.config_root` is deliberately an impossible sentinel path by default (see `FetchOptions::config_root`) -- joining `etc/portage/mirrors` onto it can fail with `ENOTDIR` (an *ancestor* component isn't a directory), not just the `NotFound` `parse_thirdpartymirrors` itself already tolerates, so this degrades to an empty `custommirrors` map on *any* resolution failure.
- Ports `doebuild()`'s `SRC_URI`-vs-`DISTDIR` fetch check, run once before the `unpack` phase (see `ebuild_phases.rs`'s call).
- `repo_root_for` tolerates a standalone ebuild outside any repo checkout the same way it does for eclass resolution (empty map, i.e. no thirdpartymirror candidates at all). `custommirrors` reuses `parse_thirdpartymirrors` directly since it's the exact same format, just a different source file (`grabdict()`'s format).
- The sentinel-path graceful degrade follows the precedent `ebuild_merge::blocked_installed_packages`'s `find_repos(config_root).ok()?` established for the same pattern.
- Lock ordering vs Portage: acquired before even checking whether the file is fetched in Portage (`fetch.py:1315`, ahead of `_check_distfile` at `:1336`); portuale acquires after the no-Manifest-entry refusal because portuale's single unified refusal for unverifiable content has no single-point equivalent (Portage's structure differs here), and there's no reason to require `DISTDIR` write access just to reach that refusal.
- The one Manifest-derived value the transport needs is Portage's `DIGESTS` substitution (`fetch.py:1797-1803`), formatted at the call site (where the entry lives) and carried pre-formatted.
- The second checksum failure switches to "primaryuri" mode per Portage `checksum_failure_count`; `_checksum_failure_temp_file` preserves the corrupt file as evidence (portuale uses a deterministic counter suffix instead of random).
- Supersedes `emerge_build.rs`'s old blanket SRC_URI refusal from the "no fetch machinery at all" era.

## tests: helpers
- `serve_once`: `file://` URIs would be simpler, but this system's `wget` build has no `file://` support at all (confirmed empirically: `wget file:///etc/hostname` -> `"Unsupported scheme."`) -- loopback HTTP has no such gap.
- `serve_mirror`'s mirror-root/`requested`/handle triple: a mirror-shaped HTTP server answering `connections` requests, serving `routes`' bodies by request path and 404 for anything else, and recording every requested path in order. Returns the mirror root (`http://127.0.0.1:<port>`), the recorded paths, and the thread handle. A caller expecting fewer requests than `connections` stops the thread with `unblock_server` (an empty connection ends it), so a thread parked in `accept` can finish.
- `serve_dropped_then_resumed`: serves `body` in two halves: connection 1 gets the real `Content-Length` header but only the first `split` bytes before the socket closes (a dropped transfer); connection 2, which `wget -c` makes with a `Range: bytes=<split>-` header, gets a real `206 Partial Content` with the rest.
- Already-verified skip test uses a reserved TEST-NET address (RFC 5737).
- `fetch_src_uri_reduces_use_conditional_groups_against_the_resolved_use`: backlog #37 S4.
- `fetch_src_uri_runs_a_configured_fetchcommand`: backlog #70 S1 (`${DISTDIR}`/`${FILE}`/`${URI}` substitution, spawned directly).
- `fetch_commands_from_config_defaults_an_absent_fetchcommand`: backlog #70 R2 / T2 (fixture config roots have no make.globals).
- `portage_ssh_opts_from_config_reads_the_scalar`: backlog #70 R4.
- `fetch_src_uri_uses_the_make_globals_default_without_a_config_value`: backlog #70 R2 end-to-end through the production parser (`resolve_config` on a root with no `usr/share/portage/config/make.globals`, T2's fixture shape).
- `fetch_src_uri_symlinks_a_verified_portage_ro_distdirs_file`: backlog #70 S2.
- `fetch_src_uri_resolves_a_real_mirror_uri_via_thirdpartymirrors`: proves the whole chain (`repo_root_for` -> `parse_thirdpartymirrors` -> `resolve_mirror_candidates` -> `Fetcher::fetch` -> `verify_digests`) together, not each piece in isolation; `serve_once` ignores the request path, so the extra `mirror://`-expansion segment is safe (appending a path segment the way a `mirror://` expansion would: `<mirror_root>/<path>`).
- `fetch_src_uri_resolves_a_real_mirror_uri_via_custommirrors`: a real `${config_root}/etc/portage/mirrors` file (`grabdict()` format, same as `profiles/thirdpartymirrors`) resolves a `mirror://<name>` token via a real local HTTP server, with no `profiles/thirdpartymirrors` entry for that name at all -- proves `custommirrors` is consulted independently, not merely as a fallback when `thirdpartymirrors` has the name.
- `fetch_src_uri_degrades_gracefully_when_config_root_is_the_default_sentinel`: regression for a genuine bug this slice's implementation hit and fixed: `FetchOptions::default()`'s deliberately impossible `config_root` sentinel (`/dev/null/...`) makes `${config_root}/etc/portage/mirrors` fail with `ENOTDIR` (an *ancestor* path component isn't a directory), not the `NotFound` `parse_thirdpartymirrors` tolerates -- an earlier version propagated the sentinel's `ENOTDIR` as a raw I/O error instead of the clean "no working candidate mirror" message.
- `fetch_src_uri_falls_back_to_gentoo_mirrors_when_the_primary_uri_is_unreachable`: the literal `SRC_URI` itself is deliberately unreachable, so the fetch only succeeds because `FetchOptions.gentoo_mirrors` names a real local HTTP server; that mirror has no `layout.conf` (404), so Portage `async_mirror_url` uses the flat `<root>/distfiles/<filename>` path and caches nothing. The literal uses port 1 (immediate "Connection refused" for unprivileged `wget` -- fast and deterministic, unlike a black-holed address that would hang for `wget -t 3 -T 60`'s full multi-minute retry budget).
- `fetch_src_uri_follows_a_mirrors_filename_hash_layout_and_caches_it`: the genuine Gentoo mirrors' layout (`0=filename-hash BLAKE2B 8`, flat path 404s); file fetched from the hashed path Portage computes (`ce/hello-1.0.tar.gz`, `FilenameHashLayout('BLAKE2B', '8').get_path`).
- `fetch_src_uri_checksum_failures_switch_to_primary_uris_then_stop_at_the_cap`: ports `fetch.py:1975-2000`. Three public mirrors serving a corrupt same-size copy, then the file's own (good) literal URI: the second digest failure jumps to the primary URIs ahead of the remaining mirror, so mirror 3 is never contacted; with a cap of 2 (`PORTAGE_FETCH_CHECKSUM_TRY_MIRRORS=2`) nothing after the second failure is tried at all.
- `assemble_candidates_groups_a_files_uris_like_portage_listonly`: expected orders are Portage's own `fetch(OrderedDict({file: uris}), settings, listonly=1)` output (portage 3.0.82.2, `GENTOO_MIRRORS` = one mirror, `gnome` = its single-root `thirdpartymirrors` entry).
- `fetch_src_uri_tries_candidates_in_assembled_order`: closed-port helper (bound then released listener) so `wget` fails fast with "connection refused".
- `fetch_src_uri_uses_a_fresh_mirror_cache_entry_and_refreshes_a_stale_one`: Portage `ts >= time.time() - 86400`: a cache entry younger than a day is used without asking the mirror again; an older one is refreshed (and rewritten with the new time).
- `fetch_src_uri_restrict_mirror_skips_the_gentoo_mirrors_fallback`: `RESTRICT=mirror` (`file_restrict_mirror`, `fetch.py:1117-1127`): the public `GENTOO_MIRRORS` fallback is NOT tried. Identical setup to `fetch_src_uri_falls_back_to_gentoo_mirrors_when_the_primary_uri_is_unreachable` (its "without restrict" counterpart -- there the mirror server rescues the fetch), but with `restrict_mirror: true`: the primary URI is unreachable (`127.0.0.1:1` -> immediate "Connection refused") and the mirror is barred, so the whole fetch fails and the mirror server is never contacted.
- `fetch_src_uri_mirror_prefix_re_permits_the_gentoo_mirrors_fallback_under_restrict_mirror`: Portage `mirror+` SRC_URI prefix (`fetch.py:1103` -> `override_mirror`) re-permits the public `GENTOO_MIRRORS` fallback for this file even under `RESTRICT=mirror`. Same setup as `fetch_src_uri_restrict_mirror_skips_the_gentoo_mirrors_fallback` (unreachable primary URI, `restrict_mirror: true`) but the SRC_URI token has a `mirror+` prefix, so the mirror server IS tried and rescues the fetch.
- `fetch_src_uri_restrict_mirror_still_allows_a_custommirror`: `RESTRICT=mirror` bars only the *public* `GENTOO_MIRRORS` mirror list -- a `mirror://` URI's own `custommirrors` expansion is still tried (Portage keeps `local_mirrors` in `location_lists` regardless, `fetch.py:1125`). Same fixture as `fetch_src_uri_resolves_a_real_mirror_uri_via_custommirrors`, plus `restrict_mirror: true`.
- `fetch_src_uri_copies_a_missing_file_from_an_on_filesystem_mirror`: Portage `fsmirrors` (`fetch.py:1503-1513`): a `/`-rooted `GENTOO_MIRRORS` entry is a local directory the missing file is copied from -- flat (`<dir>/<file>`, Portage `os.path.join`, no `distfiles/`) without a `layout.conf`, per the directory's own `layout.conf` otherwise -- before any download, and even when `RESTRICT=fetch` leaves nothing to download at all.
- `fetch_src_uri_tries_local_fsmirrors_before_gentoo_mirrors_dirs`: Portage order: `custommirrors["local"]` `/` entries before `/`-rooted `GENTOO_MIRRORS`, first mirror that has the file wins, a mirror without it is skipped. The public directory holds a corrupt same-size copy, so only the local one can satisfy the digest.
- `assemble_candidates_orders_plain_uri_after_the_mirror_lists`: Portage `fetch.py:1112-1192` order for a plain URI: local mirrors, public `GENTOO_MIRRORS`, then the literal URI itself last (no `mirror://` expansions, no third-party tail).
- `fetch_src_uri_returns_a_multiply_sourced_file_once`: Portage `A` lists a distfile once however many `SRC_URI` entries name it.
