## D — defects

### D1 — three "predicted equivalent / predicted outcome" entries in S3 are wrong (low, likely)

**Where.** Plan §2 S3, "Predicted, to be checked against the run". Code is `solver_bridge.rs` at the lines that `--list` prints.

**Divergence.** Each entry below gives the mutant, what the plan predicts, and what the source says.

- `2847:12 delete ! in compute_or_overrides` (`if !root_order.contains(&cp)` becomes `if root_order.contains(&cp)`).
  - The plan says it is equivalent ("`walk_add` ignores a second add").
  - That reasoning fits a mutant that drops the check entirely, which cargo-mutants does not generate. The real mutant never pushes anything, so `root_order` is empty and the walk adds nothing.
  - With `walk.added` empty, the fallback arm (`:2524`) makes every branch `early`. That is the order-blind rule, so `s6_compute_or_overrides_ignores_an_alternative_pulled_later` should fail. Expect **caught**.
- `2768:64 delete ! in simulate_walk_order` (`*active && children.is_empty()`).
  - The plan says "probably equivalent".
  - With the mutant, only empty `||` groups form frames, so `walk.resolved` stays empty. Every reached member then falls into the fallback arm, which returns `false`, and nothing qualifies. `…_moves_the_desired_branch_first` should fail. Expect **caught**.
- `+= → *=` is two mutants, not one.
  - `2718:15` in `walk_add`: adds stop advancing the step. Everything added before the first resolve gets step 0, and the first resolve also gets 0, so `0 < 0` is false. Probably **caught** by the desired-branch tests.
  - `2785:22` in `simulate_walk_order`: resolves stop advancing the step, but adds still advance it. "Added before a resolve" still gives `added < resolved`, and "added after" still gives `added >= resolved`. So the relation `:2523` reads is unchanged. Probably **equivalent**. The plan's "all steps become 0" reasoning holds for neither site alone.
  - `2785:22 += → -=` is not a guaranteed underflow: the step is at least the number of roots by then. The plan's "usize underflow panic, so caught" holds only for `2718`.
- The `while` loop (`2751`) has three mutants.
  - `2751:11 delete !` and `2751:29 || → &&` make the loop never run (the stack is non-empty and the disjunction stack is empty at entry). Probably **caught**.
  - Only `2751:32 delete !` (the `disj` operand) spins forever and times out.

**Fix direction.** In S3, replace the prose prediction list with the 41-line `--list` output. Give each line a predicted outcome plus a one-line reason, and correct the three entries above. State that predictions are not binding and that the run decides.

### D2 — the Portage site the plan cites for "Portage keeps `s-1`" is where `want_update` is set, not where it is applied (low, proven by source read)

**Where.** Plan §0.3 bullet 2 and Q1 cite `depgraph.py:3805-3809`. S5 plans to copy "the Portage citations from §0.3" into the code note.

**Portage.** `:3805-3809` assigns `dep.want_update` in `_add_pkg`, after the package was already chosen. Its consumer is the slot-operator probe (`:3118`). The choice that keeps the installed `s-1` is made in `_select_pkg_highest_available_imp`: `if inst_pkg is not None and parent is not None and not self._want_update_pkg(parent, inst_pkg): return inst_pkg` (`depgraph.py:8452-8457`). Under `-e`, the installed candidate is dropped earlier, at `:7859-7865`.

**Impact.** None on behaviour, because the formula is the same in `_want_update_pkg` (`:7330-7334`). The risk is the next reader: the code note would point at a line that does not decide the slot.

**Fix direction.** Cite `:8452-8457` (selection) and `:7304-7334` (`_want_update_pkg`) as the primary sources, and `:7859-7865` for the `empty` arm. Keep `:3805-3809` only as "the same formula, also stored on the dep".

### D3 — "expect no corpus drift" contradicts the precedent (low, likely)

**Where.** S2's last bullet ("Expect none: `pg367-s` is outside `world` and no existing ebuild depends on it") and §3 bullet 3.

**Precedent.** The #34 S2 pmtest commit `f4cbd92` added non-world installed `pg34-*` entries and had to bless two `--pretend --prune` corpus entries. An installed package outside `world` is exactly what `--depclean`/`--prune` list. Q11's installed `pg367-itop` adds a second one, which carries a dep.

**Fix direction.** Expect drift in `--depclean`/`--prune`/`@installed`-style corpus entries. Before blessing, capture Portage's output for those same entries on the new fixture tree, as `f4cbd92` did, and keep the bless in the pmtest commit with the captures cited.

`l0-fixture-oracle.sh` passes each atomlist line to both Portage `emerge` and portuale. A `--solver=pubgrub` line would reach Portage too. So the ad-hoc `l0-fixture-oracle-367.txt` covers only the Portage and portuale-default cells.

The `pg34` precedent Q10 cites was not an atomlist run. It was an ad-hoc `podman run` plus the unmodified `layers/l0-fixture-oracle/stage.sh` on the Portage side, and a host scratch copy on the portuale side (`LLM/evidence/2026-10-14-34-s1/cmd.txt`).

**Closes with:**
- S0 names the stage.sh method for every Portage cell.
- The atomlist becomes optional, used only to add the cells to the recurring oracle run.
- The S4 bed results get a short entry in `../pmtest/differential-test-bed/findings/l0-pubgrub.md`. The plan currently names no findings file.

### G4 — S3 test grounding and one incomplete equivalence criterion

- **Grounding.** New S3 tests that assert a `compute_or_overrides` outcome over synthetic packages assert Portage-observable `||` choices. Each needs a Portage source line or a `ResolverPlayground` capture in its docstring (AGENTS step 4). Direct `simulate_walk_order` step tests are internal and need no oracle; their docstrings should say so.
- **The `2768:61` criterion.** For `&& → ||` at `2768:61`, the plan says to confirm only "that no inactive group's key is ever read". That is not enough. An inactive frame's branch atoms are also `walk_add`ed at frame pop (`:2789-2797`), which can move a taken child's add step earlier. The equivalence argument must cover that too, or the mutant is killable.
