## 2. Critical (blocks parity/correctness)

### C1 — S1 leaf rule suppresses top-level deps
Plan §S1:109-110: `deep==NotRequested && in cpvs && !rebuilding ⇒ empty deps`. Portage always expands a directly-named target even without `--deep`. No seed/top-level exemption, and `rebuilding` is empty until S3/S4, so S1 under-merges an installed named arg's own deps.
Fix: exempt `closure_seeds` CPNs / `req.atoms` targets from the leaf rule, or land S1+S3 together.

### C2 — S4 switch mapping asserted without proof, one arm looks wrong
Plan §S4:142-150: `set_prefer_update(req.update && deep && !empty)` disables prefer-update for `-pvu` without deep, where Portage still updates top-level. `set_prefer_newest_slot(deep || empty)`, `set_selective_no_update(selective && !update)` likewise need grounding in `portage-atom-pubgrub provider/mod.rs:258-305,815-889` + `portage-cli/.../round.rs:254-264`.
Fix: S0 must quote what each setter gates (BDEPEND vs version preference vs `Favor`); do not land S4 on the comment alone.

### C3 — S3 `R` rendering has no plumbing
Plan §S3:131 says `graph_result_from_order` renders `R`, but specifies no signature change. Current code maps same-version-same-slot to `AlreadyInstalled` (`solver_bridge.rs:358-365`). `InstalledSet.rebuilding` must be threaded into `graph_result_from_order` (or post-pass) with slot-aware matching, else S3's `Rebuild` registration is invisible to display.
