## Defects found and fixed in the plan

1. **Major — the S0.2 classifier would have mis-counted the requesters (proven, host data).**
   The rule "atom text inside `||` → `or`, else `plain`" had no answer for the common shape where
   the same text occurs twice: botan's `BDEPEND` has `python_targets_python3_15? ( dev-lang/python:3.15 )`
   **and** `|| ( ( dev-lang/python:3.15 … ) … )`. Dozens of update-plan entries (pygobject, pyscard,
   qemu, zfs, pip, …) carry a `python_targets_python3_15?` conditional that is **off** on this host
   (`portageq envvar PYTHON_TARGETS` = `python3_14`); the old rule called them `plain` and would
   have pushed the verdict towards "python 3.15 enters through a non-`||` atom". Fixed: per
   occurrence, `off` / `or` / `plain` by enclosing groups and the requester's USE (plan entry `use`
   or VDB `USE`), with a stated aggregation rule; slotless atoms narrowed to 3.15 included.
2. **Medium — charter framing of Q1 (A) was wrong.** The plan said (A) "follows charter property 3
   (newest slot the constraints allow)". Property 3 (`docs/charter.md:58-59`) is per package
   version; `python:3.14` ends at its best visible version under both answers, and property 3 does
   not ask for a slot nothing requires. Rewritten: the charter is silent, the owner decides; (A)
   wins on "prefer changes that remove code" and on agreement with the two other planners.
3. **Medium — hidden scope not named.** `branch_preference` is also the `||` callback of
   `rebuild::reduced_recorded_atoms` (`crates/portage-world/src/rebuild.rs:91-115`, call at
   `:107`), i.e. the fast plan's reading of **recorded** VDB `||` groups for stale slot-operator
   bindings — the side plan 02.793 compares against. Added to Q1 (B), §5 and §7 (re-run
   `test_plan_world.py -k 766` after rebase if both ship).
