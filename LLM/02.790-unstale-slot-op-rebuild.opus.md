### 0.2 Suspected cause (read, not traced; S0.2 traces it)

1. Pass 1 upgrades `p569prov`; the stale-pin arm (`stale_pin_for_consumer`,
   `crates/portage-repo/src/slot_operator/rebuild_scan.rs:694-770`) finds no recorded pin
   (`held_back`, `:513-546`) and schedules `p573virt` (`replacement_accepts` drops the tree's
   `=…5.42*` because it matches the installed 5.42, `LLM/02.773-….opus.md` §0 cause 1).
2. The next pass walks `p573virt` as a node; its tree pin conflicts with 5.44 and the upgrade is
   skipped (the WARNING).
3. The rebuild is never removed. The two places that could remove it are in
   `step_unsatisfied_dead_end` (`crates/portage-repo/src/resolve/feedback/unsatisfied_dead_end.rs`):
   the `prune_rebuilds` restart (`:115-143`, `apply_prune_rebuilds`, `slot_operator/bind.rs:192-210`,
   clears the replace set once) and `slot_operator_eliminate_rebuilds`
   (`crates/portage-repo/src/slot_operator/eliminate.rs:37-194`, called at `:145-172`).
   Rule 8 of the latter (`eliminate.rs:130-190`) keeps a rebuild whose installed dependency atoms
   differ from the tree's atoms bound to the graph: installed `{dev-libs/p569prov:0/5.42=}`
   against tree `{=dev-libs/p569prov-5.42*, dev-libs/p569prov:0/5.42=}` → not equal → kept.
   That matches `a10pin`, where the two texts are equal and nothing is rebuilt.

Which of `prune_rebuilds`, the slot-conflict path (`feedback/slot_conflict_backtrack.rs:81-132`)
or rule 8 actually keeps `p573virt` is **not known**; S1 is written for rule 8 and STOPs otherwise.

### 0.3 What the rebuild does, and what it changes next time

The rebuild repairs no binding (the provider stays at 5.42). It does re-record the tree's
dependencies, so after it the VDB holds `a10pin`'s text. On `a10pin` every planner then
**upgrades** `p569prov` and leaves `p573virt-1` with a runtime dependency `=dev-libs/p569prov-5.42*`
no installed version meets (it is named in the NOTE, not repaired). So the `rR` is not inert: it
flips the next `-uDN @world` from "hold the provider" to "upgrade it and name the consumer". This
asymmetry between `a10` and `a10pin` is a separate question (§6, residue #823) but the owner should
see it before answering Q1.

```rust
/// Whether the installed `cp-version` records at least one `:slot/sub=`
/// atom, and every such atom names a sub-slot the plan leaves in place: the
/// graph's entry in that slot if there is one, else the installed instance.
fn bindings_hold(root: &Path, cp: &(String, String), version: &str, entries: &[GraphEntry]) -> bool {
    let mut seen = false;
    for key in ["BDEPEND", "DEPEND", "IDEPEND", "PDEPEND", "RDEPEND"] {
        for tok in read_vdb_string(root, &cp.0, &cp.1, version, key).split_whitespace() {
            let Some(atom) = parse_dep_atom(tok, "eliminate_bindings") else { continue };
            let (Some(slot), Some(sub)) = (atom.slot.as_deref(), atom.sub_slot.as_deref()) else { continue };
            if atom.slot_operator != Some(portage_dep::SlotOperator::Equals) {
                continue;
            }
            seen = true;
            let planned = entries.iter().find(|e| {
                e.category == atom.category && e.package == atom.package && e.slot.as_deref() == Some(slot)
            });
            let final_sub = match planned {
                Some(e) => e.sub_slot.clone(),
                None => all_installed_packages(root)
                    .iter()
                    .find(|p| p.category == atom.category && p.package == atom.package
                        && p.slot.split('/').next() == Some(slot))
                    .map(|p| p.slot.split_once('/').map_or(p.slot.clone(), |(_, s)| s.to_string())),
            };
            if final_sub.as_deref() != Some(sub) {
                return false;
            }
        }
    }
    seen
}
```
