## D — defects

### D1 — S2's `too_deep` formula is off by one (high, proven)

**Where.** Plan §2 S2: "`too_deep` is `Deep::recurses_at` negated". Code: `queue.rs:26-32`. `recurses_at(d)` is `false` for `NotRequested`, `true` for `Unlimited`, and `d < n` for `Bounded(n)`. That makes it `!_too_deep(d + 1)`, by its own comment (`:25`).

**Portage.** `_too_deep(depth)` is `depth > deep`, with `deep` defaulting to 0 (`depgraph.py:7359-7375`). `_want_update_pkg` applies it to the child depth, which is reset to 0 for an argument match (`:7318-7333`).

**Divergence.**
- `-pvu --deep=1 dev-libs/pg34-dtop`: `dlib` is at depth 1. Portage evaluates `_too_deep(1)` = `1 > 1` = false, so it updates. `portage/362-dtop-pvu-deep1.txt` prints `U pg34-dlib-2`.
- The plan's formula gives `!recurses_at(1)` = `!(1 < 1)` = true, so it does not update, and the control would regress.
- With no `--deep`, `!recurses_at(0)` is true even at depth 0, so a set member reset to depth 0 (for example `-pu @world`) would never update. That breaks the §3 risk-2 requirement.

**Fix direction.** Define `too_deep(d)` directly:
- `NotRequested => d > 0`
- `Unlimited => false`
- `Bounded(n) => d > n`

Add a unit test with `--deep=1` at depth 1 and a set member at depth 0.

### D2 — the `uapp -pvN` / `-pvuN` cells are explained by `_ignore_dependency`, not by the `:8445` return (medium, likely: discriminating source read, no `--debug` capture yet)

**Where.** Plan §0.2.1 says the `:8445` return fires "before any update, `--newuse` or visibility logic". §0.2.2 says this covers `uapp -pvN`. §0.2.3 says `_ignore_dependency` "does not fire" in any #362 cell.

**Portage.** In `_wrapped_select_pkg_highest_available_imp`, the ebuild db is walked before the vardb (`:809-825`).
1. The `ulib-1` ebuild matches an installed cpv. Under `--newuse`, `_reinstall_for_flags` sees the USE drift (`x`) and sets `reinstall = True` (`:8311-8329`).
2. When the vardb is reached, `want_reinstall` is true and `matched_packages` is non-empty, so the installed db is skipped (`:7860-7864`).
3. `inst_pkg` is therefore `None` at `:8436-8440`, and the `:8445` return cannot fire.
4. The ebuild child is selected. The dep is then dropped by `_ignore_dependency` (`:4423-4462`, call `:4583-4603`): the priority is satisfied by the visible installed `ulib-1`, `recurse_satisfied` is false, the child is not installed, and the tracker holds no non-installed package in that slot.

**Divergence.**

- Mechanism: different, and the difference shows elsewhere. Portage keeps the reinstall when the installed instance is **not visible** (`mypriority.satisfied.visible`), and it drops the edge entirely (`dep.child = None`, `_ignored_deps`) instead of keeping an installed node. **Fix direction.**
