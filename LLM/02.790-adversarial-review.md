### D1 (critical, proven) — the S3 rule leaves a stale binding unrepaired and unreported on `a10`

- Where: plan S3 (`bindings_hold`, inserted before `// Rule 8.` in
  `crates/portage-repo/src/slot_operator/eliminate.rs:130`).
- Proof: S3 applied to a scratch copy of `219a5653`, built, `probe.sh` on `a10`/`a10pin`.
  Default solver on `a10`, `emerge --pretend --verbose --update --deep --newuse --getbinpkg=n @world`:

  ```
  t790 demote-new ("dev-libs", "p573virt")
  t790 demote-new ("dev-libs", "p573virt")
  [ebuild     U  ] dev-libs/p569prov-5.44 [5.42] to /var/tmp/790rev/roots/a10
  NOTE: One or more installed packages keep a stale slot-operator binding that was not rebuilt:
    dev-libs/p569virt-1: its dependency =dev-libs/p569prov-5.42* is not satisfied by dev-libs/p569prov-5.44
  ```

  Before the rule (main binary, same probe): `[ebuild  rR    ] dev-libs/p573virt-1` plus the skip
  WARNING, no `p569prov` row — exactly the plan's §0.1 table.
- Shape: the provider is held today only because the rebuild is a walked node carrying the tree pin
  `=dev-libs/p569prov-5.42*`. Demoting it latches `p573virt` in `slot_operator_undone`
  (`unsatisfied_dead_end.rs:166-168`); the restarted pass walks the installed record (no pin),
  upgrades the provider, and the latch makes the rebuild scan skip `p573virt` entirely
  (`rebuild_scan.rs:226`), so its `:0/5.42=` binding is stale and not even named. Charter
  properties 1 and 5 both regress. Portage's `_eliminate_rebuilds` (`_emerge/depgraph.py:3874`)
  re-adds the installed instance in place without a re-walk; portuale's restart is why the
  "binding still holds" premise does not survive the demotion.
- Fix direction: do not demote here. If the owner wants the `rR` gone, hold the provider instead
  (option (D) added to Q1: the default solver withholds the upgrade the way pubgrub's
  `tree_refusal_fix`, `solver_bridge.rs:6018`, does since #791), so the rebuild is never scheduled.
  Needs its own plan.
- Changed in the plan: Status header, new §0.5, (B) marked REJECTED, (D) added, S0.3 routing,
  S1-S3 blocked behind STOP-0, STOP-0 widened.

the behaviour"), which leaves a judgment call to a Sonnet executor. Fixed in place:
