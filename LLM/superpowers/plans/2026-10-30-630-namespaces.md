# #630 — Raw-namespace unshare in demoted spawns Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Status:** done 2026-10-30 (backlog #630; branch `slice/630-namespaces` in both repos — portuale `3442b48d`..`5dd9717b`, pmtest clean with no commit, no pretend-output change; residues #635/#636/#637)

**Goal:** Demoted phases keep Portage's `net`/`ipc`/`mount`/`pid` namespaces by unsharing raw (no userns) in `pre_exec` while still root, then demoting in the same child — so `network-sandbox` blocks egress for `portage:portage` phases exactly like Portage.

**Architecture:** `phase_isolation` stops zeroing wrappers when demoted — except `pid`, which stays dropped for demoted phases (CLONE_NEWPID without a PID-1 re-exec is fatal: the first fork becomes init, its exit tears the ns down, later forks fail ENOMEM — proven in Task 2; full re-exec restoration is a close-out residue). No `--map-root-user` exists any more — the child is root at `pre_exec`, so no uid mapping is needed, exactly Portage `_exec`); the demoted spawn bypasses the `unshare(1)` shim (which would demote the wrapper instead of the phase) and performs `libc::unshare` + mount-propagation setup + `sethostname` + the existing id demotion inside its own `pre_exec`, with no subprocesses, no `/proc` remount, and no lo configuration there (each omission is a documented divergence with a close-out residue). Pure flag mapping stays unit-testable without root. Namespace setup is `#[cfg(target_os = "linux")]`-gated: on platforms without namespace APIs (BSDs and other non-Linux Unixes) demoted spawns skip the unshare block and run demoted-without-namespaces — today's behavior — and never fail for missing APIs.

**Tech Stack:** Rust 2024 (`crates/portuale`), Portage 3.0.83 (`3rdparty/portage`), host `unshare(1)`/`ip`/`sh` (already relied on by the shim), pmtest contract suite (`../pmtest`).

**Spec:** `LLM/backlog-tasks.md` #630, argued from `3rdparty/portage/lib/portage/process.py:1061-1109` (`libc.unshare` with no `CLONE_NEWUSER`, validated first, warn-degrade), `:1111-1145` (pid re-exec via `pid-ns-init`), `lib/portage/package/ebuild/doebuild.py:2233-2240` (`free = droppriv and not usersandbox`), and `LLM/evidence/2026-10-30-627/hyperfine-acceptance.log` (the green run this slice must not regress).

## Global Constraints

- **Expected behaviour comes from Portage, never a second portuale run.** Cite `3rdparty/portage` `file:line` in every code note (repo `// Portage:` convention: bare names).
- **Demote exactly Portage's phases under exactly Portage's gate** (unchanged from #627 — this slice touches neither).
- **No userns anywhere in the demoted path.** The raw `unshare(2)` takes no `CLONE_NEWUSER`; the `unshare(1)` shim (which exists to give non-root a userns) is never on the demoted path. Non-root unshare keeps the #629 `--map-root-user` shim untouched.
- **`pre_exec` setup failures: `unshare` itself fails the spawn loudly on Linux after successful upfront validation** (existing precedent; deliberately differs from Portage's warn-and-run-unisolated degrade at `process.py:1097-1109` — one comment line, rationale: post-validation failure is TOCTOU-only, and a silently unisolated `network-sandbox` phase is worse than a loud failure). Mount-propagation failure is **ignored with continuation** (mirrors Portage's warn-only `--make-rslave` at `:1215-1225`, minus the warning, which `pre_exec` cannot print); `sethostname` result is ignored (benign either way). No `Err` exists for any step Portage treats as non-fatal.
- **Portability: namespace setup is Linux-only and best-effort at the platform level.** `clone_flags_for`, the `CLONE_*` references, and the unshare/mount/lo block in `pre_exec` are `#[cfg(target_os = "linux")]`-gated (repo `cfg` precedent is `#[cfg(unix)]`; Linux-only APIs need the narrower gate). On non-Linux targets the demoted spawn demotes exactly as today, with no namespace calls to fail. At runtime on Linux, when upfront validation already dropped the wrappers (unusable combo), the degraded `Isolation` yields flags `0` and `pre_exec` skips the `unshare` syscall — degrade, never fail, for genuinely unavailable namespaces.
- **No printing inside `pre_exec`** (stdio locks in a multithreaded parent's forked child). Warnings live in the parent (validation path) or not at all.
- **Degradation is always user-visible, from the parent only.** Whenever requested namespace wrappers are dropped as unusable — failed `unshare` validation on Linux, or no namespace APIs on the platform at all (the `unshare(1)` probe fails where the tool doesn't exist, so the existing degrade path fires unmodified) — `phase_isolation` warns once per process. The message names the FEATURES, the phase, and — when demoted — states the phase still demotes to `portage:portage` (DAC confinement remains, namespace confinement doesn't). Message text lives in a pure `unshare_degrade_message(features, phase, demoted)` so it is unit-testable without namespaces.
- **Corpus untouched** (no pretend-output change). New backlog numbers start at **635**.
- **Root-gated tests run via `sudo <test-binary> <filter>`** (image rebuild is an owner step); skip cleanly when `euid != 0` or the `portage` user is unresolvable.

Localhost-dependent tests under `network-sandbox` fail; the guaranteed property (no default route, egress blocked) is what Task 2 pins, and lo robustness is filed as a residue at close-out.
