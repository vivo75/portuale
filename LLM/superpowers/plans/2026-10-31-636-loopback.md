**Status:** done 2026-11-01 (backlog #636; branch `slice/636-loopback` in both repos — portuale `df585d7b`, `086de529`, `8b883d5c` + this docs-only close-out; pmtest clean, no commit, no pretend-output change)

**Goal:** A demoted `network-sandbox` phase gets a working loopback (lo up + `10.0.0.1/8`, plus `fd::1/8` where IPv6 works) via raw netlink inside `pre_exec`, so localhost-dependent phases succeed like Portage instead of failing on a down `lo`.

**Architecture:** Pure stack-buffer netlink message builders in `sandbox.rs` mirror Portage's `util/netlink.py` byte-for-byte; a `#[cfg(target_os = "linux")]` sender in `commands.rs` runs them over a netlink socket inside the demoted `pre_exec` (after `unshare`, still root, before the pid fork) — no subprocess, no allocation, best-effort like Portage's warn-only path. The IPv6 probe (Portage `has_ipv6`) runs in the parent and rides into the closure as a bool.

**Tech Stack:** Rust 2024 (`crates/portuale`), Portage 3.0.83 (`3rdparty/portage`), pmtest contract suite (`../pmtest`).

**Spec:** `LLM/backlog-tasks.md` #636, argued from `3rdparty/portage/lib/portage/process.py:838-871` (`_configure_loopback_interface`: `get_link_ifindex(b"lo")` → `set_link_up` → `add_address(10.0.0.1/8)` → `add_address(fd::1/8)` iff `has_ipv6()`), `lib/portage/process.py:808-835` (`has_ipv6`: bind `::1` UDP probe), `lib/portage/util/netlink.py:18-28,94-114` (constants + the three requests), and `LLM/evidence/2026-10-30-630/s0-lo-state.log` (`lo` down in a raw netns).

## Global Constraints

- **Expected behaviour comes from Portage, never a second portuale run.** Cite `3rdparty/portage` `file:line` in every code note (repo `// Portage:` convention: bare names).
- **Demote exactly Portage's phases under exactly Portage's gate** (unchanged — this slice touches neither).
- **Loopback setup is best-effort, never fatal.** Portage warns and continues (`process.py:868-871`); the shim ignores errors (`2>/dev/null`). In `pre_exec` there is no printing, so: any netlink failure → continue silently to demotion. No `Err` path is added.
- **No subprocess, no allocation, no printing in `pre_exec`** (inherited #630/#635 rule). Messages are fixed-size stack arrays; the socket syscalls (`socket`/`send`/`recv`/`close`) are POSIX async-signal-safe; `// SAFETY:` on every unsafe block.
- **Linux-only.** Builders, sender, and the `pre_exec` call are `#[cfg(target_os = "linux")]`-gated (with the #630 non-Linux stub discipline); other targets demote exactly as today. `has_ipv6` probe is cross-platform parent code.
- **Corpus untouched** (no pretend-output change). New backlog numbers start at **638**.
- **Root-gated tests run via `sudo <test-binary> <filter>`** (image rebuild is an owner step); skip cleanly when `euid != 0` or the `portage` user is unresolvable.

## Review Focus

- The pid+net combination still works: lo setup runs once before the pid fork (shared netns), so the grandchild inherits it — pinned by Task 1's combined pid+net spawn asserting the connect inside PID 1.
- IPv6-less hosts skip `fd::1/8` without failing (parent probe false → v6 message never sent) — pinned by the builder/probe unit tests; the v6 connect itself is not asserted (host-dependent).
