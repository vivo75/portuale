## Review Focus

- A cargo-network failure must be classified as fetch/env, not as a resolver or merge defect — the `SRC_URI` vendor tarball plus `CARGO_CRATE_URIS` means a missing proxy/mirror looks like a build error one screen down.
- `PORTAGE_TMPDIR` differs by scope (`/var/tmp` run-wide vs `/var/tmp2` per `package.env/tmpfs_on_disk`): a `/var/tmp2`-only success is a config-layering finding, not a phase fix.
- `src_test` (`cargo_src_test`, `CLICOLOR_FORCE=`) is the prime suspect for a Portage-green/portuale-red split — a second Portage run with `FEATURES=-test` decides it before any code is touched.
- The `src_install` completion helpers (`newbashcomp`/`dozshcomp`/`dofishcomp` over `find $(cargo_target_dir)`) depend on the exact `cargo_target_dir`; a wrong target dir fails only at install time.
- `QA_FLAGS_IGNORED="usr/bin/hyperfine"` plus `sed -i '/strip =/d' Cargo.toml` in `src_prepare`: a QA/strip-phase failure is an `install_qa_check`/`dostrip` parity issue, not a cargo issue — check the QA gate before the compiler flags.
