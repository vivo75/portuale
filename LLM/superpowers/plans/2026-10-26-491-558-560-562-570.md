## Execution Protocol (opencode manager + subagents)

The manager is the opencode session's top-level LLM. It does not write product code; it briefs, reviews, verifies and commits.

**Branch.** One paired branch for the whole batch, opened before Task 1 in both repos from their current `main`: `git checkout -b batch/2026-10-26-491-570` in `portuale` *and* `../pmtest`. Every slice commits on it; the per-task branch names below are superseded. Leave both `main`s alone.

**Order.** 1 → 2 → 3 → 6 → 5 → 4 → 7 → 8 → 9 → 11a → 10 → 11 → 12. Task 6 (resolver change since the owner ruled it in) and Task 5 run before Task 4 so one bed re-grade covers Tasks 2, 3 and 6. Task 11a (fixture categories) precedes Task 10 because Task 10's filter makes Portage depend on those files. Cluster R (2, 3, 4) and Cluster M (7, 8) touch disjoint files but share `target/` and the pmtest corpus: run implementers **one at a time**, never two writers in parallel.

**Per slice, the manager:**
1. Writes the implementer brief: task text verbatim, the files to touch, the oracle to use, the exact RED/GREEN commands, and the line *"Do the work yourself. Do not start sub-agents or tasks."* (opencode sub-agents run inside `opencode serve` and outlive their parent). Dispatch it with opencode's own subagent mechanism; check in the subagent's log which model actually ran (agent-file `model:` lines have been ignored before — if the manager instead shells out to `opencode run`, pass `--model` explicitly and wrap it in `LLM/tools/scope/oc.sh`). Never `pkill`. Space parallel launches ≥60 s (only read-only oracle/analysis workers may run in parallel with an implementer). No Claude Code tools or agent types are available.
2. Waits until the worker exits **and** its files stop changing; then reviews the diff itself against the task's Review Focus and the Global Constraints (oracle cited in the test docstring, real-md5 cache entries, short comments + code-notes, no unrelated churn). Sends fix-ups back to a fresh worker, not the same files under a live one.
3. Runs the full gate itself: `cargo fmt --check`, `cargo clippy --release --all-targets` (0 warnings), `cargo test --release` (workspace), then in `../pmtest` `scripts/pytest-parallel.sh`. Failures are compared **by test name** against the pre-batch baseline (record one before Task 2: same commands on clean `main`); `git clean -fdq fixtures/` in pmtest if order-dependent fixture pollution shows up. Corpus drift is read line by line before any `PORTUALE_CORPUS_BLESS=1`; unexplained drift blocks the commit.
4. Commits: pmtest half first (fixtures, pins, bless, bed yaml/logs), then portuale (code, unit tests, `LLM/` docs, code-notes index), the portuale message quoting the pmtest short SHA and the pmtest message naming the branch + task. One-sided slices say "standalone, no pmtest half" (or vice versa). Messages: plain English title `<area>: <what changed> (#NNN)`, body with the why and the Portage source, trailers `Co-Authored-By: <model> <noreply@…>` for the implementing model and for the manager model (actual names).
5. Updates the docs in the same commit: backlog entry (narrow / DONE with date, branch, and *this* commit's sibling SHA once known — amend nothing; cite SHAs in the next slice's commit if needed), one appended `LLM/what-this-proves.md` paragraph for any slice that changes behaviour.

**Owner rulings already given (2026-10-25):** single batch branch, no merge, no push; Task 7 mirrors Portage (both roots); Task 6 is implemented (diagnostics parity, failure paths matter too); Task 10 implements Portage's repos.conf merge behind the suite filter; Task 11a adds `profiles/categories` to the fixtures.

**Owner gates (any new question).** The owner may not be present. At a gate the manager writes the analysis plus a crisp question with a recommended answer to `LLM/evidence/<dir>/OWNER-QUESTION.md`, commits it (docs-only, standalone), and **moves on to the next task** — it never implements on a guessed ruling. The final report lists every open gate.

**Bed runs (Tasks 4, 6, 7).** Copy the binary first and run frozen so cargo stays usable: `cp -p target/release/portuale /var/tmp/bedbin/portuale`, then `PMTEST_PM=portuale-bed PMTEST_NO_BUILD=1 differential-test-bed/run/<runner>.sh` from `../pmtest`. Fetching runs need `GENTOO_MIRRORS=http://$(ip -j -4 -o addr show eth0 | jq -r .[0].addr_info[0].local):8080`.

**Stop conditions.** Stop the batch (commit nothing further, report) if: a keeper pin (#54 K3, #222, #223, #35 R4) goes red and one fix round does not restore it; a non-target bed probe moves; the merge gate fails; or corpus drift cannot be explained. Clean `/var/tmp` of the batch's leftovers at the end.

Either way the output depends on the machine, not on the fixtures.

**The filter (verified feasible 2026-10-25).** Two options, both keep the suite deterministic:
1. *Mount-namespace wrapper (recommended).* Run each PM invocation as `unshare -r --mount sh -c 'mount --bind <fixture-global-repos.conf> /usr/share/portage/config/repos.conf && exec unshare --user --map-user=$UID --map-group=$GID -- "$@"'` — the outer userns may mount, the nested one restores the real uid, so the privilege gate and file ownership behave as today (tested here: uid 1000 inside, created files owned by `vivo`, bind mount visible). The fixture global file contains only comments (or a `[DEFAULT]`), so neither Portage nor portuale sees the host `gentoo`. Every on-disk `repos.conf` test keeps exercising the real file-reading path. Notes: the plain `unshare --map-current-user` + mount fails in this LXC (EPERM), hence the nesting; files owned by other uids show as `nobody` inside (irrelevant for a non-root suite); if user namespaces are unavailable the conftest must fail loudly, not run unfiltered. Also bind over the file only when it exists on the host.
   *Concurrency (owner asked to keep this in mind, 2026-10-25):* the bind mount lives in a private mount namespace per invocation (propagation `private` inside), so parallel workers do not see each other's mounts — verified with 4 concurrent filtered processes while the host kept reading the real 20-line file. `scripts/pytest-parallel.sh` therefore stays parallel. Still serial-only: any test that needs `sudo` or real root (`sudo` does not work inside the user namespace) — mark such tests to bypass the filter and run them in a separate serial pass; the filter's self-test must include a concurrent case.
2. *`PORTAGE_REPOSITORIES` (what the L0 fixture-oracle bed does, `in-container.sh:104-107`).* The conftest sets it to the test's repos.conf text with absolute locations. Simpler, but ~130 suite lines that write their own `repos.conf` would stop exercising portuale's on-disk parsing unless each re-derives the variable — keep it as the fallback where namespaces are unavailable.
