**Goal:** make the bed cell `MULTI_deep-update-world` match Portage on three
things: the `r` flag on `dev-lang/perl-5.44.0`, the `The following packages are
causing rebuilds:` block, and the merge order (first divergence at #10).

**Architecture (verified against `3rdparty/portage` 3.0.83 and this tree,
2026-10-28):** Portage marks a merge row `r` when a force-reinstall internal set
arg matches it (`lib/_emerge/resolver/output.py:812-816`, via
`_iter_atoms_for_pkg`, `depgraph.py:4988`). The set args are built by
`_gen_reinstall_sets` (`depgraph.py:5473-5497`) as
`__auto_reinstall__` / `__auto_slot_operator_replace_installed__` with
`force_reinstall=True`, and reach `_initial_arg_list`. The rebuild block is
`_show_abi_rebuild_info` (`depgraph.py:1146-1159`) over `_forced_rebuilds`,
filled by `_compute_abi_rebuild_info` (`depgraph.py:931-1145`), which seeds
**from those same force-reinstall args** (`depgraph.py:940-950`). So the `r`
flag and the block do share one seed in Portage. Task 0b measured portuale's
gap: the seed is never filed (§0).

Portuale splits what Portage keeps in one set, and this split is the whole
difficulty:

| field | what it is | read by |
|---|---|---|
| `slot_operator_replace_installed` (`backtrack_params.rs:361-364`) | the rebuild set; also the display scan's `already` input (`assemble.rs:38`) | `PORTUALE_BT_TRACE` (`feedback/mod.rs:158-169`) |
| `probe_replaced` (`backtrack_params.rs:367-370`) | the members the built-parent update probe filed; the display mirror of the probe's filings | `assemble.rs:295` → `result.slot_operator_replaced` → `pretend/mod.rs:495` |
| `result.abi_rebuilds` | the `(provider_cpv, consumer_cpv)` block pairs | `final_gates.rs:41-96`; **and both sides tag `r`**, `pretend/mod.rs:486,866-905` |

Measured in Task 0b (see §0): the `r` column is the **union** of
`abi_rebuild_force_reinstall_cps(result)` (both sides of every pair),
`rebuild_if_reinstalls` and `slot_operator_replaced`
(`pretend/mod.rs:486,492,495`). The control prints `r` with
`slot_operator_replaced` empty, so when a pair exists the pair list is the `r`
source; `probe_replaced` alone is not.

The block pairs are computed post-walk by `slot_operator_rebuild_scan`
(`slot_operator/rebuild_scan.rs`), assembled in `resolve/assemble.rs:18-66`
plus `slot_conflict_abi_display_pairs` (`:54-60`). The probe's child filing
exists at `installed_parent_update_probe.rs:189-190` (gated on
`child_has_slot_update`); `:119-121` is the unrelated `arg_pins_installed` gate.

### Task 0b verdict (measured 2026-10-28, `LLM/evidence/2026-10-28-601/discriminator.md`)

The instrument (all trace-only, `PORTUALE_BT_TRACE=1`; `--debug` stdout
untouched) now prints `probe_replaced`, the pass's pair stash, the
`assemble_result` counters, every `drop_masked_pairs` decision, and the two
post-assemble display fields. Measured:

- `probe_replaced` is **empty on all 26 cell tries and on the green control**
  — no installed parent or child is ever filed. Candidate 2 holds.
- The settling scan **does** produce 34 pairs, all provider
  `dev-lang/perl-5.44.0`. Candidates 1/3/4 are falsified as stated (the scan
  was not starved, `prune_rebuilds` is false on every try, the `||` edges are
  accepted).
- The pairs then die in `drop_masked_pairs`: perl is masked-installed
  (`!=dev-lang/perl-5.42.2[installed]`, `resolve/backtracker.rs:214-228`) and
  is not in the replace set, so all 68 (34 scan + 34 continuity) are dropped
  (`kept=0`, 136 `BT-DROP` lines, all `provider_off=true`). `drop_masked_pairs`
  is correct given its precondition; the missing filing is the bug.
- Control: `probe_replaced` empty yet `r` prints, because `r` also reads the
  pair list (§Architecture) — so the pair list is the `r` source once a pair
  exists.
- **Second, independent gap:** with the filing fixed, portuale would print a
  34-row block where Portage prints **48** (capture:
  `captures/task0b-cell-portage-block.txt`). The scan skips consumers that are
  `in_graph && !already` (`rebuild_scan.rs:158`), i.e. the 14 consumers that
  are upgrading in the same run. Block parity needs this closed too.
