### 0.3 #357 — accurate, scope is ~18 call sites in 4 crates plus the derived DB tables

Portage parses each line with `_contents_re` (`vartree.py:1951-1958`): `obj (.+) (\S+) (\d+)`, `sym (.+) -> (.+) (\d+)` (greedy, so the split is at the **last** ` -> `), and `(dev|dir|fif) (.+)`. A non-matching line is reported and skipped (`:2250-2253`). Paths get `normalize_path` when they look unnormalized (`:2278-2282`). Portage writes the path raw (`write_contents`, `:6500-6516`) and refuses to merge a path containing `\n`/`\r` (`:4627-4710`, "package … NOT merged").

Call sites that split a `CONTENTS` line on whitespace (grep 2026-10-15; the executor re-greps):
- `portage-vdb`: `files.rs:315` (`claim_paths`, every backend's `owners`), `sqlite/write.rs:650` (`derive_owner`), `redb_db/write.rs:882` (owner derivation).
- `portage-repo`: `installed.rs:150` (`installed_contents_files`, which `mrg_director::VdbReader::contents_files` and `owns_path` use).
- `portuale`: `ebuild_unmerge.rs:35` (`parse_contents`) and `:534` (`being_unmerged`); `ebuild_merge/installed_instance.rs:162,171,204`; `plib_merge.rs:67,256,298,306`; `plib_unmerge.rs:84`; `after_install.rs:179`; `from_binpkg.rs:345`; `ebuild_package.rs:1431` (quickpkg from vdb); `remote/binpkg_flow.rs:30` (`contents_owned_paths`).
- Deliberately **not** in scope: `files_write.rs:155` (config memory): Portage reads `_conf_mem_file` with `grabdict` (`vartree.py:2909`) and writes it with `writedict` (`portage/util/__init__.py:682-692`), both whitespace-split, so spaces break there in Portage too. `remote/binpkg_flow.rs:90` parses FILEMETA, which is whitespace-free by construction (its doc says so).
- pmtest: `differential-test-bed/layers/l1/consume.sh:234` (`awk … {print $2}`) has the same bug in the bed (S1 fixes it).

`portage-vdb` is the right home for one shared parser: `portage-repo` and `portuale` both depend on it, and `mrg-director` reaches it through `portage-repo`.

### 0.4 #358 — accurate

`consume.sh:224-242` builds `paths.txt` only from the **post-merge** `CONTENTS` of `merged-cpvs` (`:229-235`). A file that one PM deletes and the other keeps is in neither list, so `diff.py`'s `MISSING` class (`compare/diff.py:12,93-95`, a HARD category) never sees it. The reinstall gate re-merges the same binpkg images, so nothing is dropped anyway. Two facts make a differing-image reinstall cheap:
- Portage applies the **merge-time** `INSTALL_MASK` to a binary package (`treewalk` runs `preinst_mask`, `vartree.py:4580-4605`; `misc-functions.sh:371-391` writes it to `build-info/INSTALL_MASK`).
- `consume.sh:56-66` shows portuale honours a `make.conf` `INSTALL_MASK` on a `--getbinpkg` merge.

So reinstalling glibc/bash with `INSTALL_MASK="/usr/share/doc /usr/share/info /usr/share/man"` makes **both PMs delete real files on a live system** (documentation only: harmless), using the existing gate atom list.
