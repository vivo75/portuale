## 2. Critical (readability net-negative as specified)

### C1 — `ControlFlow` threading mandated where plain returns suffice
Method rule (§0.4.2, plan:35) routes every `continue`/`continue 'label`/early `return` through `ControlFlow`, and R5/R6/R7/R8 all specify `--loop` even for straight-line rung/phase blocks. `extract_block.py:379-392` then emits `if f(..).is_break(){continue}` / `let Continue(out)=...else{continue}` at every call site, plus `ControlFlow<Ret,Out>` / `ControlFlow<(),Out>` returns (`ret_type`, :338-354). For R5's five rung cuts (132–199, 201–249, 252–301, 319–384) most are pure selection computations with no host-loop `continue` in-range; forcing loop-mode is pure noise. `flatten_flow.py` only rescues the tail-call case (:24-26 asserts call ends loop body).
Fix: default to non-loop extraction returning `Option`/`(bool, Out)`; allow `--loop` only when range provably contains a host-targeted `continue`/`return`, and run `flatten_flow.py` unconditionally after. Rewrite R5/R8/R9 cuts accordingly.

### C2 — Loop-body extractions fragment single algorithms across 2–3 call levels
R7 (`for pb` 266 → `for m` 172 → `unsolvable` 56, plan:205-210), R8 (consumer 196 → dep_key 159 → atom_str 134; plan admits `constraints_from_consumer` will still be >150 and needs a second split), R6 (244 loop → `solve_one_conflict` → inner 100 → `pair_instance_with_others` with 73-line inner loop), R9 (189-line `if` → `scan_slot_moves` → split halves again). Each level shares `&mut` maps/sets via auto-inferred `>5`-param `*Args` structs (`extract_block.py:361-366,448-459`). The reader must chase `Args` + `Out` + `ControlFlow` across files to follow one loop. Line-count wins, not responsibility cuts.
Fix: per-cut coherence contract in the `///` doc (inputs/outputs/continue-protocol); at most one loop-level per slice; innermost pure predicates first.

### C3 — Auto-inferred `*Args`/`*Ctx` structs violate minimal param lists
`extract_block.py:32-35,358-359`: `>5 params → <Fname>Args struct`, types/modes from compiler errors (E0308/E0594/E0382). R2 (38 statements, 7 cuts), R8 (14-field `ReverseDependencyConstraintsArgs` already), D1 (`PrintEntryLineArgs` 20+ fields), R11/D4/R7 closure→`Ctx` conversions will all produce 6–12-field structs with `'a` lifetimes and `&`/`&mut` by error-code heuristics (`mode_fixes`, :521-557), plus body rewrites (`*x`, `&mut *x`, `.clone()→.to_vec()`, `mem::take`, :464-473,592-606).
Fix: human param-design step — reuse existing domain `Args` structs or introduce ≤5-param signatures; compiler-inferred 8-field structs rejected in review.

M6/M7: `<host>_collisions/_merge_and_publish/_finish` identically applied to two hosts — two near-identical name families without folding. Fix: rename pass before R4/R3/D4/D6; record R4/M6-M7 duplicate pairs for #338 explicitly in-task, not "if dupes.py flags it".
- **I2 — Mega-`Ctx` for unrelated closures.** D1 (`emit` 76 + `emit_nomerge` 30 + `oldbest_str` 27 + `disp_version`/`field`/`classify` → one `EntryLineCtx`, plan:238-239), R11 (4 closures → one `WalkTraceCtx`, :229), D4 (`run_resolve` 67 + `handle` 16 → one `ResolvePhaseCtx`, :255). Cap: no `Ctx` >5 fields without owner sign-off.
- **I3 — Sibling-file rule fragments modules.** Rule 5 (plan:97-98): host >~500 lines → sibling file with `mod x; pub(crate) use x::*;` (`extract_block.py:307-332,476-484`). Hosts are already 500–1100 lines. A mid-algorithm chain (host + 5 rung fns + 2 `Args` structs) across 2 files doubles navigation cost for humans and LLMs. Fix: keep each host's cut-chain in the host file until host ≤200; split files only on module boundaries, never for the 500-line heuristic mid-track.
- **I4 — Gate adequacy gaps, especially Track D.** G-D is "G-R minus fixture-oracle" with "L0 still compares the printed output" (plan:76-77) — L0 is a resolver differential; it does not cover `NoVisibleCandidate` blocks (D1 220-line match), `--tree` unordered paths (D2 nested `unordered_walk`/`add_parents`), slot-conflict reports (D3), or `--info` beyond D5's extra gate. Fix: per-D-slice named contract-test lists (like R11/D5); per-M-slice pre/post bed-cell diff baselines checked into `baseline/`.
- **I5 — Correctness-risk allowance contradicts "verbatim".** Plan:35/313 says verbatim but permits `clippy --fix` + `fmt` auto-run, `&`/`&mut`/by-value flips, `*x` insertion, `.clone()→.to_vec()/.as_str()` rewrites, `mem::take`, added `'label`, `flatten_flow` collapse to `()`. Fix: `--keep` failure artifacts + explicit `git diff --stat` review of every auto-fix before squash.
- **I6 — Process: empty pmtest branches, squash destroys bisect, worker concurrency.** Plan:38 forces `backlog/339-<slug>` in both repos with empty pmtest commit — noise contradicting AGENTS.md "standalone commits stay single". ## 6. Suggested order

1. Restrict `ControlFlow`/`--loop` to true loop-control cuts (C1); default plain-return + mandatory `flatten_flow.py` attempt. Rewrite R5/R8/R9 cuts.
2. Fix names and cap plumbing structs (C3, I1–I2): rename `*_of`/`split_root_deps*`/`assemble_*`/`render_shown_merge_list`/`force_reinstall_cps_of`; forbid auto-inferred `*Args`/`*Ctx` >5 fields; one `Ctx` per capture-group.
3. Stop mid-algorithm file fragmentation + strengthen D gates (I3–I4): keep cut-chain in-host until ≤200; named contract coverage per D slice; M bed-cell pre/post diffs into `baseline/`.

Without (1)–(2) the plan hits "every function ≤200" while leaving resolver/display logic harder for the next human or LLM to modify — the opposite of the stated reason for the split.
