**G2 [not blocking] — the false-NOTE risk is real only without `--update`, and no probe
targets that case (likely, by source).** Compare the two `stale_scope` computations
(`rebuild_scan.rs:244-250`) and the non-update gate in `stale_pin_for_consumer`
(`:640-645`):
- With `--update`, the bridge (`scope: None`, `reachable` empty unless
  `complete_seed_atoms`, `walked_installed` empty) gets `stale_scope = !walked`. The
  default gets `in_scope || !walked`. So under `--update` without a seed set, the bridge
  judges a **subset** of the default's consumers: a missing NOTE is possible (a walked
  `--deep` consumer the default reaches through `walked_installed`), a false NOTE is
  not.
- Without `--update`, the bridge gets `stale_scope = !in_scope = true` for every
  consumer, and the early return at `:640-645` never fires (both sets are empty). The
  default skips in-scope consumers there. So without `--update` the bridge judges a
  **superset**, and that is where a false NOTE can appear: a walked or reachable
  consumer with a refused pin, with no `--update`.
- With `@world` / `complete_seed_atoms`, the bridge's `reachable` is the wider closure,
  where the default uses the narrower `scan_reachable`. Again a superset.

The only non-update probe in the control set is the 02.767 argv
`--pretend --solver=pubgrub dev-libs/p569prov`. There the default prints the NOTE
(proven), so it can only show a deliberate gain. **Fix:** add at least one non-update
probe in which the stale consumer is walked by the request, and one `@world` probe on
a ROOT that holds a refused pin. Record the default solver's NOTE body for each, and
compare the consumer lines, not only whether the NOTE is present. Two cheap
candidates on the shared fixture, both with no NOTE from the default today (proven):
`--pretend dev-libs/p569pull dev-libs/p569prov` and `--pretend --update --deep @world`.
In the #698 ROOT, `--update --deep @world` gets the NOTE from the default, so it is a
deliberate-change candidate.
