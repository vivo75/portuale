## 0. What the code already tells us

1. `unmerge_replaced_same_slot` (`crates/portuale/src/ebuild_merge/after_install.rs`) walks every installed same-slot `pf` — including a `pf` equal to the one being merged (#348 S6) — and calls `unmerge_one_installed` with `also_keep = [new_pf]`.
2. `unmerge_pkgfiles_into` (`crates/portuale/src/ebuild_unmerge.rs:~442-460`) folds `also_keep` into `others_in_slot`; `remove_contents` skips a path when `owns_path_pf(root, category, other_pf, path)` is true for any of them.
3. `owns_path_pf` → `read_contents_pf` (`ebuild_merge/installed_instance.rs:~115`) reads the **live** vdb entry first and falls back to the `-MERGING-<pf>` temporary only when the live one is absent. On a different-version upgrade the new `pf` has no live entry, so the temporary (the new image's `CONTENTS`) is used: correct. On a same-version reinstall the live entry **is the old copy**, so the "new" package is credited with the old `CONTENTS`, every path is "still owned", and nothing is deleted. The doc comment of `unmerge_replaced_same_slot` even states it ("every path is still owned").
4. Portage: `dblink.treewalk` (`vartree.py:~5190-5215`) appends `self` (whose `dbdir` is still `dbtmpdir`, so `getcontents()` reads the **new** `CONTENTS`) to `others_in_slot`, then `dblnk.unmerge(others_in_slot=…)` for the old instance, then `dblnk.delete()`, then renames the temporary into place. So Portage removes exactly the old paths the new image does not own.

## 1. Scope

In: the ownership source for the replacing package in the replace loop (source merge and binary merge — both go through `unmerge_replaced_same_slot`), all vdb backends (`files`, `redb`, `sqlite`; `read_pending_file` exists on each). Out: the strict-`keepdir` question (S3 only verifies; it only becomes code if S0 finds a divergence).

## 3. Risks to put to the reviewer

- Removing files on a reinstall is destructive: the S0 matrix must show the exact rule for protected configuration files and for files that were modified on disk.
- A reinstall whose new image is *larger* must not delete anything (cell e).
- Database backends: `deferred_delete` and `already_unmerged` bookkeeping must still keep the replaced instance out of `others_in_slot` where it should be, but not hide the replacing `pf` when it equals the replaced `pf`.
- Preserved libraries: `replacement_preserved` and `replacement_needed` are computed from the temporary; confirm they are unaffected when `pf` is equal.
