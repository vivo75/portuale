## 2. The rule

### 2.1 The cut must not sacrifice a build-time need in fact

An edge is **build-time in fact** when its kinds include `DEPEND`/`BDEPEND`/`IDEPEND`, **or** when it is `RDEPEND` and its source is used at build time by a package the plan builds (a build tool must be usable, PMS 8.1; "used at build time" is transitive: `automake -B-> help2man -R-> Locale-gettext`, so `Locale-gettext`'s own `RDEPEND` edges are build-time in fact too, while `Locale-gettext -> gettext` is not, because `gettext` is reached only as a runtime dependency of a build tool's runtime dependency).

Implement as a computed **effective kind** per edge, then let `runtime_cut` skip edges that are build-time in fact (a new predicate next to `is_runtime_edge`, e.g. `is_cuttable_runtime_edge`), and keep the existing preference order inside a cycle: the first runtime-only edge that is **not** build-time in fact; if the cycle has none, §2.2. The closure is a fixpoint over `edges`/`edge_kinds` plus the build-time dependency sets the walk already has (`walk` builds them for `Memos`); compute it once per `depend_order` call, deterministically (sorted sets).

Expected for #746: the cut moves from `help2man -> Locale-gettext` to `Locale-gettext -> gettext`, so `Locale-gettext` is emitted before `automake` and the finding disappears.

### 2.2 Property 2a: a cycle with no cuttable runtime edge is broken by a second build

1. **The breaker node** is the node whose build-time need is the back edge (the consumer of the unmet atom) — not the alphabetically-first node: a rebuild of any other node leaves the finding on the consumer, and the checker excuses an unmet need only on the finding's package. When several cycles overlap (a feedback set is needed), iterate: choose the back-edge consumer of the cycle the walk meets first (name order), schedule it, remove its back edge, repeat until the graph is acyclic. Deterministic by the walk's name order.
2. **The second row.** `Order::ordered` returns `Vec<Row<'_>>`, `Row { slot: &SlotSet, pass: Pass }`, `Pass::First | Pass::Rebuild`; `depend_order` returns the node names with the breaker twice (its `Vec<String>` already allows it — `unordered` must stop de-duplicating `out` while `done` keeps the traversal acyclic). Update every caller: `plan_world.rs:63`, `portage-world/src/rebuild.rs:135` (test-only, count unique slots), `order.rs` `odw0_order` (L268), and `order.rs:307-311` `a_cycle_is_cut_and_every_node_is_listed_once`, which is a pure build-time two-cycle and **must be changed on purpose** to expect the breaker twice (say so in the commit). Only `Order::Depend` produces the pair: `--sort alpha` and `--sort resolver` print each slot once (the rebuild is an ordering artefact, not a second package).
3. **The output.** No-cycle and no-breaker output is byte-identical. With a breaker: the second row prints the same change marker as the first (both builds of one version carry the same `Change`; do not invent `R` for a new slot), the `--json` second entry alone carries `"built_twice": 2` and no `from_version` (the first keeps today's fields), and the stderr summary counts **unique slots** and appends `, 1 slot built twice: cat/pkg:slot` (today `run` prints `rows.len()`, which would overcount).
4. **The checker.** (a) A `build-order` finding on `P` at `o` becomes `cycle-noted` (reason naming `#o′`) iff the plan merges the **identical cpv in the identical slot** again at `o′ > o` and the same need is matched at `o′`: `later = [o2 for o2, p in plan.merges if o2 > order and p.cpv == pkg.cpv and p.slot == pkg.slot and _satisfied(node, index(plan.available_at(o2)), owner or pkg)]`. Identity, not atom-satisfiability (`index(...)` because `available_at` returns a list), so a slot-operator reinstall of another version never blesses an unmet need. (b) `check_final_state` collapses **identical cpv in one slot** to one package before the slot check (a second build of the same version is not two packages); two *different* versions in one slot still fails. (c) `_build_graph`, `_components`, `gap` are untouched.

Grounding: charter 2a verbatim; PMS 8.1 and `dependencies.tex` for usability; #746's dump and #745's six-order table. Determinism: sorted iteration only; no `HashMap` iteration in the choice.

## 8. Second phase — close #745 by verifying the cut result (2026-11-14, after S0–S4 shipped)

S0–S4 closed #746 and left #745 open with its trace: the #745 shape (`prov -R-> user -B-> virt -R-> prov`, all merged) still cuts the cuttable `(prov, user)` edge, gives `[prov, virt, user]`, and the checker fails on `user` because the usability closure is two levels deep (`user` needs `virt` usable; `virt` needs `prov` usable; `prov` needs `user`, still merging). The §2.2 trigger ("no cuttable runtime edge") can never fire there, because a cuttable edge exists.

**Rule (the owner-approved continuation, grounded in charter 2a):** the planner must check its own cut result against the checker's usability model and break the loop where the cut does not suffice. Concretely:

1. Port a `_Moment.gap`-equivalent closure into `portage-world`: for a merge at position `i`, a build-time need is satisfiable when every provider in its `RDEPEND` closure is installed or merged before `i`, or is a package built earlier in the plan; a runtime need counts against the merge that *uses* it, not against the package's own merge.
2. After the cut order exists, walk it in merge order; the first package `P` whose build-time need chain is unmet at its position gets a **second build of `P`** appended after the position where the closure becomes satisfied (the same `Row { pass }` machinery and `built_twice` marker as §2.2; the second build is after the last member of the closure, not necessarily adjacent).
3. Determinism: first in merge order, ties by name; the appended position is the latest closure member, so two runs agree.
4. The checker needs no change: `_second_build` already excuses a need the identical later build meets. A **negative** test pins that the checker would still fail the duplicate-free plan, so the fix is provably on the planner side.

**Acceptance for #745:** `a_usability_closure_left_open_by_the_cut_gets_a_second_build` on the #745 fixture → `[prov, virt, user, user]`, checker: one `cycle-noted`, zero failures. Host and beds: report the new second-build rows by name and confirm the `FAST_world` and default resolver beds stay at 0 findings / 0 unexplained.
