## D — defects (severity-ranked)

### D1 — HIGH, proven: Task 1 guards the Atom side, but the recurring bug was on the candidate side

- **Plan:** :95-131, File map :52-53; the spec is `recurring-issues.md:62` ("new `Atom`
  field → `Candidate` carriage (`repo/sub_slot/IUSE`)").
- **portuale facts:**
  - `portage-repo`'s `Candidate` (`candidates.rs:15-57`) is never matched against an
    `Atom` directly. Every site hand-formats a string `"{cat}/{pkg}-{ver}:{slot}/{sub}::{repo}"`.
    `portage_dep::parse_candidate` (`lib.rs:963-990`) then re-parses that string into the
    *other* `Candidate` struct (`portage-dep/src/lib.rs:925-941`), and `candidate_hits`
    consumes that one.
  - `grep -rn ':{}/{}::{}' crates --include=*.rs | wc -l` finds **78 format sites in 32
    files** (e.g. `binpkg_use.rs:74,79`, `masked_deps.rs:45,256,297,327,584`,
    `visibility_use_flip.rs:35,425,488`, `use_unsat.rs:150,250`). `candidates.rs` has no
    shared `match_str()` method.
  - The history the spec cites is exactly this layer. `what-this-proves.md:1229-1235`
    says "`portage-repo`'s own `Candidate` struct … discarded the sub-slot half … in both
    `list_candidates` … and `installed_candidates`".
- **Divergence shape:** a future `Candidate` field, or one of the 78 sites dropping
  `/{sub_slot}` or `::{repo}`, still compiles and passes the census. A destructure of
  `Atom` in `candidate_hits` would not have caught the sub-slot bug, because
  `Atom.sub_slot` existed and was read by `matches_slot`.
- **Fix direction:** keep the `Atom` destructure in `candidate_hits` (cheap, one site)
  as the minor half. Add the #492-shaped half as well: one `Candidate::match_str(&self,
  category, package)` choke in `portage-repo`, plus a source-scan test that fails on any
  hand-built `:{}/{}::{}` format outside it unless the line carries `// match-str-ok:
  <reason>`. Optionally add an exhaustive destructure of `portage_repo::Candidate` inside
  that choke, so a new candidate field also breaks the build.

### D3 — HIGH, proven: the sample destructure breaks the zero-warning clippy rule and the "underscore = unread" semantics

- **Plan:** :106-119, Step 1(b) :121-124.
- **Fact:** `candidate_hits` reads 7 of the fields only through helpers that take
  `atom: &Atom` (`matches_version` :1034, `matches_slot` :1110, `matches_repo` :1128).
  Binding `operator, version, revision, slot, sub_slot, repo, build_id` by name, as the
  sample does, leaves them unused, which triggers `unused_variables` warnings. That fails
  `cargo clippy --release --all-targets` (zero warnings, Global Constraints :40-41). The
  fix that silences them, `_`-prefixing, then marks *read* fields as "unread", which is
  exactly what Step 1(b) treats as "needs `field-ok:`".
- **Fix direction:** either destructure to `field: _` for every field and mark each with
  `// read: <helper>` or `// field-ok: <reason>`, with the test requiring one of the two
  markers per field. Or have the helpers take the bound values instead of `&Atom`. Also
  note that rustfmt reflows the pattern to one field per line, so the scan must be
  line-oriented per field.
