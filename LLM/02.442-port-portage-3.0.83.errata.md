# Errata for plan 02.442 (move the mirrored Portage 3.0.82.2 → 3.0.83)

Status: errata filed 2026-10-24 (plan residui-514-555, Task 5: backlog #525,
#529, #530, #531). The plan `LLM/02.442-port-portage-3.0.83.opus.md` is
**closed** (`Status: done 2026-10-24`); it is not rewritten here. Each item
below corrects a statement in it and cites the capture that shows the
correction. An in-place edit of the plan needs the owner's sign-off.

## E1. S10b's premise is wrong: 3.0.82.2 already agreed on the three atoms (#525)

The plan's S10b oracle line (`LLM/02.442-port-portage-3.0.83.opus.md`, "S10b —
atom-constructor/reducer parity re-probe", §Slices) says:

> 3.0.83 handles these the same way in both entry points; 3.0.82.2 did not

for `games-arcade/2048`, `dev-util/timidity--` and `cat/pkg[a(+),-a]`.

Captured behaviour: on the `portage-3.0.82.2` tag — built with its own C
parser, first by hand and then through the tag's meson `_parser` target
(#529) — the constructor and the reducer agree on all three:

- `LLM/evidence/2026-10-23-510/diffpaths-3.0.82.2.txt` — the 14 probed
  strings, all `C=… py=… same`.
- `LLM/evidence/2026-10-23-510/diffpaths-3.0.82.2.meson.txt` — the same file
  regenerated from the meson-built parser: byte-identical.
- `LLM/evidence/2026-10-23-510/diffpaths-host-3.0.83.txt` — the same rows on
  the host: also all `same`.

The C-parser fixes the plan names (`450282d84`, `8bf578fd7`, `bdce305cd` in
3.0.83) are the equivalents of `6a64fb2f4`, `4f76d9ee5`, `a2206fc32`, which
are **already in the 3.0.82.2 tag**. So the disagreement the plan refers to
predates the released 3.0.82.2 and never shipped as a version difference.

Corrected statement for the owner to apply (or to leave to this file):

> 3.0.83 handles these three atoms the same way in the constructor and the
> reducer; 3.0.82.2 already does too (the fixes are in that tag), so the
> probe is a parity check, not a version difference. The battery carries the
> three atoms since backlog #528.

The live behaviour, and portuale's already-correct handling of the three
atoms, are unaffected. The battery now contains them
(`crates/portage-dep/src/testdata/atoms-3.0.83.tsv`, 86 atoms × 9 modes).

## E2. The reducer's C-path error text did not change in 3.0.83 (#531)

Backlog #531 and quirk Q8 said 3.0.82.2 raised
`Invalid atom (Invalid use dep: '-a'), token 1` where 3.0.83 raised
`invalid use dep token: '-a'` (the plan's row 15 states only that the two
entry points disagreed before 3.0.83).

Captured behaviour: **both** versions' C path raises
`InvalidDependString: invalid use dep token: '-a'`
(`p3082-3.0.82.2.txt`, `p3082-3.0.82.2.meson.txt`, `host-3.0.83.txt`, all in
`LLM/evidence/2026-10-23-510/`). The `Invalid atom (…), token N` wrapper is
the **Python** path's text (`lib/portage/dep/__init__.py:974`), and it is the
one a user sees: `Package._validate_deps` passes `is_valid_flag`, and the C
fast path requires `is_valid_flag is None` (`:1079-1086`).

Capture of the visible text, host Portage versus portuale
(`LLM/evidence/2026-10-24-531/`, run with `probe.sh`):

```
- dev-libs/r531bad-1.0::testrepo (masked by: invalid: RDEPEND: Invalid atom (Invalid use dep: '-a'), token 1)
```

identical on both sides, rc 1/1. Portuale's wrapper is therefore correct and
is pinned by
`crates/portage-repo/src/tests/dep_validate.rs::reducer_rejects_the_510_probe_atom_with_the_visible_wrapper`.

## E3. Version wording: `3.0.83` is the version, `3.0.83-r1` the ebuild (#530)

`portage.VERSION` reads `3.0.83` and `emerge --version` prints
`Portage 3.0.83 (python 3.14.8-final-0, …)`
(`LLM/evidence/2026-10-23-510/emerge-version.txt`,
`portage-VERSION.txt`). `3.0.83-r1` is the installed ebuild
(`sys-apps/portage-3.0.83-r1`), one downstream patch (bug 984255,
`bintree.py` `USER_PATCHES`), so it is correct only when naming the ebuild.

The plan uses `3.0.83-r1` as the version throughout; when it is next touched,
write `Portage 3.0.83` (ebuild `3.0.83-r1`). Current docs were fixed:
`LLM/portage-quirks.md` (intro note plus its entries) and the
`portage-dep` battery docstrings. Historical captures and commit messages
keep their original wording.

## E4. The 3.0.82.2 C parser is now built with the tag's meson target (#529)

`LLM/evidence/2026-10-23-510/build-3.0.82.2.sh` used to compile
`src/dep_parser_core.c` and `src/dep_parser.c` with a hand-written gcc line.
It now extracts the whole tag, runs `meson setup build` and
`meson compile -C build`, and uses the `_parser` extension module the tag's
`src/meson.build` declares (with its `ln -srnf` step into
`lib/portage/dep/`). Provenance:
`LLM/evidence/2026-10-23-510/build-3.0.82.2.meson.cast`.

The probes are unchanged: `diffpaths-3.0.82.2.meson.txt` is byte-identical to
its hand-built capture, and `p3082-3.0.82.2.meson.txt` matches row for row
(only the `VERSION` line's extraction path differs), so S10b's conclusions do
not depend on the build method.
