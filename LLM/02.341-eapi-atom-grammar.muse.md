## 2. Important (fix before S1)

### I1 — S2/S4 check ordering inverts Portage — `strong_blocks` vs conditional flags
Portage order is `slot_deps(:2106) → use_deps(:2112) → use_dep_defaults(:2117) → conditional-vs-is_valid_flag(:2125-2144) → strong_blocks(:2145-2153)` (oracle report:90-98). Plan puts `strong_blocks` in S2's post-parse checks (plan:219) and `check_conditional_flags` in S4's validator after parse (plan:269). An atom violating both (e.g. `!!dev-libs/foo[x?]` with bad `x` in EAPI 2) reports `EAPI.incompatible` in portuale but `IUSE.missing` in Portage.
Fix: S2 post-parse must stop before `strong_blocks`, or `validate_dep_string` must run `check_conditional_flags` before surfacing S2's `strong_blocks` error.

### I2 — S1 `Eapi` parse rule breaks underscore pre-releases
"S leading integer before `-`" (plan:161) on `"3_pre1"` (no dash) yields `"3_pre1"`, not `3` — `int()` fails, so S1 classifies a supported spelling as unsupported/permissive. Portage accepts `3_pre1/3_pre2/4_pre1/5_pre1/5_pre2/6_pre1/7_pre1` + `9-pre1` (oracle report:11, `md5_dict.rs:20-42`).
Fix: exact transcription (split on both `-` and `_`, or table-lookup `eapi_is_supported` first); add `3_pre1`/`9-pre1` rows to the S1 test (currently only `"10"` unsupported, plan:146).

### I3 — S3 `_extended_cat` transcription drops `.`
Plan: `[\w+*][\w+*-]*?` (plan:234); oracle: `_extended_cat = [\w+*][\w+.*-]*` (`dep:252`, oracle report:59). Extended cats with `.` (cf. live `'cat./pkg'` OK, report:189) diverge. S3 also omits the `star` form `=cat/pkg-\*\w+\*` (report:69,200) — only `=…-*ver*`.
Fix: correct charset, cite both `simple` and `star` arms.

### I4 — `Improper context` ordering vs first-bad-token
Plan runs the `:slot/sub=` built check "after the per-key pass" (plan:269). Portage's check (`Package.py:347-356`) interacts with `use_reduce`'s first-failure-per-key (oracle report:267,299); a dep string with both an invalid token and a `:0/1=` atom must report whichever Portage reports first.
Fix: S0 `t341-twokeys`-style cell with a combined case; S4 must specify order (per-token during walk, not second pass).

### I5 — `profile_eapi_when_unspecified` spelling unverified
`layout.conf` keys are hyphenated (`profile-formats`, `masters`); plan asserts underscore key and tells S0 to "record the exact spelling" (plan:100) while S5 hard-codes underscore (plan:318; oracle report:349,353). If the file key is `profile-eapi-when-unspecified`, S5's node-EAPI default (→ `"0"`) breaks.
Fix: don't bake spelling into S5; make S0's finding normative.

### I6 — `^^`/`??` counted but never gated
Token counting includes `^^`/`??` (plan:269), but no slice gates their EAPI availability or empty-group semantics. S0 lists no `^^`/`??` probe cell (plan:94,99).
Fix: S0 needs a `^^`/`??` probe cell at minimum.
