## 2. The rule

`branch_preference` (`lib.rs:274-297`) prefers a branch whose every cp is installed (`AltPreference::Installed`) over one that is merely available. That is right for "do not churn" and wrong for property 3 when the installed-matching arm can only ever hold a version strictly older than the best visible one.

Add two preference ranks, **used only in plan mode** (reuse the `newest_slot` flag's source, `opts.rebuilds`; extend its doc comment to say it now feeds two rules, or add a second boolean with its own comment — do not leave it describing slot selection only):

- **`BestVisibleAvailable` / `BestVisibleInstalled`**: every non-blocker atom of the branch is matched by the **best visible candidate of that atom's slot** — the cp's best visible when the atom names no slot, and the best visible candidate **in that main slot** when it does (so `w740prov:1` is judged against slot 1's best, never against a parallel slot 2). This is what makes `openssl:0/3` fail (slot 0's best is 4.1.0, sub-slot `0/4`) while a legitimate parallel-slot arm passes.
- Order, best last: `Unsatisfiable` < `Available` < `Installed` < `BestVisibleAvailable` < `BestVisibleInstalled`. The existing `Available < Installed` order is unchanged. Declare the two new variants **after `Installed`** in the enum, because the selection uses derived `Ord` (`resolve_disjunctions` L1024 `.max()`); placing them earlier silently inverts the choice. The installed bit is the tie-break: for `|| ( www-client/firefox www-client/firefox-bin )` (`dev-python/selenium-4.52.0.ebuild:56-60`) with `firefox-bin` installed and `firefox` not, both arms are best-visible and `firefox-bin` must win — that is the churn guard. The converse is intended: an **installed arm that is not best-visible** (openssl's `:0/3`, or a stale `firefox-bin`) loses to a best-visible uninstalled one, because keeping it would violate property 3; the plan pins both directions in §4.2.
- **`portage-use-reduce` changes with it**: `AltPreference::is_selectable` (`crates/portage-use-reduce/src/lib.rs:858-868`) lists only `Installed`/`Available`/`UnsatUse*`, and `resolve_disjunctions` drops everything unselectable in the first pass (L1012-1019). Without adding both new variants there, the change is a no-op. Its module doc says the enum is a port of Portage's `choice_bins`; record that these two variants are ours and why.
- Check mode (`rebuilds == false`) keeps today's order exactly.

Grounding: charter property 3; determinism from `rank` + the listed branch order (`tie_break` unchanged); memoize `branch_preference` the way `atom_available` is memoized (`lib.rs:52-69`) because it now scans candidates per atom.
