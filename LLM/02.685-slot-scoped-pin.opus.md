# #685 — an installed consumer's pin must constrain only its own slot

**Status:** fixed 2026-11-08, uncommitted; bed run done (no change vs the 11:09 report); no pmtest fixture (see Tasks) (branch `backlog/685-xcore-llvm-abort` in both repos).

**Goal:** `portuale emerge -pvuDN --getbinpkg=n media-video/ffmpeg` exits 0, as
Portage does, instead of `there are no ebuilds to satisfy "~llvm-core/llvm-22.1.8[llvm_targets_XCore=]"`.

**Spec:** `LLM/backlog-tasks.md` #685. Charter ground: an abort where Portage
plans is a wrong plan for the user. Expected behaviour comes from the PMS
(a dependency atom is satisfied per package, here per slot instance); Portage
(`depgraph.py`, `_slot_operator_check_reverse_dependencies`, which looks at the
parents of the one existing slot node) is the hint.

## Cause (found 2026-11-08, `PORTUALE_BT_TRACE=1`)

- Pass 1 plans `llvm-23.1.5` (an update of slot 23). Installed `lld-23.1.4`,
  `lldb-23.1.4` and `clang-23.1.4-r1` record `~llvm-23.1.4`, which 23.1.5 breaks.
  `apply_enforced_pin` (`feedback/reverse_dep_pins.rs`) files the atom as a
  positive constraint under the key `("llvm-core","llvm")` -- the whole
  package, every slot -- and masks `llvm-23.1.5`.
- Every later request for `llvm-core/llvm` must now also match
  `~llvm-23.1.4`. `clang-22.1.8` (slot 22, being rebuilt) asks for
  `~llvm-22.1.8[...]`: no candidate satisfies both, so the pass is a dead end
  (try 7) and the error is printed (with the parent of another pass, a
  separate cosmetic mix-up).
- Portage never backtracks here (0/20): it ties the check to the existing slot
  node and removes the conflicting update ("Removing package llvm-23.1.5").
- `--backtrack=0` hides it: no pins are fed back, rc 0 with the same llvm block
  as Portage.

## Fix (smallest form)

1. One predicate for "does this extra constraint admit this candidate"
   (`pretend.rs`), replacing the eight copies of the same closure
   (`masked_deps.rs` x2, `pretend.rs` x4, `graph_lookup.rs`). A positive
   constraint whose atom names a slot applies only to candidates of that slot.
2. `apply_enforced_pin` files the positive with the slot of the update the
   pin breaks (read from the pass's merge entries) when the atom has none and
   exactly one slot is broken.
