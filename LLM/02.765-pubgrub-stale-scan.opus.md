## 0. Premise and what grounding found

Backlog #765 says "the pubgrub path (`solver_bridge.rs`) never calls that scan". Grounding disagrees. Fix the entry's wording at close-out.

1. **The bridge DOES run the scan; it throws the refusals away.** `graph_result_from_order` (`solver_bridge.rs:904`) → `bridge_slot_operator_rebuilds` (`:1590`) → `slot_operator_rebuild_entries` (`slot_operator/eliminate.rs:218`), a fixpoint loop calling `slot_operator_rebuild_scan` (`eliminate.rs:242`). The stale-pin arm (`stale_pin_for_consumer`, `rebuild_scan.rs`) already runs after every pubgrub solve. The function returns only `(Vec<GraphEntry>, Vec<(String,String)>)`; `SlotOpRebuildScan.refused` is dropped in the loop, and `graph_result_from_order` hard-codes `stale_pin_refusals: Vec::new()` (`:952`). Commit `0ca6e91c`'s comment ("the pubgrub path does not run this scan and stays silent") has the same drift.
2. **Everything downstream is solver-agnostic.** `show_stale_pin_refusals` (`crates/portuale/src/pretend/problem_reports.rs:265`, called from `pretend/mod.rs:608`) and the `--json` `stale-bindings` key (`pretend/json.rs:549-630`) read `GraphResult.stale_pin_refusals`. Filling the field is the whole fix.
3. **`holder_fix` / `resolve_pubgrub_unstale` do not overlap.** `holder_fix` (`:5664`) handles a reachable holder whose recorded dep rejects the provider's move (rebuild the holder, or withhold the provider and file the #703 note). The stale-pin scan covers the plan that keeps the consumer and whose repair is refused by a recorded `=` pin. Only the last round's `GraphResult` is returned, so a refusal is not duplicated across rounds. S0 checks no consumer is named by both notes.
4. **Live evidence (read-only probe).** On the #761 fixture, `--pretend --update dev-libs/p569prov`: default prints the `NOTE: ... stale slot-operator binding ...` block naming `dev-libs/p569virt-1`; `--solver=pubgrub` prints only the `[ebuild U ] dev-libs/p569prov-5.44 [5.42]` row.
5. **Scan arguments differ between the two callers.** Default (`resolve/assemble.rs:49`): `effective: Some(..)`, `scope: Some(scan_reachable)`, real `walked_installed`, `undone`. Bridge (`eliminate.rs:242-259`): `effective: None`, `scope: None`, empty `walked_installed`/`undone`, `reachable` empty unless `complete_seed_atoms` is set. On the #761 fixture the gate passes; refusals can differ on other shapes (accepted, Q2).
