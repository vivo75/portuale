# Task 6 (#579) S0: remote-binary `pkg_pretend` order, Portage 3.0.83

Probe: `s0-probe.sh` builds a `file://` binhost serving the
`binpkgpretendpkg-1.0.tbz2` fixture (whose own metadata carries `pretend`
in `DEFINED_PHASES`) with a hand-written `Packages` index, then runs
`emerge -k --getbinpkg --oneshot --nodeps dev-libs/binpkgpretendpkg`
under Portage (`/usr/sbin/emerge`, host 3.0.83) and under portuale with
the same flags. Captures: `portage-*.stdout/stderr/rc`,
`portuale-ok.*` (pre-fix portuale).

Reference source (all `3rdparty/portage`):
- `lib/_emerge/Scheduler.py:938-944` (`_pkg_needs_pretend`): Package, not
  uninstall, EAPI not in 0-3, `pretend` in `defined_phases` (from
  `x.metadata`, the bintree record).
- `lib/_emerge/Scheduler.py:1147-1180`: in `_run_pkg_pretend_one`, for
  `x.built`, `download_required` starts a `BinpkgFetcher` and then a
  `BinpkgVerifier`; the metadata unpacks to `build-info` (`:1250-1253`)
  only after, before the `pretend` phase (`:1303-1315`).
- `lib/_emerge/Scheduler.py:1206-1212`: a verifier failure ends the entry
  with `finish(verifier.returncode)` before the metadata step.
- `lib/_emerge/BinpkgVerifier.py:139-166`: the failure-block shapes
  (missing-digests vs digest exception with the `File renamed to` line).

## (a) ok: order is pass-fetch, pass-verify, then merge

`portage-ok.stdout`:
```
>>> Running pre-merge checks for dev-libs/binpkgpretendpkg-1.0
 * binpkgpretendpkg-1.0.tbz2 MD5 SHA1 size ;-) ...                       [ ok ]

>>> Emerging binary (1 of 1) dev-libs/binpkgpretendpkg-1.0::testrepo ...
```
(The merge phase itself hangs in this sandbox -- a hand-rolled binhost
without live-index fields trips `download_required`'s `_mtime_` lookup
at merge time -- but the pass order is fully captured: status, fetch,
verify, all before `>>> Emerging binary`.)

Pre-fix portuale (`portuale-ok.stdout`) shows the defect: no
`>>> Running pre-merge checks` line at all; the verify line prints at
merge time, and the fixture's `pkg_pretend` never runs (the run's
`var/lib/binpkgpretendpkg.log` holds `setup/preinst/postinst` but no
`pretend`: the pass stays silent for the remote entry, and the merge
runs with `skip_pretend`).

## Probe limitations (documented, not blocking)

- The Portage runs read the host running-root config (global updates from
  the live tree print first); the merge target ROOT is still the scratch
  root and the order lines are unaffected.
- Fixture `make.conf` lacks `RPMDIR`, which host Portage requires; the
  probe appends it (plus `PKGDIR`/`PORTAGE_TMPDIR`/`DISTDIR`) to the probe
  copy only. Host `ROOT`+`EPREFIX` stacking differs from portuale's
  `PORTAGE_OVERRIDE_EPREFIX` convention, so the probe unsets the override
  for the Portage leg and pins downloads with binrepo `location`.
