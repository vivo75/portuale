## Harness (`tools/`)

- `r6trace.py`: host `emerge` with `_backtrack_depgraph` re-exec'd from its own installed source text plus
  trace statements only (every anchor asserted to match exactly once), and `Backtracker._add`/`feedback`
  wrapped call-through. Per loop pass it prints `R6 PASS bt_before=... success need_restart infos
  unexplored_after_get`, then the arm taken (`break` with reason / `restart D:12414` / `failed-no-restart,
  unexplored nonempty D:12417` / `failed-no-restart, unexplored EMPTY`), every child `_add` with
  ACCEPTED/REJECTED + reason (duplicate / `mask_steps>max_depth` / bug-375573 invalid), then
  `LOOP-END`, `BEST-RUN`, `BREAKAGE`, `RETURN backtracked=N/M`. Side-effecting calls are guarded
  (`need_config_change` only re-evaluated when `success` is false, as the original condition does).
- portuale side: `PORTUALE_BT_TRACE=1 PORTUALE_PROFILE=1`. The `[profile] run_pass` span
  (`pass/mod.rs:65-79`) marks **every** `run_pass` call, including the `Err` walks that never reach
  `collect_feedback` (no `BT try=` line). `pseq.py` prints one token per `run_pass`: `SC MD CF RD CI OK DE`
  (= `collect_feedback` kind) or `ERR` (no `collect_feedback`: an `Err` walk, the autounmask-disabled
  pseudo-pass, the naked re-run `driver.rs:279`, or the breakage clean pass `replay.rs:111`).
- `seq.py` prints Portage's arm sequence: `R<k>` restart with k unexplored nodes left after feedback,
  `F+` failed pass counted (stack non-empty), `F0` failed pass, stack empty (not counted, loop ends),
  `B:<why>` break, `+best`/`+brk` the get_best_run and breakage passes.
- `pair.sh <name> <cell> <args>`: same argv on both sides; Portage on `$S/<cell>` with config root
  `$S/<cell>.cfg` (`mkcfg.sh`: absolute repos.conf/make.profile), portuale on its own copy `$S/<cell>p`.

## Portage's counter, every arm (D:12357-12461)

`backtracked = 0` (D:12371); loop `while backtracker:` (D:12378; `Backtracker.__len__` = unexplored nodes,
B:141). Each pass pops a node (`get`, B:131-139), runs `select_files`, then exactly one arm:

| arm | condition | effect on `backtracked` |
|---|---|---|
| break | `success or need_config_change() or not allow_backtracking or backtracked >= max_retries` (D:12407-12412) | none; loop ends |
| restart | `need_restart()` = `_need_restart and not _skip_restart` (D:11821-11825) | `+= 1` **before** `feedback()` (D:12414-12416), whatever `feedback` then accepts |
| failed, stack non-empty | `elif backtracker` (D:12417-12418), evaluated after this pass's `get()` | `+= 1` |
| failed, stack empty | (no arm) | none; `while` ends |

After the loop nothing increments: the `get_best_run` pass (D:12420-12438, only if `backtracked and not
success and not need_display_problems()`) and the breakage clean pass (D:12441-12459) run with the count
frozen; `RETURN` shows it unchanged on every capture. The printed line is `_show_resolution_report`
(D:12265-12270) from `backtrack_depgraph` (D:12341-12351).

So, with k = number of loop passes: **Portage prints k-1, except k when the last loop pass is a restart
all of whose children `_add` rejected** (`R0`: B:118-129 rejects a child that is a duplicate, has
`mask_steps > max_depth` with `max_depth = max(1, (max_retries+1)//2)` D:12368, or fails
`_check_runtime_pkg_mask` B:144-176). Every pass that does not end the loop is counted.

Observed `R0` (all children `REJECTED mask_steps>max_depth`): the `r6c0` chain at `--backtrack=2..6`
(`R1 R0`, `R1 R1 R0`, ...). No pmtest fixture cell in this S0 ends in `R0`.

`Err` arm (`driver.rs:38-48`) which bumps `passes` only while `bt.unexplored` is non-empty. Over the
k loop passes it therefore prints k-1 on every exit **except**:

## The rule (pseudo-code on driver.rs's variables)

`restarts` becomes Portage's `backtracked`: bumped once per loop pass that does not end the loop, never
by the pass that ends it, except a restart, which always counts.

```text
restarts = 0                                   // D:12371
loop {
    params = feed_params.take() or bt.get() else break              // D:12378 `while backtracker`
    match run_pass(params) {
        Err if from_feed  => continue                                // portuale-only pass: not counted
        Err if !first_pass => {                                      // Portage: failed, no restart
            bt.adopt_current(params)
            if restarts >= backtrack_max { break }                   // D:12411, this pass not counted
            if !bt.unexplored.is_empty() { restarts += 1 }           // D:12417-12418
            continue                                                 // empty: loop ends, not counted  (rule A)
        }
        Err(e) => return Err(e)
        Ok(pass) => {}                                               // no counting here any more
    }
    ... every early return/break above the decision match reports `restarts` unchanged   // break arm
    match decision {
        Settle (returns)                       => return with restarts
        Settle (failed-iteration `continue`, :188-195),
        DeadEnd                                => { adopt; if restarts >= max { break };
                                                    if !bt.unexplored.is_empty() { restarts += 1 } }   // F+ / F0
        Feedback(kind) => {
            if backtrack_max == 0 { ...as now... }
            if restarts >= backtrack_max { break }                   // D:12411
            portage_restart = !(kind is Config from step_autounmask's grow arm)
                              || grow_flip_reached_and_wants_restart  // rule B
            bt.feedback(kind)
            if portage_restart { restarts += 1 }                     // D:12415, even if no child is accepted (rule C)
        }
    }
}
// get_best_run pass, naked re-run, breakage clean pass: no increment (D:12420-12459)
```

`grow_flip_reached_and_wants_restart` is Portage's `want_restart_for_use_change(pkg, new_use)` on the
flipped existing package (its flattened `*DEPEND`/`LICENSE` change under the new USE, or the change breaks
a USE dep of one of its existing parents), restricted to flips the fail-fast replay (`replay_walk`, which
already stops at Portage's first failure) records before its failure. **The second half is inferred**
from `bt-y-abc` alone (Portage records no `config` on that pass); I did not instrument portuale to prove
which flip its try-3 `CF` folded.

Equivalent closed form, for checking: printed = (loop passes that are Portage passes) - 1, plus 1 if the
last loop pass was a restart whose children were all rejected.

Consumers of `restarts` besides the print: `driver.rs:109` (inside the loop, unaffected by A/C),
`:244` (`restarts > 0` picks the `--backtrack=0` context for the best-run pass) and `:338`
(`prune_unresolved_after_backtrack`). With A, cells such as `ormissbad` go from 0 to 1, so `:244` switches
the best-run pass to backtracking off. That is what Portage does (D:12420 is gated on the same
`backtracked`), but it can move output beyond the count; not verified (no build allowed in this S0).
Keep a separate print counter if the slice must not touch that.
