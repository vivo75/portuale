## The rule (Portage)

Whether a dependency matched only by masked packages reaches `_feedback_missing_dep` is decided
inside `_add_dep`'s `if not dep_pkg:` block (D:3410-3535). The arms, in order:

1. Optional or ignored build-time dep: return 1 (D:3411-3413).
2. `allow_unsatisfied` (the `_complete_graph` re-walk): appended, return 1 (D:3419-3421).
3. `_complete_mode`, installed parent beyond the requested depth, no installed match: return 1
   (D:3438-3453).
4. Recorded for display (D:3455-3457). The rest runs only with `_allow_backtracking`
   (D:3462); without it the function returns 0 at D:3535 with nothing filed (`--backtrack=0`,
   and the final `get_best_run` pass D:12420-12437).
5. Built slot-operator dep that the probe heals: return 1 (D:3463-3470).
6. Installed parent already in `runtime_pkg_mask`, no match in any db: return 1 (D:3478-3486).
7. Reselect with `atom.without_use` (D:3494-3498). If that finds a package, the miss is USE-only:
   nothing is filed and the function returns 0 (D:3535), so the walk stops with no restart.
8. Otherwise, if a package the atom matches sits in `runtime_pkg_mask` with only an empty
   `"slot conflict"` reason (bug 693836): `_skip_restart`, return 0 (D:3505-3515).
9. Otherwise file `"missing dependency"` and `_need_restart` (D:3517-3518), return 0. The loop
   then counts it (D:12414-12416) and `_feedback_missing_dep` masks `dep.parent` (B:197-206).

Masking does not change this: with the default options `--autounmask` keeps keywords and masks
(`create_depgraph_params.py:61-94`), and `--autounmask-license` defaults to `n`, so
`_autounmask_levels` (D:7474-7535) only tries USE changes. A package.mask'd, `~arch` or
license-masked dep therefore has no `dep_pkg` and, when no visible version satisfies the atom
without its USE deps, reaches arm 9. Live (matrix below): shapes **p** (package.mask), **k**
(`~amd64`), **l** (license), **u** (`~amd64` plus a `[flag]` the masked version has) all take
`D:3517`, at the default options and with `--autounmask=n`. With an option that lets autounmask
unmask (`--autounmask-keep-masks=n`, `--autounmask-keep-keywords=n`, `--autounmask-license=y`)
nothing is filed; the run stops on the config change.

Two walk-order facts decide **which** unsatisfied dep a pass stops at (the walk stops at the
first one, D:3535 → D:3276-3280 → D:5691-5693):
- **Within one dependency string**, `_minimize_children` (D:4766-4788) yields the atoms that have
  no package at once, in textual order (D:4784), and the satisfiable ones only afterwards. The
  caller adds them in that order and returns at the first failure (D:4536, D:4630-4631). So an
  atom that autounmask can satisfy with a USE change never gets its change recorded if an
  unsatisfiable atom shares its dependency string (`D-c-portage-debug.trim.txt`: `vdep` is
  selected, but no `Child:` line, before `maskeddep` files).
- **Across parents**, children are expanded from `_dep_stack` LIFO (D:3276): with
  `top: a b`, `b`'s dependencies are walked before `a`'s.

And one loop fact: `need_config_change` (D:11838-11885) is checked **before** `need_restart`
(D:12407-12418). If the pass recorded an autounmask change that is in the graph
(`_have_autounmask_changes`, D:11887-11904) and `--autounmask-backtrack` is not `y`, the search
breaks (D:11865-11883) even though a missing dependency was filed: `backtracked` stays 0, no
`get_best_run`, and "backtracking has terminated early" is printed.

## What portuale does

- **The parent mask is already ported for every mask kind.** `maybe_missing_dep_backtrack`
  (`crates/portage-repo/src/resolve/pass/unresolved_dep.rs:53-131`) arms `missing_dep_trigger`
  for a `NoVisibleCandidate` dep that no visible version satisfies without its USE deps
  (`atom_currently_satisfiable` on the bare atom, :68-75). That is Portage's arm 7 test.
  `step_missing_dep` (`resolve/feedback/missing_dep.rs:7-72`) then masks the parent. On p, k, l, u,
  g and every `--autounmask=n` / `--backtrack=0` / `=1` variant of them, the counts, rc and rows
  match (`tools/cmp.sh`: SAME after the noise filter). The BT trace shows the mask, for example
  `P-s-maskmaskedconsumer.txt`:

      BT try=1 kind=Feedback:MissingDep
      BT   mask dev-libs/maskmaskedconsumer neg=!=dev-libs/maskmaskedconsumer-1.0 reason=MissingDependency { ... atom: "dev-libs/hardmaskedpkg" }

- **G0's `0/20` is the dead-end count (#600, R6 case 1), not a missing mask.** On G0 portuale
  masks `abort-masked-mid-1.0` at try 1, just like Portage (`P-g0.txt`). The pass with that mask
  fails the argument, so `run_pass` returns `Err`. With an empty stack, the `Err` arm does not
  count the pass (`resolve/driver.rs:38-49`, the `!bt.unexplored.is_empty()` test at :44), and
  the printed count stays `passes - 1 = 0`. This is inferred: the trace has no try with
  `masks-in [!=…abort-masked-mid-1.0]`, and try 2 is the best-run re-pass (`masks-in []`,
  driver.rs:214-238). Portage counts the feedback (D:12414-12416). The failed pass then ends the
  loop (`while backtracker:` D:12378; `Backtracker.__len__` B:141), and `get_best_run` prints 1.
  The same off-by-one is on every dead-end cell, plain misses included: `abort-masked-{mid,last,cycle}`,
  `abort-unsat-{mid,last}`, `maskmaskedconsumer`, `licensemaskedconsumer`, with and without
  `--autounmask=n`, and G0 with `--backtrack=1` (1/1 against 0/1).
- **G0's slot-conflict block is never in Portage's graph.** portuale prints a `dev-libs/p569prov:0`
  conflict between the merge-bound 5.44 and the installed 5.42 (`P-g0.txt`, and `P-g0-bt0.txt`
  with `--backtrack=0`). It comes from the residual installed-instance conflicts that
  `assemble.rs:527-545` builds from the dropped pins of the fallback re-pass
  (`driver.rs:253-289`). In Portage the installed 5.42 node enters only through `_complete_graph`
  (D:9482, inside `altlist` → `_resolve_conflicts`). The walk stopped at `maskeddep`, so `_resolve`
  returned at D:5691-5693 before `altlist` (D:5696). The final display tests only
  `_package_tracker.slot_conflicts()` (D:11273-11276, D:1735-1736), so no block. R1's `walk_stopped`
  gate (`feedback/mod.rs:303-326`) suppresses only the feedback steps, not this display.

## The divergences R3 owns (trigger conditions)

**T1. A USE-only miss that Portage meets first stops the walk with no restart; portuale arms the
trigger on a later masked dep anyway.** `maybe_missing_dep_backtrack` keeps the first masked or
missing dep it meets (`state.missing_dep_trigger.is_none()`, :74). It never asks whether a USE-only
miss (arm 7) comes first in Portage's order. A USE-only miss sets no trigger, but nothing stops a
later one either. The R1 `walk_stopped` gate does not help: it gates the slot-conflict steps, and
`step_missing_dep` runs after them unconditionally (`feedback/mod.rs:340`).
- Same dependency string (order by D:4766-4788: unsatisfiable atoms first, in text order):
  `c --autounmask=n` (`vdep[flag] maskeddep`), Portage **0/20 rc 1**, only
  `emerge: there are no ebuilds built with USE flags to satisfy "dev-libs/r594vdep[r594flag]"`
  + `- dev-libs/r594vdep-1::testrepo (Change USE: +r594flag)` + 3 required-by lines; portuale
  1/20 rc 0, merges `r594cm-1 r594ctop-1`. `e` (`xdep[flag] maskeddep`) does the same at the
  **default** options, because autounmask cannot add a missing IUSE: Portage 0/20 rc 1,
  portuale 1/20 rc 0. `--backtrack=1`: Portage 0/1 rc 1, portuale 1/1 rc 0.
- Across parents (LIFO order, D:3276): `q --autounmask=n` (`top: qb qa`, so `qa`'s USE-only dep is
  walked first): Portage 0/20 rc 1; portuale 1/20 rc 1, plus a masked block Portage never
  reached. `h` (xdep, default options): Portage 0/20 rc 1; portuale 1/20 rc 1.
- Keepers, already equal: `d`, `d --autounmask=n` (the masked dep first in text); `j`,
  `j --autounmask=n`, `f`, `f --autounmask=n` (the masked dep's parent walked first: Portage files,
  masks it, and the next pass stops at the USE-only dep).

**T2. A pass that recorded an autounmask change before its stop ends the search; portuale
backtracks on.** `q` at the default options: `qa`'s `vdep[r594flag]` gets an autounmask USE change
(`Child: … r594vdep-1 … USE="r594flag"` in `D-q-portage-debug.trim.txt`), then `qb`'s `maskeddep`
files a missing dependency. `need_config_change` breaks first (D:11865-11883, D:12407-12411):
Portage **0/20 rc 1**, the USE change block, ` * In order to avoid wasting time, backtracking
has terminated early`, and the masked block. portuale gives 1/20 rc 1 and a 4-row list
(`qb-1 vdep-1 qa-2 qtop-1`), because its `--autounmask-backtrack=n` break
(`driver.rs:127-152`) applies only to `BacktrackFeedback::SlotConflict`. Control:
`--autounmask-backtrack=y` makes Portage backtrack (1/20, rc 1), and the two sides then match.
`--backtrack=1`: Portage 0/1, portuale 1/1. Do not over-apply T2: in `c` at the default options,
the same USE change is never recorded (D:4784 puts `maskeddep` first), so Portage gives 1/20 rc 0,
and portuale already matches. T2 needs "a change reached before the stop point", not "any change
in the pass".

## Escapes and arms with no divergence found

- Arm 7 alone (no masked dep after it): `v`, `x` and their variants match on count and rc.
- `--backtrack=0`: every cell matches on count and rc (arm 4, `D:3535`).
