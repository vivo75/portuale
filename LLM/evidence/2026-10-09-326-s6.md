- Phase defaults (added in review): every case above runs with empty

  `phase-defaults-distfile` use `phase-helpers.sh:15,18`'s

Real behaviour the oracle pins:
- An empty `--distdir` is `b"/"`, so every absolute symlink is
  dereferenced (`doins.py:432,527`).
- A hardlink pair installs as two inodes.
- A failed `-o root` as a user still leaves the copied file behind, with
  rc 1.
- Only the leaf dir gets `diropts`; makedirs parents are
  `0o777 & ~umask`.
- `doheader` and `doconfd` force `-m0644`.

## Tests (`helpers/doins.rs`)

All oracle tests are child processes with
`PORTUALE_PORTAGE_CHECKOUT=/nonexistent` and
`PORTUALE_REAL_PYTHON=/nonexistent/python`, staged on `/dev/shm`.
- Oracle: one test per case. Each compares:
  - rc;
  - the `!!!` and exception lines of real's stderr, in order, skipping
    the wrapper's die banner;
  - the full tree dump.
  As root, the `*.root.*` files are used.
- Argv: real's argparse usage/help texts byte for byte, and type errors.
- Install-option forms: `-m0600`, `-m 0600`, `--mode=`, `--mo`, `-pm0600`,
  `-mp` falls back, `-pv` leaves `['-v']`, `-- -v`.
- Unit tests:
  - `int(x, 8)`;
  - passwd/group parsing (no NSS);
  - the xattr excluder;
  - the rc rule;
  - empty sources.
- The D7 write guard: pure checks plus a child run where `-r` would write
  through a dest symlink pointing outside. It is refused with rc 1, and
  the outside is untouched.
- End to end: `dev-libs/packagepkg`'s `insinto` + `doins` src_install,
  in process and re-run as a child with no checkout.
- Added in review (each value probed against Python 3.14 / real
  `doins.py`):
  - `shlex_split_matches_python`;
  - extra fnmatch cases in `xattr_excluder_matches_real`;
  - `install_namespace_repr_names_each_id`;
  - `unterminated_insoptions_quote_is_reals_value_error`.

Isolation proof (the implementing agent's): with the distdir condition
dropped, every symlink is preserved. Only the 6 symlink-dependent oracle
cases fail, `oracle_distdir_deref` among them (`abs-in-dist` is `l`, not
`f`). The binary was rebuilt before the run and after the restore.

## Review corrections (relative to the implementing agent's port)

- The `Failed to copy file: _parsed_options=Namespace(group=…, owner=…)`
  line printed each id in the other's field. The oracle has 0/0, so it
  could not see this.
- `shlex.split` did not follow Python:
  - inside `"…"` a backslash is kept unless it precedes `"` or `\`;
  - outside quotes, `\` followed by a newline is a literal newline;
  - an unterminated quote or a trailing backslash is real's uncaught
    `ValueError` (rc 1, raised before `--dest` is created).
- fnmatch: a backslash is literal, only `!` negates (`[^a]` matches `^`),
  and the class bracket is scanned as `fnmatch.translate` scans it.
- `CalledProcessError` text: dest prints as `b'…'`, and the message ends
  with `.`.
- Walk order: real's loop body runs per yielded level, so each level's
  files are queued before `os.walk` descends. The port had descended
  first. The tree was the same; the order of operations and messages
  was not.
- Environment, not product: the agent ran `sudo cargo test`, which left
  568 root-owned files under `rust/target`. Their owner was restored.
