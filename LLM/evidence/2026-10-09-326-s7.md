## The port

`helpers/xattr.rs` ports:
- `xattr-helper.py`:
  - its argparse surface;
  - `--dump`: argv paths, else stdin split on NUL. The getfattr text
    escapes only NUL, `"`, newline, CR and backslash in values, plus `=`
    in names; 0xff and UTF-8 pass through raw. A symlink is followed.
  - `--restore`: real's line rules and its two `ValueError`s.
- `install.py`:
  - chdir to `__PORTAGE_HELPER_CWD`;
  - `Which("install")`, skipping the helper by (ino, dev);
  - verbatim `install(1)`;
  - then the xattr copy through doins.rs's shared copier, with
    `PORTAGE_XATTR_EXCLUDE` (one copier, not two).

The D1 transition table and its re-exec machinery are deleted. Every
`python <script>` that is not native now exits 127 with
`portuale: no native helper for: python <argv>`. That includes
`dohtml.py`, which is never in scope: `dohtml` dies first for EAPI >= 7.

D7: no write guard here. `--restore` and `install.py` write exactly the
paths the caller names. There is no `--dest`/`$D` anchor to check
against, unlike doins.

## Tests (`helpers/xattr.rs`, `helpers/mod.rs`)

- 21 oracle tests, one per case dir. Each is a child process with no
  checkout and no real Python, staged on `/dev/shm`. It compares stdout
  bytes, rc, the stderr key line, and the xattrs or tree. A test skips
  with a printed reason when user xattrs are unsupported.
- Unit tests for `quote` and `unquote`.
- `install_parse_args_matches_reals` (added in review). 15 argv shapes;
  the expected files, `target_directory` and `directory` for each came
  from calling real `install.py`'s `parse_args`.
- Dispatcher:
  - `python_with_a_non_native_script_exits_127` (`dohtml.py`,
    `frobnicate.py`) is the "table empty" assertion;
  - `python_xattr_helper_routes_natively_without_interpreter_or_checkout`.
  - The re-exec test was deleted together with the machinery it tested.

Isolation proof (the agent's): with `"` dropped from the value escape
set, only `oracle_dump_escapes` fails (byte 34 where `\042` is
expected). The binary was rebuilt before the run.

## Review corrections (relative to the implementing agent's port)

- **`install.py` files list.** Real runs its files loop over the
  `parse_known_args` EXTRAS, so an option's value is never a file. The
  port ran it over the raw argv. Two effects:
  - `install -m 0644 src dest` took `0644` as a source, so the xattr copy
    failed with rc 1;
  - `-t dest a b` put `dest` in the list. The agent had reported that as
    a real-Portage surprise; it was this bug.
  Now the loop runs over the extras, with the probed test above.
- **Copy failure.** Only `OperationNotSupported` is caught by real
  (traceback, rc 71, then the `!!! install: copy_xattrs failed` note).
  Any other error escapes `main`: rc 1, and no note. The port printed the
  note for both.
- **Stale comment.** `ebuild_phases.rs`'s comment that the `.py` helpers
  are "reached only through the D1 transition table" is corrected.

## Filed

#329: under `FEATURES=xattr`, `phase_path` does not append
`ebuild-helpers/xattr` the way real `_doebuild_path` does
(`doebuild.py:346-348`). So a phase's `install` drops xattrs that real
keeps, and native `install.py` is unreachable from a phase. That is why
the plan asked for this check.
