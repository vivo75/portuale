## Harness notes (deviations from the plan's §2 script)

1. `scripts/run.sh` takes `PM=portage|portuale` from the environment (PATH
   prefix + provenance lines in `.env`). `scripts/snap.sh` records `fif`/`sock`/
   `dev` nodes by type only (the first F1 run hung `md5sum` on the fifo).
2. `t355-app` uses `exeinto /usr/bin; doexe` instead of `dobin`: portuale's
   `dobin` fails unprivileged (`install: cannot change ownership …: Operation
   not permitted`, first P1-pl-3 capture, since overwritten by the re-run).
   Out of scope (ebuild-helper territory, 02.346's family); install images are
   byte-identical either way, and all P cells were re-run on both sides with the
   fixed ebuild so both PMs used identical ebuilds.
3. `t355-f1` needs `dodir /usr/share/t355` before `mkfifo` (first F1a-pg-1
   capture, rc=1, since overwritten).
4. `portageq owners` needs the path rooted at `<eroot>`:
   `portageq owners $R $R/usr/share/t355/a\ b.txt`. The in-cell `S1-*-owners`
   captures (rc=1) ran after `-C` had removed the package and are superseded by
   the `S1q-*` supplement (merge + decoy + owners while installed, both PMs).
5. `U1a`/`U1b` edit `make.conf` (`UNINSTALL_IGNORE` literal vs append form)
   around the `-C` run only, restored afterwards (see `mc_set`/`mc_restore` in
   `scripts/cells.sh`).

## Source-only verdicts

- **U2 (R1 packdebug).** `vartree.py:2926-2931`: under `"packdebug" in
  self.settings.features`, `uninstall_ignore += f" {PACKDEBUG_PATH}/*"`;
  `const.py:113`: `PACKDEBUG_PATH = "/usr/lib/debug/.tarball"`. portuale has no
  packdebug handling in any merge/unmerge path (only the phase-env allow-list
  entry `phase_environ.rs:105`, which merely passes the name through). Verdict:
  Portage would keep the tarball dir (`--- cfgpro`); portuale would remove it.
  Not run (portuale never writes the tarball; confirmed by code absence).
- **F2 (R7 `dev`).** Orphan arm (`vartree.py:3098-3111`) unlinks any
  non-directory that is not a symlink-to-a-directory and not protected — a dev
  node qualifies (`<<<` under default FEATURES, like the F1a fifo). Under
  `-unmerge-orphans` the `dev` arm (`:3229-3230`) keeps it (`---`). portuale's
  orphan arm covers only `obj`/`sym`, so it would keep the node in both modes.
  Not run (needs `CAP_MKNOD`; no sudo per task brief, Q8 default).

## Stop-rule evaluation (plan S0)

The slice stop rule fires when a cell shows portuale already matching where §0
predicts a divergence (drop the rule), or when Portage contradicts §0 (capture
wins; stop for the owner only if the item's premise is gone). No item premise
is gone; all firing is of the refine-and-continue kind:

- (a) **E1**: Portage contradicts the *cell design* (merge backs the symlink
  aside to `link.backup.0000`; R4/R4b never reached). The R4/R4b premise stands
  (E2/E3/D-cells reach it). E1-as-designed cannot pin S5's "another owner keeps
  it" half — S5 needs a redesigned probe (e.g. an owner via a path Portage's
  implicit-parent `getcontents` attributes to the symlink path).
- (b) **C1b**: Portage *removes* `/bin` when no other package records it (R4b
  second half at `bin` scale) — §0/C1 text does not predict this. The C1a
  must-survive property (the S4 failing-first test) is unaffected.
- (c) **Outcome-coinciding rules stay**: E3/E3b (PL unlinks via the mtime arm),
  F1b, T3b (file kept on both, but PL hard-errors and leaves a stale vdb), C1a.
  In each, the Portage rule is still absent in portuale — verified by mechanism
  (E1-pl-2/T1a-pl-2/T3a-pl-2 hard errors; F1a), not just by outcome. Nothing is
  dropped from S3–S5.
- (d) **Plan-text corrections**: U1a "both kept" shorthand (literal form drops
  the make.globals default — the plan text itself says so); E3b parenthetical
  (portuale prints no per-file unmerge lines at all, so it cannot print an R4b
  elog). The #354 matrix "Not established" fif/dev line is now established by
  F1a/F1b (plus F2 by source): default unlinks, `-unmerge-orphans` keeps.
