## What changed (portuale)

**S8.1, the server's identity and the read-only gates.**
- The server takes the SHA-256 and the ELF `e_machine` of the binary it
  ships: `current_exe()`, or `--remote-portuale-binary`.
- Preflight reports, for each candidate, its full digest or `missing`.
  The candidates are `portuale` and `portuale-<hash16>` in `/opt/bin`,
  then `/usr/local/bin`, or only the `--remote-portuale-dir` pair.
  Preflight also reports `uname -m`, and each directory's existence,
  writability and mode.
- The tool floor gains `sha256sum`, `mv`, `uname` and `mktemp`.
- Gates (`evaluate_bin_gates`):
  - the first full-digest match is used;
  - with no match, an install is planned in the first usable directory;
  - a mismatched plain `portuale` is reported and left alone;
  - a corrupted `portuale-<hash>` is replaced;
  - an arch mismatch fails, naming `--remote-portuale-binary`;
  - with no usable directory, preflight fails, naming
    `--remote-portuale-dir` and the root-login alternative;
  - a world-writable directory without the sticky bit is refused.

**S8.2, the install stage.**
- It runs only when a unit ships, after the read-only stages, and never
  under `--pretend`.
- The steps are: `mktemp`, stream, `chmod 0755`, re-check the digest,
  `mv`, then `__helper ping`, which must print the D8 token.
- A failure removes the temp file before any unit streams.
- The status line is `portuale-remote: install-bin 0`. A reuse prints
  nothing.

**S8.3, an absolute path everywhere.**
- The phase, postinst-regen and merge scripts and the old-hook driver
  export `PORTUALE_BIN=<abs>` and `PORTAGE_PYM_PATH=/`, unset
  `PORTAGE_IPC_DAEMON`, and set
  `PORTAGE_PYTHON="$UNITBIN/portuale-python"`. It was `/usr/bin/python`.
- The local transport keeps `current_exe()`.
- A test generates every script kind and finds no bare `portuale` call.

**S8.4.** `docs/remote-merge.md` §1, §2, §5.5 (stage 3b), §6 (the exact
tool floor), §9 (the install writes outside ROOT and is unowned; Q6), and
§10 (the two new options).

**S8.5.** The bundle runtime is copied with `cp -aL`, so it ships real
files, never an overlay's symlinks.

## Review correction

`run_raw_command` (the `mktemp`/`mv`/`rm`/`sha256sum`/`chmod`/ping and
`cat`/`tar` path) appended its argv words to `ssh` unquoted. ssh joins
them with spaces for the remote shell, so a client path with spaces or
metacharacters (now reachable through a user-supplied
`--remote-portuale-dir`) would split or expand. Each word is now
`sh_quote`d. Every existing caller passes plain argv words, so their
behaviour is unchanged. The l31 bed, which uses real ssh, is green after
the change.
