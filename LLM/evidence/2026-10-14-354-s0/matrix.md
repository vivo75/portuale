## Mechanism (the same for every cell)

1. treewalk (4352) puts the old instance of the same CPV into `others_in_slot` (4525-4529) and
   makes it `_installed_instance` (4570-4579).
2. The new image is merged first (`_merge_contents`, 5114). The new vdb entry is built in
   `dbtmpdir` and gets a fresh `counter_tick()` COUNTER (5075-5084).
3. The old instance is then unmerged through the regular `dblink.unmerge` (5190-5222), with
   `others_in_slot=[new]`. Inside `_unmerge_pkgfiles` (2869), every old CONTENTS entry is
   handled by the first arm below that applies:
   - not under EROOT: `!prefix`, kept (3016-3018).
   - missing on disk: `!found` (3031-3033).
   - matches UNINSTALL_IGNORE (default `/lib/modules/*`, make.globals:93), or is a /lib or
     /usr/lib symlink: kept, label `cfgpro` (3037-3049).
   - **the path is owned by the new instance** (`isowner`): `--- replaced`, kept (3052-3092).
     This covers type changes too: obj to sym and sym to obj.
   - **FEATURES=unmerge-orphans** (the default) and the path is not a directory, not a symlink to
     a directory, and **not CONFIG_PROTECTed**: unlinked with **no mtime and no md5 check**
     (3096-3112).
   - otherwise, a non-dir/fif/dev entry whose mtime differs from CONTENTS: `!mtime`, kept (3114-3119).
   - dir: collected for `_unmerge_dirs`, which runs `rmdir` and labels a non-empty one `!empty`
     (3121-3125, 3232, 3370-3446).
   - sym: unlinked. The `!empty` guard applies only to a symlink to a directory that holds
     files not owned by it (3126-3199).
   - obj: md5 differs from CONTENTS: `!md5`, kept. Otherwise unlinked (3200-3223).
4. The old vdb dir is deleted and `dbtmpdir` is moved into place (5216-5241).
5. There is no separate code path for a same-version reinstall. The upgrade control (cell h)
   gives identical per-file results. The version difference only matters for confmem: a
   downgrade forces `cfgfiledict["IGNORE"]=1` (5105-5112).

## The rule for the implementer

On replace (same version or not), each path in the old CONTENTS that the new CONTENTS also lists
is left alone. That includes type changes and libraries kept by preserve-libs, which are added to
the new CONTENTS before the unmerge. Every other path is unmerged:
- **Unprotected file or symlink, default `unmerge-orphans`:** deleted unconditionally, even when
  modified on disk.
- **Unprotected, with `-unmerge-orphans`:** deleted only if both the mtime and the md5 (for a
  symlink, the mtime) still match CONTENTS. Otherwise it is kept.
- **Path under CONFIG_PROTECT and not under CONFIG_PROTECT_MASK:** deleted only if the mtime and
  the md5 match CONTENTS (unmodified). A modified one (`!mtime` or `!md5`) is left on disk, owned
  by no package.
- **Directories** are removed when empty and not owned by the new instance.

Protected files present in both images: overwritten if the disk copy is unmodified relative to the
old CONTENTS (config-protect-if-modified). Otherwise the image goes to `._cfgNNNN_<name>` unless
the md5 values are identical.

## S0.9: keepdir, EAPI 7 vs 8

Argv: `ebuild /var/tmp/t354/repo/app-misc/t354-kd/t354-kd-{7,8}.ebuild clean install`, then `... qmerge`,
with PORTAGE_VERBOSE=1. Captures: `cells/K{7,8}-{install,qmerge}.*` and `cells/K{7,8}.tree`.

- **keepdir behaves identically in both EAPIs.** The helper is `dodir` plus an empty
  `.keep_${CATEGORY}_${PN}-${SLOT%/*}` file (`/usr/lib/portage/python3.14/ebuild-helpers/keepdir:11-17`).
  Both EAPIs merge `/var/lib/t354kd/.keep_app-misc_t354-kd-0` and
  `/usr/share/t354kd/kept/.keep_app-misc_t354-kd-0` as `obj ... d41d8cd9...` with the same `dir` lines.
  A zero-size `.keep*` file is never config-protected (vartree.py:5592-5597).
- **The difference is empty directories without keepdir.**
  - `eapi.sh:92`: `___eapi_has_strict_keepdir` is true for EAPI != 0-7.
  - When it is true, `install-qa-check.d/95empty-dirs:22-28` runs `find ${ED} -type d -empty -delete`.
  - EAPI 7 keeps `usr/share/t354kd/emptydodir` and `var/t354kd-emptyvar` in the image, merges
    them, and records them as `dir` in CONTENTS.
  - EAPI 8 strips both from the image, so they are absent from ROOT and from CONTENTS.
  - `FEATURES=strict-keepdir` turns this on for EAPI 7 as well (95empty-dirs:22).
  - Both EAPIs print the `QA Notice: One or more empty directories installed to /var` for
    `/var/t354kd-emptyvar` (95empty-dirs:27-40).
- This is all bash that Portage ships, so a PM that runs Portage's own install-qa-check gets the same result.
