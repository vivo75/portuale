## The port

`helpers/gpkg.rs` is `gpkg-helper.py` (`main`, `command_compose`) plus,
from `gpkg.py`:
- `compress`, `_add_metadata`, `_add_manifest`, `_add_signature`,
  `_record_checksum`;
- `_generate_metadata_from_dir`, `_check_pre_image_files`,
  `_get_tar_format_from_stats`, `_get_binary_cmd`;
- `tar_stream_writer`, `checksum_helper` (signing).

It writes tar headers by hand, following `tarfile.TarInfo.tobuf`:
- USTAR directory names keep the trailing `/`;
- `_posix_split_name` splits long names into prefix and name;
- GNU `L`/`K` blocks are emitted only above 100 bytes;
- numbers overflow into base-256 only in GNU format.

The `tar` crate cannot produce these. The container format covers
`gpkg-1`, the `.sig` members and `Manifest`. It switches to GNU when the
basename has 154 or more characters. The `metadata.tar` member header is
always USTAR, and the `image.tar` header carries the image tar's format.

metadata is copied in sorted order onto `/dev/shm`, and the image is

  `oracle_basename_154_gnu_container`; `oracle_basename_153_stays_ustar`;

- the image walk reversed instead of sorted: only `oracle_special` fails,
  the one case with several entries per directory (my proof). A first
  attempt that skipped the rebuild passed, because `cargo test` does not
  rebuild the spawned `target/release/portuale`.

## Settings reach the helper

Real's helper rebuilds `portage.settings` from the config files. The
native one has no config loader (D7). It reads the process env over the
`make.globals` defaults.
- `BINPKG_COMPRESS`, `BINPKG_COMPRESS_FLAGS[_<NAME>]` and
  `BINPKG_GPG_SIGNING_*` were exported by `invoke_dyn_package` but dropped
  by the calling-env filter in the `package` phase. Python had hidden this
  by re-reading make.conf. Symptom: four `test_emerge_buildpkgonly_*`
  contract tests produced zstd instead of gzip.
- Fix: `ebuild_phases::gpkg_helper_setting` exempts exactly these keys,
  and only in the `package` phase.
- Side effect: they are visible in the `package` phase env, where real's
  `environ_filter` drops the compression three. No ebuild code runs in
  that phase, and its environment is not saved.
- `MAKEOPTS` from make.conf/profile is now exported when the calling env
  lacks it. A make.conf `-j5` gives `zstd -T5`; it gave `-T32` before.
  The `quickpkg_from_vdb` path may still miss it: #328, unverified.
