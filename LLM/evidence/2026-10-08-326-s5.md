## Review corrections (relative to the implementing agent's port)

Both were found by reading real `xpak.py` and confirmed with live
probes.
- `addtolist`'s UTF-8 checks only fire on `bytes`, and `os.walk` yields
  `str`. So real does not skip non-UTF-8 names: it sorts them by code
  point and packs them with `backslashreplace` (`\udcff`). The brief
  had said "skip"; that was wrong.
- `recompose_mem` breaks a hardlink with a content-only `copyfile`.
  Its `apply_stat_permissions(self.file, …)` targets the original path
  before the rename, so the new file ends up `0o666 & ~umask` with the
  caller's owner, not the old file's mode.

## Merge side: XPAK members verbatim

The L2 xpak control (portuale merging portage-built xpak) showed two
VDB rows:
- `DEBUGBUILD` was `""` in real and `"\n"` in portuale;
- the trailing space of the last `NEEDED` line was lost.

`extract_binpkg` reserialized scalar members as `trim + "\n"`. Real
`tbz2.unpackinfo` (`xpak.py:486-524`) writes them verbatim, and now so
does portuale. A leading `/` is stripped, a name escaping with `..` is
skipped, and parent dirs are created. `read_xpak_member_raw` is gone,
because nothing used it any more.
