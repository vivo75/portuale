## What was wrong

With `--binpkg-respect-use` (or equivalent: `--newuse`, `--reinstall=changed-use`)
and a user `package.use` line no binary build's baked USE satisfies, Portage 3.0.82.2
prints rc 1 + `!!! All ebuilds that could satisfy "dev-libs/t341-dep" … have been
masked.` + one cpv-deduped `- dev-libs/t341-dep-1::t341 (masked by: use flag
configuration mismatch)` row. Portuale printed rc 1 +
`emerge: there are no binary packages to satisfy "dev-libs/t341-dep"`.

Root cause (as S3 §4 diagnosed): `binary_candidates.retain(binpkg_respect_use_ok)`
in `crates/portage-repo/src/resolve/pretend.rs` drops the mismatched binaries before
the masked report sees them, and `masked_rows_for_pool` bails (`None`) whenever any
version-matching pool member `is_visible` — a USE-mismatched binary *is* visible, so
the top-level `--usepkgonly` path fell through to the plain miss. Portage models the
same binaries as masked: built pkgs whose `ignored_binaries` carry `respect_use` get
`mreasons = ["use flag configuration mismatch"]`, and only when no other mask fires
(`elif pkg.built and not mreasons and …`, `lib/_emerge/depgraph.py:6658-6663` in
`_show_unsatisfied_dep`; rows cpv-deduped in `show_masked_packages`, `:12453`).
