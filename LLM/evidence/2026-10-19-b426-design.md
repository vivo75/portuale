# #426 design: the failed-build endgame (S-22)

Ground truth: `LLM/evidence/2026-10-19-b423/portage.txt` (re-captured cleanly 2026-10-20, host Portage 3.0.82.2,
`EMERGE_DEFAULT_OPTS=--package-moves=n`, one process per cell; `cells.sh`/`setup.sh` there) against
`portuale.txt` (current binary). Portage source: `Scheduler.py` 1148-1163, 1280-1448, 2366-2382, 2435-2540;
`depgraph.py` 12285-12406.

## What Portage prints (cells kg-bad-good-top, nokg-bad-good-top, kg-bad-only, kg-bad-good-jobs)

1. Right after a failed phase, on **stdout**: `\n>>> Failed to emerge <cpv> for <ROOT>/, Log file:\n\n>>>  '<T>/build.log'\n`
   (foreground and background alike; portuale's accepted `ROOT` display has no trailing `/`).
2. Under `--keep-going`, when more packages are left: `*** Resuming merge...` / `Calculating dependencies ... done!` /
   `Dependency resolution took <s> s.` / blank, then for every package that can no longer be built
   ` * emerge --keep-going: <cpv> for <ROOT>/ dropped because` + ` * it requires <atom>` (stdout, wrapped at 75
   columns), a blank line, and the progress counter restarts: `>>> Emerging (1 of 1) dev-util/good-1...`.
   With `-jN` the banner appears after the running jobs end (cell kg-bad-good-jobs).
3. A package that still merges after a failure is recorded in `world` and the run ends with the normal
   post-merge steps (`* GNU info directory index is up-to-date.`).
4. At the very end, on **stdout**, the elog summary: ` * Messages for package <cpv> merged to <ROOT>/:` for the failed
   build (the `ERROR:` block of the dying phase) and for each dropped package (the `emerge --keep-going` text).
5. On **stderr**, only when 2+ packages failed or one failed under `--keep-going`:
   `\n * \n * The following [N ]package[s] ha[s|ve] failed to build, install, or execute\n * postinst:\n * \n`
   then one ` *  (<cpv>:<slot>/<sub>::<repo>, ebuild scheduled for merge to '<ROOT>/')` row per package, `, Log file:`
   and ` *   '<build.log>'` after built-and-failed ones only (dropped packages have a bare row), then ` * `.
6. Nothing else: no `The resume list contains packages...`, no `emerge: N package(s) failed to merge`, no
   `----- last lines of ... -----` dump. Exit code 1.

## Current portuale gaps (portuale.txt)

- no step-1 block (foreground source builds have no announced log), no steps 2-4;
- stderr carries portuale-only text (`The resume list contains...`, `emerge: ... failed to merge (--keep-going):`,
  `1 dependent package(s) not merged`, the `last lines of` dump at `emerge_build/scheduler.rs:107`);
- the successful packages after a failure are not recorded in `world` and no post-merge info step runs
  (`pretend/merge_run.rs:62-101` returns early);
- the progress counter keeps the original `(2 of 3)` instead of restarting at `(1 of 1)`.

## Plan (two slices, each ending with a clean tree)

- **S-22a** steps 1, 5, 6 for every failing source build (serial fg, serial captured, `-jN` scheduler): the
  `>>> Failed to emerge` block with the real `${T}/build.log` path, the Portage stderr summary replacing the
  portuale-only text, no `last lines` dump.
- **S-22b** steps 2, 3, 4 under `--keep-going`: resume banner and `Calculating dependencies` notice, the
  dropped-package notice (also kept as that package's elog for step 4), counter restart, `world` + post-merge info
  for what merged, and the end-of-run `Messages for package` blocks.
