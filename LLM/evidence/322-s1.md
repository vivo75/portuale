## As built, against the plan

- `portage_checkout()` is **unchanged** (still `PathBuf`): once `repo_root()`
  cannot panic, a missing checkout is a nonexistent path, which every caller
  already tests for. The planned `Option` would have added nothing.
- `repo_root()` returns the compiled-in path when the tree is gone (never
  panics); `bin_dir()` returns `Result<&Path, String>`; `resolve_bin_dir` is the
  pure resolver; `require_phase_runtime()` is the gate.
- Gates: `run_remote` (explicit `--remote-binpkg`, before the first
  connection), `run_remote_plan` (any merge-bound entry), `run_merge_plan`
  (source builds only: a hookless local binary merge never spawns a shell and
  must keep working).
- **Correction to the plan text:** the resolve path's read-only client
  preflight (stage 2) runs *before* the resolve, so on that path the gate comes
  after the preflight, not before any contact. It still comes before any unit
  ships or any write. The pmtest pin asserts that order.
