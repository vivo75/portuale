## Finding against the plan: the transition table has nothing to fall back to

The embedded runtime (#322, `extract_embedded_runtime`,
`rust/portuale/src/ebuild_phases.rs:869`) writes the vendored `bin/`,
which holds 19 entries. The only Python script among them is
`filter-bash-environment.py`. `doins.py`, `gpkg-helper.py`,
`xpak-helper.py`, `xattr-helper.py`, `install.py` and `dohtml.py` are not
vendored. Plan D1 says a script with no native port yet "is re-executed
with the real interpreter, with the original argv". The original argv
names `$PORTAGE_BIN_PATH/<script>.py`, which does not exist on a bare
binary. So on [noportage] the S2–S6 transition rows fail exactly as above
until their own slice lands. D2's `PORTUALE_PYTHON_HELPERS=real` oracle
mode needs those scripts too.

All of these scripts except `filter-bash-environment.py` also import the
`portage` library (`doins.py:36-37`, `gpkg-helper.py:19`,
`xpak-helper.py:19`, `xattr-helper.py:32`, `install.py:23`,
`dohtml.py:45` in `3rdparty/portage/bin/`), so vendoring the files alone
would not help.
