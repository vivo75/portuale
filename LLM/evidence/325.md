# #325 — a refused helper exec does not fail the phase: same as real Portage

Date 2026-10-07. Probe, run with identical ebuild and options on both sides
(`PORTAGE_TMPDIR=/var/tmp/r325/w`, ebuild in a throwaway repo, host real
`/usr/bin/ebuild --skip-manifest nx-1.0.ebuild clean install` vs
`portuale ebuild nx-1.0.ebuild install`):

```
EAPI=8
DESCRIPTION="rc 126 repro"
SLOT="0"
KEYWORDS="amd64"
S="${WORKDIR}"
src_install() {
	printf '#!/bin/sh\nexit 0\n' > "${T}/helper" || die
	chmod 644 "${T}/helper"
	"${T}/helper"
}
```

`src_install` ends with a call to a file that is not executable (bash status
126, `Permission denied`).

| side | output | rc |
|------|--------|----|
| real Portage (host) | `.../temp/helper: Permission denied`, then `>>> Completed installing dev-libs/nx-1.0 into .../image` | 0 |
| portuale | `.../temp/helper: Permission denied`, then `Final size of installed tree: 1 KiB` | 0 |

Both swallow it: `src_install` is the same bash function in the same vendored
`ebuild.sh`, and a function whose last command returns 126 is not treated as a
failure by that machinery in either. So the observation in #324 (phase rc 0
with a refused `doins`) is real Portage behaviour, not a portuale divergence.
Helpers that run and fail do fail the phase (`doins failed`, rc 1).

No code change. Closed as withdrawn.
