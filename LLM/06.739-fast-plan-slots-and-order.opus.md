## 2. #739 and #742 — the rule

Today `narrow_slotless` (`lib.rs`) keeps, for an atom without a slot that matches more than one slot, the visible slots that are already installed, and the best slot only when none is. This is right for a *check* (an installed slot meets the atom) and wrong for a *plan* (property 3: the newest visible version wins, so its slot is wanted even when an older slot is installed; the resolver does this, #739 evidence).

**Rule (default; the owner confirms or changes it at review):**

- In plan modes (`Options::rebuilds == true`: `--plan-world` including `=emptytree`) an atom without a slot reaches the **best visible slot only** (the order of `rank`: visible first, then highest version, then repo priority). An older installed slot is listed only if another atom reaches it (an atom with that slot, or a dependency).
- In check mode (`rebuilds == false`: `--check-world`) nothing changes: the installed-first narrowing stays.

Grounding: charter property 3; `LLM/backlog-tasks.md` #739 (resolver adds `wine-staging:11.21`), #742 (`mrg -pe @world` lists only `dualslotpkg:2`).

## 3. #743 — a `||` build dependency is merged after its provider

Finding (`pmtest` `differential-test-bed/logs/l0-health-20261112T224433Z`, plan `plans/FAST_world.json`, findings in `health.jsonl`): `dev-perl/PerlIO-utf8_strict-0.10.0` has `BDEPEND virtual/perl-ExtUtils-MakeMaker`, whose `RDEPEND || ( =dev-lang/perl-5.44* ~perl-core/ExtUtils-MakeMaker-7.780.0 )` is met only by `dev-lang/perl-5.44.0`; the plan merges perl at #45, the virtual at #18. Two hypotheses; S0b decides which, with a fixture, not by reading the code:

- (a) **missing edge:** `dependency_atoms` resolves the `||` group to one branch (`branch_preference`: installed beats available by `cat/pkg`, ties go to the first). The branch it follows is not the one the final set satisfies it with, so no edge points to the changed `perl` slot.
- (b) **cut cycle:** the edge exists, but `depend_order` (depth-first in name order, an edge back into a node being walked is dropped) meets the cycle perl → … → `virtual/perl-*` → perl from the other side and cuts the wrong edge, so the virtual is listed first.

World: `w743user`, `w743prov`. Run `--plan-world --sort depend --json` and feed it to `python3 ../pmtest/pytests-contract-suite/health_checker.py --vdb ROOT plan.json`. A second fixture for (b): add `RDEPEND="w743user"` to `w743prov` so the three form a cycle through a `BDEPEND`. Neither reproduces → STOP (§0).

### B1 — the fix, as diagnosed

Pick by S0b, with the red test from S0b turned into a pin:

- (a): when a `||` group has a branch whose package the plan changes (is a key of `World::reached` and has a change), the order uses that branch's edge too. Prefer a small, local change in `order.rs` (`ordering_edges`) or in `dependency_atoms` (`edge_kinds`), not a second resolution pass. The install-first preference for the *set of packages followed* stays (it decides what is reached); only the ordering gains the extra edge.
- (b): cut a cycle at an edge a PMS-weaker kind carries: `RDEPEND`/`PDEPEND` before `DEPEND`/`BDEPEND` (the checker's own rule: a runtime cycle counts as usable). `World::edge_kinds` already holds the kinds. Replace "drop the edge back into the node being walked" by "among the edges of the cycle drop a runtime-only one if any".

Test names: `a_build_dependency_on_an_or_group_is_ordered_after_the_changed_branch` (a) or `a_cycle_is_cut_on_a_runtime_edge_first` (b), in `order.rs`. Command: `cargo test --release -p portage-world order` — red before, green after. Then `cargo test --release -p portuale plan_world`: all existing pins stay (the order of the unaffected tests must not move; a moved row is a finding, not a bless).

Check: re-run `health_checker.py` on the S0b fixture plan: 0 `build-order` findings. On the host: `mrg --plan-world --sort depend --json > fast2.json; python3 ../pmtest/pytests-contract-suite/health_checker.py --vdb /var/db/pkg fast2.json`: the failures must not grow beyond S0's (the host plan has none today).
