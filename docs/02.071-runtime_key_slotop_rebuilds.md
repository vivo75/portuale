## 1. What real Portage does (source-grounded, and what is still open)

The #65 S0/S1/S2 work established the option gate and the build-time
half (`depgraph.py:97-103`, `:4194-4247`, `:3089-3132`, `:3802-3806`).
The runtime keys (`RDEPEND`/`PDEPEND`/`IDEPEND`) were deliberately left
with the wide `reachable` gate because the argument-shape matrix shows a
non-uniform rule. The rule to implement is exactly the merge set real
produces per argument shape, deduplicating the ABI listing rows (the
no-root `[ebuild rR]` lines real prints between the merge list and
`Total:`).

From the committed captures
(`TEST/logs/l0-fx-20260916T153720Z/real/`, `-uDvN --oneshot <consX>`,
bdeps auto; provpkg upgrades 1.0:0/1 → 2.0:0/2; five installed
consumers, one per dep key, the other four world-only):

| argument | real merge set (rows) | real ABI listing (no-root rows) |
|---|---|---|
| `consrdep` (RDEPEND) | consrdep, conspdep | consrdep, conspdep |
| `conspdep` (PDEPEND) | conspdep, consrdep | consrdep, conspdep |
| `consdep` (DEPEND) | consdep, considep | considep, consrdep, conspdep |
| `consbdep` (BDEPEND) | consbdep, considep | considep, consrdep, conspdep |
| `considep` (IDEPEND) | considep | considep, consrdep, conspdep |
| `@world` | all five | considep, consrdep, conspdep |

Portuale S2 scans every `slot_op_reachable` runtime consumer, so it
prints all runtime consumers in every argument cell; the comparator
counts real's listing rows as present, which is why only the two
`considep` extras (`consrdep`/`conspdep` argument shapes) are
allowlisted as `slotop-idepend-world-only-arg-consumer`. The observable
rule from the captures: **the world-only `considep` is rebuilt when a
build-time or IDEPEND consumer is the argument, never when an
RDEPEND/PDEPEND consumer is.** The S0 note already hints the mechanism:
the `--debug` `_slot_operator_deps` dump carries
`buildtime_slot_op`/`runtime_slot_op`/`runtime_post` only for consumers
the walk reached non-optionally; the rest stay `optional`.

Real's moving parts for S0 to trace: `_add_pkg` sets
`dep.want_update = not complete_mode and (arg_atoms or update) and not
too_deep(depth)` and registers every `:=` dep in `_slot_operator_deps`
(`:3796-3817`, `:4143-4148`); `_process_slot_conflicts` calls
`_slot_operator_trigger_reinstalls` (`:2107-2132`); that trigger probes
registered deps (`:3089-3132`) and `_slot_operator_update_backtrack`
adds the dep's **parent** (the consumer) to
`slot_operator_replace_installed` (`:2400-2451`); the
`backtrack: 2/20` in every argument capture means the merge set is the
fixpoint of a restart, not a single pass.

## 2. Portuale today

`slot_operator_rebuild_scan`'s dep-key gate is
`with_bdeps && walked.contains(cp) → all five keys, else the three
runtime keys`, where `walked` is every cp in this pass's `entries` (the
argument-reached set; the world-only consumers are not in it in the
argument shape). Runtime consumers are gated only by `reachable`
(`slot_op_reachable`, the complete-mode required-set closure), so
`considep` is always scheduled. `slot_operator_slot_change_probe` is a
different mechanism (merge-bound parents) and must stay untouched.

## 8. Risks

- **Over-narrowing the runtime keys** regresses the `@world` shape
  (all five) and the host `@world` (the 19 Go consumers are gone, but
  runtime cascades must not move). The six-cell Rust matrix and the bed
  are the guard.
- **Heuristic lock-in.** The captures are one provider/five-consumer
  fixture; if S0's rule is only a fit to this matrix, a second provider
  or a consumer with two providers can break it. S0 must state the
  mechanism in real's terms (registered dep + probe), and S1's comment
  must say which real condition it mirrors.
- **Restart artifacts.** `backtrack: 2/20` differences between cells
  could make the rule pass-order dependent; if so, the deterministic
  projection is what S0 must define, and the `--backtrack=0` cells
  should be captured as a control.
