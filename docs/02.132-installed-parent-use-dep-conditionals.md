## 1. The defect, stated once

### What is wrong

`rust/portage-repo/src/lib.rs`, `fn enqueue_dependencies` — the
`--deep` recursion into an **already-installed** package's own
dependencies — flattens that package's dep string against its vdb `USE`
(correct, #74/`deepvdbusepkg` pinned it) and then queues each resulting
token **without evaluating the token's own conditional use-deps**. The
code says so itself, in a comment that has been sitting there since
before `--autounmask-use`:

```rust
// This path never calls `evaluate_atom_conditionals` at all (a
// real, pre-existing gap unrelated to `--autounmask-use`: an
// `AlreadyInstalled` package's own further-dependency walk under
// `--deep` doesn't evaluate conditional use-deps against its own
// USE either) -- so there's never an "unevaluated" form to
// preserve here.
```

So an installed parent's `~cat/child-1.2:6[wayland=]` reaches candidate
selection **verbatim**. `portage_dep::use_deps_satisfied` treats a
conditional form as "the flag must be declared, no state constraint"
(its own `conditional_forms_only_require_the_flag_be_declared_no_state_constraint`
test) — which is right for an *unevaluated* atom and is exactly why the
atom must never arrive unevaluated. Result: **every `[flag=]` /
`[flag?]` dependency of every installed package is vacuously satisfied
by whatever is installed**, on every `--deep` run.

### What real does

Real evaluates at flatten time, inside `use_reduce` itself: with
`token_class=Atom` each token gets `token.evaluate_conditionals(uselist)`,
and `depgraph._add_pkg_deps` passes `uselist=self._pkg_use_enabled(pkg)`,
which for a built package is `pkg._metadata["USE"]` — the vdb `USE`.
Everything downstream (candidate match, `_parent_atoms`,
`_show_unsatisfied_dep`) therefore sees the evaluated atom, and keeps the
raw one as `atom.unevaluated_atom` for display.

Captured, not read (#111 S0, `differential-test-bed/logs/l111-s0-20260921/`):
installed `dev-qt/qtdeclarative-6.11.2-r1` (built `-wayland
-accessibility`) declares
`~dev-qt/qtbase-6.11.2:6[accessibility=,gui,network=,opengl=,sql?,ssl?,vulkan=,wayland=,widgets=]`
(`real-rest-debug.log:6278`), real evaluates it to
`~dev-qt/qtbase-6.11.2:6[-accessibility,gui,network,opengl,sql,ssl,vulkan,-wayland,widgets]`
(`:6284`), installed qtbase was built `+wayland`, no pool can satisfy
`-wayland`, rc 1. Portuale evaluates nothing (`port-rest-debug.log:6004`
shows the raw atom), selects the installed `+wayland` qtbase as `Child`
(`:5990`), rc 0.

### Why this is not the display layer

Portuale's failure rendering already takes both forms: the
"no ebuilds built with USE flags to satisfy" block
(`use_unsat_candidates_for_atom`) is parameterised on
`display_atom` (unevaluated) **and** `evaluated_atom`, `QueueItem` already
carries an `unevaluated: Option<String>` field, and the main
New/Upgrade/Reinstall walk (`enqueue_flat_deps`) already populates both.
The candidate filters already check use-deps against a candidate's vdb
`USE` (`dependency_avoid_update_candidate`), a binary's baked `USE`
(`Candidate::binary_use`) and an ebuild's profile-folded USE. **Only the
one producer is missing.** That is why the fix is small and its
consequences are not.

### Blast radius, stated honestly

Every installed package with a conditional use-dep, on every `--deep`
run, starts imposing a constraint it never imposed. Expected direction:
portuale *rejects more*, i.e. more rebuilds and more aborts, converging
on real. Expected damage: any pin whose expectation encoded the lenient
behaviour. S2 measures it; nobody guesses it.

## 3. The three fixture arms, and why three

The live shape is one arm. It is not enough on its own: a fix that only
hardened the *failure* display would pass it. The arms separate the
three things that must all become true.

- **Arm A — abort.** Parent built `-flip`; the atom evaluates to
  `[-flip]`; the installed child is `+flip` **and** the profile enables
  `flip` for the child, so no ebuild candidate can satisfy `[-flip]`
  either. Real's three-pool USE failure, rc 1. This is #111's live
  shape, shrunk.
- **Arm B — rebuild.** Same parent shape, but no profile entry on the
  child, so the *ebuild* pool can satisfy `[-flip]`. Real must schedule
  a rebuild of the child with `flip` off rather than abort. This is the
  arm that proves the evaluated atom reaches **candidate selection**,
  not just the failure path.
- **Arm C — control.** Parent built `+flip`; the atom evaluates to
  `[flip]`; the installed `+flip` child satisfies it. Nothing changes.
  This is the arm that catches an over-broad fix that rejects installed
  candidates whenever any conditional use-dep is present.

### S5 — the fix (product code, one function)

- [ ] **Step 1: evaluate each token against the parent's vdb USE.** In

```rust

        // use-deps (`flag?`/`!flag?`/`flag=`/`!flag=`) against the
        // *parent's* USE before the token is ever classified or queued
        // -- `use_reduce(..., token_class=Atom)`'s own per-token
        // `token.evaluate_conditionals(uselist)` step, with `uselist` =
        // `_pkg_use_enabled(pkg)`, which for a built package is its vdb
        // `USE`. `use_flags` above is exactly that set (the same one
        // this function already flattens the dep string with). Without
        // this an installed parent's `foo[bar=]` reached the candidate
        // filters verbatim, where a conditional form imposes no state
        // constraint at all (`use_deps_satisfied`), so every such dep
        // was vacuously satisfied by whatever happened to be installed
        // (#111 S0: installed qtdeclarative built `-wayland` accepted
        // installed qtbase built `+wayland`, rc 0, where real aborts).
        // Applied before the blocker split, like `enqueue_flat_deps`
        // and like real -- a blocker atom can carry use-deps too.
        //
        // `raw` is kept for the two `root_deps_*` membership tests
        // below **only**: those sets come from
        // `root_deps_satisfied_atoms`/`unsatisfied_root_deps_atoms`,
        // which flatten the same metadata without evaluating, so they
        // are raw-keyed. Looking an evaluated token up in a raw-keyed

        // satisfied build dep. Evaluating those two producers as well
        // is real's own shape but widens this slice into the
        // `--root-deps` path; it is filed as a residue instead.

            Some(raw.clone())
        } else {

        };
        let tok = evaluated;
```
