## 1. What real Portage does (source-grounded)

- The auto-rebuild trigger is `_slot_operator_trigger_reinstalls`
  (`depgraph.py:3089-3132`), driven by
  `self._dynamic_config._slot_operator_deps`. Those entries are
  registered in `_add_pkg` (`:3801-3817`) only while walking a dep whose
  child is being added to the graph, and the trigger's probe
  (`_slot_operator_update_probe`, `:2576`) searches for a *replacement
  parent* (a similar available package) to rebuild against the new
  sub-slot.
- For a **built** package, `_add_pkg_deps` builds its dep tuple with
  `DEPEND`/`BDEPEND` marked `optional=(pkg.built or …)` and only
  `RDEPEND`/`IDEPEND`/`PDEPEND` as required priorities
  (`depgraph.py:4253-4289`; `self._priority(runtime=…)`,
  `runtime_post`, `buildtime=True, optional=(pkg.built …)`).
  An optional dep whose provider sub-slot moved away is therefore not a
  rebuild trigger — the consumer's link is simply dropped.
- Live confirmation: `app-containers/runc-1.4.3`'s vdb `BDEPEND` is
  `dev-go/go-md2man >=dev-lang/go-1.24.11:0/1.26.5= app-arch/unzip`; go
  updates to `1.27.1` and `emerge -puDvN --oneshot app-containers/runc`
  proposes **0 packages**. Portuale marks runc `rR` and rebuilds 20 Go
  consumers (`portuale-abi_rebuilds.json`).
- Required-key control: runtime consumers *are* rebuilt in place when a
  provider sub-slot moves (the `@__auto_slot_operator_replace_installed__`
  set) — this is what #24 shipped and must keep working.

## 2. Portuale today

`slot_operator_rebuild_scan` (`lib.rs:13090-13182`) scans every installed
package's vdb deps with

```rust
let mut providers: Vec<String> =
    ["RDEPEND", "PDEPEND", "DEPEND", "BDEPEND", "IDEPEND"]   // :13141
```

and schedules the consumer whenever the provider entry's `(slot,
sub_slot)` differs from the consumer's built `:S/SS=` atom. No
optionality/priority distinction exists in portuale's model, so
build-time deps cascade exactly like runtime ones. The separate
`slot_operator_slot_change_probe` (`:13211`, real `_slot_change_probe`,
bug 456208) reads all five keys of **merge-bound** parents' tree
metadata — that half is correct by construction (a merging parent's
build deps are required) and must not be narrowed.

The 20 spurious pairs all come from the `:13141` list; the same list also
drives the `r` bracket column and the "The following packages are
causing rebuilds" block (`pretend.rs:10755-10766`, `:11571-11630`).

## 3. Design

**S0 — oracle matrix.** Fixture: `provpkg-1.0:0/1` (installed) with a
tree `2.0:0/2` upgrade; installed consumers `cons{rdep,dep,bdep,pdep,idep}`
each with a built `:0/1=` atom in only one dep key; world = the
consumers. Capture real for each cell (`emerge -puDvN @world` on the
fixture-oracle tree and/or `--debug`'s
`slot operator dependencies:`/`forced rebuilds:` dump) and record:

| key | expected (to confirm) |
|---|---|
| RDEPEND `:=` | `rR` rebuild + abi pair |
| IDEPEND `:=` | to confirm (real priority is runtime+installtime, not optional) |
| PDEPEND `:=` | to confirm (runtime_post, not optional) |
| DEPEND `:=` | no rebuild |
| BDEPEND `:=` | no rebuild (host runc case) |

Also record the same matrix with `--usepkg` / binary consumers if cheap —
real empties `DEPEND`/`BDEPEND` for binaries without `--with-bdeps`
(`depgraph.py:4195-4247`), which portuale already models for the main
walk (`lib.rs:19708-19712`).

**S1 — narrow the installed-consumer key set.** In
`slot_operator_rebuild_scan`, replace the five-key list with the
non-optional keys the oracle confirms (expected
`["RDEPEND", "IDEPEND", "PDEPEND"]`), leaving the `slot_pullers` and
`GraphEntry::deps` plumbing untouched. Update the function's doc comment
(the current one explicitly claims "an installed package whose vdb
`*DEPEND` carries a built slot-operator atom … must be rebuilt" — that
claim is the bug).

**S2 — oracle pins + docs.** §5.

Design note: do **not** try to model `_slot_operator_update_probe`'s
replacement-parent search in this slice. The observed divergence is fully
explained by the key set; the probe's "rebuild only when the consumer has
a newer available version" subtlety can be a later refinement if an
oracle cell shows it matters (file as residue then).

## 8. Risks

- **Over-narrowing:** if `PDEPEND`/`IDEPEND` turn out to trigger in real,
  dropping them regresses a runtime-parity case. S0's matrix is the
  guard; do not guess.
- **Cascade interactions:** `abi_rebuilds` feeds the `r` column, the
  "causing rebuilds" block and merge order; a narrowed set changes the
  merge list on host-scale trees (that is the point), so the L0 bed and
  the host diff are part of done.
- **Backtracking:** #24's undo path (`_eliminate_rebuilds`, the
  `slot_operator_undone` latch) operates on whatever is scheduled; a
  narrower set can only reduce its inputs, but re-run the `slotop*`
  oracle pins to be sure.
