**Revision note.** The first version proposed dropping `DEPEND`/`BDEPEND`
from `slot_operator_rebuild_scan` unconditionally, on the theory that a
built package's build-time deps are "optional" and never trigger a
rebuild. That is wrong: with build-time deps walked
(`--ignore-default-opts`), real **does** rebuild `app-containers/runc`
(`rR`) through its `BDEPEND` `dev-lang/go:0/1.26.5=`. The real gate is
the `bdeps` parameter, plus (with build deps on) *which* consumers get
probed.

## 1. What real Portage does (source-grounded)

- **The `bdeps` gate.** `create_depgraph_params.py:97-103`:
  `myparams["bdeps"] = "auto"` only when `--with-bdeps` is unset,
  `--with-bdeps-auto != n` and `--usepkg` is not in effect
  (`--getbinpkg` implies `--usepkg`, `actions.py:3719-3720`).
  `_add_pkg_deps` (`depgraph.py:4194-4247`): for a built package with
  `bdeps` not `y`/`auto`, `ignore_build_time_deps = True`, and unless a
  `--rebuild-if-*` mode is active (`self._rebuild.rebuild`) `DEPEND` and
  `BDEPEND` are emptied **before** any dep is added. An emptied dep is
  never passed to `_add_pkg`, so it is never registered by
  `_add_slot_operator_dep` (`depgraph.py:3810-3815`) and can never trigger
  `_slot_operator_trigger_reinstalls` (`depgraph.py:3089-3132`).
- **Who gets probed when build deps are walked.** Every `:=` dep that
  reaches `_add_pkg` is registered, build-time or not. The trigger then
  only probes when `want_update_probe = dep.want_update or not
  dep.parent.installed` (`:3114`), and `dep.want_update = not
  complete_mode and (arg_atoms or update) and not too_deep(depth)`
  (`:3802-3806`). An installed consumer reached only through
  `_complete_graph` (complete mode) is not probed.
- **Live, host defaults (`--getbinpkg` ⇒ bdeps off), `@world`:** real
  `[binary gU] dev-lang/go-1.27.1-1` with **no `r` flag** and **no**
  consumer rebuilds. Portuale marks go `r` and rebuilds 20 Go consumers
  (`rR`) — the scan reads vdb `DEPEND`/`BDEPEND` regardless of
  `with_bdeps`.
- **Live, `--ignore-default-opts --oneshot app-containers/runc`** (bdeps
  auto): real `rR` only `dev-go/go-md2man` and `app-containers/runc`
  (both reached from the argument walk); portuale `rR` 18 Go consumers
  including world-only ones (helm, kubectl, podman, …).
- Runtime control: runtime consumers of a moved sub-slot are rebuilt
  (`@__auto_slot_operator_replace_installed__`); #24 shipped this and it
  must keep working.

## 2. Portuale today

`slot_operator_rebuild_scan` scans every **reachable** installed
package's vdb deps with a hardcoded
`["RDEPEND", "PDEPEND", "DEPEND", "BDEPEND", "IDEPEND"]` list and
schedules a consumer whenever the provider entry's `(slot, sub_slot)`
differs from the consumer's built `:S/SS=` atom. It takes no
`with_bdeps` argument. `reachable` is the complete-mode set (arguments
plus `@world`/`@selected`/`@system` forward-installed deps, #54), so it
also covers consumers real would reach only in complete mode.

`slot_operator_slot_change_probe` reads all five keys of **merge-bound**
parents' tree metadata. That half is correct by construction (a merging
parent's build deps are required, `optional=pkg.built` is false) and
must not be narrowed.

The same scan drives the `r` bracket column on the provider, the
"The following packages are causing rebuilds" block and merge order.

## 3. Design

**S0 — oracle matrix.** Fixture: `provpkg-1.0:0/1` installed with a tree
`2.0:0/2` upgrade; installed consumers `cons{rdep,dep,bdep,pdep,idep}`
each with a built `:0/1=` atom in exactly one dep key. Two reachability
shapes: (i) consumers in `@world` only, run `emerge -puDvN @world`;
(ii) one consumer given as the argument, run `emerge -puDvN --oneshot
<consumer>` with the other consumers in world. Each × three option
sets: default (bdeps auto), `--usepkg` (or `--with-bdeps=n`),
`--with-bdeps=y`. Stage the fixtures in
`TEST/layers/l0-fixture-oracle/stage.sh` in this slice. Record the
`rR`/`r` columns and `--debug`'s `slot operator dependencies:` dump.
Expected (to confirm, do not assume):

| key | bdeps off | bdeps on, argument-reached | bdeps on, world-only |
|---|---|---|---|
| RDEPEND `:=` | rebuild | rebuild | rebuild (via complete-mode conflict path, #24) |
| IDEPEND / PDEPEND `:=` | confirm | confirm | confirm |
| DEPEND / BDEPEND `:=` | **no rebuild** | **rebuild** (host runc) | **confirm** (host: no rebuild) |

**S1 — honour `with_bdeps`.** Thread `with_bdeps` into
`slot_operator_rebuild_scan` (all three callers already have
`ctx.with_bdeps` or the request's value) and read `DEPEND`/`BDEPEND` from
the vdb only when it is true. Keep `RDEPEND`/`PDEPEND`/`IDEPEND`
unconditional. Do not touch `slot_operator_slot_change_probe`. Update the
function's doc comment (cite `create_depgraph_params.py:97-103` and
`depgraph.py:4194-4247`). This alone removes all 20 host `@world` pairs
and the spurious `r` on `dev-lang/go`.

**S2 — build-time keys only for update-probed consumers (bdeps on).**
Only if S0's world-only BDEPEND cell confirms "no rebuild": when
`with_bdeps` is true, apply the `DEPEND`/`BDEPEND` half of the scan only
to consumers real would reach with `want_update` (the argument walk
under `--update`/argument atoms, within `--deep` depth), not the full
complete-mode `reachable` set. Candidate implementation: a second,
narrower reachability set computed from the non-complete walk (reuse the
walker's own visited set / `ResolveCtx::slot_op_reachable` machinery; no
second walker, per #54). If the oracle shows runtime keys follow the same
`want_update` rule, stop and report — that would widen the scope into
#24's territory.

**S3 — pins + docs.** §5.

## 8. Risks

- **Over-narrowing (S1):** `with_bdeps=true` must keep today's
  behaviour for DEPEND/BDEPEND; the runc probe is the guard.
- **S2 depth semantics:** `want_update` also depends on
  `--deep=<n>`/`_too_deep`; the oracle must include a bounded-depth
  cell if S2 is implemented.
- **Cascade interactions:** fewer scheduled rebuilds change the `r`
  column, the "causing rebuilds" block and merge order on host-scale
  trees (intended); the L0 bed and host diff are part of done.
