`remote.rs` import it (the `portuale` crate already depends on
`portage-repo` — `vdb_entry_slot` calls prove it); `split_installed_dir`'s
one call site calls `split_pf` directly. No behaviour change by
construction: the three bodies implement the identical rule
(`split('-')`, first `i` whose trailing join `ververify`s wins —
verified 2026-09-23 by diffing the bodies; only variable names and one
comment differ).

**Tests (TDD: write first, watch fail, then consolidate).**

## S2 (#126) — route `read_installed_slot` through `vdb_entry_slot`

**Merge-path safety gate: YES.**

**Where.** `rust/portuale/src/ebuild_merge.rs`, `pub(crate) fn
read_installed_slot(root, category, package, version) -> Option<String>`
— the third and last production direct `SLOT` read. It does
`read_to_string(.../SLOT)` + `.trim().split('/').next()`, so it misses
the #109 snapshot win and `_aux_get`'s normalisation — the same gap
#116 closed at the two named scans.

**Its five readers** (all compare `as_deref() == Some(slot)` except as
noted — grep `read_installed_slot` to re-enumerate on the day):

1. `installed_instance_pf` (same file) — same-slot "highest COUNTER"
   selection (`vartree.py:4409-4418`).
2. `find_collisions`' `own_versions` filter (same file) — same-slot
   ownership for `protect-owned`.
3. The merge replace-scan (same file, `replaced` loop) — same-slot
   predecessors unmerged on reinstall.
4. `ebuild_unmerge.rs` `others_in_slot` — same-slot survivors whose
   files must stay (`vartree.py` `unmerge`/`_unmerge_pkgfiles`).
5. `pretend.rs` preserved-libs consumer atoms — already
   `.unwrap_or_else(|| "0")`, i.e. it *assumes* the ruling below; the
   fallback becomes dead but stays (harmless, documents the real
   default).

**The change.** Build `pf = format!("{package}-{version}")`, read
`portage_repo::vdb_entry_slot(root, category, &pf)`, keep the main-slot
projection verbatim (`.split('/').next()`), then apply the **O5 ruling**:

> **O5 — ANSWERED 2026-09-23 by the owner.** A missing *or empty* `SLOT`
> reads as `Some("0")`, matching real `aux_get`'s invalid-`SLOT` → `"0"`
> translation (`vartree.py:967-972`), not merely real `_aux_get`'s `""`.
> A `SLOT`-less vdb entry therefore groups with slot-`"0"` entries in
> `others_in_slot`/`installed_instance_pf`/`find_collisions`, exactly as
> real's `dbapi.match("cp:0")` finds it. This folds #115's *empty*-SLOT
> half into this slice; #115 keeps the *invalid-nonempty*-SLOT half (a
> `SLOT` that is present but fails `_get_slot_re`, e.g. a collapsed
> multi-line value — no live instance, S0 probe (a)) and the `EAPI` /
> `_mtime_` thirds, so narrow the #115 entry to that when closing out.

Concretely: `""` (missing file, empty file, or an unsplittable `pf` —
the last cannot happen here since `pf` is constructed, say so) maps to
`Some("0")`; every non-empty value keeps today's projection untouched.
The function stays `Option<String>` (callers' `None` arms stay as the
"no such entry" shape — unreachable through current callers, which only
query listed installed versions; do not restructure them).

**Do not** touch the direct reads in `emerge_build.rs` /
`emerge_getbinpkg.rs` (test assertions, per #116) or the
