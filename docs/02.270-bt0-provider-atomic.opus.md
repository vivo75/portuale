## 2. Agent protocol (every slice)

All implementation goes through opencode, **one agent at a time, never in
parallel**, using the scripts in `portuale/helpers/`. No `pkill`/`pgrep`
(see `helpers/no-pkill.md`): the scope `oc-<slug>` is the only handle.

```
# briefs and logs live outside both repos (not tmpfs /tmp):
mkdir -p ~/repo/PORTUALE/oc-270/{briefs,logs}

# launch (in the background of the Bash tool; one at a time):
helpers/oc.sh <slug> <agent> <workdir> ~/repo/PORTUALE/oc-270/briefs/<slug>.md \
              ~/repo/PORTUALE/oc-270/logs/<slug>.log
# wait / health (read-only; exit 0 RUNNING, 1 STOPPED, 2 HUNG):
helpers/ocstatus.sh <slug> ~/repo/PORTUALE/oc-270/logs/<slug>.log 240
# only if HUNG, or to abort exactly that agent and its descendants:
helpers/ocstop.sh <slug>
```

- Before launching, confirm nothing else runs: `helpers/ocgrep.sh <slug-of-previous>`
  must print `STOPPED`. A new agent starts only after the previous scope is
  `STOPPED` **and** its log has been read.
- `HUNG` (empty log after 240 s): `ocstop.sh`, then relaunch the same brief once;
  a second hang goes to the owner.
- Agents by job (all `muse-*` in `~/.config/opencode/agents/`):

| Job | Agent | Writes? |
|---|---|---|
| verbatim real/portuale probe captures | `muse-probe-capture` | no |
| fixtures + md5-cache | `muse-fixture-smith` | pmtest fixtures only |
| code + tests | `muse-spark` | yes, only the files the brief names |
| fmt / clippy / test / pytest vs baseline | `muse-verify-pass` | no |
| L0 resolver / fixture-oracle beds | `muse-bed-runner` | no (reports) |
| read-only diff review | `muse-spark-ro` | no |
| close-out chores | `muse-closeout-scribe` | docs only |

- **The coordinator (this session) commits**, after reading the agent's log
  and re-running the slice's acceptance check itself — an agent's "green" is
  a claim, not evidence. Briefs state: exact files, exact acceptance
  command, "do not commit", "do not touch anything else", and the stop-and-ask
  triggers of §0.
- Diagnosis stays with the coordinator; `muse-probe-capture` only executes.
- No bed (L0) runs while another resolver bed step runs; no two agents ever
  overlap, so this holds by construction.
