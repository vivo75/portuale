## 2. Real mechanism — the backlog text is incomplete

The backlog says complete mode is enabled "only on an existing slot
conflict" (`depgraph.py:9446-9453` `_resolve_conflicts`). That is one
gate. `_complete_graph` itself (`3rdparty/portage/lib/_emerge/depgraph.py`
8562-8660) **also auto-enables complete mode** when
`complete_if_new_ver`/`complete_if_new_use`/`complete_if_new_slot`
(all default `y`) and a merge node changes an installed package's
version, USE or slot. `--update dev-libs/paired` (1.0 -> 2.0) therefore
does enter complete mode. What complete mode then walks is the point:

- it seeds from `_initial_arg_list` plus the **required sets**
  (`_required_set_names`: `@world`/`@selected`/`@system`), deep, with
  `_select_pkg_from_graph` (installed or already-graphed packages only);
- an installed consumer enters the graph only if it is **reachable from
  those seeds** over the installed dependency graph, or is a dep of a
  node already in the graph;
- the end-of-walk installed-satisfier loop (`_unsatisfied_deps`, ~8770)
  only reports deps of nodes that are in the graph.

`keeper` is in neither `@world` nor `@system` in the staged fixture, so
real never sees its `=paired-1.0` atom — except in the triangle, where
`othermod`'s `<paired-2.0` keeps installed `paired-1.0` in the graph and
the block names only `othermod` as its parent.

Portuale (`rust/portage-repo/src/lib.rs`):

- `reverse_dependency_constraints` (~12438) "scans the vdb for the
  consumers of each upgrade-bound `cat/pkg` directly" — **every**
  installed consumer, reachable or not — and splits them into enforced
  pins and dropped pins (the latter feed `build_residual_slot_conflicts`,
  ~14639). Called from the backtrack loop (~19707).
- `required_set_reachable_cps` (~13313) already computes exactly the
  reachable installed closure of `@world ∪ @selected ∪ @system`, and is
  used to gate slot-operator rebuilds (~16228). It is not applied to the
  reverse-dependency scan.
- `complete_graph_auto_enable` (~15647) mirrors real's auto-enable
  checks.

**Hypothesis (H):** the 511e659 docstrings ("verified live") came from a
live probe where keeper was reachable from `@world` (a merged package is
added to world). If so, both oracles are right under different world
states, and the fix is to restrict the consumer scan to reachable
consumers. S0 must confirm H before anything changes; the four contract
pins were written against the unconfirmed claim.
