## Finding truth about real Portage

- Run it, don't read it: translating an upstream `ResolverPlayground`
  case into a fixture and diffing beats reasoning from `depgraph.py` —
  three items misread the source first. A claim from a trace, a
  subagent or an earlier plan is not a fact until the coordinator has
  checked it against source or a probe (#270: the plan's "gap (b)"
  was a misreading; real's `_want_installed_pkg` is already `True`
  under `--update`).
- Capture `--debug` merged (`PYTHONUNBUFFERED=1 ... >log 2>&1`);
  separate streams hid walk/solver/dump ordering and produced a wrong
  theory that cost two implementation attempts.
- Pin `PYTHONHASHSEED=0` (set-order wobble is real, not flakiness);
  point `PORTAGE_GNUPGHOME` at a writable `chmod 700` keyring copy or
  nothing runs; stop the `gpg-agent` it spawns and delete its `/tmp`
  home (leaks accumulated across runs).
- A test file may rebind `test_cases` right before the consuming loop
  — verify what actually executes before citing "upstream proves".
- Host probes always `-p`, confirmed on two consecutive runs before
  becoming a claim; `-e` + `--usepkg=n` for a genuine rebuild;
  determinism blocks go in resolved config (`make.conf`), never the
  calling shell's env (silently different settings, identical CLI).
- **Identical effective options on both sides, proven by printing both
  argvs.** `--getbinpkg` implies `--usepkg`, and real then ignores
  built packages' `DEPEND`/`BDEPEND`; host `EMERGE_DEFAULT_OPTS` folds
  into both unless `--ignore-default-opts`. Two items were invented or
  mis-aimed by comparing runs that did not share options. If the
  options differ, that is the whole finding.
- Oracle binaries must be real-built (`--buildpkgonly` + `--usepkgonly`
  pipeline); crafted archives are rejected by real and prove nothing.
  A bed whose real side silently sees no binaries (`Packages` header
  lacking `VERSION:`) makes every binpkg cell vacuous — assert the
  bed's inputs, not just its outputs.
- Bed staging lies: `ROOT=$FX` splits cascades across two roots — a
  whole item was an artifact; the host-exact control (`ROOT=/`) is
  mandatory before any code. A partial run is not a parity run: mark
  `partial`, keep the log, never diff it. Run L1 *with* the portage
  upgrade — skipping it fakes a `metadata` finding on every package.
- Real disagrees with itself (parallel-`estrip` race, hash-seeded
  sets, hardlink-set `.debug` naming): one allowlist row, never chased
  to zero. Compiled-payload bytes never gate except hand-written
  fixtures. Corrupt-dentry (overlayfs) host deltas are not findings.
- Masked/unsat aborts show no list at all — a "partial list" premise
  is false for 2 of 3 abort shapes; no list also means no `Total:`
  line (`display()` is never reached). A mid-vs-last sibling pair is
  the control proving unobservability, not two behaviours.
- Disproving the premise is a result: a filed item's text may be
  wrong (dir sets were identical; the delta was comparator-side;
  titular "silence" was walk-order reuse, no handler ran). Close it as
  a comparator/diagnosis item, never fix the stated symptom.
- Evidence must outlive the session: nothing under `/tmp`, nothing
  only in a gitignored report dir. Copy captures into
  `docs/evidence/<date>-<n>/` (or pmtest `logs/`) before the commit
  that cites them; a fresh clone must be able to follow every pointer.
- Grep the symbol before citing real: `circular_dep_handler` does not
  exist (`circular_dependency_handler` does), and plans repeatedly
  carried stale counts (fixture-oracle lists 12 vs 13), wrong artifact
  names and wrong "default 10" sites. A pre-batch review pass by a
  second reader found 5–8 false claims per batch — worth its cost.

## Before writing code

- S0 oracle matrix first, code second; a contradicting cell means
  stop, not reinterpret. S0 commits hold probes only, zero product
  code. A re-scope forced by S0 needs owner sign-off, then the plan
  and entry are amended in place (never two truths).
- Time-box investigations (owner-fixed, e.g. 2–4h); expiry without a
  reproduction is a documented cut with the matrix attached, never a
  guessed fix. Fifteen negative probes are a result: file what it is
  NOT, with the excluding probe named per rejected rule.
- Never implement against a symptom fixed elsewhere: re-diff the host
  after every neighboring landing — items evaporated that way
  (options mismatch, staging artifact, already-shipped fix whose entry
  still said OPEN: verify `git log` before scheduling "open" items).
- Require the `--debug` markers before touching code (e.g. all three
  cascade markers); absent markers mean the wrong family — stop.
- First-draft unconditional rules are usually wrong (unconditional
  bdeps drop, runtime gate, never-walk-bdeps): find the real probe
  that contradicts the draft before coding, not after.
- Check gates before machinery: a "missing rebuild" was the
  complete-mode gate; an exemption justified by a scan must be gated
  on the scan actually running (`backtrack_max > 0`).
- Smallest fix that flips the pin. A wider fix that breaks an existing
  pin is narrowed (e.g. require an installed instance), not
  accompanied by moving the pin. A walk-time change that adds entries
  perturbs rank-keyed solvers — prefer a post-solve synthesis.
- Find the real mechanism by variation, then name each rejected rule
  with its excluding probe; a first-named cause is a hypothesis (the
  F-B4 "no edge" theory was wrong twice).

## Reading real source (also for future Portage versions)

- The cited line is often the wrong branch: the gap was the
  early-return branch bypassing the tracked structure, not the
  tracking code. Read callers + early exits, not just the named
  function.
- Real auto-enables modes in more places than any backlog text says
  (complete mode on ver/USE/slot, not just the conflict path). Grep
  all writers before porting a predicate.
- Distinguish same-named things: `identical_binary` (installed
  candidate) vs the binary skip; unfiltered `forced_flags` vs the
  `retain(iuse)` variant; cp-level vs atom-level installed match;
  `optional` matters only when no child is selectable;
  `Package.__str__` (appends `to '<root>'` for ROOT≠`/`) vs the
  merge-list renderer (`EROOT`, unquoted).
- Port intent, not literal shape: xpak paths → gpkg flat
  `metadata/<KEY>`; `FILE`=basename vs `.__download__` temp;
  `DIGESTS` sorted; error classes (`Invalid` skip vs `Fatal` abort —
  all xpak errors are `Fatal`).
- Real `varexpand` has no env (`\$` literal); POSIX `shlex` unescapes
  only `\"`/`\\` inside quotes. Test parsers through `resolve_config`
  + live `portage.settings`, never hand-built structs (hid a bug for
  a full slice).
- Dead versions are dead: EAPI 0–4 and 6 have no live consumers, so
  EAPI-conditional branches for them are skipped, not ported — and
  within the live floor (5+) portuale treats every EAPI identically
  rather than parametrizing. Check the floor before porting any
  version-gated logic from a future Portage.
- Evaluated metadata, never source text: scanning an ebuild for a
  literal `SLOT=` broke computed slots; read md5-cache/`aux_get`.
  Route every vdb read through the one seam (`vdb_aux_get`) so
  real's `aux_get` translations (empty `SLOT`→`"0"`, multi-line
  collapse) apply once.
- `get_pregenerated_cache` takes the first format only; empty layout
  means auto (`md5-dict` then `pms`); lowercase + split before
  comparing anything from `layout.conf`.
- Conditionals/use-deps: evaluate a parent's conditionals against its
  own (vdb) USE before any membership test; a raw-vs-evaluated
  asymmetry silently drops deps. A rescue path in real is narrow
  (`_initially_unsatisfied_deps`) — porting it broadly hid aborts.
- Config layering: a `package.env` scalar loses to the calling
  environment but outranks config scalars; incrementals append inside
  the container then fold with `-*`/`-tok`. Recompute `FEATURES` and
  `PORTAGE_TMPDIR` after the match; never delete them from the
  computed set as a shortcut, never reorder the `extend` pair
  wholesale.
- Budgets are counted in real's units: `--backtrack=N` counts restarts
  (depth `max(1,(N+1)//2)`), not mask steps; a failed iteration with
  no feedback still consumes one. Check the unit before copying a
  number.
- Walk order is not merge order: the merge list derives from graph
  structure (DFS replay), so never "fix" truncation by flipping
  BFS→LIFO. A cycle list is the serialize-stuck remainder (drained
  leaves excluded), never a discovery prefix; its counters count
  displayed rows, duplicates included. Walk-time failure beats
  serialize-time failure — order abort arms accordingly; error blocks
  print circular → slot → blockers → autounmask even if another arm
  fired first.
- Block/row order follows real's *insertion* order (first-seen key
  keeps its position even when a higher pkg overwrites the value);
  sorting alphabetically is a bug. `^` markers apply only to the part
  of the atom that fails.
- Shared on-disk formats must round-trip both directions (real reads
  portuale's output and vice versa) — verify live, not by schema. Do
  not bump format versions or delete per-field files real still reads.
  Where every candidate is digest-verified, deterministic order
  replaces real's shuffle as a documented cut, correctness-neutral.
- Merge writes never touch the existing inode: materialize a sibling
  temp and `rename(2)` (mmap'd libraries, running executables). Any
  commit adding a `merge_tree` file type or changing a merge driver
  states why the old inode is never written.
- Always create real's `files` symlink (even dangling) or the
  post-merge `rm -f` aborts under `set -e`.

## Scope and process discipline

- One slice, one commit, no squash; paired across repos (product
  here, fixtures/pins/bless in pmtest, messages quote each other;
  pmtest commits first). Commits are never pre-authorized unless the
  plan/owner says so; pushes are a separate ask, portuale first.
- Same branch name in both repos, opened together, even when a slice
  looks one-sided. Worktree pairs `../wt-<slug>/{portuale,pmtest}`
  need the `fixtures` symlink and a real `3rdparty/portage` checkout
  in each (a symlink dangles inside the L1 container → portageq 127).
- Per-slice `--no-ff` merge into `main` as soon as verified, never a
  rebase (paired-sha quotes stay valid), then delete the branch in both
  repos. A merge pile skipped its integration gate once — gate the
  integration tip. If a rebase is forced, use `--rebase-merges`,
  reword the paired quotes, and re-baseline L0 by finding name.
- Backlog numbers are never reused and are global across *all live
  branches*: scan every branch's `backlog-tasks.md`, not just the
  worktree's; two items claimed #58 thirteen minutes apart and parallel
  batches collided on #262–#266. One coordinator allocates; implementers
  ask.
- A plan's `Status:` header, its backlog entry and `what-this-proves.md`
  flip in the same close-out commit; cite hashes reachable from `main`.
  Shipped items whose heading still said OPEN (#261, #269, #182,
  #191) got scheduled as work — flip at ship time.
- Drops are owner decisions with names, not silence; rejected
  narrowings stay rejected — reintroduce only with new oracle
  evidence citing the excluding probe. Judgment calls go to the owner
  as written questions (Italian, plain words); the blocked slice stops,
  others continue. Everything in the repos is English.
- Order matters (USE-fold before binpkg gate; probe-ordering before
  display). Re-scoping to a bed-fix with no product code is a valid
  outcome when S0 STOPs. File the split halves (display vs
  scheduling, gate vs fix) as separate numbered items immediately.
- Before writing "does not model", grep portuale (the helper
  usually exists behind a gate). Enumerate feedback/enum variants
  explicitly. Oracle cells need per-cpv granularity. Re-run L0 after
  touching resolver/merge code, recording mtime + HEAD. Corpus bless
  rides only in the pmtest commit after line-by-line drift review.
- Never edit the harness to make a PM pass: a red is fixed in the
  product, an accepted divergence goes in `known-divergences.yaml`.
  Conversely an allowlist row filed as `portuale-bug` is part of the
  fix: the fixing slice deletes it and shows the cell green
  unsuppressed.
- Name a shared-mechanism link both ways from the start; one fix
  closes both residues or evidence splits them. A later slice that
  supersedes a DONE must amend that DONE entry — never two truths.
- Model one abort outcome with N consumers, not one shape per
  trigger (autounmask+cycle is the same remainder, not a fourth
  shape). Hook the outcome around the retry loop — the final pass
  decides; read `backtrack: N/M` as a signal, never pin it. An
  exit-code change breaks standing conventions: gate it by owner
  decision and update every affected pin in the same slice.
- Test-only phases change no product byte: a test that needs a source
  change, or reveals a bug, stops and files an item. Measure and fix
  never share a commit. Triage mutation/coverage output by cluster
  (six items, not 200), each survivor classed real gap / equivalent /
  unreachable.
- A coordinator model plans, briefs, verifies every report against
  source/probe, owns numbering, beds and commits; cheaper models
  implement from briefs naming: the entry, real-source lines already
  established, exact probe argv, expected files, pins expected to
  move, stop conditions. Start with the cheapest model that suffices
  and escalate after two failed verifications. Agents never commit
  unless told, never `pkill`/`pgrep` (a hung agent is reported, not
  killed); on "overloaded/invalid JSON" retry with a shorter prompt
  pointing at the brief file.

## Gates, beds and host hygiene

- Compare by test/finding name, never by count (the suite has an
  order-dependent isolation bug); `git clean -fdq fixtures/` first.
- Z0 first: re-take every baseline on `main` before any slice; each
  later slice's guard is "row-identical to Z0, or better on a row it
  names". Resolver slices: L0 + fixture oracle (all lists); a cell
  added to a default atomlist is everyone's baseline from then on, so
  it ships only green or with its fix.
- `cargo test` does not relink `target/release/portuale`; pty/e2e tests
  spawn that artifact — `cargo build --release -p portuale` first (a
  stale binary caused phantom failures). Export
  `RUSTUP_TOOLCHAIN=stable-x86_64-unknown-linux-gnu` for fmt/clippy.
  A concurrent campaign holding `target/` → separate
  `CARGO_TARGET_DIR`. `PMTEST_PROFILE=debug|release` for pmtest runs;
  wall times compare only within one profile; the final gate is release.
- Merge-path gate (glibc + bash, `l1-merge-gate.txt`,
  `L1_CONSUME_REINSTALL=1`; copy `_l1-pkgcache` + `L1_SKIP_BUILD=1`
  turns ~20 min into ~3–5) for anything reaching `ebuild_merge.rs`,
  `emerge_build.rs`, `emerge_getbinpkg.rs` or `mrg`; a stale
  `_l31-pkgcache` fails consume ("`$PKGDIR` incomplete") — rebuild with
  `L31_REBUILD=1`.
- Beds: at most two at once, none alongside an L3 bed; the coordinator
  owns the queue (implementers report BED-PENDING). L3 control pairs
  are noisy at `-j28` (#261) — read a control first. L3 smoke ≈15 min
  (tmpfs build dir made no measurable difference on the smoke; baked
  portage image removes the per-container upgrade). Scripts that
  rewrite a shared meta file with `>` erase earlier writers — append.
- Root-gated tests: `sudo <test-binary> <filter>`; image rebuild is an
  owner step. Sweep leftover `gpg-agent --homedir /tmp/…` and loopback
  `sshd` at close-out. `/tmp` can exhaust inodes — don't park evidence
  there. Host facts (cores, kvm, sudo) change between machines: check
  at H0, don't inherit.
- `ETXTBSY` stub-script flakes under parallel load are a test bug
  (fix the test, don't retry). pty tests need a watchdog.

## Display vs mechanism

- Satisfied rows print inline, unsatisfied rows trail; flat and tree
  are different serializers (greedy leaf pop off in tree) — never
  unify their predicates by deletion.
- Counters exclude uninstalls; nondeterministic values (timing) ride
  `--json` only, never stdout; no wildcard arm on large enums (~500
  match sites).
- Tree edges need the `merge_bound_only` split from the scheduler
  digraph; the cp-keyed `required_by` fallback misattributes slots —
  skip owners whose own atom resolved to another instance. A `[nomerge]`
  ancestor row carries the instance USE column.
- Surviving slot conflicts print one merge row per instance; a blocker
  uninstall follows the merged candidate, not walk order;
  `--buildpkgonly` evaluates only DEPEND/BDEPEND blockers.

## Performance work

- Measure first, ordered by profile; re-measure every slice on the
  reference workload *and* a second shape (`sys-devel/gcc`, the
  `-p nano` blocker-scan shape). Record honest non-results (sharing
  binary-candidate pools moved 0.03 s inside run-to-run spread for +16 MB: the
  item was withdrawn). Count call sites vs distinct inputs with a
  temporary counter before memoising (40 k calls / 1.5 k inputs).
- A memo key must hash everything the body reads: a field read through
  a helper (`repo_location`), a pointer-derived key (ABA on realloc),
  and sampled fingerprints each produced silent staleness. One
  definition per constant (23 vdb fields), exact fingerprints, frozen
  bases with recompute guards, and the invariant in a doc comment.
- Hoist per walk, not per list (list-level hoisting regressed
  12.4s→15.8s). Cheap exact guards first (no-`!` skip, no-merge-bound
  early return, `HashSet` walked set). A faithful single-file read
  beat the clever skip (0.99s→0.83s). Gate speculative slices on the
  profile (the plan's own gate cancelled two).
- No threads before memoisation lands; do not silence a second
  `run_pass` to win a benchmark (it is a behaviour question). A
  complete-snapshot read is a semantic (absent field reads `""`) —
  write it at the function and pin it, or a later reader "fixes" it
  back into a fallback.
- A committed fixture can never carry a valid `#dir_mtime=` (git
  checkout resets it) and the suite runs in place: positive-path
  snapshot tests stamp a tempdir at runtime; fixtures pin rejection.

## Fixture and pin hygiene

- Committed fixtures declare minimal features so existing pins stay
  byte-identical; host shapes reproduce via copied configroot, never
  production-fixture edits.
- New fixtures need real md5s + md5-cache entries + `git add` before
  any `git clean` (clean deletes untracked fixtures). Backquote in
  `DESCRIPTION` fails the depend phase on both PMs. Check name
  collisions (`sct`/`oldc` style abbreviations map to
  `slotconflict*`).
- Pin both ways (withholding shape + updating twin). Strict-xfail
  XPASS fails the suite — convert to a pin on first XPASS. Never move a
  pin to whatever portuale now prints: re-derive from a real capture.
  A pin's mutation check = revert the fix, a named pin fails.
- Crafted hostile archives are scratch-only and must error, never
  skip-and-win; device cells need passwordless sudo; keep the
  decompressor a subprocess piped into the in-process reader.
