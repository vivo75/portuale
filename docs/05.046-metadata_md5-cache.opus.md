## 1. What real does, what portuale does

Real `portdbapi._pull_valid_cache` (`lib/portage/dbapi/porttree.py`,
~603-651) walks three auxdb rungs for a cpv, in order: the repo's pregen
`metadata/md5-cache`, the depcachedir cache, then
`doebuild(mydo="depend")`. **Every rung goes through the same validation**
before it is trusted:

1. an entry whose `EAPI` (empty -> `"0"`) is unsupported is skipped
   (`continue`);
2. `auxdb.validate_entry(metadata, ebuild_hash, eclass_db)` — for the
   `md5-dict` format: `_md5_` must equal the md5 of the ebuild's
   *content*, and every `_eclasses_` pair must match the md5 of the
   eclass file that wins across the masters-then-self chain.

A stale pregen entry therefore falls through to the depcachedir rung and
then to the depend phase, whose result is written to depcachedir
(`_write_cache`). Oracle (C0, `TEST/logs/c0b-20260914T111856Z/`):

| probe | ebuild | repo cache | real, after `emerge -p` |
|---|---|---|---|
| P6 | valid | `_md5_` matches | cache used, nothing written |
| P7 | `touch`ed only | `_md5_` matches | cache used, nothing written (**mtime never invalidates**) |
| P8 | content changed | `_md5_` stale | depend phase ran, depcache entry written |

Portuale today:

- `portage_repo::read_md5_cache` (`rust/portage-repo/src/lib.rs`, ~1339)
  reads the file verbatim, memoised per path, and applies
  `profiles/updates` to the `*DEPEND` keys.
- `portage_repo::repo_aux_metadata` (~1424) is the single entry point
  (C1). Only a **missing** file reaches the registered provider;
  a present-but-stale file is returned as-is.
- The provider `portuale::ebuild_phases::depend_phase_metadata` (~3105)
  already does rungs 2 and 3 exactly like real (C3): it validates a
  depcachedir entry with `regen::entry_is_valid`, runs the phase, writes
  the entry back best-effort.
- `regen::entry_is_valid` (`rust/portuale/src/regen.rs`, ~567) already
  implements the full `md5-dict` validator (`_md5_`, EAPI, `_eclasses_`
  over the masters chain), shared by `--regen` and the depcache rung.
- `list_candidates_uncached` (`lib.rs`, ~1698) enumerates `*.ebuild`
  files, then asks `repo_aux_metadata`. So a cache entry without an
  ebuild is never reached from the resolver, and an ebuild without a
  cache entry already goes to the provider (C2). **The only gap is
  rung 1's validation.**

So the product change is small: validate in `repo_aux_metadata` and
treat an invalid entry as a miss. The hard part is the test tree.

## 2. The blocker: every committed fixture cache entry is "stale"

Measured on `ba42d8e` (audit script: md5 of `<repo>/<cat>/<pn>/<pf>.ebuild`
vs the entry's `_md5_`):

| repo | entries | valid | stale |
|---|---|---|---|
| `TEST/images/overlay/porttest` | 10 | 10 | 0 |
| `fixtures/repo` | 550 | 0 | 550 |
| `fixtures/overlay` | 11 | 0 | 11 |
| `fixtures/independentoverlay` | 2 | 0 | 2 |
| `fixtures/layoutmasteroverlay` | 1 | 0 | 1 |
| `fixtures/repnamerepo` | 1 | 0 | 1 |

Every hand-written fixture entry carries the placeholder
`_md5_=0000000000000000000000000000000` (31 zeros, not even a valid md5).
Real treats all of them as stale — which is why the #49 fixture oracle
already sees real run the depend phase on every staged fixture (its
staging delta 7, backquotes in `DESCRIPTION`, exists because of that).
Validating without first fixing the fixtures would push every contract
test through the depend phase: slower, and it changes results.

rc 1) sized the reconciliation. Of 550 entries:

  `dev-libs/singletargetpkg-1.0`: a `` `flag` `` backquote in

  Real fails the same way;
- **376** differ. Almost all of it (365 `IUSE`, and most `*DEPEND`,
  `KEYWORDS`, `IDEPEND` rows) is only `KEY=` (empty) in the hand-written
  entry vs the key being absent in real's writer, which omits empty

## 3. Decisions

**Owner decisions 2026-09-15:** E1 and E2 are decided (below). E3–E7
are still proposed defaults; the owner may override them before the
slice that needs them starts. **The plan is not being executed yet.**

| id | question | decision / proposed default | why |
|---|---|---|---|
| **E1** | Direction for a substantive fixture mismatch (ebuild vs committed cache) | **DECIDED (owner): no fixed direction.** For each mismatch, evaluate which side is wrong from the evidence (see S1 step 4). When the evidence does not settle it, **stop and ask the owner**; never pick a side by default. | Neither the cache nor the ebuild is presumed right: the cache is what tests have been reading, but it was hand-written; the ebuild is what real reads, but may be the stale half. |
| **E2** | Who writes the committed fixture caches | **DECIDED (owner): real `egencache --update`** in the test container is trusted as the authority, the rule `TEST/images/overlay/porttest/README` already uses. `portuale emerge --regen` on the same tree must be byte-identical: a free differential of portuale's writer. | Real is the authority; the diff is a bonus check. |
| **E3** | Stale entry, **no provider registered** (portage-repo unit tests, `mrg`-only builds) | **Return the stale entry**, as today. | Same "no provider == pre-C2 behaviour" contract C2 documents; nothing without a provider can run a phase. |
| **E4** | Entry present, **ebuild missing** | **Trust the entry.** | Unreachable from `list_candidates` (it walks ebuilds). Real would raise `KeyError` (the package does not exist), but no portuale reader depends on it. Document it as a narrowing. |
| **E5** | Stale entry, provider **fails** (depend phase dies) | **Treat as a miss (`Err`)**; never fall back to the stale data. | Real's `aux_get` raises; the package is dropped from candidates. Confirm the exact user-visible output in S0 cell (d). |
| **E6** | Perf budget | **≤ 5 %** wall on the host `portuale emerge -puD --getbinpkg net-libs/rest` baseline (`docs/performances-tuning.md`, ~4.6 s), plus one `-puD @world` spot check. | Hashing each read ebuild once per process is inherent (real's `hashed_path` does the same); eclass md5s get memoised. |
| **E7** | Rust-only or contract pin | **Rust-only** (`tests/test_portuale.py`), as C2/C3 (D2 of the Tier5/2 plan). | Needs a real depend phase; there is no Python mirror any more. |

### S3 — validate in the read path (executor F)

The behaviour change. Depends on S1 (committed) and S2.

Design:

1. **Where.** In `repo_aux_metadata`, not `read_md5_cache`: keep the raw
   reader a reader. Compute validity **once per path** and memoise it
   next to the map (extend the `read_md5_cache` memo value to
   `(Arc<map>, validity)` or add a sibling memo keyed like it). Validate
   the **raw** text: `apply_updates_to_dep_string` rewrites only
   `*DEPEND`, which the validator does not look at, but do not rely on
   that silently — validate before the rewrite.
2. **Ebuild path.** `<repo>/<category>/<pn>/<pf>.ebuild`; find the
   crate's existing pf -> pn split helper (`strip_version_prefix` is the
   inverse used by `list_candidates_uncached`; `portuale` has
   `remote_bundle::split_pf`) instead of writing a new one.
3. **Decision table** (in code order):
   - entry file missing -> today's miss path (unchanged);
   - ebuild missing -> return the entry (E4);
   - entry valid -> return it (P6, and P7: mtime is never consulted);
   - entry invalid, no provider registered -> return the entry (E3);
   - entry invalid, `IN_PROVIDER` set (a nested read from inside the
     depend phase's own env assembly) -> `Err`, same as a nested miss;
   - entry invalid, provider registered -> the existing miss path:
     fallback memo, recursion guard, provider (which already checks the
     depcachedir rung, runs the phase, writes back). Provider failure ->
     `Err` (E5). The error returned should still read as an unusable
     entry (keep `Error::ReadFile`'s shape or add a variant; check the
     callers that match on it).
   - unsupported EAPI (S0 cell e): follow whatever the oracle showed. If
     real skips the phase, add the `_parse_eapi_ebuild_head` short-circuit
     to the provider rather than to the reader.
4. **Concurrency.** C2 already had one race (`dc8022b`, the shared
   depend-phase metadata file). The new memo must be safe under the
   parallel `read_dir_entries` / rayon paths: insert-if-absent under
   the write lock, never hold a lock across the provider call.
5. **Doc comments.** Update `repo_aux_metadata`'s and
   `has_usable_md5_cache`'s docs ("a per-cp cache miss" becomes "a miss
   or an entry `validate_entry` rejects"), and `read_md5_cache`'s
   "immutable for the process lifetime" note.

Pins (Rust-only, E7), in `tests/test_portuale.py` next to
`test_cache_less_repo_metadata_is_written_to_the_depcache`, all on a
tmp copy with `PORTAGE_DEPCACHEDIR` in `tmp_path`:
