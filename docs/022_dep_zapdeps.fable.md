## My own take

Claude's document is the more accurate of the two on the code; ChatGPT's is the better-written task brief but contains three factual slips (file location, nine-vs-eight bins, broken pseudo-code) and one big omission (the mirror). If you keep one as the agent hand-off, keep Claude's and lift ChatGPT's "first separate `all_available` / `all_use_satisfied` / `all_use_unmasked`" warning into it verbatim — that sentence is the single most useful thing in either document.

On the ordering disagreement I side with Claude, with one refinement: the ordering rules and `all_use_satisfied` split are genuinely independent, so do ordering first. It has zero dependency on the USE-mask machinery, it's the only slice with user-visible effect on a healthy system, and it forces the API decision (the probe must return per-cp versions for `vercmp`, or selection moves into `portage-repo`) early, when it's cheap.

One thing neither document makes explicit and that matters for the "cheap model" question: this repo has two different notions of "differential test". The 432 contract tests prove Rust == Python mirror — both are portuale, so a fixture can pass while both are wrong in the same way. Real-Portage parity is only checked by L0 in a container against a real tree. There's a `porttest` overlay skeleton in `TEST/images/overlay/`, so per-bin synthetic ebuilds *can* be run against real `emerge`, but that's container work, not md5-cache fixture boilerplate. ChatGPT's "real Portage differential tests for each bin" is achievable but heavier than its cheap/mid label implies. My split would be: contract fixtures for every bin (cheap model, mechanical), plus a handful of `porttest` ebuilds covering the four cases that actually diverge from today's behaviour (upgrade promotion, USE-unsat-unmasked, USE-unsat-masked, `allow_masked` second pass), run once through L0 at the end.

On difficulty: 7/10 for the classification plus ordering, and I'd resist bundling the downgrade guards and `minimize_slots` into #22 at all — they depend on state that doesn't exist and are `--depclean`-motivated, so they belong with #23/#24. The `other_*` bins are only ever returned in the `allow_masked=True` pass, which means their entire effect is on the failure path and on what autounmask/masked-disclosure (#20) sees. That makes them lower risk than they look, and a reasonable place to stop a cheaper model.

Net: frontier for the design doc, the API decision, the cut list, and the diff review of each slice; a Sonnet-class model for the refactor, the ordering slice, the `other_*` slice, and all of the Python mirroring; anything smaller for fixtures and doc updates. The one slice I would not delegate below frontier is `unsat_use_*` with the `use.mask`/`use.force` check, because it changes how portuale falls back from "keep the literal `||`" to "pick a branch and let autounmask complain", and that interacts with the backtrack loop.
