## 1. Real semantics (read from source)

`lib/portage/repository/config.py`:

- `parse_layout` (~1564-1577): `cache-formats` is lowercased and split.
  **When empty, auto-detect**: `md5-dict` if `metadata/md5-cache` is a
  directory, then `pms` if `metadata/cache` is a directory, in that
  order.
- `iter_pregenerated_caches` (~576-605): walks the formats left to right,
  yields a `metadata/cache` (`pms`) or `metadata/md5-cache` (`md5-dict`)
  database for each **known** name; unknown names are skipped. It does
  **not** check that the directory exists.
- `get_pregenerated_cache` (~607-616): the **first** yielded database
  only. So `cache-formats = pms md5-dict` uses `metadata/cache` even if
  only `metadata/md5-cache` exists: every lookup misses and falls through
  to depcachedir, then to the depend phase.

`lib/portage/dbapi/porttree.py`:

- `_create_pregen_cache` (~392-411) is called only when
  `"metadata-transfer" not in FEATURES` (~322). A `pms` cache emits a
  `DeprecationWarning` (invisible by default).
- `_pull_valid_cache` then validates each rung (see #46's plan). `pms`
  (`cache/metadata.py`) is positional (18 keys in `auxdbkey_order`) or
  `KEY=value`, reconstructs `_eclasses_` from `INHERITED`, and validates
  by **mtime** (the `flat_hash` default `validation_chf`), not md5.

Every Gentoo repo on this host sets `cache-formats = md5-dict`
(`/var/db/repos/{gentoo,kde,buildovl}/metadata/layout.conf`).

## 2. Portuale today

- `parse_layout_conf` (`rust/portage-repo/src/lib.rs` ~1036) returns the
  raw `key = value` map. The repo-config pass (~1210-1235) reads only
  `profile-formats`, `aliases`, `repo-name`, `masters`.
- `has_usable_md5_cache` (~1496) = "`metadata/md5-cache` is a
  directory", memoised per location. Callers: `mrg-director`
  `Md5Cache::category` (~826) and C1's listers.
- `read_md5_cache` / `repo_aux_metadata` (~1339 / ~1424) read
  `metadata/md5-cache/<cat>/<pf>` whenever the file exists, regardless of
  `layout.conf`; a miss goes to the C2 depend-phase provider.
- **No `pms` reader exists** (`metadata/cache` appears only in doc
  comments).
- `--regen` (`rust/portuale/src/regen.rs`) always writes
  `metadata/md5-cache`.

## 3. Decisions for the owner

| id | question | proposed default | why |
|---|---|---|---|
| **L1** | Port a `pms` reader? | **No.** A repo whose first effective format is not `md5-dict` is treated as having no pregen cache: every read goes to the depcachedir rung / depend phase (C2/C3), which yields the same metadata real would read from a valid `pms` cache. Record the missing `pms` reader as a documented narrowing (slower, not different). | `pms` is deprecated since portage 2.1.11.32 (2012), no known repo uses it, and it brings mtime validation plus a positional parser for no observable gain. |
| **L2** | Honour `FEATURES=metadata-transfer` (disables the pregen cache) at the same gate? | **Yes**, same predicate, one extra check. | Same code site, cheap; otherwise a second silent divergence at the same line. |
| **L3** | Should `--regen` follow `cache-formats`? | **Decide from S0's oracle**: record which directory real `emerge --regen` / `egencache --update` writes for `pms` and `pms md5-dict`; if real writes `metadata/cache`, make portuale's `--regen` refuse or skip (no `pms` writer, L1) with a clear message rather than write the wrong dir. | Keep the writer consistent with the reader. |
| **L4** | Order vs #46 | **Independent**, but if #46 S3 has landed, the new gate goes in front of #46's validation in `repo_aux_metadata`; if not, #46 S3 must preserve it. | Both edit `repo_aux_metadata`. |

1. `has_usable_md5_cache(repo_location)` becomes the resolved predicate
