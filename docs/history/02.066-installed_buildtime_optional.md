## 1. What the original plan claimed

That real Portage treats a built package's `DEPEND`/`BDEPEND` as
*optional* and therefore never installs, updates or downgrades them, with
`emerge -puDvN --oneshot <installed parent>` probes as proof
(scipy→pythran, cloudpickle→`<flit-core-4`, libtracefs→source-highlight,
okteta→cmake).

## 2. What real actually does (source + re-probe)

- `optional=True` only matters in `_add_dep` when **no** child can be
  selected ("unnecessary build-time dep", `depgraph.py:3396-3398`). A
  selectable child is added normally, and under `--deep`
  `recurse_satisfied` is true, so `_ignore_dependency`
  (`depgraph.py:4423-4463`) does not discard it: updates/downgrades/new
  installs **do** happen.
- What removes those deps is the `bdeps` parameter:
  `create_depgraph_params.py:97-103` sets `bdeps="auto"` only when
  `--with-bdeps` is unset **and `--usepkg` is not in effect**;
  `_add_pkg_deps` (`depgraph.py:4194-4247`) sets
  `ignore_build_time_deps` for a built package otherwise and empties
  `DEPEND`/`BDEPEND` (unless a `--rebuild-if-*` mode is on).
- `--getbinpkg` implies `--usepkg` (`actions.py:3719-3720`). The host's
  `EMERGE_DEFAULT_OPTS` carries `--getbinpkg=y`, so **every** real probe
  in the original plan ran with build-time deps off, while pre-#63
  portuale ignored `EMERGE_DEFAULT_OPTS` and walked them.

Re-probe (`--ignore-default-opts`, i.e. `bdeps=auto` on both sides): real
downgrades `flit-core` to 3.12.0 for cloudpickle, installs
`source-highlight` for libtracefs, updates `cargo-c`/`libgit2` — the
exact "spurious" entries the plan wanted to remove. With host defaults,
portuale (post-#63) is package-for-package identical to real on the
scipy/cloudpickle/libtracefs/runc probes, and none of the #66 packages
appear in the host `@world` diff any more.

Portuale already models the rule: `pretend.rs` (`with_bdeps =
with_bdeps_auto && !(usepkg || usepkgonly || getbinpkg ||
getbinpkgonly)` when `--with-bdeps` is not given) feeds
`enqueue_dependencies`' key choice.

## 3. The one worthwhile slice (S1, landed 2026-09-16)

| slice | commit subject | contents |
|---|---|---|
| S1 | `#66 S1: pin the bdeps default both ways` | contract pin on a fixture installed parent with `BDEPEND=">=dep-2"` (dep-1 installed, dep-2 visible): `--getbinpkg`/`--usepkg` (no `--with-bdeps`) → dep **not** updated; plain `-uDN` or `--with-bdeps=y` → dep **updated**; `--with-bdeps-auto=n`/`--with-bdeps=n` → not updated. Landed with no resolver code change, as expected: the container oracle
(real 3.0.82.2 on the staged fixture tree, six cells) and portuale agreed

their `metadata/md5-cache` entries; the test is
`test_oracle_bdeps_default_of_an_installed_parent_drives_dependency_updates`
in `tests/test_emerge_pretend_contract.py`.
