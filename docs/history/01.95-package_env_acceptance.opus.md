## 1. What real does (source + live probe)

`config._grab_pkg_env` (`3rdparty/portage/lib/portage/package/ebuild/
config.py:2269-2300`) is called from `setcpv` (`:2038`) with
`container = configdict["pkg"]` and `protected_keys = pkg_configdict`
minus `USE` (`:2032-2038`; that is `{PKGUSE}` — `USE` is popped at
`:2045` and re-appended after `package.use`, so `package.use` wins).
For every file named by the matching `/etc/portage/package.env` entry,
in order:

- `k in protected_keys or k in _non_user_variables` ->
  `!!! Illegal variable '<k>' assigned in '<file>'` and the key is
  dropped. `_non_user_variables` (`:724-733`) is the profile's dynamic
  `PROFILE_ONLY_VARIABLES` ∪ `env_blacklist` ∪ `global_only_vars`
  (`special_env_vars.py:15-74`, `:351-355` = `CONFIG_PROTECT`).
- `k in incrementals` (`const.py:125-140`) ->
  `container[k] = container[k] + " " + v` (append).
- else `container[k] = v` (set; a later file replaces, an empty value
  blanks).

The pkg layer is then folded like every other incremental layer by
`config.regenerate()` (`:2778-2825`): tokens from all layers in order,
`-*` clears the set, `-tok` removes, then
`" ".join(sorted(myflags))` — so the effective value is the **sorted
pruned union** of the lower layers and the pkg layer, not a
concatenation. Finally `config.environ()` (`:3263-3350`) drops every
`environ_filter` key (`special_env_vars.py:257-348`) from the *export
set*: a package.env key that is filtered (e.g. `ACCEPT_KEYWORDS`,
`CONFIG_PROTECT_MASK`) still enters the config — it can affect
resolution/merge — but never reaches a phase.

Live capture (host `/usr/bin/ebuild` 3.0.82.2, a scratch copy of the
fixture configroot/repo; the probe ebuild's `pkg_setup` dumps the env;
`env -u PORTAGE_TMPDIR` so the pkg layer's value is visible):


| key | real pkg layer | real phase env | rule |
|---|---|---|---|
| `CC` `CXX` `CPP` `AR` `NM` `RANLIB` `LD` `RUSTFLAGS` `CGO_*` `GOFLAGS` `NINJAOPTS` `COMMON_FLAGS` `INSTALL_MASK` `PORTAGE_NICENESS` `__PROBE_LOCAL` | set | exported as-is | accepted, non-incremental |
| `ENV_UNSET` | append | exported | incremental |
| `FEATURES` | append | exported, folded | incremental |
| `ACCEPT_KEYWORDS`, `CONFIG_PROTECT_MASK` | set/append | empty | accepted into the config, `environ_filter`ed from the phase |
| `CONFIG_PROTECT` | dropped | — | `global_only_vars` + `environ_filter` |
| `SLOT`, `DEPEND`, `EAPI`, `ROOT`, `PKGUSE`, … | dropped | — | `env_blacklist` |
| `ARCH`, `ELIBC`, `KERNEL`, `IUSE_IMPLICIT`, `USE_EXPAND*` | dropped | — | dynamic `PROFILE_ONLY_VARIABLES` |
| `USE` | accepted, `package.use` appended on top | exported | real's special case |
| `CC=""` | set (blanks) | `CC=` | set semantics, empty included |
| two matching files, same key | append (incremental) / last file wins (scalar) | — | container order |

Two more probes ground the incremental fold (`ENV_UNSET` in a scratch
profile `make.defaults` + the env file):

```
profile ENV_UNSET="PROFILE_UNSET"          pkg ENV_UNSET="PKG_UNSET"
  -> ENV_UNSET=PKG_UNSET PROFILE_UNSET            # sorted union
profile ENV_UNSET="PROFILE_UNSET BASE_UNSET"  pkg ENV_UNSET="-PROFILE_UNSET PKG_UNSET"
  -> ENV_UNSET=BASE_UNSET PKG_UNSET               # pkg prunes the base
pkg ENV_UNSET="-* ONLY"                     -> ENV_UNSET=ONLY
```

## 2. Portuale today

`match_package_env_vars` (`ebuild_phases.rs`, shared by
`emerge_build::entry_package_env_vars` and
`phase_standalone_base_env`) keeps only
`pretend::BUILD_VARS` (`CFLAGS CXXFLAGS CPPFLAGS LDFLAGS FFLAGS FCFLAGS
ASFLAGS MAKEOPTS CHOST CBUILD CTARGET`), drops every empty value, and
has no incremental semantics. Same scratch fixture, pre-fix binary from
`main`:

```
$ portuale ebuild .../envdumppkg-1.0.ebuild setup     # package.env -> penv-probe
CC=   CXX=   RUSTFLAGS=   ENV_UNSET=   FEATURES=
SLOT=0   PORTAGE_TMPDIR=<process env>   PORTAGE_BUILDDIR=<process env>/portage/…
```

`CFLAGS` from the same file lands (it is in `BUILD_VARS`), which is the
live `tc-getCC` failure: `toolchain-funcs.eclass`'s `_tc-getPROG`
exports `CC` from the env, the drop makes `tc-getCC` fall back to `gcc`,
and `tc-is-lto`'s `gcc` branch dies on `-flto=thin`
(`mail-client/thunderbird`, host `llvm-lto`).

The illegal-variable message is already a documented cut
(`portage-profile`'s `read_env_file_kv` doc comment: "real portage warns
from `setcpv`; portuale follows its standing 'no warnings from deep in
config resolution' precedent").

## 3. Decisions

| id | question | decision |
|---|---|---|
| **D1** | What is the accepted set? | Real's gate minus what portuale's own phase pipeline owns: reject `ENV_BLACKLIST` (covers `PKGUSE`), `ENVIRON_FILTER` (accepted into real's config but never exported to a phase — portuale's layer only exists in the phase env), `PORTUALE_COMPUTED` (portuale computes these; `FEATURES`/`PORTAGE_TMPDIR` become #98/#99), and the dynamic `PROFILE_ONLY_VARIABLES` list (passed in from the resolved `Config`). `USE` stays on `Config::package_env_use`. Everything else is accepted, including `__`-prefixed names (real does not strip them here) and empty values. |
| **D2** | Incremental semantics? | Two levels, both real's: within the container, a later matching file appends to an incremental (`container[k] += " " + v`) and replaces a scalar; across layers, the container value is folded onto the base env with `-*`/`-tok` pruning and a sorted union (`regenerate()`), where the base is the run-wide env the caller already carries (`options.build_env` for merge builds, `build_config_env` for standalone). |
| **D3** | Empty values? | Keep them (real blanks a variable with `VAR=""`); drop the old `!v.is_empty()` skip. |
| **D4** | Illegal-variable warning? | Out of scope (see §2); stays the documented no-warnings-from-config-resolution cut. |
| **D5** | Residues? | Filed in the same commit as this plan: **#98** per-package `FEATURES`, **#99** per-package `PORTAGE_TMPDIR`, **#100** the standalone run-wide config env (`build_config_env` is still `BUILD_VARS`-only, so `make.conf`'s `CC` never reaches a standalone `ebuild` — S0 capture in §1). **#101** was added during S2: real's calling-env layer outranks its `pkg` layer for a scalar, while portuale's `entry_build_env` lets `package.env` win (and `test_emerge_atom_source_build_package_env_overrides_the_build_flags` pins that inverted precedence). |
| **D6** | Fixture shape? | Extend the existing `penv-buildflags` / `penvbuildpkg` pair with the toolchain selectors, and add `penvccpkg` + a hermetic stub compiler for the `tc-getCC`/`tc-is-lto` end-to-end pin. |

## 5. Non-goals

- The illegal-variable warning (D4).
- Real's `*/*` package.env entry -> global `conf` layer semantics
  (`config.py:905-920`); portuale treats it as a matching atom.
- `ordered_by_atom_specificity` for several matching package.env atoms;
  portuale keeps parse order (pre-existing, unfiled).
- The config-side effects of accepted-but-`environ_filter`ed keys
  (`ACCEPT_KEYWORDS` on resolution, `CONFIG_PROTECT_MASK` on merge);
  only the phase-env drop is mirrored here.
- Per-package `FEATURES` (#98), per-package `PORTAGE_TMPDIR` (#99),
  the standalone run-wide config env (#100), and the calling-env vs
  `pkg`-layer precedence (#101).
- `PATH`: `PORTUALE_COMPUTED` owns it (portuale's own overlay), so a
  package.env `PATH` stays dropped.
