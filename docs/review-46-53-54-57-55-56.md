### #57 — directly-requested hard-atom conflict vs an installed instance

This is the most design-sensitive of the six, and it tracks its plan
closely:

- **S1 item 1**: `PassState::installed_slots`
  (`lib.rs:17510`) is a **separate map**, not a new `resolved_slots`
  arm — the plan's explicit preference, taken so the `unreachable!`
  invariant on the merge-outcome slot check stays truthful. The doc
  comment says so.
- **S1 item 2, both directions**, both implemented and both commented
  with their argv order:
  - direction 1 at `lib.rs:18415-18467` — inside the `AlreadyInstalled`
    branch, **before** the `other_outcomes` dedup (the plan's
    requirement; the comment explains why a repeat visit under a
    different atom is how the second constraint arrives);
  - direction 2 at `lib.rs:19104-19147` — the merge-outcome check now
    also consults `installed_slots`.
  Both build the sub-slot-carrying match string the same way, and both
  pass an `InstalledSide` so the renderer marks the right instance.
- **S1 item 3 (K2)**: no second solver. The record falls through to the
  existing backtracker; `collect_feedback`'s `slot_want` solvability
  check reconciles a jointly-satisfiable slot on retry and the record
  disappears with it. The "decide on the final per-slot parent set, not
  at first sight" requirement is met by that mechanism rather than by a
  new end-of-pass pass.
- **S1 item 5 (interplay with #54)**: `build_residual_slot_conflicts`'s
  output is now fed through `record_slot_conflict`
  (`lib.rs:20772-20780`) instead of being appended blind, deduping on
  the `(package, merge version, installed version)` triple
  (`record_slot_conflict`, `lib.rs:15097-15109`). The residual record
  wins, so the keeper-reachable triangle renders **one** block carrying
  both parents — the plan's stated goal, and the reason the comment
  gives matches real's rendering.
- **K3 resolved to alternative A**: `test_oracle_slotop_complete`'s
  strict xfail is removed and the test is a permanent pin, with its
  docstring rewritten to explain the mechanism.
- **K1** honoured: rc stays 0; `triangle-residual-conflict-exit` and
  `-suppressed-merge-list` remain in the allowlist with `owner:
  claude-opus-5` (the "a deliberate convention is not a filed bug"
  rule), while `-missing-block-header` and `-second-line` are gone.
  Exactly S1 item 7.
- One **deviation beyond the plan** was made and is visible in the code
