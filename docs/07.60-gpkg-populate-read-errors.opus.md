## 1. What real does (source + live probe)

`bintree._populate_local` wraps **one** call — `self._read_metadata(...)`
— in a two-class catch:

```python
try:
    pkg_metadata = self._read_metadata(full_path, s, keys=..., binpkg_format=...)
except (PortagePackageException, SignatureException) as e:
    if invalid_errors:
        writemsg(f"!!! Invalid binary package: '{full_path}', {e}\n", noiselevel=-1)
    self.invalid_paths[mypkg] = [full_path]
    continue
```

`PortagePackageException`/`SignatureException` (`exception.py:172-260`)
cover `InvalidBinaryPackageFormat`, `InvalidCompressionMethod`,
`CompressorNotFound`, `CompressorOperationFailed`, `DigestException`,
`MissingSignature`, `InvalidSignature` — raised by `gpkg._verify_binpkg`
(structure/depth/prefix/duplicate/marker), `_get_inner_tarinfo`
(missing/unsupported metadata member), `_get_decompression_cmd`,
`_strip_metadata_prefix` (name outside `metadata/`) and the Manifest
digest loop. Everything else propagates: Python `tarfile` key errors and
attribute errors (unresolved link, directory/FIFO/device member),
`RecursionError` (link cycle), an inner `tarfile.ReadError`, and OSErrors.

Live confirmation (`--mode real` over the #58 cells):

| cell | real `get_metadata()` | class |
|---|---|---|
| i0 fixture (regenerated, real-writer-shaped) | OK (13 keys) | — |
| i8 inner `other/KEY` | `InvalidBinaryPackageFormat: Invalid metadata path: other/KEY` | skip |
| i12b inner `/metadata/KEY` | `InvalidBinaryPackageFormat: Invalid metadata path: /metadata/KEY` | skip |
| i1 inner symlink -> `/etc/hostname` | `KeyError: linkname 'metadata//etc/hostname' not found` | abort |
| i10 inner symlink cycle | `RecursionError: maximum recursion depth exceeded` | abort |

Note `get_metadata()` goes straight to `unpack_metadata()`, which calls
`_verify_binpkg(metadata_only=True)`; the *merge* path (`decompress()`)
has its own, stricter handling and is out of scope here (non-goal).

`invalid_errors=False` only suppresses the message, never the skip; every
in-tree caller leaves it at its `True` default (the second
`_populate_local` inside the index lock included), which is why the S0
captures show the message twice.

## 2. Portuale today

`populate_local_pkgdir` (binpkg.rs) walks `$PKGDIR` and calls
`scan_binpkg_file`, whose `read_gpkg_metadata`/`read_xpak_metadata` calls
return plain `String` errors. Any of them aborts the whole scan
(`pretend.rs` prints `emerge: scanning <pkgdir>: <e>`, rc 1). The
function's own doc comment records this as a deliberate v1 cut ("a
`$PKGDIR` full of unreadable binpkgs is a real problem worth surfacing,
not silently resolving against a partial pool"); #60 reverses the part
that disagrees with real.

Reproduced live (S0, host binary from `main` @ `28b7806`):

```
pool = fixtures/pkgdir + one crafted file
$ emerge --pretend --usepkgonly dev-libs/binaryonlypkg      # no crafted file
[binary  N     ] dev-libs/binaryonlypkg-1.0-1               # rc 0

$ ... + dev-libs/invalidotherpkg-1.0.gpkg.tar               # i8, real skips
emerge: scanning /tmp/.../60-pkgdir: .../invalidotherpkg-1.0.gpkg.tar:
  inner metadata member "other/KEY" is outside metadata/    # rc 1, pool lost

$ ... + dev-libs/invalidfatalpkg-1.0.gpkg.tar               # i1, real aborts
emerge: scanning /tmp/.../60-pkgdir: .../invalidfatalpkg-1.0.gpkg.tar:
  inner metadata member "metadata/DESCRIPTION" link target "/etc/hostname" not in the archive  # rc 1 (stays)
```

So today's failure is exactly the backlog's: real's *skip* file poisons
the entire pool, and the valid `binaryonlypkg` candidate disappears with
it.

## 3. Decisions (owner, 2026-09-16)

| id | question | decision |
|---|---|---|
| **D1** | Which Invalid/Fatal split? | **Mirror real's exception classes** (§4 table): Invalid = real's `PortagePackageException`/`SignatureException` family; Fatal = real's uncaught family (inner-tar parse errors, link resolution/cycles, non-regular members, IO) **plus every xpak read error** (real's `tbz2.scan()` returns None, then `None.get` raises `AttributeError`). Portuale's extra hardening checks (zip-bomb caps, `..` names) ride Invalid: a crafted archive is skipped with a warning, never an abort. |
| **D2** | Where does the warning print? | **Inside `populate_local_pkgdir`** — real prints in `_populate_local` itself, so every caller (`--info`, the main `--usepkg`/`--usepkgonly` scan) gets identical behaviour, and the function stays the direct analog. Message verbatim real's shape: `!!! Invalid binary package: '<walked path>', <portuale's reason>`. |

## 4. Error classification (S1's contract)

`BinpkgError { Invalid(String), Fatal(String) }`, `Display` +
`From<BinpkgError> for String` so every existing String-returning caller
(merge path, `--info`, tests via `to_string()`) is unchanged.

| site (populate-reachable) | class | real grounding |
|---|---|---|
| gpkg `not a file` | Invalid | `FileNotFound` (PortagePackageException) |
| outer container tar-parse error (`reading gpkg container`) | Invalid | `_verify_binpkg` catches `tarfile.ReadError` -> `InvalidBinaryPackageFormat("Cannot read tar file")` |
| outer structure: depth/prefix/absolute, duplicate, trusted member non-regular | Invalid | `_verify_binpkg` -> `InvalidBinaryPackageFormat` |
| missing `gpkg-1` marker | Invalid | `InvalidBinaryPackageFormat` |
| missing `metadata.tar` member / unknown compression | Invalid | `_get_inner_tarinfo` -> `InvalidBinaryPackageFormat` |
| metadata member over the 64 MiB cap | Invalid | hardening; real's `metadata too large` family |
| metadata member read error before/inside the tar | Invalid | digest/size check on the member fires first -> `DigestException` |
| decompressor spawn failure / non-zero exit | Invalid | `CompressorNotFound` / `CompressorOperationFailed` (both PortagePackageException) |
| inner metadata: member count / total bytes caps | Invalid | portuale hardening (skip, never abort) |
| inner metadata: absolute name / `..` component | Invalid | absolute -> `Invalid metadata path`; `..` is portuale-stricter |
| inner metadata: name outside `metadata/` | Invalid | `_strip_metadata_prefix` -> `InvalidBinaryPackageFormat` |
| inner metadata tar parse/entry/read error | Fatal | `tarfile.ReadError` on the inner tar, uncaught |
| inner link resolution: unresolved symlink/hardlink | Fatal | `KeyError` |
| inner member directory/FIFO/device | Fatal | `extractfile` -> `None.read()` -> `AttributeError` |
| inner link depth exceeded | Fatal | `RecursionError` |
| IO open errors (`File::open`) on the container | Fatal | OSError, uncaught |
| **all** `read_xpak_metadata` errors (`no XPAKSTOP`, `no XPAKPACK`, overrun, too small) | Fatal | `tbz2.scan()` -> falsy -> `get_data()` None -> `AttributeError` |

## 6. Non-goals

- Real's `invalids`/`invalid_paths` state (`bintree` exposes it to
  `--depclean`/`--quiet` consumers); portuale's scan stays stateless.
- `--quiet`/noiselevel gating and `invalid_errors=False`.
- The write-back of the re-walked index (`Packages` reindex) and real's
  second `_populate_local` under the index lock (portuale never writes
  the index on a pretend run).
- Real's other populate messages: `!!! Permission denied to read binary
  package`, `!!! Binary package name is invalid` (the `invalid_name`
  path), the missing `CATEGORY`/`PF`/`SLOT` block — all separate
  behaviors, unchanged here.
- The merge path (`verify_gpkg_manifest`/`extract_binpkg`) keeps its
  current abort-on-any-error semantics.
