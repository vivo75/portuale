## 1. The five defects, stated once

### #141 — `resolve_root_deps_build_entries` constructs display-blank entries

`rust/portage-repo/src/lib.rs`, `fn resolve_root_deps_build_entries`
(`:12252`) builds every `GraphEntry` it returns with
`use_flags_display: Vec::new()` — and `oldbest`, `slot`, `sub_slot`,
`repo_name`, `use_expand_display`, `use_expand_display_p`, `blockers` and
`deps` empty too. Its own doc comment (`:12240-12251`) calls that a tolerated
default ("the `--pretend` renderer … skips the USE display when it is
empty"). #133's S1 made the cut observable: the first `--root-deps` rebuild
with a flag change prints

```
[ebuild   R    ] dev-libs/deeprootdepchild-1.0 to <root>
```

where real prints `USE="-flip*"` on the same row. The `-D` control (no
`--root-deps`) prints `USE="-flip*"` correctly, so the gap is the
constructor, not the renderer (`candidate_use_flags_display`,
`reinstall_flags_for_use_change` — the main walk's machinery at `:8585`
(`e.use_flags_display = display`) and `:12521`/`:13346`).

**Not display-only in consequence:** #133 S0 put
`-D --root-deps dev-libs/deeprootdepconsumer` into the *default*
`l0-fixture-oracle.txt`, and `l0-fx-20260922T093846Z` reports
`[use] dev-libs/deeprootdepchild USE: real ['-flip*'] vs portuale []` as a
4th unexplained finding — 35 probes / 29 clean / parity 0.829 against Phase
3b S7's 34 / 29 / 3. Until it is fixed, every later phase's bed baseline
carries it (the #140 failure mode).

Likely twin, unexercised by any fixture today: `oldbest` — a running-root
**Upgrade** entry would print without real's `[oldver]` bracket. Fix it in
the same constructor pass if S0's capture shows it; do not invent a fixture
for it here.

### #135 — the abort/autounmask block is five lines short of real

rc converges (Phase 3b S7 live acceptance); the blocks do not, line for line.
Five arms, evidence `l132-pins/s5b-rest.log` vs S0 `real-rest-1.log` (timing
normalised) and the two beds `l0-fx-20260921T231520Z` (arm D) /
`l0-fx-20260921T234153Z` (libcnoisepkg):

- **(a)** real appends a parent-flip row
  (`- dev-qt/qtdeclarative-6.11.2-r1::gentoo (Change USE: +wayland)`)
  portuale never proposes. The *format* already exists —
  `rust/portuale/src/pretend.rs:2747`'s cycle-break suggestions print
  `- {parent_cpv} (Change USE: …)` — but the USE-failure abort block
  (`use_unsat_candidates_for_atom`, `missing_use_reasons`) only renders the
  child-side `Change USE:` rows, never the parent-flip alternative.
- **(b)** real qualifies chain atoms (`[qml]`, `[kde]`) where portuale prints
  bare cpvs. The `ParentAtom`/`unevaluated` pair
  (`rust/portage-repo/src/lib.rs:18856`, `enqueue_flat_deps` `:18991`) already
  carries the raw token; the abort/autounmask renderers do not use it.
- **(c)** real prints the merge-list preamble and the timing line and *then*
  aborts; portuale suppresses the list (the deliberate "Slice 4 cut" —
  **O7 ruled 2026-09-22: reverse it**). Lessons-of-backlog-ops records the
  shape: masked/unsat aborts reach no `display()` call at all, so no list and
  no `Total:` line. Un-suppressing means running the list renderer on the
  settled remainder *before* the abort block, in the same order real does.
- **(d)** real's plain-miss block is
  `emerge: there are no ebuilds to satisfy "<unevaluated atom>"` plus the
  chains (`depgraph.py`'s `_show_unsatisfied_dep`); portuale prints a bare
  `!!! no visible ebuild for dependency "<cp>"` line
  (`rust/portuale/src/pretend.rs:1792`) and never the atom it already holds
  in `nvc_dep_atoms` (`rust/portage-repo/src/lib.rs:18295-18348`). **This is
  the arm a user sees** — fix it first inside S2. Portuale already prints
  real's sentence in two other places (`pretend.rs:7303`, `:11094`); the
  plain-miss dependency arm is the one that never grew the pair.
- **(e)** portuale's autounmask `USE changes necessary` chain renders an
  installed owner short (`# required by dev-libs/deepusedepparent`) where real
  qualifies it (`-1.0::testrepo`, arm A bed). Same class as (b): the
  renderer drops the version/repo suffix real's `show_unsatisfied_dep` keeps.

### #138 — `Candidates:` repeats `Depstring:` verbatim

Real's `--debug` prints `Depstring:` **raw** and `Candidates:` **evaluated**
(`real-rest-debug.log`, #111 S0):

```
Depstring: ~dev-qt/qtbase-6.11.2:6[accessibility=,...,wayland=,...]
Candidates: ['~dev-qt/qtbase-6.11.2:6[-accessibility,...,-wayland,widgets]']
```

Portuale builds both lines from the same `GraphEntry::deps` list
(`rust/portage-repo/src/resolver_trace.rs:468-479`), which
`merge_order::dep_edges_from_metadata` (`rust/portage-repo/src/merge_order.rs:250`)
fills with the raw token (`DepEdge::atom = t`, no
`evaluate_atom_conditionals`). Verified post-#132 on arm A:
`emerge -p -D --debug dev-libs/deepusedepconsumer` prints
`Candidates: ['~dev-libs/deepusedepchild-1.0[flip=]']` while the walk queues
`[-flip]` — so the line contradicts real **and** portuale's own walk, and the
`--tree`/`Depstring` consistency claim in `resolve_pretend_graph`'s
`already_installed_deps` comment no longer holds for conditional atoms.
`--debug`-only; sibling of #134, same seam.

### #134 — installed `Child:` rows print `USE=""`

`#111 S0`'s `port-rest-debug.log:5990` shows
`Child: (dev-qt/qtbase-6.11.2-r2 …, installed) USE=""`; real prints the built
USE. Still present post-#132. The primary `Child:` printer
(`rust/portage-repo/src/resolver_trace.rs:410-412`) calls `use_str(e)`, which
renders `GraphEntry::use_flags_display` — always empty for an installed
nomerge entry (the resolver never builds display fields for a keep). Real's
equivalent, and portuale's own `installed_use_str` (`:294-310`, the vdb
`IUSE`/`USE` fold in bare-name-sorted order), is already written and is
already used by the *shadowed-child* printer (`:503-504`, the #59 S1 block).
The fix is to make the primary printer pick the same helper for an installed
row. `--debug`-only; no resolve effect.

### #136 — a slot-conflict notice lists one instance short

Bed `l0-fx-20260921T225746Z` (`-D` fixture-oracle probe of the corpus-drift
atoms): real merges **both** `slotusetarget-1.0 USE="x y"` **and**
`2.0 USE="(-x)"` into the conflict; portuale lists only 1.0, and the
comparator reports `USE: real ['(-x)'] vs portuale ['x', 'y']`. Pre-existing
(byte-identical with and without #132); plain `[x]`/`[y]` slot shape, no
conditional in play.

`build_slot_conflict` (`rust/portage-repo/src/lib.rs:17006`) is a
**two-instance** constructor by signature — `existing_version` and
`current_version` — and `slot_conflict_flag_sets` (`:16953`) renders real's
`(…)` "flag in one IUSE but not the other" form only across *those two*. If
the graph holds three colliding instances (or the pair passed in is the wrong
pair), one instance is structurally unreachable. **Needs a real-grounded
fixture pin before designing** — S5's first step is that pin, not a code
edit. #27's `SlotConflict::parents` work (Phase 5, now landed) decided the
*parent* set; this item is the *instance* set beside it.
