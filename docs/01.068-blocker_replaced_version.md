## 1. What real Portage does (`depgraph.py:9095-9255`, read in full)

Per blocker atom:

- `blocked_initial` = **vdb** matches (`initial_db.match_pkgs`,
  `:9123-9129`), filtered by the atom's USE deps.
- `blocked_final` = `_package_tracker.match(root, atom)` (`:9131-9137`).
  The tracker holds graph packages **and installed packages that are not
  replaced** by a graph package in the same slot. So `blocked_final`
  contains merge-bound matches *and* surviving installed matches.
- Neither set non-empty → the blocker is irrelevant (dropped).

Then, per blocker **parent**:

1. For each `pkg` in `blocked_initial` (`:9153-9179`):
   - skip if `pkg.slot_atom == parent.slot_atom` and the blocker is soft
     (`!overlap.forbid`);
   - skip if `parent.installed` ("damage already done");
   - if `parent.operation == "merge"` → `depends_on_order.add((pkg,
     parent))` (uninstall `pkg`);
   - else → `unresolved_blocks = True`.
2. For each `pkg` in `blocked_final` (`:9181-9207`):
   - same soft same-slot skip;
   - skip if `parent.operation == "nomerge" and pkg.operation ==
     "nomerge"` (handled later);
   - if `parent.operation == "merge" and pkg.installed` →
     `depends_on_order.add((pkg, parent))`;
   - elif `parent.operation == "nomerge"` →
     `depends_on_order.add((parent, pkg))` (uninstall the **parent**);
   - else (parent merges, `pkg` is merge-bound) → `unresolved_blocks =
     True`.
3. (`--buildpkgonly` clears `depends_on_order` except strong build-time
   blockers, `:9209-9212`.)
4. If still resolved and `depends_on_order` non-empty: any `inst_pkg`
   that is **in the digraph with parent nodes** → `unresolved_blocks =
   True` (`:9216-9224`); otherwise an `uninstall` task is added with a
   hard edge before the merge (`:9226-9246`) → satisfied (`b`).
5. Resolved with empty `depends_on_order` → irrelevant for that parent.

Host `@world` shape: installed `gtk-doc-1.34.0-r2` is in
`blocked_initial`; `gtk-doc-1.36.1` (graph) replaces it in the same slot,
so the tracker no longer returns 1.34.0 and 1.36.1 is outside the atom →
`blocked_final` empty. Parent `gtk-doc-am-1.36.1` merges →
`depends_on_order = {(gtk-doc-1.34.0, gtk-doc-am)}`. 1.34.0 is not a
digraph node (the graph holds 1.36.1) → uninstall task → `b`, rc 0.

Host runc probe shape: gtk-doc not replaced → installed 1.34.0 is in both
sets → `depends_on_order`; it **is** a digraph node with parents (pulled
in by installed consumers under `--deep`) → `B`, unsolvable.

## 2. Portuale today

`resolve_blockers` builds candidates from `installed_candidates` plus
merge-bound entry versions (deduplicated by `(version, slot)`), matches
the atom, and for every matched version:

```rust
let blocked_installed = installed_candidates(root, cp).iter().any(|(v, ..)| v == version);
let unsolvable = blocked_installed
    && installed_has_foreign_dependents(root, cp, &pb.owner_key, entries);
```

`installed_has_foreign_dependents` scans the whole vdb for any *other*
installed package (not being replaced this run) with a non-blocker
`RDEPEND`/`PDEPEND`/`DEPEND`/`BDEPEND` atom on the blocked **cp** (any
version, no `with_bdeps` gate).

Gaps against §1:

1. **No "replaced in its slot" check.** Installed `gtk-doc-1.34.0` stays
   a match although a merge-bound 1.36.1 replaces it; any foreign
   dependent then makes it unsolvable (the host bug).
2. **Merge-bound matches are never unsolvable.** A matched merge-bound
   version gets `blocked_installed = false`, while real marks it
   unresolved when the parent merges (2, last arm).
3. **Same-version reinstall is invisible.** A `Reinstall` entry at the
   installed version is deduplicated into the installed candidate, so it
   looks like an installed-only match (real: it is merge-bound in the
   tracker → unresolved).
4. **Parent operation is not modelled.** `PendingBlocker` has no
   merge/nomerge bit, yet blockers are also pushed from installed
   parents by `enqueue_dependencies`. Real ignores an installed parent's
   `blocked_initial` matches and, for a no-merge parent vs a merge-bound
   `pkg`, schedules uninstall of the parent instead of failing.
5. **The "pulled in" test is a vdb reverse scan**, not "is a graph node
   with parents". Under `--deep`, portuale's `entries` already carry
   `AlreadyInstalled` nodes with their `deps`, which approximates real's
   test far better (only packages actually walked this run count, and
   build-time deps only when `with_bdeps`).
6. **Soft same-slot skip** (`pkg.slot_atom == parent.slot_atom`) is only
   approximated by the "own owner version" skip.

| b | `blocked-1.0` installed, same-version reinstall graphed (`--newuse` flip), `bparent` merged | `B` (merge-bound match) |
| c | `blocked-1.0` installed, not replaced, installed `consumer` RDEPENDs on it and is walked (`-uD @world`), `bparent` merged | `B` (digraph node with parents; host runc shape) |
| d | `blocked-1.0` installed, not replaced, its installed reverse dep is **not** walked (`--oneshot bparent`, no `--deep`) | `b` (uninstall-ordered) |
| e | `blocked-2.0-r0` merge-bound (New), `bparent` merged, atom `!<blocked-3` | `B` |
| f | installed `bparent` (nomerge, walked via `--deep`) with the blocker; `blocked-1.0` installed, not replaced | ignored / no block line (both nomerge) |
| g | as f, but `blocked-1.5` graphed as a New/upgrade matching the atom | uninstall of the parent → `b` unless the parent has graph parents |
| h | strong `!!` variants of a and of a same-slot self-block | `overlap.forbid`: same-slot skip does not apply |

**S1 — replaced installed versions (host fix).** For an installed matched
version `v` with slot `s`: if a merge-bound entry
(`Upgrade`/`Downgrade`/`Reinstall`) for the same cp targets slot `s` at a
version `≠ v`, `v` leaves the tracker; it only contributes to
`depends_on_order` and its "has graph parents" test is false (the graph
node is the replacement). Report the block **satisfied**
(`unsolvable = false`, `[blocks b]`), whatever the replacement version:
if the replacement itself matches the atom, it is matched separately and
S2 makes that row unsolvable. Match with the existing
`match_from_list` on `cat/pkg-ver:slot/subslot` strings; compare slots
from `installed_candidates`' `(version, slot, sub_slot)`.

**S2 — merge-bound matches and parent operation.**
- Add `owner_merging: bool` to `PendingBlocker` (true from the
  merge-bound walk, false from `enqueue_dependencies`).
- Keep a separate candidate row for a same-version `Reinstall` entry
  (do not deduplicate it into the installed row), tagged merge-bound
  (cell b).
- Merge-bound match + merging owner → `unsolvable = true` (cells b, e).
- Installed match + non-merging owner → no conflict row (cell f).
- Merge-bound match + non-merging owner → satisfied unless the owner has
  graph parents (cell g; see S3's test).
- Soft same-slot skip: skip a match whose `(cp, slot)` equals the
  owner's, unless the blocker is strong (cell h).

**S3 — "pulled in" = walked with parents.** Replace the vdb reverse scan
for installed matches that are *not* replaced with: some **other** graph
entry (any outcome, including `AlreadyInstalled`, excluding the blocker
owner) whose recorded `deps` (`GraphEntry::deps`, runtime keys, plus
build-time keys only when `with_bdeps`) have an atom matching the
installed `cpv:slot/subslot`. Keep `installed_has_foreign_dependents` as
the fallback only when the run is not `--deep` **and** S0's cell d says
real still marks it unresolved; otherwise delete it. If S0 shows cells
c/d disagree with this model, stop and report.

**S4 — pins + docs.** §5.
