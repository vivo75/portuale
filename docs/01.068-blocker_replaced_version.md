## 1. What real Portage does (source-grounded)

`depgraph._validate_blockers` (`depgraph.py:9116-9255`) classifies, for
each blocker atom of a merging parent:

- `blocked_initial`: **installed** packages matching the atom
  (`depgraph.py:9124-9132`, `vatree.dbapi.match_pkgs`).
- `blocked_final`: packages in the **current graph** matching the atom
  (`:9134-9141`, `_package_tracker.match`).

Then, per parent:

- A `blocked_final` match sets `unresolved_blocks = True` immediately
  (`:9180`) — a merge-bound package that still matches the block is a
  real conflict.
- An installed-only match whose `parent.operation == "merge"` is
  *resolvable*: it goes to `depends_on_order` (`:9155-9160`) and later
  gets an `uninstall` task with a hard order edge **before** the blocker
  parent (`:9230-9254`), i.e. the blocked installed version is removed
  while the blocker's package is merged.
- That uninstall path is abandoned (`unresolved_blocks = True`) only if
  the installed match is itself **in the current digraph and has parent
  nodes** (`:9218-9226`) — i.e. something else in this run is still
  pulling it in.
- `parent.installed` matches are ignored entirely ("damage already
  done", `:9146-9151`).

For the host case: `<dev-util/gtk-doc-1.36.1` from
`gtk-doc-am-1.36.1`; installed `gtk-doc-1.34.0` matches initially, but
the graph holds `gtk-doc-1.36.1` (an upgrade, outside the atom), so
`blocked_final` is empty, the installed match is uninstall-ordered and
the block renders `b`/"all satisfied" with exit 0.

## 2. Portuale today

`resolve_blockers` builds the candidate list from installed packages
plus merge-bound entry versions (`:14526-14547`), matches the atom
against it, and for every matched version computes:

```rust
let blocked_installed = installed_candidates(root, cp).iter().any(|(v, ..)| v == version);
let unsolvable = blocked_installed
    && installed_has_foreign_dependents(root, cp, &pb.owner_key, entries);
```

(`:14642-14653`). `installed_has_foreign_dependents` (`:14468-14516`)
scans the vdb for any *other* installed package (skipping packages this
run replaces) with a non-blocker dep on the blocked cp.

Gaps against real:

1. **No "superseded" check.** Installed `gtk-doc-1.34.0` counts even
   though a merge-bound `1.36.1` replaces it outside the block. Every
   foreign dependent then makes it `unsolvable`.
2. **Inverted classification for graph matches.** A matched version that
   is a merge-bound entry (`blocked_final`) currently yields
   `blocked_installed = false` → `unsolvable = false` (reported
   satisfied), where real marks it unresolved.
3. **The "pulled in" approximation is the vdb reverse scan**, not the
   current graph; real only cares whether the installed instance is a
   node with parents *this pass*. That over-approximation is what turns
   the case fatal.

## 3. Design

**S0 — oracle first.** Build a fixture matrix and capture real 3.0.82.2
with the fixture-oracle bed (or a copied configroot on a scratch tree):

| cell | setup | expected real |
|---|---|---|
| a | `blocked-1.0` installed, `blocked-2.0` graphed, `bparent-1.0` merged with `!<blocked-2.0` | `b` satisfied, rc 0 (host shape) |
| b | `blocked-1.0` installed, `blocked-1.0` reinstall graphed (same version), `bparent` merged with `!<blocked-2.0` | unresolved (`blocked_final`) |
| c | `blocked-1.0` installed and pulled in as a dep of `consumer-1.0` which is merged in the same run; `bparent` merged with `!<blocked-2.0` | unresolved (`digraph.contains && parent_nodes`) |
| d | `blocked-1.0` installed, not in graph, only installed reverse-deps; `bparent` merged with `!<blocked-2.0` | `b` satisfied (uninstall-ordered) |
| e | strong `!!` blocker, same shapes | per `overlap.forbid` rules (`:9157-9163`) |

Cells a/c/d are the ones that decide the portuale predicate; b guards
`blocked_final`; e checks the strong-blocker exemption is not lost.

**S1 — superseded check.** For an installed matched version `v`, treat
it as going away when some merge-bound entry for the same `cat/pkg`
replaces it (`Upgrade`/`Downgrade`/`Reinstall`) to a target version that
does **not** match the blocker atom. In that case the block is
satisfied regardless of foreign dependents:

```rust
let superseded_by_nonmatching = entries.iter().any(|e| {
    e.category == pb.target_category
        && e.package == pb.target_package
        && matches!(e.outcome, Upgrade { .. } | Downgrade { .. } | Reinstall { .. })
        && entry_target_version(e) != version
        && !atom_matches_cpv(&pb.atom_str, entry_target_cpv(e))
});
let unsolvable = blocked_installed
    && !superseded_by_nonmatching
    && installed_has_foreign_dependents(...);
```

Matching must reuse the same slot-aware path `resolve_blockers` already
uses for candidates (`match_from_list` on the `cat/pkg-ver:slot/subslot`
strings), not a new parser.

**S2 — graph-match classification.** If the matched version comes from a
merge-bound entry (not the vdb), mark `unsolvable = true` per real's
`blocked_final` (`:9180`). Keep the existing exception that skips the
blocker's own owner (`:14625`).

**S3 — tests + docs.** §4.

Do **not** replace `installed_has_foreign_dependents` with a graph-edge
walk in this slice: portuale has no complete graph here. Instead, narrow
its over-approximation only via S1 (the host-visible bug) and leave the
"pulled-in" approximation documented, with cell c pinned so the
approximation's intended direction is at least tested.

## 7. Non-goals and residue

- Full `_complete_graph`-based "pulled in" detection (backlog #25's
  territory); S1/S2 keep the vdb approximation and only remove the
  fatal false positive.
- Uninstall-task scheduling for the blocked version (real actually
  unmerges `gtk-doc-1.34.0` in the merge run): portuale's pretend list
  and real execution of blocker-induced unmerges stay out of scope; the
  fix here is the *report* (satisfied, rc 0) and the merge list, not the
  unmerge step.
- Strong-blocker `overlap.forbid` rules beyond what cells e/f pin.

## 8. Risks

- **Over-satisfying:** S1 must only fire when the replacement target is
  outside the atom; a same-version reinstall or a version still inside
  the block must stay unresolved (cell b is the guard).
- **Slot awareness:** a replacement in a *different slot* does not
  remove the blocked instance; the superseded check must compare the
  installed instance's slot and only consider an entry replacing that
  same slot (the entry carries `slot`, and installed candidates carry
  `(version, slot, sub_slot)`).
- **Exit-code convention:** this slice keeps portuale's existing
  `unsolvable → rc 1` wiring; it does not touch the informational
  slot-conflict convention (backlog #60/#62).
