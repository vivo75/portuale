### P15 — #149: evaluated `SLOT` on the source merge path

Real grounding (read before the slice): `vartree.py` `dblink.treewalk`,
the `for var_name in ("CHOST", "SLOT")` loop. Real reads **`SLOT` from
`inforoot` (`build-info/SLOT`)**, which bash wrote after `src_install`
(vendored `bin/phase-functions.sh`, the build-info write list that
includes `SLOT`). That is the *evaluated* value, e.g. `4` for
`SLOT="$(ver_cut 1)"`. When it is empty, real falls back to
`settings["SLOT"]` and writes it back. When both are empty it prints
`!!! SLOT is undefined` and returns 1. On a source build, a value that
differs from `settings` gets a `QA Notice: Expected SLOT=…` eqawarn.
The binary path already reads the same file through `merge_binpkg`'s
`meta_get("SLOT")`.

- **S0.** Confirm portuale's install phase writes `build-info/SLOT`
  (`env.build_info()`) for mpdecimal. Capture both vdb `SLOT` values
  (real `4`, portuale `$(ver_cut 1)`) from the repro in the item text.
  List every consumer of the literal slot in `merge_after_install`
  (`installed_instance_pf`, `blocked_installed_packages`,
  `find_collisions`, `write_vdb_entry`, `unmerge_replaced_same_slot`).
  Also search for other raw-ebuild-text reads on the source path besides
  `parse_slot`. `parse_eapi` is legitimately literal (PMS). Anything
  else is in scope only if it has the same defect; otherwise file it.
- **S1.** `merge_after_install` takes `full_slot` from
  `build-info/SLOT`, with real's fallback chain (settings/metadata slot,
  then the `!!! SLOT is undefined` rc 1). Whether to port the QA notice
  is decided in S0: port it if the phase runtime already has an eqawarn
  seam, file it otherwise. `parse_slot` either goes (with its two unit
  tests) or survives only if S0 finds a consumer that still needs it.
  The stale module doc comment in `ebuild_merge.rs` ("a `SLOT` computed
  by real bash logic … is out of scope") is corrected. Tests: a Rust
  fixture-driven end-to-end test with a hand-built fixture whose
  ebuild has `SLOT="$(ver_cut 1)"` (fixture-smith: collision-checked,
  real md5-cache entry). The test runs a reinstall under `protect-owned`
  and asserts no collision abort and vdb `SLOT` = the evaluated value.
  The expected value comes from real Portage on the host or the container,
  and the test's docstring says which.
- **Close.** Full verification pass; L1 gate (P14 made it runnable) **and**
  the R5 source-path cell. Merge-path rule: both must be green, with
  glibc and bash merged from source over the running container. #149 →
  `DONE`.
