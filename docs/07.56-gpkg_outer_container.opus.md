## 1. What real does (read from source, to confirm in S0)

`3rdparty/portage/lib/portage/gpkg.py` (portage-3.0.82.2):

- `_verify_binpkg` (~1626-1780) opens the outer container with Python
  `tarfile` and never extracts it to disk. It rejects absolute names,
  names not exactly one directory deep, no common prefix, duplicate
  names, a missing `Manifest`; every non-Manifest member needs a Manifest
  record whose size equals `container.getmember(f).size`.
- Member bytes are read with `container.extractfile(member)`. For a
  **symlink/hardlink** member `tarfile` resolves the link target *inside
  the archive* (never on the host filesystem); for a **device/FIFO**
  member it returns `None`, so the following `.read()` raises. A link or
  special member is also size 0 in its header, so the Manifest size
  check fails first for any listed member.
- `_get_inner_tarinfo` (~2193) finds `metadata.tar*`/`image.tar*` by
  name without a type check; the same `extractfile` behaviour applies.

So real's *effective* behaviour is: special members are never followed
out of the archive, and they fail (size mismatch or an exception). The
review's "not a verified divergence" is partly answered: real does not
check entry types explicitly, but it can never read through them.

## 2. What portuale does

`rust/portuale/src/binpkg.rs` extracts the outer container with the
system `tar -xf <gpkg> -C <scratch>/outer` (`run_tar` ~1018) and then
walks the **filesystem**:

| site | walk | what trusts a name |
|---|---|---|
| `read_gpkg_metadata` (~134) | `basename_dir.is_dir()`, then members by name | `gpkg-1` marker, `metadata.tar*` (then copied/decompressed) |
| `verify_gpkg_manifest` (~399) | `entry.is_dir()` for the prefix (~413), `manifest_path.is_file()` then `fs::read` | `Manifest`, every listed member hashed |
| `extract_gpkg_member` (~718) | same shape as `read_gpkg_metadata` | `gpkg-1`, `<want>.tar*` (`fs::copy` / decompressor) |

`Path::is_dir`/`is_file`, `fs::read` and `fs::copy` all **follow
symlinks**. Consequences for a crafted outer tar (to be demonstrated in
S0, not assumed):

- a `<prefix>/Manifest` or `metadata.tar` **symlink** is read through to
  whatever it points at on the host (GNU tar strips leading `/` and
  refuses `..` in *member names*, but a symlink's *target* is stored
  verbatim);
- a **symlinked prefix directory** makes the walk list a host directory;
- as root, GNU tar creates **FIFOs and device nodes**; reading a FIFO
  member blocks forever, a char device like `/dev/zero` never ends;
- a **hardlink** member whose target is another member is just a regular
  file (harmless); one whose target escapes should be refused by GNU tar
  (verify).

## 3. Decisions for the owner

| id | question | proposed default | why |
|---|---|---|---|
| **N1** | Scope | **All three walk sites** through one shared helper, not only ~413. | Same pattern three times; fixing one leaves two. |
| **N2** | Mechanism | **`symlink_metadata` / `DirEntry::file_type()` (no follow) after extraction**: the prefix must be a real directory; `gpkg-1`, `Manifest`, `metadata.tar*`, `image.tar*` and `.sig` members must be regular files; anything else is an error naming the member and its type. Keep `tar -xf`. | Minimal change at the existing sites. A pre-extraction `tar -tv` listing parse is locale/format fragile; switching to an in-process tar reader is a larger change (and `binpkg.rs` deliberately shells out). |
| **N3** | Extraction flags | Add **`--no-same-owner`** (and consider `--no-same-permissions`) to the outer `tar -xf`, so root never recreates archive ownership in the scratch dir. Device nodes may still be created but are never opened after N2. | Cheap defence in depth; behaviour for valid archives is unchanged. |
| **N4** | Error wording vs real | **Portuale's own message**, not a copy of real's exception text; no contract pin on wording. | Real's behaviour here is an exception or a digest error, not a user-facing message worth matching. |

### S0 — crafted-archive matrix (executor M)

1. Write `scripts/gpkg_crafted_members.py`: starting from a valid gpkg
   (the fixture `read_gpkg_metadata_extracts_the_embedded_scalar_metadata`
   uses, or `build_gpkg` in the `binpkg.rs` tests as a model), emit one
   archive per cell into a given directory. Each cell replaces one member
   with the special entry and keeps the Manifest otherwise valid:

   | cell | member | entry |
   |---|---|---|
   | a | `Manifest` | symlink -> `/etc/hostname` |
   | b | `metadata.tar.zst` | symlink -> `/etc/hostname` |
   | c | prefix dir | symlink -> `/etc` (plus members beside it) |
   | d | `metadata.tar.zst` | FIFO |
   | e | `image.tar.zst` | char device (major/minor of `/dev/zero`) — root only |
   | f | `metadata.tar.zst` | hardlink -> `<prefix>/gpkg-1` |
   | g | `metadata.tar.zst` | hardlink -> `../../etc/hostname` |
   | h | `gpkg-1` | symlink -> `Manifest` |

2. Real: for each archive, run real's reader on the host's installed
   portage (`/usr/lib/python3.*/site-packages/portage`, read-only use) or
   the vendored `3rdparty/portage/lib` via `PYTHONPATH`:
   `portage.gpkg.gpkg(settings, basename, path)._verify_binpkg()` and
   `.get_metadata()`. Record the exception class/message or result.
3. Portuale: exercise the same archives through `read_gpkg_metadata`,
   `verify_gpkg_manifest` and `extract_gpkg_member` — a temporary
   `#[ignore]`d Rust test or an `emerge -K`/`--usepkgonly -p` run against
   a throwaway `PKGDIR`. Use `timeout 10` for the FIFO/device cells.
   Record: followed the link? read host bytes? hung?
4. Write `## #56 S0` in `TEST/findings/l2.md` (binpkg findings live
   there): the matrix with real vs portuale columns, commands, and a
   verdict on which cells are genuine divergences (expected: a, b, c, d,
   e for portuale; none follow the host for real).
5. Commit (script + findings; drop the temporary `#[ignore]` test).

### S1 — the check (executor M, F review)

1. Add a helper in `binpkg.rs`, e.g.
   `fn regular_outer_member(path: &Path, gpkg: &Path) -> Result<(), String>`
   using `fs::symlink_metadata(path)?.file_type().is_file()`, and
   `fn outer_prefix_dir(...)` using `file_type().is_dir()` (no follow).
2. Use them at every name-trusting point of the three sites (N1):
   the prefix directory, `gpkg-1`, `Manifest`, the selected
   `metadata`/`image` member, and each member `verify_gpkg_manifest`
   hashes (including `.sig`). A non-regular member is an error, never
   "skipped and keep looking" (a skipped `metadata.tar` symlink must not
   let a second, regular one win silently).
3. N3: `--no-same-owner` on the three outer `run_tar` calls.
4. Tests next to `verify_gpkg_manifest_rejects_*` (extend `build_gpkg`
   to add a symlink/FIFO/hardlink entry — `tar` via
   `--transform`/a staged directory, or write headers directly):
   one test per non-root S0 cell (a, b, c, d, f, h) per affected
   function, asserting an error that names the member; cell e as a
   root-only test gated like `test_merge_skips_an_identical_file_preserving_ownership`.
   A valid gpkg (the committed fixture) still reads and verifies.
5. Workspace-root build/test/clippy; `pytest tests/ -k "gpkg or binpkg"`
   plus the full suite by failing names; if cheap, L2 porttest normal
   track unchanged (**U**).
6. Commit.
