## 0. The finding as filed

3.0.82.2:

```
emerge -puD --getbinpkg net-libs/rest      # and sys-devel/gcc
-> rc 1
emerge: there are no ebuilds built with USE flags to satisfy
  "~dev-qt/qtbase-6.11.2:6[accessibility=,gui,network=,opengl=,sql?,ssl=,vulkan=,wayland=,widgets=]"
```

(installed consumer chain: qtdeclarative → qt5compat → libplasma →
polkit-kde-agent → polkit → polkit-qt.)

Targeting qtbase **directly** (`-pv --getbinpkg dev-qt/qtbase`) resolves
on **both**, same binary, same `USE="… wayland …"`. So this is not a
missing binary: it is the deep-update × binpkg-USE interaction.

**Pre-existing, not from the #109/#110 batch** — the pre-batch baseline
binary and the post-batch binary both resolve while real aborts.

**It blocks** the interleaved real-vs-portuale comparison in
`performances-tuning.md`, so every later Tier-8 measurement is on hold
behind it.

## 1. The standing trap this item must not fall into

[Memory: `getbinpkg ⇒ bdeps off probe trap`.] `--getbinpkg=y` implies
`--usepkg`, and real then ignores built packages' `DEPEND`/`BDEPEND`.
Two earlier items (#66 invented, #65 mis-aimed) came from comparing
runs whose *effective* options differed. **Before any other work,
confirm both sides run identical effective options**: dump them from
each side and diff them. If they differ, that is the whole finding and
the slice ends there.
