## 1. Problem

`portuale emerge -uDpvN @world` on this host ignores every option in
`EMERGE_DEFAULT_OPTS`:

```
/etc/portage/make.conf:   source /etc/make.local
/etc/make.local:          EMERGE_DEFAULT_OPTS="... --binpkg-respect-use=y
                          --load-average=11 --autounmask=y
                          --ask-enter-invalid --usepkg=n --getbinpkg=y"
```

The visible symptom is the binary/source form of the merge list
(evidence file): real uses the binhost for `dev-lang/go-1.27.1-1` and
`dev-build/cmake-4.3.5-1` (`[binary gU]`, plus the
`[f1r] Local copy of remote index is up-to-date` notice); portuale lists
both as `[ebuild U]`. It is not a resolver or binpkg-reader bug: the same
run with the option **on the command line** works today
(`portuale emerge -pv --getbinpkg --oneshot dev-build/cmake` prints
`[binary gU] dev-build/cmake-4.3.5-1`). Only the defaults plumbing is
missing. The other defaults (`--binpkg-respect-use=y`,
`--load-average=11`, `--autounmask=y`, `--ask-enter-invalid`,
`--usepkg=n`) are equally inert.

## 2. What real Portage does (source-grounded)

`_emerge/main.py` parses the command line **twice**:

- First pass: just enough to know `--config-root` (and the early
  actions), because "they will be parsed again later, together with
  EMERGE_DEFAULT_OPTS (which may vary depending on the value of
  `--config-root`)" (`main.py:1221-1232`). `--help`/`--moo`/`--status`
  return before any config load (`main.py:1254-1259`).
- Config load, then the second pass (`main.py:1352-1360`):

  ```python
  tmpcmdline = insert_optional_args(
      shlex.split(
          emerge_config.target_config.settings.get("EMERGE_DEFAULT_OPTS", "")
      )
  )
  tmpcmdline.extend(args)
  myoptions, myaction, myfiles = parse_opts(tmpcmdline, silent=silent)
  ```

  So the defaults are **prepended** and ordinary argv wins for
  last-wins options. `EMERGE_DEFAULT_OPTS` is read from the resolved
  settings, i.e. process env over make.conf/profile.

Downstream folding that matters here:

- `--getbinpkg` reaches the trees as `getbinpkgs=True`
  (`actions.py:167-173`), so the bintree is consulted even when
  `--usepkg=n` is also present; portuale already folds the family the
  same way (`let usepkg = usepkg || getbinpkg || getbinpkgonly;`,
  `pretend.rs:10330-10352`), so once the option is parsed the existing
  binpkg code paths do the rest.
- `--binpkg-respect-use` / `binpkg_changed_deps` auto-enable unless
  `--usepkgonly` (`create_depgraph_params.py:46-56,196-203`); portuale
  already models the latter (`pretend.rs` "auto-enabled whenever
  --usepkgonly is not given") and the former in its binary-candidate
  filtering.

## 3. Portuale today

- `EMERGE_DEFAULT_OPTS` is already read into the config: it is in
  `ENV_SCALAR_VARS` (`portage-profile/src/lib.rs:1276-1304`, entry
  `:1301`), so `resolve_config` stores the effective value (env, else
  make.conf/`source`d file) in `config.other_vars`
  (`config.other_vars = scalars`, `portage-profile/src/lib.rs:3303`).
  It is only ever *displayed* (`pretend.rs:6607`, the `--info` var list)
  — nothing consumes it.
- `pretend::run(args)` (`pretend.rs:7494`) parses argv directly into
  locals; `wants_help(args)` is its first check.
- Config resolution lives *below* the parse loop
  (`pretend.rs:9792-9863`): `root_from_env()`/`config_root_from_env()`,
  `find_repos`, `resolve_config`. Nothing in that block depends on
  parsed options — only environment roots — so it can move earlier
  without behavioural change except for error precedence.
- A shlex-like splitter already exists: `shell_split`
  (`pretend.rs:3588`, built for `PORTAGE_IONICE_COMMAND`; quoting +
  backslash escapes, unterminated quote consumes the rest).

## 4. Design

**S1 — move config resolution above the argv loop.** Cut
`pretend.rs:9792-9863` (roots → repos → `resolve_config`) and paste it
immediately after the `wants_help` early-return. Keep `color`
instantiation, `apply_portage_scheduling_policy`, and every later use
site where they are. This mirrors real's "config first" order and gives
the parser a `config` to read defaults from.

**S2 — extract the prepend helper and call it.** Factor a tiny pure
function so the ordering rule is unit-testable:

```rust
/// Real `main.py:1352-1360`: `EMERGE_DEFAULT_OPTS` tokens (`shlex.split`)
/// prepended to argv, so command-line options win. `[]` when unset.
pub(crate) fn args_with_emerge_defaults(config: &Config, args: &[String]) -> Vec<String> {
    let mut out = config
        .other_vars
        .get("EMERGE_DEFAULT_OPTS")
        .map(|v| shell_split(v))
        .unwrap_or_default();
    out.extend(args.iter().cloned());
    out
}
```

In `run`:

```rust
let effective: Vec<String> = args_with_emerge_defaults(&config, args);
let args: &[String] = &effective;   // shadows the parameter
```

`wants_help` stays **before** config resolution (real's early `--help`
returns before config load, `main.py:1254`). Every other early action
(`--info`, `--search`, `--config`, …) already resolves config
unconditionally today, so no action path changes.

**S2b — the host defaults' own missing options.** Applying the variable
made two options in this host's `make.local` reachable for the first
time: `--ask-enter-invalid` was recognized-but-unimplemented (every
`portuale emerge` on the host would have exited 2 with the
"not yet implemented" message) and `--ignore-default-opts` was the same.
Both are now implemented rather than left as blockers:

- `--ignore-default-opts`: real `main.py:1352-1353` gates the whole
  prepend on it; `args_with_emerge_defaults` checks the raw argv and
  returns it unchanged, the parser accepts the flag as a no-op.
- `--ask-enter-invalid`: real `UserQuery.query`'s `enter_invalid`
  argument (`_emerge/UserQuery.py:63-72`) only matches a response when
  it is non-empty or the flag is off; portuale stores it process-wide
  (`ASK_ENTER_INVALID`, reset at `run` entry), `classify_yes_no` takes
  the flag, and `ask_confirm`/`ask_select` honour real's bare-Enter
  behavior. This is the one host default that had no implementation at
  all; without it the fixed defaults plumbing would still fail every
  host invocation.

Both move out of `emerge_options::BOOLEAN_OPTIONS` (the
recognized-but-unimplemented table) and into the implemented help text.

**S3 — tests + docs.** See §6.

Known narrowings, to state in the docstring and §7:

- Portuale has no `--config-root`/`--root` CLI implementation (they are
  recognized names only; roots come from `PORTAGE_CONFIGROOT`/`ROOT`),
  so the two-pass dance collapses to one pass. If `--config-root` ever
  lands, this helper must run *after* the early root parse.
- `mrg` (the clap-based relaxed CLI) is a separate applet and does not
  read defaults; keep it out unless the owner asks.
- Error precedence shifts: a broken repo config now fails before an
  unknown-option error. Real behaves the same way (config load precedes
  the second `parse_opts`), so this is intended, not a regression to
  paper over in tests.

## 7. Non-goals and residue

- `--config-root`/`--root` CLI parsing (their absence is why one pass
  suffices here) — separate work.
- `mrg` reading defaults.
- Full `argparse`-style optional-value semantics beyond what
  `shell_split` + the existing parser already provide.
- **Filed as backlog #69 (exposed by this slice):**
  `--getbinpkg`/`--usepkg` + `--newuse` drops a needed rebuild.
  `dev-qt/qttools` needs a USE-change reinstall (`LLVM_SLOT="… (-23%)"`);
  real rebuilds it, portuale does not once `--getbinpkg` (or the host
  defaults) enables remote binrepo candidates — `--usepkg` alone is
  fine, and `--ignore-default-opts` is fine. Likely the remote binary
  candidate for an installed package shadows the newuse rebuild across
  `--binpkg-respect-use`; needs its own oracle.
- The host's post-fix `-uDpvN @world` still differs from real by #65's
  20 Go `rRg` rebuilds, #67's xorg-drivers/sane-backends, #68's gtk-doc
  block, and #69 above — this slice's own scope ends at the defaults
  plumbing and the world-set fix.

## 8. Risks

- **Config errors surface earlier.** An unknown-option test that relies
  on the error text may need re-grounding if its config is broken; run
  the suite and compare failures by name.
- **Double resolution is avoided**, but anyone later adding a
  `--config-root` early parse must not re-resolve after argv parsing
  without re-reading defaults — leave the `main.py:1221` source comment
  attached to the moved block.
- **Env leakage:** the session fixture already strips the variable;
  tests that set it must pass a private `env` dict, never `os.environ`.
