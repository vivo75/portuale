## 1. What real does (3.0.82.2, `3rdparty/portage/lib/portage/gpkg.py`)

**Writer** — `gpkg._add_metadata`: one `TarInfo("metadata/<KEY>")` per key,
regular files only, USTAR, **no directory entries, no links**. So no
archive real produces can be affected by a regular-file-only check.

**Populate/read** — `unpack_metadata(dest_dir=None)` (via `get_metadata`):
reads the inner tar fully into memory, then for **every** member
`metadata.extractfile(k).read()` keyed by `_strip_metadata_prefix(k.name)`:

| inner member | real result |
|---|---|
| regular `metadata/KEY` | bytes |
| name not under `metadata/` | `InvalidBinaryPackageFormat` |
| symlink, target inside the archive | the **target member's** bytes (tarfile resolves in-archive) |
| symlink, target outside (`/etc/hostname`, `../..`) | `KeyError: linkname ... not found` (verified 2026-09-15) |
| hardlink to an archive member | the target's bytes |
| hardlink to a non-member | `KeyError` |
| directory / FIFO / char / block device | `extractfile` -> `None` -> `AttributeError` on `.read()` |
| nested `metadata/sub/KEY` | key `sub/KEY` (never produced by the writer) |

No host file is ever read. `bintree._populate_local` (`bintree.py` ~288,
~748) only catches `SignatureException` around `get_metadata()` — whether a
`KeyError` there aborts real `emerge` with a traceback or is caught higher
is **to be confirmed in S0**, it decides what "matching real" means for the
caller.

**Merge** — `unpack_metadata(dest_dir)` -> `tar_safe_extract(metadata,
"metadata").extractall(dest)`: rejects duplicate names, absolute names,
`../` traversal, **device members**, and **hardlinks whose target is not an
earlier member**; **symlinks are extracted as-is** (`fully_trusted_filter`)
into a temp dir and `shutil.move`d into build-info. So on the merge path
real *does* write a symlink into build-info — but for an escaping symlink
the preceding populate `get_metadata()` already failed, so real never gets
there for a package from its own pool. S0 confirms both halves.

## 2. What portuale does

`rust/portuale/src/binpkg.rs`:

| site | inner handling | problem |
|---|---|---|
| `read_gpkg_metadata`, step 4-5 | `run_tar -xf metadata.tar -C md` (no `--no-same-owner`), then `read_dir_sorted(md/metadata)`, `f.is_file()` + `fs::read(&f)` | `is_file`/`fs::read` **follow** symlinks: an escaping `metadata/DESCRIPTION -> /etc/hostname` returns the host file as the value (verified). FIFO member: `is_file` false -> skipped (no hang, but real errors). Names outside `metadata/` silently ignored (real errors). |
| `extract_gpkg_member(_, "metadata", build_info)` (merge, via `extract_binpkg`) | `run_tar -xpf metadata.tar -C build_info --strip-components=1` | symlinks, FIFOs and (as root) device nodes land in `${PORTAGE_BUILDDIR}/build-info`; everything that later reads build-info (`write_vdb_entry_from_dir`, `BINPKGMD5` write, env extraction of `environment.bz2`, `pkg_*` phases) follows them — and a later **write** into build-info through a symlink is a host write as root. |
| `extract_gpkg_member(_, "image", image)` | same `tar -xpf` | image symlinks are legitimate; real rejects only device members / escaping hardlinks / abs / traversal here. **Out of #58 scope by default (K2)**; S0 measures it. |

Callers that matter (`graft callers extract_binpkg` / `read_gpkg_metadata`):
`ebuild_merge::merge_binpkg` (reads metadata **before** extracting — so
fixing the read path already blocks the merge for an escaping symlink),
`remote_bundle::build_bundle` (same order), `pretend::run_info` (calls
`extract_binpkg` **directly** — no prior read; S0 verifies), and
`scan_binpkg_file` (populate; its `?` propagates — S0 records what its
caller does with the `Err`: skip-with-warning or abort).

## 3. Decisions for the owner

Defaults are what the slices implement if the owner does not answer.
Ask before S1 only if S0 contradicts a default's premise.

| id | question | proposed default | why |
|---|---|---|---|
| **K1** | Read-path semantics for a non-regular inner member | **Error** (the whole `read_gpkg_metadata` fails, message names the member and its type) for every symlink, hardlink-to-non-regular, FIFO, device, and for a directory other than `metadata/` itself. Checked with `fs::symlink_metadata` (no follow) on each entry, **before** any `fs::read`. A GNU-tar-extracted in-archive hardlink is a regular file and stays accepted (same bytes as real). | Matches real for every escaping/special cell. Deliberate **narrowing** for an in-archive symlink (real returns the target's bytes, portuale errors): real's writer never emits one, and resolving in-archive links after `tar -xf` would need an in-process tar reader (#56 N2 rejected that). Documented as a cut. |
| **K2** | Scope of the merge-path extraction | **`extract_gpkg_member(_, "metadata", _)` only**: after `tar -xpf`, walk `dest` with no follow and error on anything that is not a regular file (the strip leaves no directories in a valid archive). The `image` extraction is not touched; S0 records the image cells and, if portuale diverges from real's `tar_safe_extract` (device members as root), files a **new backlog item** instead of widening #58. | Keeps #58 to what it was filed for. The image tree legitimately holds symlinks and needs real's exact `tar_safe_extract` rule set (dup/abs/traversal/dev/hardlink), which is its own design. |
| **K3** | Names outside `metadata/` in the inner tar (real: `InvalidBinaryPackageFormat`) | **Error on the read path** (any top-level entry of `md/` other than the `metadata` directory), same wording style as K1. | Cheap, same walk, closes a silent-ignore divergence. The merge path's `--strip-components=1` already drops the prefix; K2's walk covers what lands. |
| **K4** | Nested `metadata/sub/KEY` | **Error** (a directory under `metadata/` is a non-regular member under K1). | Real yields key `sub/KEY`, but its writer never emits it and no reader consumes such a key. Narrowing, documented. |
| **K5** | Extraction flags | Add **`--no-same-owner`** to both inner `tar -x` calls on the metadata path (and `--no-same-permissions` only if S0 shows a valid archive is unaffected). | Mirrors #56 N3; valid archives unchanged. |
| **K6** | Error wording | **Portuale's own message** (`<gpkg>: inner metadata member <name> is a <type>, not a regular file`), reuse the #56 `outer_entry_error` style/helper if its signature fits. No contract pin on real's exception text. | Real's behaviour is an exception, not a user-facing message (#56 N4). |
