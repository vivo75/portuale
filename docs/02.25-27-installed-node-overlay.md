#26's entry reads: *"with the gate on, only
`test_oracle_slotop_undo_cascade` (the dropped consumer) still fails, so
that one Rust case is the whole remaining blocker."*

`../pmtest/differential-test-bed/findings/l0.md` **"#78 E0"

**verdict (b): the flag does not reproduce real**:

| cell | real | portuale | portuale, `APPEND=1` |

| `consrdep --backtrack=0` | `Total: 0 packages` | `[ebuild U] provpkg-2.0` | `[ebuild r U] provpkg-2.0` |
| `consrdep` (backtrack 20) | provider `r U` + three consumers `rR` | identical set | **`Total: 0 packages`** |

and **both** #24 pins fail with the flag on, not one:
`test_oracle_slotop_slotchange_case4_changedslot` loses its
`[ebuild rR] app-arch/libarchive-3.1.1` rebind row, and
`test_oracle_slotop_undo_cascade` loses its
`[ebuild rR] app-misc/soccascb-0` cascade row.

So with the gate on and backtracking at its default, portuale **drops
the whole plan** where real rebuilds three consumers and upgrades the
provider. That is not "one case away from default-on".

*not*: real's empty list there is the backtracking gate itself
(`_slot_operator_trigger_reinstalls` is behind
`if self._dynamic_config._allow_backtracking`, `depgraph.py:2131-2132`;
`--backtrack=0` clears it at `:12188-12190`), **not** a dynamic-deps
model difference.
