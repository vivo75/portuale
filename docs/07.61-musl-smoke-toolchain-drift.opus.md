## 1. What is broken (reproduced S0, 2026-09-16)

Three walls, in the order the fixed bed hits them:

- **`alpine:3.22.1`** (the pinned base) ships rustc **1.87.0**. The
  Containerfile's five-package build includes `portuale`, whose graph
  reaches `portage-repo` -> `portage-atom-pubgrub` -> `portage-solver`;
  those crates declare `rust-version = 1.95` (also
  `gentoo-interner` 1.95, `portage-atom` 1.95, pubgrub 1.92, smol_str
  1.89, the brush/uucore/icu family 1.88). Cargo aborts at graph
  construction with `rustc 1.87.0 is not supported by the following
  packages: ...`. Building only `versions-harness` on the same base
  succeeds — the abort is per **build graph**, not per workspace.
- **`alpine:edge`** (rustc 1.98.1) resolves everything but the
  `x86_64-alpine-linux-musl` static link fails:
  `attempted static link of dynamic object .../libc.so`. Root cause is
  the interaction of three link-line facts (captured with
  `-C link-arg=-Wl,-v` in S0):
  1. `x86_64-alpine-linux-musl` has no `crt-static-default` (Alpine is
     a dynamic-musl distro), unlike `x86_64-unknown-linux-musl`
     (`crt-static-default: true`, std not shipped by the apk);
  2. with `-C target-feature=+crt-static` rustc emits `-static` plus a
     `-Wl,-Bstatic ... -Wl,-Bdynamic` wrapper around the system-lib
     section;
  3. gcc then appends its own trailing `-lssp_nonshared -lgcc -lgcc_eh
     -lc` **after** rustc's `-Wl,-Bdynamic`, so the final `-lc` is
     searched dynamically, finds `/usr/lib/libc.so`, and the global
     `-static` makes GNU ld refuse it.
- **`portuale` does not compile against musl's `libc::sched_param`** —
  discovered while validating D1's fix, since the broken builder had
  hidden it. `pretend.rs::apply_scheduling_policy` builds the struct
  with a literal that names only `sched_priority`; glibc's definition
  is single-field, musl's carries the four `SCHED_DEADLINE` members
  (`sched_ss_repl_period`, `sched_ss_init_budget`,
  `sched_ss_low_priority`, `sched_ss_max_repl`), so the musl build
  fails `E0063 missing fields`. Real Portage passes
  `os.sched_param(priority)` to `os.sched_setscheduler`; CPython's
  `sched_param` -> `struct sched_param` conversion is a C11 compound
  literal with only `sched_priority` set, i.e. every other field zero.
  This is a source portability bug, not a builder one.

## 2. Decisions (owner, 2026-09-16)

| id | question | decision |
|---|---|---|
| **D1** | Builder strategy: rustup-pinned stage, or Alpine's own rustc with corrected static-link flags? | **Alpine's own rustc**, bumped to the newest stable release that clears the 1.95 floor — **`alpine:3.24.1` (rustc 1.96.1)** — plus a trailing `-C link-arg=-Wl,-Bstatic` on the `x86_64-alpine-linux-musl` rustflags. Keeps the Containerfile's "no rustup/target-add" design, smallest diff, base tag still a pin. Rejected: rustup-pinned stage (~200 MB toolchain download, contradicts the design note), `rust:alpine` builder image (large third-party base). |
| **D2** | Add a workspace `rust-version` guard so a too-old builder fails early with Cargo's own message? | **Yes** — `rust-version = "1.95"` in `[workspace.package]` + `rust-version.workspace = true` in every member. The 3.22.1 abort already produced a clear message; the guard makes the floor explicit at the source so the next drift can't read as an unrelated link error. |

`-Wl,-Bstatic` is appended last so it lands **after** rustc's
`-Wl,-Bdynamic` and survives into gcc's appended trailing libraries
(verified: the resulting binaries have no `INTERP` and no dynamic
section, i.e. stricter than a plain `-static` link).

## 3. Slices (all landed on `backlog/61-musl`)

### S0 — evidence (this plan + `TEST/findings/musl.md`)

and the base-image/toolchain matrix, and state the fix hypothesis.
Commit: `#61 S0: evidence -- Alpine rustc floor and static-link root cause`.

### S1 — builder fix

1. `musl/Containerfile`: `FROM ... alpine:3.22.1` -> `alpine:3.24.1`;
   update the "Build stage uses Alpine ..." comment with the MSRV floor
   and the link-flag reason.
2. `rust/.cargo/config.toml`: add `"-C", "link-arg=-Wl,-Bstatic"` to the
   `[target.x86_64-alpine-linux-musl]` rustflags, with the why in the
   comment (gcc's trailing `-lc` after rustc's `-Wl,-Bdynamic`).
3. Build the five packages in the container; confirm the link succeeds.
   Commit: `#61 S1: build the musl image on alpine:3.24.1 with a static trailing -lc`.

### S2 — musl portability of `sched_param`

`apply_scheduling_policy`: replace the `libc::sched_param { sched_priority }`
literal with `unsafe { std::mem::zeroed() }` + field assignment, with the
CPython/real citation in the comment. Host build/test unchanged; the
musl build of `portuale` now succeeds. Commit:
`#61 S2: build sched_param portably (musl has the SCHED_DEADLINE fields)`.

### S3 — workspace MSRV guard

`[workspace.package] rust-version = "1.95"` + `rust-version.workspace =
true` in every member `Cargo.toml` (the floor is `gentoo-interner` /
`portage-atom*`). Workspace build/test unchanged on the host (1.98.1).
Commit: `#61 S3: declare the workspace MSRV floor (1.95)`.
