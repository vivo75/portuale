## 1. Problem

Two distinct gaps in `emerge --pretend --debug`'s narration, both
deliberately left open by #57 S1:

**(a) `Parent Dep` content and attribution.** Real
`_add_pkg` (`depgraph.py:3568-3603`) prints, for the child it is adding:

```
Parent Dep:    <atom>[(<unevaluated>)] required by <parent>
```

— the **dependency atom** and the parent that required it, filed under
the **child instance** that atom resolved to. Portuale's
`dump_resolution_walk` (`resolver_trace.rs:278`, called once from
`assemble_result` at `lib.rs:20625`) prints

```
Parent Dep:    <child cat/pkg> required by <parent label>
```

from `GraphEntry::required_by` — a cp-keyed `(category, package)` pair
list with **no atom text** and **no installed-node entry** when the atom
resolved to a graphed instance. On the `needer`/`othermod` triangle the
line for `<dev-libs/paired-2.0` is filed under the merge-bound
`paired-2.0`; real files it under the installed `paired-1.0` (the
instance `_add_pkg` actually added for that atom). #57 S1's
`slot_pullers` work carried both parents correctly (the block renders
right) but the trace reads the other map, so the attribution stayed
wrong.

**(b) The resolution footer / backtrack-step count.** Real
`backtrack_depgraph`'s `finally` calls
`_show_resolution_report(start_time, backtracked, max_retries)`
(`depgraph.py:12135-12145,12171-12172`) whenever
`spinner.end_notice()` is true — i.e. on **every** non-quiet resolution,
not only under `--debug` (the host `emerge -uDpvN @world` capture in
[`evidence/2026-09-16-post63-probes/`](evidence/2026-09-16-post63-probes/README.md)
has `Dependency resolution took 35.06 s (backtrack: 0/20).`). It prints

```
Dependency resolution took <T> s (backtrack: <N>/<M>).
```

`show_lru_cache_info()` prints only when `PORTAGE_SHOW_LRU_CACHE_INFO` is
set in the environment (`portage/util/portage_lru_cache.py:9-11`), so it
is not part of the normal output. The footer therefore belongs to the
same class as the static `Calculating dependencies ... done!` preamble
(an already-recorded deliberate cut in `backlog-tasks.md`). Portuale
prints neither the count nor the line. The **timing** half is a standing deliberate cut
(`backlog-tasks.md` "Deliberate cuts": non-deterministic by plan
invariant, never pinned); the **count** is deterministic and currently
not surfaced anywhere.

## 2. What portuale has to build on

- `resolver_trace::dump_resolution_walk` is the one narration site
  (`tr!`-style stdout, gated by `portage_repo::resolver_debug()`, i.e.
  `--debug`). It already emits the stages #57 shipped and states the
  BFS order divergence in a header comment.
- The walker knows, for every queued atom, the atom text and its owner:
  `QueueItem { atom, owner, .. }` in `resolve_pretend_graph`, and
  `slot_pullers` records `(owner cp, version, atom)` per **child cp**
  for slot-conflict purposes. Neither is per child *instance*, and
  neither is threaded to the trace today.
- `GraphEntry` carries `required_by: Vec<(String, String)>` (cp-keyed,
  no atom), `deps: Vec<DepEdge>` (the child's own outgoing atoms) and
  the outcome/slot/sub-slot — enough to label instances, not enough to
  reconstruct the incoming atoms.
- `backtracking_resolve` (`lib.rs`) runs the `Backtracker` loop
  (`while let Some(params) = bt.get()`); the restart count real prints
  is exactly `iterations - 1`, and `ctx.backtrack_max` is real's `M`.
  `GraphResult` (`lib.rs`) is the assembled output `assemble_result`
  builds; a counter field would ride out with it.
- The `--json` dump is a portuale extension (`print_json` /
  `entry_to_json` in `pretend.rs`), so adding a field there does not
  break any real-parity contract, only portuale's own pinned JSON.

## 5. S1 design (the only non-trivial slice)

Real's `Parent Dep:` list is per **child instance** and carries the
**atom**. The cleanest port that does not reshape the public
`GraphEntry`:

1. During `resolve_pretend_graph`'s queue consumption, push
   `ParentAtom { child_cpv, child_installed: bool, parent_label, atom,
   unevaluated }` into a per-pass side table (the queue item already
   carries `owner` + `atom`; the resolved child and its outcome are
   known when the item is consumed). Dedup by
   `(child_cpv, parent_cp, atom)`.
2. Thread the table into `dump_resolution_walk` (one new argument) and
   render each child's `Parent Dep:` rows from it, falling back to
   `required_by` when the table has no entry (e.g. argument-seeded
   entries, whose real shape is `Parent Dep: <cp> (Argument)` and must
   stay byte-identical).
3. Instances: the trace must emit a `Child:` block for the installed
   instance when it is the atom's actual child, even if the graph only
   walks the merged instance (real adds both). The side table's
   `child_installed` bit distinguishes them; the label comes from the
   existing `node_label` / vdb lookup.
4. Unevaluated atoms: real prints `atom (unevaluated_atom)` when the two
   differ; `QueueItem` preserves an `unevaluated` form today, so carry
   it through rather than re-deriving.

What this deliberately does **not** do: reorder the narration (BFS
stays), touch `GraphEntry::required_by`/`--json` semantics, or change
the `Child:` trailer/`Exiting...` markers.

## 7. Non-goals and residue

- Narration **order** (BFS vs real's LIFO) — documented divergence,
  stays.
- The timing value ever being pinned — standing cut (K1 option (b) is an
  opt-in human aid, never a test input).
- The static preamble (K2).
- `--debug` narration of backtracking reasons (`docs/history/023-*`,
  #23's non-goals) and the `masked by backtracking` listing — separate
  items, not touched here.

## 8. Risks

- **Pins:** the `--debug` trace is pinned in several contract tests;
  every S1/S2 output change must be a reviewed, oracle-backed move, not
  a bulk re-bless.
- **Attribution semantics:** the side table must key on the actual
  resolved child (installed vs graphed), not on `required_by`; getting
  this half-right reproduces the #57 bug. The S0 capture is the guard.
- **JSON consumers:** if K1(a) adds a `--json` field, update the JSON
  doc comment and its pinned tests in the same slice.
