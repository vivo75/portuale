### S0.1 — what real does (re-cited, not re-derived)

`lib/portage/dbapi/vartree.py` @ 3.0.82.2:

- `_aux_get` (`:975-1053`): `_mtime_` is answered from the package
  dir's `st.st_mtime` **float** (`:1003-1009`, "Float, matching the
  value `aux_get()` seeds itself with"); every other in-set key comes
  from the validated snapshot or the per-field file, normalised with
  `" ".join(myd.split())`; then `results["EAPI"] == ""` becomes
  `"0"` (`:1049-1051`).
- `aux_get` (`:909-973`): seeds `mydata = {"_mtime_": mydir_mtime}`
  (`:941`), fills the session memo, then translates any `SLOT` that
  fails `_get_slot_re` to `"0"` (`:967-972`, "Empty or invalid slot
  triggers `InvalidAtom` exceptions when generating slot atoms for
  packages, so translate it to `'0'` here").
- `_get_slot_re` (`lib/portage/versions.py:76-90`): `[\w][\w+.-]*`
  (`:38`), optionally `/`-suffixed iff the EAPI has `slot_operator`
  (`:82-85`); `slot_operator = eapi >= Eapi("5")`
  (`lib/portage/eapi.py:319`) — so after the `EAPI ""→"0"` step the
  EAPI is `"0"`, the operator is off, and the SLOT pattern is the
  single-slot half. Empty and invalid both fail the match; both
  become `"0"`.
- Real `_mtime_` consumers (grep over `lib/portage`): `bintree.py`
  (binary-db staleness `:1115`/`:1322`/`:2738`, remote metadata
  `:119`/`:222`, `MTIME` mapping `:640`, index writes `:2132`/`:2306`),
  `porttree.py:866` (ebuild mtime), `cache/metadata.py:132-171` and
  `cache/template.py:83-95` (cache invalidation), `vartree.py:357`
  (`_pkg_str_aux_keys`) and `:1565` (`COUNTER`+`_mtime_` re-read).
  Every one lives in binary-package, cache, or display-string
  machinery portuale has not ported.

### S0.3 — every portuale consumer (re-enumerated 2026-09-24)

`SLOT`, all through the `vdb_entry_slot` seam
(`rust/portage-repo/src/lib.rs`, `pub fn vdb_entry_slot` — normalised,
`""` for missing, **no** validity check; the doc comment names #115):

1. `ebuild_merge::read_installed_slot` — `Some("0")` for empty (O5);
   a present-but-invalid value passes through with only the
   `.split('/').next()` main-slot projection. Its five readers are
   #126 S2's list (`installed_instance_pf`, `find_collisions`'s
   `own_versions` filter, the merge replace-scan,
   `ebuild_unmerge::others_in_slot`, `pretend.rs` preserved-libs
   atoms) — **all on the merge path**.
2. `pretend.rs` depclean scan (`vdb_entry_slot(...).split('/').next()
   .unwrap_or("0")`) — display/sort only, not merge.
3. `ebuild_merge.rs` merge-scan `installed` census (`split_once('/')`
   into `(slot, sub_slot)`, `("", "")` for missing) — feeds
   `candidate_str` matching on the merge path.
4. `installed_candidates_uncached` via `vdb_aux_get(..., "SLOT")` +
   `split_slot` (empty → `("0","0")`; invalid → kept verbatim).

`EAPI`: **no vdb reader**. `read_vdb_string(..., "EAPI")` has no call
site; `installed_pkg_repo`'s `__unknown__` and `split_slot`'s empty
case default from other sources. Real's `EAPI ""→"0"` is therefore
unobservable in portuale today.

`_mtime_`: **no reader**. Real's consumers (§S0.1, last bullet) are
all in machinery portuale has not ported; portuale's own mtime-keyed
memos (`AUX_CACHE`, `CANDIDATES_CACHE`) key on the stat directly and
never expose the value.

### S0.4 — the O11 decision (open, for the owner)

Batch §2 **O11**: *"If the probe finds no consumer in portuale where
the translation is observable, the ruling is whether to port it anyway
(seam hygiene) or close #115 as a documented cut."* The probe splits
three ways, so the decision has three arms — rule each independently:

- **(a) invalid-`SLOT` → `"0"`: OBSERVABLE, divergence confirmed**
  (S0.2 table). An invalid value mis-groups the entry in all four
  S0.3 readers instead of grouping it with slot `"0"` as real's
  `dbapi.match("cp:0")` would. Live likelihood is ~nil (no host
  instance; the value can only arrive hand-edited or corrupt), and
  the fix touches the merge path, so S1 re-runs the gate. Proposed:
  **port** — validate in one place (see S1), gate it, keep the
  output-preserving rule.
- **(b) `EAPI` `""→"0"`: UNOBSERVABLE** (no vdb EAPI reader, S0.3).
  Porting it today is seam hygiene with no caller: a
  `vdb_entry_eapi` helper (or the translation inside `vdb_aux_get`
  for the `EAPI` key) that nothing calls. Proposed: **documented
  cut** — record this section as the evidence, do not add the helper.
- **(c) `_mtime_`: UNOBSERVABLE** (no reader; real's consumers are
  unported machinery, S0.1/S0.3). Proposed: **documented cut** —
  when (if) the bintree/cache paths are ported, their plan re-opens
  this arm with real consumers attached.

## S1 (#115 arm (a)) — port invalid-`SLOT` → `"0"` (only if O11(a) rules "port")

**Merge-path safety gate: YES** (S0.3 reader 1 + reader 3).

**Where.** One place — either `portage_repo::vdb_entry_slot`
(`rust/portage-repo/src/lib.rs`, every SLOT consumer flows through
it) or `portuale::read_installed_slot`
(`rust/portuale/src/ebuild_merge.rs`, the merge-path readers only).
The cluster file does not pre-decide: the implementer diffs the
caller lists (S0.3) and rules in the commit, with this constraint —
whatever is chosen, all four S0.3 readers must agree on the same
value for the same entry afterwards (today they already do for every
real value; the fix must not split them). Note the existing contract:
`vdb_entry_slot`'s doc comment says callers keep their own
defaulting; moving the translation into it amends that comment, and
the amendment is part of the slice.

**What "invalid" means.** Real's rule is EAPI-dependent
(`_get_slot_re(eapi_attrs)`, S0.1): with the operator (`EAPI >= 5`,
i.e. every live EAPI per the repo's EAPI floor in `agent-context.md`)
the shape is `slot(/slot)?` with
`slot = [\w][\w+.-]*` (`versions.py:38`); without it (only reachable
through the `EAPI ""→"0"` step, arm (b)'s cut) the single-slot half.
Portuale does no EAPI parametrization inside the 5+ floor, so the
port is the operator shape — and an entry whose `EAPI` is itself
empty is out of scope here (arm (b)), say so in the doc comment
rather than re-deriving it.

**Tests (TDD: failing first).**

- Rust unit test: a fixture vdb entry with `SLOT`=`!!bad slot!!`
  (S0.2's value) reads `"0"` through the chosen seam (**RED** before:
  the raw value; **GREEN** after). Plus the valid twin `0/2` staying
  `0/2` (the sub-slot must survive — the operator shape).
- Existing `vdb_entry_slot_*` / `read_installed_slot_*` /
  blocker/merge/unmerge tests unchanged — copy expectations, do not
  re-derive.
- No pmtest pin, no fixture (a committed `SLOT`=`!!bad slot!!`
  fixture would poison every scan that walks the fixture vdb; the
  Rust tempdir test is the pin). If a pmtest pin moves, that is the
  STOP condition (a fixture must carry an invalid SLOT — check before
  assuming the code is wrong).

**Blast radius, enumerated before coding:** the four S0.3 readers
plus `pretend.rs`'s depclean display. If any caller depended on
seeing the raw invalid value (grep says none does — every site
compares or prints), STOP.

**Verify.** The full pass (`cargo fmt --check`, `cargo clippy
--release --all-targets` zero warnings, `cargo test --release` whole
workspace; then the pmtest contract suite in the repointed
`pmtest-115` worktree, diffed **by test name** against the
clean-`main` baseline), **plus the merge-path gate**: a successful
test merge of `sys-libs/glibc` **and** `app-shells/bash`; record both
in the report. No corpus drift is accepted (output-preserving on real
data — §0).
