## 2. Oracle — what real does (`lib/portage/dbapi/vartree.py`)

All cites are `3rdparty/portage` @ `7309192`.

**The field set is the format.** `_METADATA_FILE_FIELDS`
(`vartree.py:79-104`) is a 23-field `frozenset`; `_in_metadata_file(fname)`
(`:110`) is membership in it; `vardbapi.__init__` sets
`self._aux_cache_keys = set(_METADATA_FILE_FIELDS)` (`:418`) so the
cached set and the snapshot set are *identical by construction*. The
module comment (`:70-78`) says why: a key outside this set **and** outside
`_aux_cache_keys_re` (`:355`, `^NEEDED\..*$`) falls back to an
`environment.bz2` search (bug 395463), which the snapshot must never
silently answer with `""`. `_METADATA_FILE_FORMAT_VERSION = 1` (`:105`);
the docstring at `:130-137` states the rule — **bump the version on any
change to the field set, in either direction.**

**`_read_metadata_file(path, dir_st)`** (`:115-187`), the reader to port
exactly:

1. Line-oriented parse. A line starting with `#`: `#format=<int>` sets
   the version and, if it is not `1`, **returns `None` immediately**
   (written first precisely so an unusable file is abandoned early);
   `#dir_mtime=<int>` sets the mtime; a non-integer in either is `None`;
   every other `#` line is ignored. A non-`#` line without `=` is
   skipped; otherwise `k, v = line.split("=", 1)`, last wins.
2. `version is None or dir_mtime is None` → `None`. (`#dir_mtime=` is
   written **last**, so an interrupted write is rejected rather than read
   as a short snapshot.)
3. `dir_mtime != dir_st.st_mtime_ns` → `None`.
4. Otherwise the dict — and it is a **complete** snapshot.

**`_aux_get(cpv, wants, st)`** (`:975-1053`), the read path:

1. `st = os.stat(mydir)` once (ENOENT → `KeyError`; not a dir →
   `KeyError`). `aux_get` passes its own `st` in, so there is **one** stat
   per lookup, not one per key.
2. `_read_metadata_file(mydir/metadata, dir_st=st)`, `OSError` → `None`.
3. Per want: `_mtime_` → `st.st_mtime` (float). Else **if the snapshot
   validated and `_in_metadata_file(x)` → `metadata_data.get(x, "")`,
   with no `open()` at all** (`:1010-1017`, whose comment states the
   rule: "a field missing from it therefore had no individual file
   either, so serve it as empty instead of paying an `open()` that would
   just fail"). Else `open(mydir/x)`; on `OSError`, a key outside
   `_aux_cache_keys` and not matching `^NEEDED\..*$` goes to the
   `environment.bz2` search, otherwise the value is `""`.
4. **Normalisation:** unless `_aux_multi_line_re` (`:356`,
   `^(CONTENTS|NEEDED\..*)$`) matches, the value is
   `" ".join(myd.split())`. So real normalises on the *individual-file*
   path too — the snapshot is not a second shape, it is the same shape
   pre-computed (`_write_metadata_file`, `:208-229`, applies the same
   `" ".join(v.split())`).
5. `results["EAPI"] == ""` → `"0"`.

**`aux_get`** (`:909-973`) adds the in-session memo:
`self._aux_cache["packages"][str(cpv)] = (mydir_mtime, cache_data)`, keyed
on the package dir's **float** `st_mtime` with an
`int(cache_mtime) == st.st_mtime` tolerance for truncated mtimes on
livecd squashfs (bug 564222), and it pulls
`cache_these = _aux_cache_keys ∪ wants` on a miss — **one miss fills all
23 fields**. `_bump_mtime(cpv)` (`:570-587`) utimes the category *and*
base dirs before and after every modification so consumers may key caches
on dir mtimes (bug #290428).

**The freshness hole, and why it is safe by construction.** Adding a
per-field file bumps the package dir's mtime, which invalidates the
snapshot, so the "complete snapshot" rule can never hide a field that was
added after the write. The residual hole is an **in-place rewrite of an
existing field file**, which leaves the dir mtime alone — exactly why real
calls `_bump_mtime` on both sides of `aux_update` (`:1129-1156`). That is
real's own documented hole and the same in-process property `#102`'s
`installed_candidates` cache already has; document it at the cache, do not
try to beat it.

### S1 (#109) — normalise `read_vdb_string` like real's `_aux_get`

**Where.** `portage_repo::read_vdb_string` returns
`fs::read_to_string(…).unwrap_or_default()` — **raw**, trailing newline
and embedded newlines intact. Real applies `" ".join(myd.split())` to
every field that is not `CONTENTS`/`NEEDED.*` (§2.4). No call site passes
`CONTENTS` or `NEEDED*` through this helper (audited: the keys ever passed
are `repository`, `SLOT`, `USE`, `IUSE`, `KEYWORDS`, `LICENSE`,
`PROPERTIES`, `RESTRICT`, `BUILD_TIME`, `DEFINED_PHASES` and the five
`*DEPEND` — all 23-set members), and `read_vdb_flag_set` already
normalises implicitly by `split_whitespace`.

**Why first, and alone.** S3 serves values from the snapshot, which is
stored pre-normalised. If the fallback path is not normalised too, the
same field returns different bytes depending on whether the snapshot
validated — a host-dependent, fixture-vs-live split, i.e. exactly the
class of nondeterminism the contract suite exists to prevent. Normalising
is therefore a **prerequisite**, not a cleanup, and it is the one change
here that can move output, so it lands by itself where a corpus drift is
unambiguous.

**Design.** Normalise inside `read_vdb_string` (`value.split_whitespace()
.collect::<Vec<_>>().join(" ")`). Then audit the ~24 call sites for ones
that were compensating: `.trim()` becomes redundant (harmless, but drop
it where it reads as load-bearing), and any site that embeds the value in
**output** must be diffed against real, not just against the prior
binary — `installed_pkg_repo`, the `BUILD_TIME` parse, the `--info` /
changed-deps display paths, and `quickpkg_direct_index_entries` (which
already does its own `split_whitespace().join(" ")`, so it should now
simply use the helper's value).

**Tests.** Rust unit tests on `read_vdb_string`: a multi-line `RDEPEND`
collapses to one space-separated line; a trailing newline is gone; an
absent file is still `""`. Contract suite: **expected to be
byte-identical** (no committed fixture has a multi-line vdb field — check
that, and add one if it is missing, because otherwise the suite proves
nothing about this slice). Any real drift is reviewed against real
`emerge`'s own output for the same query before it is blessed.

**Expected.** No measurable time change. This slice buys correctness
(parity) and unblocks S3.

### S2 (#109) — one shared `METADATA_FILE_FIELDS`, in `portage-repo`

**Where.** The constant lives in `portuale/src/ebuild_merge.rs`
(`METADATA_FILE_FIELDS`, byte-identical to real's set) and is used only
by the writer. The reader S3 adds lives in `portage-repo`, which
`portuale` depends on — so the constant must move **down** to
`portage-repo` and `ebuild_merge` import it.

**Why its own slice.** Real states the invariant explicitly (§2): reader
and writer must agree on the field set, and the set is part of the format
version. Two copies of a 23-element list that must never drift is the bug
this slice exists to prevent. It is also a `pub` signature change in a
lib crate, which per this repo's standing lesson needs a workspace-root
`cargo build/test/clippy --release` (the `mrg-director` and `*-harness`
bins are easy to miss).

**Design.** `pub const METADATA_FILE_FIELDS: &[&str]` +
`pub const METADATA_FILE_FORMAT_VERSION: u32 = 1` +
`pub fn in_metadata_file(name: &str) -> bool` in `portage-repo`, with
real's own "bump the version if you change the set" warning in the doc
comment. `ebuild_merge` re-exports or imports; no behaviour change.

**Tests.** A Rust unit test asserting the set has exactly the 23 real
names (a literal list, so a drift fails loudly) and that
`in_metadata_file` rejects `CONTENTS` and `NEEDED.ELF.2`. Merge-path
safety gate (the writer is on it).

**Expected.** No time change.

### S3 (#109) — read the snapshot: `vdb_aux_get`

**Where.** A new `portage-repo` seam both existing helpers call:

```rust
fn vdb_aux_get(root, category, package, version, key) -> String
```

`read_vdb_string` and `read_vdb_flag_set` become thin wrappers over it
(the flag-set one splitting the returned string), so **all ~43 call sites
are covered with no call-site edits**. Route the two remaining direct
readers through it as well: the `fs::read_to_string(e.path().join("SLOT"))`
in `installed_candidates_uncached` and the one in the installed-cache
scan — both already `.trim()`, so the normalised value is equivalent.

**Design — port §2's `_aux_get`, in order:**

1. `stat` the package dir once. Absent or not-a-directory → `""` (today's
   `unwrap_or_default()` behaviour; portuale has no `KeyError` to raise
   and no caller that wants one — say so in the doc comment).
2. Read `<dir>/metadata` and validate exactly as `_read_metadata_file`
   does: `#format=` must parse and equal `METADATA_FILE_FORMAT_VERSION`
   (reject immediately on mismatch), `#dir_mtime=` must parse and equal
   the dir's `st_mtime_ns`, both must be present, other `#` lines
   ignored, `=`-less lines skipped, `split("=", 1)` last-wins.
3. If it validated **and** `in_metadata_file(key)`: return
   `map.get(key).cloned().unwrap_or_default()` — **no `open`**. This is
   the "complete snapshot" rule; it is safe by construction for added
   fields (§2's last paragraph) and its residual in-place-edit hole is
   real's own.
4. Otherwise fall back to today's read + S1's normalisation.
5. Portuale has no `environment.bz2` fallback on this path and needs
   none: every key any caller passes is in the 23-set (audited in S1), and
   the one `environment.bz2` reader, `read_vdb_env_vars`, is a separate
   `--info`-shaped path. Assert that with a debug assertion or a
   documented precondition so a future caller with an out-of-set key
   cannot silently get `""` where real would search the environment.
6. **No `EAPI == "" → "0"` translation here.** Real does that in
   `_aux_get`/`aux_get` for `EAPI` and `SLOT`; portuale's callers handle
   their own defaults today (`installed_pkg_repo`'s `__unknown__`,
   `split_slot`'s empty case). Adding real's translation is a separate
   parity question — file it as a residue, do not smuggle it in.

**Tests.** Rust unit tests over a tempdir vdb, each **stamping
`#dir_mtime` at runtime** (a committed fixture's stamp can never match
after checkout — see the trap in §4): (a) valid snapshot serves a field
and does **not** open the individual file (assert by writing a
*different* value into the individual file and getting the snapshot's);
(b) a field absent from a valid snapshot is `""` even when an individual
file exists; (c) `#format=2` → fallback; (d) missing `#dir_mtime=` →
fallback; (e) `#dir_mtime=` off by one → fallback; (f) garbage in either
header → fallback; (g) no `metadata` file at all → fallback. Committed
pmtest fixtures get the **negative** cases only (a stale snapshot, which
is what a checkout produces anyway) — and one of those is worth adding
precisely because it pins that a stale snapshot is ignored rather than
trusted. All 93 existing vdb fixtures keep exercising the fallback path,
so the contract suite is the regression guard for it.

**Expected.** ~88 k successful opens + ~40.5 k ENOENT + their `read`s
replaced by ≤ 2089 snapshot reads plus one `statx` per lookup. Sys time
~1.0 s → **~0.3–0.5 s**; wall ~3.9 s → ~3.3–3.5 s. Measure, don't assume:
the added `statx` per lookup is a real cost and it is the reason S4
follows immediately.

### S4 (#109) — per-instance aux memo, keyed on the dir mtime

**Where.** `vdb_aux_get`. S3 still pays one `statx` + one snapshot read
*per call*; real's `aux_get` pays them once per `(cpv, dir mtime)` and
fills all 23 fields on the miss.

**Design.** Thread-local memo, the established `EUF_CACHE` shape
(`performances-tuning.md`: "the `EUF_CACHE`-style thread-local `Rc`/`Arc`
memo is now the established shape for per-resolve pure functions — reuse
it before inventing a new one"):

```
HashMap<(PathBuf, String, String, String), (u128 /*dir st_mtime_ns*/,
                                            Rc<HashMap<String, String>>)>
```

- Miss or mtime change → stat, read+validate the snapshot, and populate
  the map with **all** fields the snapshot carries (real's
  `cache_these = _aux_cache_keys ∪ wants`); on a fallback, populate
  lazily per key and record which keys were resolved so a second key on
  the same instance does not re-stat.
- Keep the `statx` on every call — it is the validity signal and real
  does the same (`aux_get` stats before consulting `_aux_cache`). What the
  memo removes is the snapshot *read* and every per-key `open`.
- Document the in-process staleness property (real's `_aux_cache`, and
  `#102`'s cache, have it too).

**Tests.** (a) a second lookup on the same instance does not re-read (a
read counter, or a `ptr_eq` on the `Rc`); (b) touching the package dir
invalidates; (c) a fallback-path instance memoises too; (d) the
merge-path readers still see a freshly written vdb entry — **the
merge-path safety gate applies**, glibc + bash.

**Expected.** ~2089 stat+read pairs total instead of per call. Sys
→ ~0.2 s (real's own territory); user unchanged.

### S5 (#110) — memoise `metadata_key_accepted`

**Gated on S0.3's re-profile.** If the number has collapsed with
`#102`–`#108`, record that and stop — `performances-tuning.md` has the
"honest non-result" precedent.

**Where.** `metadata_key_accepted`, 13 call sites, pure in its eight
arguments. Its cost is `use_flags_if_conditional` (→ the already-memoised
`effective_use_flags`), `resolve_accept_tokens`, `all_mentioned_tokens`,
`resolve_acceptable_tokens` and `use_reduce_flat`.

**Design.** `RUMF_CACHE`'s shape exactly (`#104`). The two `&[…]`
arguments are never arbitrary: every call site passes either
`(config.accept_properties, config.package_properties)` or
`(config.accept_restrict, config.package_accept_restrict)` — **verify
that across all 13 sites**, then add an explicit
`enum MetadataKey { Properties, Restrict }` parameter rather than
inferring, and key the memo on `(MetadataKey, use_context_fingerprint
(config), candidate_str, value_str)`. Keep the empty-value early return

## 4. Risks and traps

- **A committed snapshot fixture can never validate.** `git checkout`
  sets the package directory's mtime, so any `#dir_mtime=` in a committed
  fixture is wrong by construction — and the contract suite runs **in
  place** against `fixtures/` (`conftest.py`'s `FIXTURES_ROOT`, with
  `ROOT`/`PORTAGE_CONFIGROOT` pointed straight at it), not against a
  copy. Positive-path coverage must therefore be Rust unit tests that
  stamp a tempdir at runtime; committed fixtures can only pin the
  *rejection* path. Writing a fixture with a hardcoded stamp and watching
  the test "pass" is the way to ship this slice untested.
- **Portuale's own snapshots must validate post-`rename`** — S0.4. If
  they don't, the reader is dead on every portuale-merged package and the
  measured win silently decays as the vdb turns over.
- **The "complete snapshot" rule is a semantic, not an optimisation.** A
  valid snapshot suppresses the per-field read entirely, so a field it
  lacks reads as `""`. Safe by construction for added fields (§2), but it
  must be written down at the function and pinned by test (b) in S3, or a
  later reader will "fix" it back into a fallback and lose the ENOENT win.
- **S1 is the output-risk slice.** If the contract suite is byte-identical
  *and* no committed fixture has a multi-line vdb field, the suite proved
  nothing — add the fixture. Any genuine drift is diffed against real
  `emerge`, not blessed on the grounds that real "probably" normalises.
- **Two constants drifting (S2)** is the failure real's own module
  comment warns about. One definition, one format version, one test that
  lists the 23 names literally.
- **Over-fitting one workload.** Every slice re-measures §1 *and*
  spot-checks a second shape (`sys-devel/gcc`, or the `nano` probe from
  `#83`, which is dominated by the all-installed blocker scan and so
  exercises the vdb readers differently).
- **`statx` does not go away.** 294 k of them, only ~1.5 k failing;
  `installed_candidates`' scan (`#102`) and this batch's per-lookup
  validity stat are both legitimate. If sys time does not fall as far as
  §3's estimate, the next thing to profile is where the remaining `statx`
  come from — not a thread pool.

## 5. What not to do

- **Do not add threads anywhere in this batch.** That is the whole point
  of the ordering in `cleanroom/parallelism.md` §2.0: if S1–S5 land, the
  residual may not justify a pool, and §1's numbers are the only honest
  basis for deciding.
- **Do not delete the individual per-field files.** Real's default keeps
  them (`_consolidate_to_metadata_file(delete_individual=False)`) for
  tools that read the vdb directly, and `_explode_metadata_file` exists
  to undo consolidation. Portuale already matches; leave it.
- **Do not bump `METADATA_FILE_FORMAT_VERSION`.** Portuale's writer and
  real's reader interoperate on this host's live vdb today; changing the
  version breaks that in both directions.
- **Do not fold in real's `EAPI ""→"0"` / invalid-`SLOT`→`"0"`
  translations.** They live in `aux_get`, they are parity questions with
  their own blast radius, and they belong in a residue (§6), not in a
  slice whose guard is "byte-identical".
- **Do not touch `#107`** (the second `run_pass`, ~30 % of the run). It is
  a blocker-parity bug in the `#68` family; making it faster hides it.

## 6. Residues to file with the batch

- Real's `aux_get` translations portuale does not do: `EAPI == "" → "0"`
  and an invalid/empty `SLOT → "0"` (`vartree.py:967-972`), plus the
  `_mtime_` pseudo-key. Portuale's callers currently default
  individually; whether that ever diverges is an unanswered parity
  question.
- `portage_util::shuffle_seed` calls `std::env::var("PORTUALE_SHUFFLE_DIRS")`
  on **every** `read_dir_entries` (42,524 per run on §1's workload),
  allocating a `String` each time. A `OnceLock` read at first use is the
  established env-free pattern here; trivial, but it is real work in the
  measured path and it is also a `set_var`-race surface
  (`cleanroom/parallelism.md` §1.6).
- Whether `metadata_key_accepted`'s whole caller, `is_visible`, is itself
  memoisable per `(candidate, config)` — a strictly bigger memo than S5's
  and the obvious follow-up if S5 measures well.
