1. **Separate tables, always — nested worktree pairs.** P7b
   (`backlog/52-librs-mutants`) owns the home checkout
   (`~/repo/PORTUALE/{portuale,pmtest}`), its `target/`, and its
   `cargo mutants --in-place` run (which leaves `portage-repo/src/lib.rs`
   *mutated* on disk while it runs). Every phase opens its **own worktree +
   branch in both repos**, even if the slice looks one-sided (`AGENTS.md`
   "Two repos, one project"), **nested under one directory and branched
   from `main` explicitly**:

   ```sh
   cd ~/repo/PORTUALE
   git -C portuale worktree add ../wt-<slug>/portuale -b backlog/<slug> main
   git -C pmtest   worktree add ../wt-<slug>/pmtest   -b backlog/<slug> main
   readlink -f wt-<slug>/portuale/fixtures   # must print wt-<slug>/pmtest/fixtures
   ```

   Why nested, not `../portuale-<slug>` + `../pmtest-<slug>` siblings: both
   cross-repo links are *relative* and resolve by directory layout.
   pmtest's `managers/managers.yaml` hardcodes `repo: ../portuale` and
   `emerge: ../portuale/rust/target/release/portuale`, and
   `registry._provide()` runs `cargo build --release` there before every
   contract/bed run; portuale's `fixtures -> ../pmtest/fixtures`. From a
   sibling worktree both land in the **home checkout**: the contract suite
   would build and grade P7b's mutated binary (and fight it for the cargo
   lock and `target/`), the bed would mount P7b's tree as `PM_REPO`, and
   `cargo test` would read main pmtest's fixtures, not the branch's.
   Precedent: #152's entry records a mid-campaign rebuild of the mounted
   binary by a concurrent build. Omitting `main` would branch from `HEAD`
   (= P7b's branch once it commits). Nothing merges to `main` in any
   checkout until P7b has landed and §P-Z runs.
2. **Slow, talkative builds (where the tooling allows).** Local Rust loops
   use the **debug build**: `cargo test` / `cargo build` (never `--release`
   until §P-Z's final gate). **Caveat:** pmtest's registry hardcodes
   `cargo build --release` and `target/release/` paths, so the contract
   suite and the beds run **release** until H0 step 3 lands a profile knob
   — record the actual profile in every run header. Rationale for debug:
   asserts + un-stripped backtraces on the new L3/L4/L5 paths. Cost
   accepted: slower runs; wall times compare only within the same profile.
3. **A commit per slice.** Every S-step that changes product, fixtures, bed,
   or docs ends in its own commit (`<what changed>: <short description>`,
   body with the why + real-source grounding, `Co-Authored-By` trailer).
   pmtest-first where fixtures move, so the portuale message quotes the
   pmtest short sha. Push only when asked, both repos together.
4. **Compare by finding / test name, never by count.** Baselines are retaken
   per worktree at H0 (the numbers below are the last-known-good, not the
   gate).
5. **Don't starve P7b.** The host has 24 cores; `cargo mutants` grades by
   timeout, so a saturating bed run (P-C3 at `L3_JOBS=20`, P-G1/P-G2 bed
   runs) can turn slow mutants into spurious TIMEOUT/caught verdicts. While
   P7b runs: heavy beds wait, or run under `nice -n 19` with a small `-j`
   (≤ 8) and the header says so; P7b's triage checks its TIMEOUT count
   against the run windows of any concurrent bed. Cap concurrent debug
   worktrees by disk: `/home` had 139G free (87% used) at draft, P7b's
   `target/` is 6.3G — `df -h /home` and `df -i /tmp` before each bed run
   (the `/tmp` inode cap has bitten parallel pytest runs before).
