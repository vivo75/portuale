## Slice 3 — probe once per atom (F3)

Inside the new helper (both languages), restructure the per-atom loop so
each atom's availability is computed once:

```
for a in atoms:
    if circular_self(a): all_available = False; break
    stripped = without_use(a)
    avail = satisfiable(stripped, constraints(a)) or running_root_ok(a)
    if not avail: all_available = False; break          # real: also all_use_satisfied = False
    if stripped == a:            # no `[use]` block: real's `if atom.use:` is False
        use_ok = avail           # == True
    else:
        use_ok = satisfiable(a, constraints(a)) or running_root_ok(a)
    all_use_satisfied &= use_ok
    if not use_ok:
        all_use_unmasked &= atom_all_use_unmasked(a, constraints(a))   # slice 4 adds the constraints arg
```

Rules:
- Real breaks out of the atom loop on the first unavailable atom
  (`dep_check.py` `if not avail_pkg: … break`); keep that short-circuit.
- Real evaluates `all_use_unmasked` per atom *inside* the same loop, only
  for atoms whose USE-match fails; keep the gate lazy (it is the most
  expensive probe: it re-lists candidates and computes mask/force).
- Rust: compare `without_use(a).len() == a.len()` (the helper returns a
  prefix slice of the same string), not a string compare.
- No behaviour change is expected. Verify empirically: full fixture run
  Rust == Python, and every existing pin unchanged.
- Optional micro-cleanup while there: `highest_available_candidate_ignoring_use`
  builds a `by_str: HashMap` only to look up matches; zip
  `candidate_str_refs` with `visible` and filter by membership in
  `matched` instead (same as the pattern `atom_currently_satisfiable`
  could also use, but leave that function alone in this task).
