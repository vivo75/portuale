### S1 verdict (filled 2026-09-23)

Two product changes, both RED→GREEN gated (contract pin
`test_slot_conflict_use_reason_keys_unconditional_before_violated`
+ Rust unit test
`surviving_slot_conflict_graphs_both_same_slot_instances`).

**Ruling — walk-time graphing was tried and reverted in favour of
post-walk synthesis.** The first implementation made the
`resolved_slots` conflict arm fall through to entry creation. It
produced the right rows for the oracle cell but changed the
solver's inputs (second entries shift `direct_solve`'s walk-order
ranks and per-instance USE source), regressing solved cells
(`--backtrack`-masked shapes gained rows, blocker/uninstall cells
reordered) — a re-tuning of #142's solver decisions with fresh
oracles, out of this slice's size. Reverted byte-clean (`git diff`
purely additive afterwards). The shipped design instead:
`solve → removal → synthesize survivors`. Cost if wrong: a
surviving conflict whose second instance has merge-relevant deps
or blockers misorders or under-reports them (filed shape-by-shape
as residues; the F3 precedent).

1. `synthesize_surviving_conflict_entries` (`lib.rs`, called after
   the direct-solve/removal block, before the installed-blocker
   collection): for every surviving conflict's merge instance
   without a merge-bound entry, pushes a display-complete entry
   (slot/sub-slot/repo/USE via `refresh_entry_use_display` on a
   one-entry slice — the #141 precedent; `required_by` from the
   same cp-union as its siblings; `new_slot` mirrored) filed
   adjacently after its siblings. No deps walked, no blockers
   flattened, ebuild-metadata decorations defaulted — each a
   documented gap in the fn docs, not silent scope.
2. `narrow_by_use` (`merge_order.rs::match_candidates`): USE-aware
   narrowing of multi-instance edge matches (real matches atoms
   against pkgs *with* use), so the conflict parents edge to the
   instance they actually pull and `_merge_order_bias` prints
   real's 1.0-first order. Fair-abstention design: singletons,
   unparseable atoms, atoms without use-deps, candidates without
   display USE, and narrowings that would empty the set all keep
   today's behavior — the filter can only ever move
   multi-instance USE shapes.
