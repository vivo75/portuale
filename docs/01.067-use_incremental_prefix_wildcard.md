## 1. What real Portage does (source-grounded)

Real `config.regenerate()` expands each profile level's `USE_EXPAND`
variable values into pseudo-USE-flags (`config.py:2837-2866`), turning a
leading `-` into `-<var>_` — so `VIDEO_CARDS="-* intel …"` becomes the
tokens `-video_cards_* video_cards_intel …` in that level's `USE`
string. The single USE loop then processes each config db's `USE`
(`config.py:2888-2960`):

```python
if x[0] == "-":
    if x[-2:] == "_*":                       # negative prefix wildcard
        prefix = x[1:-1]
        prefix_len = len(prefix)
        myflags.difference_update(
            [y for y in myflags if y[:prefix_len] == prefix]
        )
    myflags.discard(x[1:])
    continue

if iuse is not None and x[-2:] == "_*":      # positive wildcard, IUSE-driven
    ...
```

So: `-<prefix>_*` removes every accumulated flag starting with
`<prefix>_`; the positive form `foo_*` adds every matching IUSE flag (and
passes the literal through when the package has no matching IUSE).
Non-USE incrementals (`FEATURES`, `CONFIG_PROTECT`, …) only know literal
`-*` and exact `-token` removal — the wildcard arm is inside the USE
loop, not the generic incremental loop.

Host facts that make this the whole bug: the active profile's
`make.defaults` sets exactly

```
VIDEO_CARDS="-* intel i965 nouveau radeon radeonsi amdgpu qxl modesetting virgl"
SANE_BACKENDS="-* hp hp3500 hp3900 hp4200 hp5400 hp5590 hpljm1005"
```

and real's installed `media-gfx/sane-backends` USE is exactly the listed
seven `sane_backends_*` flags; real's installed `x11-base/xorg-drivers`
USE is exactly the listed video cards that exist in its IUSE. The
`ebuild` itself contributes `+sane_backends_*` IUSE defaults
(`sane-backends-1.3.1-r2.ebuild:116-125`); real's `-sane_backends_*` from
the profile removes them at the `defaults` tier.

## 2. Portuale today

- `apply_incremental_token` (`portage-profile/src/lib.rs:1239-1251`)
  handles only literal `-*` (clear all), exact `-flag`, `+flag`, `flag`.
- The USE_EXPAND expansion path prefixes `-*` into `-video_cards_*`
  (`prefix_tok`, `portage-profile/src/lib.rs:2514-2522`, used by the
  per-level fold at `:2537-2563`) — a token `apply_incremental_token`
  treats as an exact removal of a flag literally named
  `video_cards_*`, i.e. a no-op.
- Consequently the parent profile levels' `VIDEO_CARDS` (e.g.
  `arch/amd64/make.defaults`'s `amdgpu fbdev intel nouveau radeon
  radeonsi vesa`) and the ebuild's `+sane_backends_*` defaults survive
  the leaf profile's `-*` list. Reproduced narrowly:
  `portuale emerge -pv --newuse --oneshot x11-base/xorg-drivers` →
  `R` + three `xf86-video-*`; `… --oneshot media-gfx/sane-backends` →
  `R` with all `+` backends.
- Call sites that apply USE tokens today: `portage-profile`'s own
  `USE`/`USE_EXPAND`/`USE_EXPAND_UNPREFIXED` folds
  (`:1420-1432, :2537-2563, :2597, :2622`) and `portage-repo`'s
  `effective_use_flags_uncached` layers (`:3242-3310`: env.d, repo,
  features, IUSE defaults, per-level `make.defaults_use`, user/config
  package.use, `conf_use_tokens`, pkg/env). Positive `prefix_*`
  expansion is already handled separately in
  `effective_use_flags` (needs a candidate's IUSE) per that function's
  doc comment, so only the **negative** wildcard is missing.

## 3. Design

**S1 — a USE-scoped applier.** Add

```rust
/// Real `config.py:2888-2945`'s USE loop token semantics: like
/// `apply_incremental`, plus `-<prefix>_*` removes every accumulated
/// flag with that prefix. Non-USE incrementals keep using
/// `apply_incremental` (real has no wildcard arm there).
pub fn apply_use_incremental(tokens: &str, set: &mut HashSet<String>);
pub fn apply_use_incremental_iter<S: AsRef<str>>(tokens: &[S], set: &mut HashSet<String>);
```

The negative arm orders exactly like real: wildcard prefix removal
first, then `discard(token[1..])` (which is a no-op for the literal
`-foo_*`). Positive `foo_*` stays out of scope here (handled where IUSE
is available; document the boundary in the function doc).

**S2 — migrate USE call sites** (no semantic change for any token
without `_*`):

- `portage-profile`: the `"USE" =>` arm of `process_lines` and
  `process_make_conf_file` (`:1420-1432`), the per-level `USE_EXPAND` /
  `USE_EXPAND_UNPREFIXED` folds (`:2537-2563, :2597, :2622`), and the
  user/file-level USE application helper that feeds `config.use_tokens`.
- `portage-repo::effective_use_flags_uncached`: every
  `apply_incremental`/`apply_incremental_iter` call that applies a
  **USE** token list (`envd_use_tokens`, `repo_make_defaults_use`,
  `features_use`, `iuse_defaults`, per-layer `make_defaults_use` and
  `package_use`, `conf_use_tokens`, `env_use_tokens`). Leave generic
  incremental call sites (`resolved_incremental`, `FEATURES`,
  `CONFIG_PROTECT` handling in `--info`) untouched.

**S3 — tests + docs.** §5.

Deliberately **not** changed: the `-*` handling itself (already
correct), the positive wildcard (already handled elsewhere), the
USE_EXPAND `conf_overrode` guard (`:2536, :2540`) — its behaviour is
orthogonal and already matches the observed installed sets.

## 5. Tests and pins

Rust (`portage-profile`, modelled on the USE tests near
`apply_incremental_is_reusable_for_per_package_use_overrides` `:5825`):

- `apply_use_incremental("-video_cards_* intel", …)` clears previously
  added `video_cards_*` and keeps `video_cards_intel`.
- Non-prefix `-*` still clears everything; `-flag`/`+flag`/`flag`
  unchanged; a `-video_cards_*` with no accumulated flags is a no-op;
  `apply_incremental` (generic) still does **not** expand `_*`.
- A `resolve_config` unit test with a synthetic profile chain whose leaf
  `make.defaults` carries `VIDEO_CARDS="-* intel"` while its parent
  carries `VIDEO_CARDS="dummy fbdev intel"`: assert the resolved USE
  contains `video_cards_intel` and none of `video_cards_dummy` /
  `video_cards_fbdev` (today it keeps them — the regression pin), plus
  a `SANE_BACKENDS` analogue proving an ebuild `+`-default is cancelled.

Python contract (`tests/test_emerge_pretend_contract.py`, through a
copied fixture configroot so shared fixtures stay untouched):

- fixture package `dev-libs/videodrv` with `IUSE="+video_cards_dummy
  video_cards_intel"` and a profile `make.defaults` with
  `VIDEO_CARDS="-* intel"`; assert portuale does not reinstall it and
  does not expose `video_cards_dummy` in the output. Add the inverse
  cell (no `-*`) proving the `+` default still applies when the profile
  does not clear it.
- the same fixture as an `emerge --pretend --newuse` case, asserting the
  `R`/`N` set matches an oracle capture from real Portage on the same
  tree (fixture-oracle bed).

## 7. Non-goals and residue

- Positive wildcard `foo_*` expansion beyond the existing IUSE-aware
  path (already implemented where IUSE is known).
- `USE_EXPAND` variable values in `package.use` shorthand
  (`VIDEO_CARDS: nvidia` syntax) — separate reader, unaffected.
- Non-USE incremental wildcards: real has none; do not add them.

## 8. Risks

- **Blast radius:** USE tokens feed every candidate's effective flags.
  Restrict the change to `-<prefix>_*` handling; any suite movement
  outside `_*` tokens is a bug, not drift.
- **Fixture vs host:** the host profile's lists exercise the bug; the
  committed fixture does not use `_*` at all today, so it must gain a
  dedicated profile fixture for the pin (S3), not a mutated shared
  profile.
- **Order within a tier:** real removes prefix matches from the flags
  accumulated *so far*; applying the wildcard before the literal discard
  in the same token preserves real's per-token order.
