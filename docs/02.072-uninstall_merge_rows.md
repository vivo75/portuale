## 1. What real Portage does (source-grounded)

- **Producer.** `_validate_blockers` (`depgraph.py:9226-9246`): when
  `depends_on_order` resolves a block by uninstalling a package, real
  creates a `Package(... operation="uninstall" ...)` task and adds a hard
  edge before the task that needs it:
  `digraph.addnode(uninst_task, inst_task, priority=BlockerDepPriority.instance)`.
  The shape in scope is exactly the satisfied `b` case: parent merges,
  matched installed package survives (cell d), or a nomerge owner is
  uninstalled before a merge-bound match (#73's cell g once fixed, if it
  is not `B`).
- **List membership.** `_serialize_tasks` (`depgraph.py:10311-10360`)
  puts uninstall tasks into `mylist` (the flat merge list), and pulls
  satisfied blockers in right after an uninstall/scheduled uninstall
  ("Include satisfied blockers in the merge list"). It also re-enables
  complete mode when any uninstall task exists (`:10340-10360`) -- that
  retry is why an uninstall can turn a `b` into a `B`; portuale's
  `installed_closure` already approximates the re-walk for the target
  arm.
- **Counters.** `set_pkg_info` (`output.py:619-621`) counts
  `counters.uninst += 1` for an ordered uninstall node.
  `_PackageCounters.__str__` (`output_helpers.py:104-180`) appends
  `"{n} uninstall[s]"` to the `Total:` details **after `binary`, before
  `interactive`**, and deliberately excludes it from `total_installs`.
- **Row.** `output.py:285-286` colours the cpv with `PKG_UNINSTALL`
  (red). The row itself is the non-merge bracket arm
  (`_set_no_columns`, `output.py:513-529`):
  `[{operation.ljust(13)}{addl}] {indent}{cpv} {oldbest}` with
  `operation = "uninstall"` and `addl = empty_space_in_brackets()`
  (one space at verbosity > 1) → `[uninstall     ] dev-libs/<pkg>-<ver>`.
  For ROOT != "/" the inline branch (`output.py:844-860`) adds
  ` to <root>`; `--columns` skips the row entirely (`output.py:869`)
  and `-q` uses another branch (`:466`). S0 pins the bytes.
- **Order.** The uninstall node is a child (prerequisite) of its owner
  in the digraph, but `_serialize_tasks`' uninstall-task selection and
  `leaf_nodes` heuristics decide where the row lands; S0 captures the
  position for each fixture shape rather than assuming "always first".

## 3. Design

**Decision (D1): model the removal as `PretendOutcome::Uninstall {
version }` on a real `GraphEntry`**, not as a display-only side list.
Reasons: real models it as a Package with `operation="uninstall"`; the
entry can carry `required_by = [owner]` so `build_digraph`'s
`required_by` fallback edge orders it before the owner and `--tree`
nests it there; `--json` and the counters get one representation. The
compiler will list every site that must decide what an Uninstall is (all
of them non-merge); the executor must go site by site, not
`matches!(... | Uninstall)` blindly. If a site turns out semantically
impossible to express this way, stop and report before adding a
display-only fallback.

**S0 — oracle capture (exact rows, order, counters).** Container,
real 3.0.82.2, using the checked-in fixtures (vdb has `samepkg-1.0`) and
the `_b1_root`-style staged roots for cell d:

Difficulty: medium (several small captures).

**S1 — resolver model + plumbing.** In `resolve_blockers`, for each
matched version where the block resolves by removal (the arms that push
`unsolvable: false`), record a removal row `(target cpv, owner_key,
owner_version)` and return it alongside the conflicts. In `run_pass`,
turn each row into a `GraphEntry { outcome: Uninstall { version },
required_by: vec![owner_key], ... }` (a small constructor helper, same
shape as the test-side `graph_entry` helpers) and push it into
`state.entries` after the blocker pass. Verify with S0 that the resolved
owner actually exists in `entries` (a satisfied block whose owner is
absent -- the bridge path -- must not fabricate an entry; bail out of
that row and document). Then sweep every `PretendOutcome` match the
compiler surfaces and give them the non-merge semantics:
`merge_bound_version` → `None`, `is_nomerge` (resolver_trace) → true,
`outcome_version`/`merge_bound_cpv` in `merge_order.rs` → the removal is
not a merge target, `slot_operator_rebuild_scan`'s `in_graph`/`new_slot`
and `rebuild_if_entries` → ignore, `buildpkgonly_deps_unsatisfied` →
ignore, `merge_unit_for_entry`/`emerge_build`/`emerge_getbinpkg` → skip
(execution is a non-goal, §7). Keep the entry's `deps` empty; ordering
comes from `required_by`.

Rust unit tests: `resolve_blockers` returns the removal row for the
satisfied installed-match arm and not for the unsolvable/replaced arms;
`serialize_merge_order` puts the Uninstall entry before its owner on the
blockerpkg fixture (and after the owner's own deps -- pin whatever S0
u1/u4 show).

## 7. Non-goals and residue

- **Executing** the removal in a real (non-pretend) merge: real unmerges
  the package before its owner merges; portuale keeps skipping it
  (`merge_unit_for_entry` returns `None`), same as today. If the same
  slot is upgraded the replacement already removes it; a surviving
  package is a pre-existing execution gap, file it if it bites.
- Real's post-serialisation blocker "solved blockers" list ordering
  (`depgraph.py:10347-10352`) beyond the row position S0 captures.
- `-C`/`--depclean`/`--prune` (their `_unmerge_display` model).
- Slot-cleanup removals that do not come from `_validate_blockers`:
  S0 u7 decides whether any are reachable in pretend mode; if yes, file
  a follow-up rather than widening this item silently.

## 8. Risks

- **Model cost.** `PretendOutcome` is matched in ~500 places; the
  compiler is the checklist, but each arm must be reasoned about (a
  wildcard `_` arm added to silence the compiler is a bug). If S1's diff
  starts to touch scheduling semantics, stop and report -- a display-only
  row is the fallback, but it costs `--tree`/`--json` fidelity.
- **False rows.** The removal rows must be emitted only where S0 shows a
  row; in particular the `owner_merging && installed_match` arm must
  keep its replaced-in-slot skip from #68 S1.
- **Ordering.** If `required_by`'s fallback edge is too weak, the row can
  land before the owner's own deps; S0's position pin is the guard, and
  a dedicated hard edge in `build_digraph` is the fix (do not widen
  `required_by` globally).
- **Counter drift.** `total_installs` must not include uninstalls
  (real's `_PackageCounters`), or every `Total:` pin in the suite moves.
