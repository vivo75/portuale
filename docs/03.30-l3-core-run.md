## A — #30: the `l3-core` source-build parity run

**Where it stands.** The harness shipped 2026-09-14:
`differential-test-bed/run/l3-source-parity.sh`,
`layers/l3/build-and-merge.sh`, atomlists
`l3-{smoke,core,system}.txt`, full-tree snapshot,
`compare/diff.py --layer l3 --tolerate-payload`, metrics JSON.

**P3 (2026-09-15) lifted the S4 stop rule**: the full candidate+control
pair `TEST/logs/l3-20260914T234404Z` is **0 hard / 0 unexplained on
both** — the last 12 rows were #47's `BUILD_TIME`/`metadata` gap, fixed
in P3. So `l3-core` (344 ebuilds) is unblocked and has simply never been
run.

### Launch (owner)

```sh
cd /home/vivo/repo/PORTUALE/pmtest
differential-test-bed/run/l3-source-parity.sh --atomlist l3-core
```

Check the script's own `--help` / `USAGE.AGENTS.md` for the current flag
spelling before running — do not trust this line blind.

**Two preconditions, both of which have faked a finding before:**

- **Run the portage upgrade as part of L1/L3 staging.** Skipping it
  fakes a `metadata` finding on *every* package.
- **The control pair is mandatory.** A candidate run without its
  portage-vs-portage control proves nothing. The host-exact control
  (`ROOT=/`) is what separates a real divergence from the `ROOT=$FX`
  staging split that turned out to be an entire phantom item once
  already.

### Triage (agent)

For each divergent row, classify into exactly one bucket and write it
into `differential-test-bed/findings/l3.md` under a new `## #30 core`
section:

| Bucket | Action |
|---|---|
| **producer class** (portuale builds a different artefact) | new numbered backlog item, one per *class*, with the smallest reproducing package named |
| **compiled-payload bytes** | ignore — payload bytes never gate outside hand-written fixtures |
| **real disagrees with itself** (parallel-`estrip` race, hash-seeded sets) | one allowlist row, never chased to zero |
| **staging artifact** | fix the bed, no product code; say so explicitly |

**Stop rule, inherited from S4 and still in force:** if more than **3
systemic producer classes** appear, stop triaging, report the classes,
and let the owner decide whether to continue. Grinding through a long
tail of rows from a broken producer is the failure mode this rule exists
to prevent.

**Partial runs:** a partial run is not a parity run. Mark it `partial`,
keep the log, and never diff it against a full one.

**Do not** fix a producer class inside this phase. Each becomes its own
slice with its own oracle.

## B — #52: the `lib.rs` mutation run

**Where it stands.** `cargo-mutants` v27.1.0, `--in-place` (the sandbox
copy breaks manifest-relative test fixtures). Already run:
`resolver_trace.rs` (35/35 missed, trace-only, accepted),
`solver_bridge.rs` (44 caught / 26 missed / 16 unviable, all 26 in the
parked pubgrub/resolvo bridge → Tier-4 gap #33/#34).
`merge_order.rs` is **Phase 4 S3**. This is the remaining one:
`portage-repo/src/lib.rs`, 2207 mutants, ≈3 h.

### Launch (owner)

```sh
cd /home/vivo/repo/PORTUALE/portuale/rust
cargo mutants --in-place --file portage-repo/src/lib.rs 2>&1 | tee mutants-lib.log
```

`--in-place` mutates the working tree: start from a **clean** tree, and
confirm `git status` is clean again when it finishes.

### Triage (agent)

Same three buckets as Phase 4 S3 — **real test gap** / **equivalent
mutant** / **unreachable-or-trace-only** — appended to
`differential-test-bed/findings/mutants.md`.

`lib.rs` is ~30 k lines and the single largest surface in the tree, so
expect a long tail. **Cluster before filing**: one backlog item per
related group of gaps (e.g. "the `installed_*` enumerators have no
negative-path coverage"), never one per mutant. A triage that files 200
items is a worse outcome than one that files six.

**Do not write the missing tests in this phase.** Measuring and fixing
in one commit makes both unreviewable.
