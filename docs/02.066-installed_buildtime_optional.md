## 1. What real Portage does (source-grounded)

For a package that is `built` (installed or binary), `_add_pkg_deps`
inserts its build-time deps at **optional** priority
(`depgraph.py:4253-4289`):

```python
(
    depend_root,
    edepend["DEPEND"],
    self._priority(cross=..., buildtime=True, optional=(pkg.built or ignore_depend_deps), ...),
),
(
    self._frozen_config._running_root.root,
    edepend["BDEPEND"],
    self._priority(cross=..., buildtime=True, optional=(pkg.built or ignore_bdepend_deps), ...),
),
```

and `_wrapped_add_pkg_dep_string` ignores an optional dep with no
selectable child (`depgraph.py:3396-3398`: "This is an unnecessary
build-time dep."). The observable rule, confirmed live with
`emerge -puDvN --oneshot <installed parent>`:

| probe (installed parent → build-time dep) | real |
|---|---|
| `dev-python/scipy` → `>=dev-python/pythran-0.16.0` (0.19.0 available) | no update |
| `dev-python/cloudpickle` → `<dev-python/flit-core-4` (4.0.2 installed) | no downgrade |
| `dev-libs/libtracefs` → `dev-util/source-highlight` (missing) | no install |
| `app-editors/okteta` → `>=dev-build/cmake-3.28.5` (newer available) | no update |
| control: installed `x11-libs/gtk+-3.24.52` → RDEPEND `pango` | pango **is** updated |
| control: merged `dev-qt/qtdeclarative` → BDEPEND `>=cmake-3.28.5` | cmake **is** updated |

So: required (runtime) deps of installed packages still drive updates;
build-time deps of installed packages only ever get *satisfied*, and a
newer/missing/downgrade-forcing build-time dep is ignored. Build-time
deps of a **merge-bound** parent remain required (the last control row),
which portuale already implements in the main New/Upgrade loop
(`lib.rs:19708-19712` drops them only for binaries without
`--with-bdeps`).

## 2. Portuale today

`enqueue_dependencies` (the `--deep` recursion into an
`AlreadyInstalled` entry, called from `:18575`) builds one dep string
from all five keys when `with_bdeps` is true (`:21318-21325`), flattens
it and pushes **every** atom as an ordinary `QueueItem`
(`:21458-21525`) with no optionality notion. Selection for such a child
then applies the atom's version bounds to candidate choice, which is how
`<flit-core-4` forces the 3.12.0 downgrade, `source-highlight` gets
installed, and pythran/uv/cargo-c/… get upgraded.

The walk already has the needed classification machinery one function
away: the main loop flattens `DEPEND`/`BDEPEND` and
`RDEPEND`/`PDEPEND`/`IDEPEND` separately
(`flatten_keys(&["DEPEND", "BDEPEND"])` / `flatten_keys(&["RDEPEND",
"PDEPEND", "IDEPEND"])`, `:19746-19778`) to tag atoms. `GraphEntry::deps`
for the AlreadyInstalled display is built separately
(`real_order_keys`, `:18536-18572`) and must keep its current shape (real
prints those depstrings in `--debug`).

## 3. Design

**S0 — oracle matrix** (fixture-oracle bed; one cell per
key × {missing, newer, incompatible-bound} plus the two controls in §1):

- `instbdnew`: installed `parentpkg` `BDEPEND=">=dev-libs/dep-2"`,
  `dep-1.0` installed, `dep-2.0` visible → real: portuale must not
  update `dep`.
- `instbdmiss`: missing `BDEPEND` → no install.
- `instbdbound`: `BDEPEND="<dev-libs/dep-2"` with `dep-2.0` installed →
  no downgrade.
- `instrdepnew`: runtime control → `dep` updated.
- Same three build-time cells for `DEPEND`.
- `IDEPEND`: confirm (install-time deps of a built package are
  non-optional in real's priority table; the oracle decides whether they
  drive updates from an installed parent).

**S1 — skip queuing build-time atoms from `AlreadyInstalled` parents.**
In `enqueue_dependencies`, keep reading the full dep string (for the
disjunction choice/`GraphEntry::deps` display bookkeeping), but only
push atoms that are **runtime** for this installed parent:

- compute `runtime_atoms = flatten_keys(["RDEPEND", "PDEPEND",
  "IDEPEND"])` exactly like the main loop (`:19778`);
- an atom present only in `DEPEND`/`BDEPEND` is not queued, does not
  record a `slot_pullers` entry, and does not add `union_constraints`;
- an atom present in both runtime and build-time keys stays (already
  covered by the runtime set).

The `--root-deps` running-root branch (`:21429-21456`) becomes inert for
installed parents; that matches real (the `--root-deps` re-rooting only
happens for parents being merged). Remove it from this function if the
compiler flags it dead, otherwise leave with a comment.

**S2 — oracle pins + host diff + docs.** §4.

## 7. Non-goals and residue

- `--with-bdeps=n` handling for **merge-bound** parents (already
  implemented; unchanged).
- Real's `_slot_operator_update_probe` replacement-parent search (#65's
  residue).
- The `--deep=<depth>` semantics beyond what the existing `Deep` type
  models: this slice does not change which packages are recursed into,
  only which atoms from the installed parent get queued.
- Updating an installed build-time dep that real *would* update when it
  is also a runtime dep of something else in the graph (covered by the
  runtime path; verify in S2).

## 8. Risks

- **Missing legitimate updates:** the control cells (runtime and
  merge-bound build-time) are the guard; S2's host diff is the second.
- **Display regressions:** `GraphEntry::deps` / `--debug` depstrings for
  installed parents must stay byte-identical; only the queue shrinks.
  Check `--tree`/`--debug` pins by name against a clean-`main` baseline.
- **`slot_pullers` interplay:** skipping the puller record for
  build-time atoms changes `SlotConflict::parents` inputs; re-run the
  slot-conflict and `need_rebuild` pins (#27's trailer, #54/#57 cases).
- **Fixture-oracle staging:** new fixtures need the staging step updated
  (`TEST/layers/l0-fixture-oracle/stage.sh`) before captures are
  meaningful — do that in S0, not S1.
