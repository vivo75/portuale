## 1. Problem (live probes, host 2026-09-16)

`dev-qt/qttools-6.11.2` needs a `--newuse` reinstall: the profile now
exposes `llvm_slot_23` and real reports `[ebuild R] qttools …
LLVM_SLOT="22 … (-23%)"`. Portuale drops it whenever **remote** binary
candidates are eligible:

| command (portuale, `--ignore-default-opts` where noted) | qttools entry |
|---|---|
| `emerge -uDpvN --oneshot dev-qt/qttools` + host defaults (`--getbinpkg=y`) | **absent** (`already_installed`, `changed_use: null`) |
| `emerge -uDpvN --ignore-default-opts --getbinpkg --oneshot …` | absent |
| `emerge -uDpvN --ignore-default-opts --usepkg --oneshot …` (local `$PKGDIR` only) | `[ebuild R]`, `changed_use: ["llvm_slot_23"]` |
| `emerge -uDpvN --ignore-default-opts --getbinpkg --binpkg-respect-use=n --oneshot …` | absent |
| **`emerge -uDpvN --ignore-default-opts --getbinpkg --usepkg-exclude=dev-qt/qttools --oneshot …`** | **`[ebuild R]`** (matches real) |

Real rebuilds it in every one of those shapes
(`emerge -puDvN --getbinpkg --oneshot dev-qt/qttools` →
`[ebuild R] dev-qt/qttools-6.11.2 … LLVM_SLOT="22 -17 … (-23%)"`).

The `--usepkg-exclude` row is decisive: the suppressor is a **remote
binary instance at the installed version** entering the candidate pool,
not the `--binpkg-respect-use` flag itself (n changes nothing) and not
the `with_bdeps`-off path (#63's getbinpkg run also turns build-time
traversal off; that alone does not explain the row, because the atom is
top-level and the `--usepkg` row walks the same atom).

Observed state in both the broken and correct runs: the entry's
`source` is `ebuild` and no `binary:` candidate appears for qttools in
the `--debug` candidate dump, so the binary is influencing the
*comparison*, not being displayed as the merge candidate.

## 2. What real does (source-grounded, `_emerge/depgraph.py`)

Real's selection loop runs `_reinstall_for_flags` **twice**, with
different argument sets (`depgraph.py:8260-8284` and `:8326-8334`):

1. For a **binary** candidate that is not installed
   (`elif reinstall_use or (not installed and respect_use)`):
   `old_use = self._pkg_use_enabled(pkg)` (the binary's baked USE),
   `old_iuse = pkg.iuse.all` (the binary's own IUSE),
   `now_use = self._pkg_use_enabled(myeb)` (the tree ebuild's
   profile-computed USE) and `cur_iuse = myeb.iuse.all` unless
   `usepkgonly`/`useoldpkg`. A non-empty result records
   `ignored_binaries[pkg]["respect_use"]` and **continues searching**
   (the ebuild wins).
2. For the installed-vs-current comparison (`:8326-8334`):
   `old_use = inst_pkg.use.enabled`, `old_iuse = inst_pkg.iuse.all`
   (the **vdb** record) versus `cur_use = self._pkg_use_enabled(pkg)` and
   `cur_iuse = pkg.iuse.all` where `pkg` is the surviving **ebuild**
   candidate — the profile-computed view, never a binary's baked flags.

Plus `identical_binary` (`:8300-8318`): a binary candidate whose cpv and
`build_time` equal the installed package's is skipped outright
(`usepkg and pkg.installed`), so the ebuild candidate is compared.
On this host the installed qttools `BUILD_TIME` (1788553903) **equals**
the remote index's `BUILD_ID 3` stanza (`BUILD_TIME: 1788553903`), so
real's path is: skip the identical binary → compare vdb vs ebuild →
`llvm_slot_23` presence diff → `[ebuild R]`.

## 3. Portuale today

- Candidate ranking prefers a binary over the same-version ebuild
  (`resolve_pretend`, `src_rank`, `lib.rs:12134-12140`).
- The installed branch (`lib.rs:12146-12159`) calls
  `reinstall_flags_for_use_change(..., best, ...)`, and
  `candidate_iuse_and_use` (`lib.rs:8334-8341`) special-cases
  `CandidateSource::Binary` to return the binary's **baked** IUSE/USE
  instead of the ebuild/profile view real uses. So once a binary is
  `best`, the newuse diff is computed against the binary's flags and can
  come out empty.
- `already_installed_or_reinstall` (`lib.rs:11338-11437`) has the same
  shape for the non-`--update` paths.
- `binary_reinstall_warranted` / `ebuild_visible_at`
  (`lib.rs:8251-8260`, unit test `:21854`) model real's
  `identical_binary`/`_equiv_ebuild_visible` only for the
  `--rebuilt-binaries` decision, not for the newuse comparison.
- `binpkg_respect_use` only filters binary candidates
  (`lib.rs:11585-11587`), it does not redirect the comparison to the
  ebuild.

## 7. Non-goals

- `binpkg_changed_deps` / `--rebuilt-binaries` semantics beyond the
  `identical_binary` interaction fixed here.
- `--usepkgonly` ebuild-less selection beyond the comparison fallback.
- Reworking `candidate_iuse_and_use`'s binary arm wholesale: it is
  correct for the *binary-vs-installed respect-use* comparison real
  performs; the bug is using it for the *vdb-vs-current* newuse
  comparison. Keep both, route them like real.

## 8. Risks

- **Pins:** `--usepkg`/`--getbinpkg`/respect-use/exclude cells are
  heavily pinned; every moved output must be oracle-backed.
- **`best` instability:** the fix intentionally changes which candidate
  wins (ebuild over a rejected binary) and therefore the displayed
  `[binary g]`/`[ebuild]` form and `source`; re-check the
  `remotebinpkg`/`binaryonlypkg`/`dirbinhostonly` cases closely.
- **`--usepkg-exclude` must remain a test-only oracle lever**, not a
  workaround: the fix has to make the default shapes correct.
