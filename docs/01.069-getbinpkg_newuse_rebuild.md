## 1. Problem (live probes, host 2026-09-16)

`dev-qt/qttools-6.11.2` needs a `--newuse` reinstall: the profile now
exposes `llvm_slot_23` and real reports `[ebuild R] qttools …
LLVM_SLOT="22 … (-23%)"`. Portuale drops it whenever **remote** binary
candidates are eligible:

| command (portuale, `--ignore-default-opts` where noted) | qttools entry |
|---|---|
| `emerge -uDpvN --oneshot dev-qt/qttools` + host defaults (`--getbinpkg=y`) | **absent** (`already_installed`, `changed_use: null`) |
| `emerge -uDpvN --ignore-default-opts --getbinpkg --oneshot …` | absent |
| `emerge -uDpvN --ignore-default-opts --usepkg --oneshot …` (local `$PKGDIR` only) | `[ebuild R]`, `changed_use: ["llvm_slot_23"]` |
| `emerge -uDpvN --ignore-default-opts --getbinpkg --binpkg-respect-use=n --oneshot …` | absent |
| **`emerge -uDpvN --ignore-default-opts --getbinpkg --usepkg-exclude=dev-qt/qttools --oneshot …`** | **`[ebuild R]`** (matches real) |

Real rebuilds it in every one of those shapes
(`emerge -puDvN --getbinpkg --oneshot dev-qt/qttools` →
`[ebuild R] dev-qt/qttools-6.11.2 … LLVM_SLOT="22 -17 … (-23%)"`).

The `--usepkg-exclude` row is decisive: the suppressor is a **remote
binary instance at the installed version** entering the candidate pool.
The entry's `source` stays `ebuild` in the broken run, so the binary
influences the *comparison*, not the displayed merge candidate.

## 2. What real does (source-grounded, `_emerge/depgraph.py`)

Selection iterates `dbs` in order (ebuild tree, then binaries, then
installed); an unbuilt candidate sets `myeb` (`if not built: myeb = pkg`),
so the ebuild at a version is known before that version's binary is
examined.

1. **Binary rejection (`:8260-8294`).** For a built candidate the gate is
   `elif reinstall_use or (not installed and respect_use)`, where
   `reinstall_use = "--newuse" in myopts or "--reinstall" in myopts`
   (`:8220-8223`) and `respect_use` is `binpkg_respect_use in ("y",
   "auto")` (`:8230-8232`). So under `-N` **every** candidate is checked,
   independently of `--binpkg-respect-use`:
   `old_use = _pkg_use_enabled(pkg)` (a binary's baked USE),
   `iuses = pkg.iuse.all` (the binary's IUSE),
   `now_use = _pkg_use_enabled(myeb)` (the ebuild's profile-computed USE),
   `forced_flags = myeb.use.force ∪ myeb.use.mask`,
   `cur_iuse = myeb.iuse.all` unless `usepkgonly`/`useoldpkg` (then the
   binary's own). `_reinstall_for_flags` (`:3134-3162`): if `--newuse`,
   or respect-use is `y`/`auto` without `--reinstall=changed-use`, it
   reports `(old_iuse ^ cur_iuse) - forced_flags` plus the
   enabled-within-IUSE symmetric difference; otherwise (`changed-use`, or
   respect-use under `changed-use`) only the enabled-within-IUSE
   difference. Non-empty → a non-installed binary is recorded in
   `ignored_binaries[pkg]["respect_use"]` and **skipped** (`continue`);
   an installed one ends the search (`break`).
2. **Installed comparison (`:8309-8336`).** For a surviving non-installed
   candidate at an installed cpv: `old_use = inst_pkg.use.enabled`,
   `old_iuse = inst_pkg.iuse.all` (vdb) vs `cur_use =
   _pkg_use_enabled(pkg)`, `cur_iuse = pkg.iuse.all` of **that
   candidate** (an ebuild, or a binary that survived step 1 — whose flags
   then already agree with the ebuild's view modulo forced flags).
3. **`identical_binary` (`:8001-8017`)** is about the **installed**
   candidate: with `--usepkg`, if a matched binary has the same cpv and
   `build_time` as the installed package, the installed package is
   exempt from the `_equiv_ebuild_visible` / `buildpkg-proactive`
   rejection block — i.e. it is *kept*. It does not skip a binary, and it
   does not route any comparison to the ebuild. Not part of this bug.

qttools: the ebuild's IUSE gained `llvm_slot_23`; the remote binary (same
`BUILD_TIME` as installed) lacks it → step 1 rejects the binary under
`-N` even with `--binpkg-respect-use=n` → step 2 compares vdb vs ebuild →
`[ebuild R]`.

## 3. Portuale today (root-cause hypothesis for S0 to confirm)

- `binpkg_respect_use_ok` is the portuale analogue of step 1, applied as
  a candidate filter in `resolve_pretend` and in the graph walk. Two
  mismatches with real:
  - **gate:** it runs only `if binpkg_respect_use`; real runs the check
    when `reinstall_use || respect_use`. Explains the
    `--binpkg-respect-use=n` row.
  - **IUSE:** it computes `effective_use_flags` over the **binary's**
    `iuse` and compares only flags in the binary's IUSE. A flag that
    exists only in the ebuild's IUSE (`llvm_slot_23`) is invisible, and
    `--newuse` IUSE-set changes are never detected. Explains the
    default (respect-use=y) rows.
- Then the binary survives, `src_rank` makes it `best` at the installed
  version, and `reinstall_flags_for_use_change(…, best, …)` →
  `candidate_iuse_and_use`'s binary arm compares vdb vs the binary's
  baked IUSE/USE, which equals the installed record → no change → entry
  `AlreadyInstalled`.
- `candidate_iuse_and_use`'s binary arm is itself faithful to step 2
  (real also compares against a surviving binary); it only yields the
  wrong answer because step 1 let the binary through.

## 8. Risks

- **Pins:** `--usepkg`/`--getbinpkg`/respect-use/exclude cells are
  heavily pinned; every moved output must be oracle-backed.
- **`best` instability:** rejecting more binaries under `-N` changes the
  displayed `[binary g]`/`[ebuild]` form on host-scale runs (intended).
  Check the host `@world` diff for binaries real still takes
  (e.g. `dev-lang/go`, `dev-build/cmake`).
- **Performance:** the check now runs for every binary under `-N` and
  needs the same-version ebuild's effective USE; reuse the
  `effective_use_flags` cache, and re-time `emerge -puDN @world`.
- **`--usepkg-exclude` must remain a test-only oracle lever**, not a
  workaround.
