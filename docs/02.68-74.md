## 0. Rules for every slice (read twice)

1. **One commit per slice, as soon as that slice is green, before the
   next slice starts.** Subject `#<item> <slice-id>: <what>` (slice ids
   are the ones in this file, e.g. `#70 R1`, `#73 S1`). Trailer
   `Co-Authored-By: <actual model name> <noreply@…>`. No squashing two
   slices into one commit, no amending an earlier slice's commit, no push.
   This plan **is** the user's explicit request to commit per slice
   (AGENTS.md rule 9). A slice that ends with no file change (e.g. an
   oracle capture that only confirms the model) still records its result
   in `TEST/findings/l0.md` and commits that.
2. **Slices are self-contained.** Each slice states its goal, the files it
   may touch, and its verification. If a slice needs a file outside its
   list, or its verification cannot go green without work from a later
   slice, **stop and report**; do not borrow work from the next slice.
3. **Oracle before code.** Every expected output comes from real Portage:
   source citation *and* a capture (container fixture-oracle bed, host
   `emerge`, or `python3 -c "import portage; …"` for config values). A
   portuale docstring, a previous plan, or a commit message is **not** an
   oracle — several were wrong (§1).
4. **Full verification pass** (AGENTS.md step 8) before each commit:
   `cargo fmt --check`, `cargo clippy --release --all-targets` (0
   warnings), `cargo test --release` (workspace root),
   `python3 -m pytest tests -q`. Plus the slice's own "Verify" list.
   Compare failing pytest **names** against the pre-slice baseline, never
   counts (`contract-suite-pollutes-fixtures`, `/tmp` inode exhaustion:
   check `df -i /tmp` before believing a cascade).
5. **Stop-and-report conditions** (write the finding into
   `TEST/findings/l0.md`, commit that, and stop the phase): an oracle cell
   contradicts this plan; a fix would need a heuristic fitted to one
   fixture; a pin that exists today would have to move without a real
   capture backing the new value.
6. **Close-out** (AGENTS.md rule 11): the last slice of each item flips
   `docs/backlog-tasks.md`'s entry and the item's plan `Status:` header in
   the same commit, and appends a `what-this-proves.md` paragraph with a
   runnable, live-verified example.
