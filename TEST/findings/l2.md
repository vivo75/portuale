## l2-pkgindex-version-missing · HIGH · FIXED

`<PKGDIR>/Packages` written by portuale carried a header with only
`TIMESTAMP:`. Real Portage's `bintree._load_pkgindex` discards any index
whose header fails `_pkgindex_version_supported`
(`lib/portage/dbapi/bintree.py:2429-2437`: needs a numeric `VERSION`).
With the image's `FEATURES=pkgdir-index-trusted`, portage does not walk
`$PKGDIR` to rebuild the index — so **every portuale-built archive was
invisible and `emerge -k` silently rebuilt from source**, i.e. the
cross-install test would have "passed" while testing nothing.

Evidence (before the fix):

```
$ emerge -pK porttest/docs
emerge: there are no binary packages to satisfy "porttest/docs".
```

After adding `VERSION: 0` to the header by hand: `[binary N]` for both
archives; `>>> Emerging binary … porttest/docs::__unknown__`; rc 0.

Fix: `ebuild_package.rs::packages_index_header` now emits
`TIMESTAMP: …\nVERSION: 0` (real's writer always stamps it,
`bintree.py:2388`/`:2397`); unit test
`write_packages_index_entry_creates_a_header_then_the_entry` pins it.
Real's config-fingerprint header fields stay omitted (real only uses
them when it rewrites the index itself). No Python mirror: real-execution.

## l2-no-md5-cache-ebuild-fallback · MEDIUM · OPEN (harness worked around)

Real Portage resolves ebuilds from a repo with no `metadata/md5-cache`
by parsing the ebuild (`cache-formats = md5-dict` is a *format*, not a
requirement). Portuale's repo reader only consults
`metadata/md5-cache` (`portage-repo/src/lib.rs::read_md5_cache`), so
every `porttest/*` atom was invisible to portuale:

```
$ emerge -p porttest/docs
emerge: there are no ebuilds to satisfy "porttest/docs".
```

L0/L1 never hit this (the real tree ships a cache; L1 only merged
binpkgs). Workaround: the generated `metadata/md5-cache` for all nine
fixtures is now committed under
`TEST/images/overlay/porttest/metadata/md5-cache/` (per AGENTS.md's
"fixtures + metadata/md5-cache" convention). The missing ebuild
fallback itself is a real drop-in gap for cache-less repos — filed,
not fixed.

## l2-gpkg-metadata-members · MEDIUM · OPEN

`metadata.tar.zst` of a portuale-built archive is missing members real
Portage always writes (porttest/docs, source build):

| member | real value | portuale |
|---|---|---|
| `IUSE` | present (empty for a no-IUSE ebuild) | absent |
| `IUSE_EFFECTIVE` | profile-computed flag set | absent (documented gap: needs a resolved `Config` at phase depth) |
| `SIZE` | installed size in bytes (`807`) | absent (`write_post_install_metadata` does not walk `${D}`) |
| `repository` | `porttest` | absent (phase env never sets `PORTAGE_REPO_NAME`, so real `phase-functions.sh:762` writes nothing) |
| `REPO_REVISIONS` | `{}` | absent (same; `PORTAGE_REPO_REVISIONS`) |
| `BUILD_ID` | present | present only under `FEATURES=binpkg-multi-instance` (deliberate conservatism in `ebuild_package.rs`; harness exports it) |

Consumer-visible effect: portage records `::__unknown__` and the merged
VDB has no `repository` file. Filed as a producer-parity follow-up.

## l2-gpkg-docompress · MEDIUM · OPEN

Real `FEATURES=binpkg-docompress` (default-on via `make.globals`) runs
`ecompress` over `${D}` before packaging
(`bin/misc-functions.sh:147-149`); portuale implements no
`docompress`/`ecompress` at all. On the `porttest/docs` fixture, real's
archive image carries `BIG.txt.bz2`, portuale's carries `BIG.txt` —
a path-set diff in cross-install parity even though both merge cleanly.

Per-package `db` markers are unaffected; it is the payload path set.
Filed as a producer-parity follow-up; the fixture track will allowlist
it (owner: portuale-bug) until implemented.

## S1 — `gpkg-structure.sh` (2026-09-13)

`TEST/compare/gpkg-structure.sh` validates one archive or a whole
`$PKGDIR`: outer member set (`gpkg-1`/`image.tar[.comp]`/
`metadata.tar[.comp]`/`Manifest` + optional `.sig`), inner tar roots,
the stable metadata-key set (the exact intersection of all 78 real
archives in the L1 pkgcache), the Manifest DATA record set and digest
lengths, filename `<->` inner-prefix `BUILD_ID` agreement, and with
`--packages` the `Packages` stanza (`PATH`/`SIZE`/`MD5`/`BUILD_ID`/
`BUILD_TIME`/`REPO`).

Host verification (no container):

```sh
TEST/compare/gpkg-structure.sh --dir TEST/logs/_l1-pkgcache --packages   # rc 0, 78/78 clean
TEST/compare/test-gpkg-structure.sh                                      # 10 passed, 0 failed
```

The self-test pins one mutation per category (truncated container,
Manifest member removed, Manifest DATA record dropped, metadata key
removed, corrupt `metadata.tar.zst`, renamed `BUILD_ID` copy, spoofed
`Packages` `MD5`, missing `REPO`) and proves each is caught.

Against the S0 portuale archives the checker reports exactly the filed
producer gaps — 5 metadata members per archive (`SIZE`, `IUSE`,
`IUSE_EFFECTIVE`, `repository`, `REPO_REVISIONS`) plus the missing
`Packages` `REPO` field — i.e. `l2-gpkg-metadata-members`, not new
findings.

The metadata-key intersection also settled the required set: real does
*not* always write `LICENSE`/`HOMEPAGE`/`INHERITED`/`NEEDED*` (virtual
and acct packages), so those are deliberately not required.

## S2 — `gpkg-diff.sh` + `diff.py --layer/--tolerate-payload` (2026-09-13)

`TEST/compare/gpkg-diff.sh` (wrapper over `gpkg_diff.py`) is the
normalised archive-vs-archive diff: outer member-kind set, metadata
after `BUILD_TIME`/`BUILD_ID`/`COUNTER` blanking + `NEEDED*` sorting +
`environment.bz2` through `normalize.py`'s own `norm_environment` (one
ruleset, imported not copied), image path + type/mode/uid/gid/symlink
attr parity, payload sha256, and Manifest DATA *names* only (digest
values are volatile by construction). `--mode strict` = payload diffs
hard (deterministic `porttest` fixtures); `--mode payload-tolerant` =
payload diffs reported as `[payload]`, non-fatal (the real set).

`diff.py` gained `--layer` (allowlist `layer:` filter, report
header/JSON name) and `--tolerate-payload` (CONTENT/SIZE and `CONTENTS`
`obj`-md5 differences become non-fatal `[PAYLOAD]`; path/type/mode/
owner/xattr/symlink and `sym` targets stay hard). Defaults are
byte-for-byte L1 behaviour -- the existing L1 run re-diffs rc 0 with the
identical `# L1 merge-parity report`.

Host verification (no container):

```sh
TEST/compare/test-gpkg-diff.sh              # 9 passed, 0 failed
python3 TEST/compare/test-diff-tolerance.py # all checks OK
```

Pins: two `porttest` instances hard-clean in strict, two real Portage
`tree` instances hard-clean in tolerant, and one mutation per bucket
(metadata key, payload byte, mode, removed path, truncated archive)
with payload severity flipping correctly between modes. A real bug in
`gpkg_diff.py` was caught by the tests themselves (class-level mutable
dicts shared between the two `Side` instances made every comparison
see one side twice -- fixed before commit).

### The producer gaps this run filed

**`l2-bpkgonly-env` · HIGH.** `--buildpkgonly` runs the build with the
*standalone* ebuild env, not the resolved graph env the `emerge <atom>`
path uses (`emerge_build.rs::run_buildpkgonly` calls
`ebuild_package::run_package(&path, root, portage_tmpdir, options)`
with no `build_env`/`per_entry`; the merge path threads them). Evidence
from the archive diff vs real:

| metadata | real | portuale |
|---|---|---|
| `USE` | `abi_x86_64 amd64 elibc_glibc kernel_linux` | empty |
| `FEATURES` | resolved incremental list (`assume-digests …`) | raw process env (`buildpkg binpkg-multi-instance splitdebug …`) |
| `.keep_<cat>_<pn>-<slot>` | `.keep_porttest_emptydirs-0` | `.keep_porttest_emptydirs-` (SLOT unset) |
| `NEEDED` lib path | `/usr/lib64/libptsd.so.0.0.0` | `/usr/lib/libptsd.so.0.0.0` (no multilib `LIBDIR_*`) |
| `environment.bz2` | resolved env | bare env |

**`l2-gpkg-dostrip-splitdebug` · HIGH.** The packaging path runs no
`dostrip`/`estrip` and no `splitdebug`: portuale archives ship
unstripped binaries (setuid fixture: 15424 vs 14384 bytes) and zero
`/usr/lib/debug/**` objects where real (default `binpkg-dostrip` +
`FEATURES=splitdebug`) ships `.debug` files + `.build-id` symlinks.

**`l2-needed-elf2-format` · MEDIUM.** portuale's own `NEEDED.ELF.2`
records 5 fields; real writes the trailing ELF-class field
(`X86_64;/usr/bin/x;;;libc.so.6;x86_64`).

**`l2-consumes-portuale-env-degraded` · MEDIUM.** Real Portage merging
a portuale-built archive runs the merge phases with a degraded saved
environment: `MERGE_TYPE` is unset (fixture prints `?`) and
`pkg_pretend` is skipped, so `porttest/phases`'s
`/var/lib/porttest/phase.log` is 226 B where the portage-built
reference gives 322 B (`pretend setup preinst postinst` vs
`setup preinst postinst`). Reproduced directly; root cause not yet
isolated (the archive's `DEFINED_PHASES`/`EAPI` are correct).

**`l2-gpkg-metadata-members` · MEDIUM (expanded at S3).** Beyond the
S0 five (`SIZE`, `IUSE`, `IUSE_EFFECTIVE`, `repository`,
`REPO_REVISIONS`), the source-build path also omits the ebuild-derived
`RDEPEND`/`REQUIRES`/`PROVIDES` and writes no `Packages` index `REPO`
field.

**`l2-gpkg-docompress` · MEDIUM.** Unchanged from S0 (no
`docompress`/`ecompress`; `BIG.txt` vs `BIG.txt.bz2`).

### Harness fixes made while adjudicating (not bug-hiding)

- `normalize.py`: `BINPKGMD5` blanked (VDB records the *source
  archive* md5; L2 compares different builds by design) and
  presence-only paths (regenerated caches) now have their `size`
  blanked too -- `/etc/ld.so.cache` drifts legitimately.
- `diff.py`: `CONTENTS` line diffs are no longer capped at 8/side; a
  `... +N more` aggregate cannot be adjudicated precisely.
- `gpkg_diff.py`: the `only in a`/`only in b` image labels were
  inverted (found by comparing the pair output against a direct tar
  listing). Fixed.
