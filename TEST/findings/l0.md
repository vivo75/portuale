## A. Autounmask required → exit code + merge-list disclosure  ·  HIGH · ~15 probes  ·  **FIXED (exit code) — `c883662`**

**Exit-code half fixed** (`c883662`): real `action_build` returns 1
whenever `_have_autounmask_changes()` — before any merge, `--pretend`
included (verified against a live `emerge -pv www-client/firefox`).
portuale now exits 1 when any `autounmask_{keyword,mask,use,license}_
changes` is non-empty, except `--autounmask-only` / real non-pretend
`--autounmask-continue`. **Merge-list-truncation half still open**: real
withholds the full list on a hard-mask cascade (`need_config_change` →
terminate); portuale still prints the complete list. That half is
cluster C's real content — deferred.

Original notes:


`podman`, `plasma-meta`, `gtk:4`, `gtk+:3`, `gnome-shell`, `nautilus`,
`gedit`, `firefox`, `thunderbird`, `libreoffice`, `gimp`, `nginx`,
`wireshark`, `i3`, `systemd-utils`, `MULTI_emptytree-system`.

Real portage, when autounmask changes are needed: prints the changes,
prints `* … backtracking has terminated early due to the above
autounmask change(s)`, **withholds the full merge list**, exits **1**.
Portuale: applies the changes, prints the **complete** merge list, exits
**0**.

A script that checks `$?` after `emerge -p` would treat "you must edit
package.use first" as success. Portuale should exit non-zero when
autounmask changes are required and neither `--autounmask-write` nor
`--autounmask-continue` is given, and match real's decision to withhold
the merge list.

Next: compare against real `_emerge/depgraph.py` `_display_autounmask`
and the `need_config_change` / backtracking-terminated path; check
portuale's autounmask-in-loop exit-code plumbing (memory:
`autounmask-in-loop-complete`).

## B. Spurious `use.force`/`use.mask` parens  ·  HIGH · ~13 probes  ·  **FIXED — `c883662`**

Root cause: real `UseManager.getUseMask`/`getUseForce` stack the four
sources (`use.mask`, `use.stable.mask`, `package.use.mask`,
`package.use.stable.mask`) **interleaved per profile level**, one
incremental `stack_lists`. `base/package.use.stable.mask` masks
`sysprof` for `dev-libs/glib`; `arch/amd64/use.mask` (a *later* chain
level) un-masks it globally with `-sysprof`. portuale flat-unioned the
four sources, so the per-package entry re-added `sysprof`
unconditionally → `(-sysprof)`.

Fixed: `portage_profile::Config::use_mask_force_levels` (per-chain-level
+ synthetic repo-level [0]); `portage_repo::resolved_use_mask_or_force`
replays the interleave; `effective_use_flags` +
`forced_or_masked_flags` use it. Fixture `dev-libs/crossmaskcancelpkg`,
dual-language, `test_later_level_global_use_mask_cancels_earlier_
package_use_stable_mask`.

## D. `dev-lang/go-bootstrap` not pulled  ·  MEDIUM · 2 probes · **FIXED**

`dev-lang/go` (Total 1 vs real 2), `runc` (Total 3 vs 4).

go's `BDEPEND` is `|| ( >=dev-lang/go-<v> dev-lang/go-bootstrap )` with
nothing installed. The first branch's only tree match is `dev-lang/go`
itself (circular self-dep), so real `dep_zapdeps` falls through to the
`go-bootstrap` branch; portuale flat-ranked both as `Available` and took
the first, which then resolved to the package being built (self) → the
`||` contributed nothing.

**Fixed:** the `_disj_pref` / disjunctive `alternative_satisfiable`
closure (both the main `resolve_pretend_graph` walk and the
`_enqueue_dependencies` `--deep` recursion, dual-language) now treats an
atom whose `cat/pkg` is the entry's own and which nothing installed
satisfies as unavailable — so a self-only branch can't win. Fixture
`dev-lang/selfbootpkg` + 2 contract CASES. Verified in the L0 container:
`dev-lang/go` → Total 2, `runc` → Total 4 (both match real).

## L. installed dep lacks a `[flag]` use-dep → not autounmasked  ·  HIGH · many probes · **PARTLY FIXED**

Root cause shared by the `nginx` exit finding, most of E, all of G, and
part of F/`kdecore-meta`/`gnome-shell`. A dependency atom `foo[bar]`
where `foo` is **installed without `bar`**: real portage reinstalls
`foo` with `bar` and, since `bar` needs `package.use`, autounmasks it
(`[ebuild R] … bar*`, exit 1, the `nghttp2`/… that `bar` pulls appear).
portuale treated the installed `foo` as satisfying `foo[bar]` and
returned `AlreadyInstalled` → exit 0, subtree missing.

**Fixed (first-encounter case):** `resolve_pretend`'s
`candidate_is_installed(best)` branch now forces a `Reinstall` (not
`AlreadyInstalled`) when `atom.use_deps` aren't satisfied by the
resolved candidate's effective USE and `autounmask_use` is on -- so the
graph layer's own child-flip block records the autounmask change,
applies the flip, and walks the newly-USE-gated deps. Dual-language,
fixture `dev-libs/flipinstconsumer` + 2 contract CASES. Verified:
`www-servers/nginx` now `rc=1`, matching real.

**Still open:** when `foo` was already resolved `AlreadyInstalled` by a
plain (no-`[flag]`) atom from another package *before* `foo[bar]` is
reached, `foo[bar]` hits the `other_outcomes` dedup and the constraint
is lost -- the `resolved_slots` re-check only covers New/Upgrade. This
is the `net-misc/curl:=[http2,ssl]` (E) and `sys-apps/systemd[policykit]`
(G) case; also the `:=` slot-op may be stripping the `[flag]` before the
walker sees it. Needs an `other_outcomes` counterpart to the
`resolved_slots` autounmask-use re-check.

## H. `@world` didn't include `@system`  ·  HIGH · **FIXED** (`72ea263`)

documented simplification), so it omitted the entire `@system` set and
an empty world file gave `emerge: no package atoms to resolve` (rc 2).

**Fixed:** `@world` now = `@selected ∪ @system` (real `WorldSet`);
`@selected` alone stays the world file; a trailing dedup keeps first
position. `TEST/layers/l0/in-container.sh` seeds a small realistic
`@world` (`tmux`/`eix`/`gentoolkit`/`blake3`, none installed) so the L0
`@world` probes exercise the resolver. `emerge -pv @world` in the L0
container now produces the exact same 76-package set as real portage.
Dual-language, `test_world_missing_file_expands_to_system_not_an_error`
+ CASES.

Residual (not H): portuale emits a few `[blocks B]` soft-blocker lines
for `@world`/`@system` (`coreutils[kill]` vs `procps` etc.) that real
resolves silently -- a blocker-evaluation nuance, tracked separately.

## Notes for the comparator itself

- When exit codes differ, the merge-list set/order/totals comparison is
  complete-vs-truncated; `resolve-compare.py` now suppresses those and
  reports only `exit` + `advice` + `error`.
- Package identity is keyed by `(type, category/pn)` — multi-slot
  packages in one list collide (last wins). Slot-aware keying is a
  refinement if it starts hiding real findings.
- `@world` probe would be far stronger with a populated `world` file in
  the image (see H).
