## A. Autounmask required → exit code + merge-list disclosure  ·  HIGH · ~15 probes  ·  **FIXED (exit code) — `c883662`**

**Exit-code half fixed** (`c883662`): real `action_build` returns 1
whenever `_have_autounmask_changes()` — before any merge, `--pretend`
included (verified against a live `emerge -pv www-client/firefox`).
portuale now exits 1 when any `autounmask_{keyword,mask,use,license}_
changes` is non-empty, except `--autounmask-only` / real non-pretend
`--autounmask-continue`. **Merge-list-truncation half still open**: real
withholds the full list on a hard-mask cascade (`need_config_change` →
terminate); portuale still prints the complete list. That half is
cluster C's real content — deferred.

Original notes:


`podman`, `plasma-meta`, `gtk:4`, `gtk+:3`, `gnome-shell`, `nautilus`,
`gedit`, `firefox`, `thunderbird`, `libreoffice`, `gimp`, `nginx`,
`wireshark`, `i3`, `systemd-utils`, `MULTI_emptytree-system`.

Real portage, when autounmask changes are needed: prints the changes,
prints `* … backtracking has terminated early due to the above
autounmask change(s)`, **withholds the full merge list**, exits **1**.
Portuale: applies the changes, prints the **complete** merge list, exits
**0**.

A script that checks `$?` after `emerge -p` would treat "you must edit
package.use first" as success. Portuale should exit non-zero when
autounmask changes are required and neither `--autounmask-write` nor
`--autounmask-continue` is given, and match real's decision to withhold
the merge list.

Next: compare against real `_emerge/depgraph.py` `_display_autounmask`
and the `need_config_change` / backtracking-terminated path; check
portuale's autounmask-in-loop exit-code plumbing (memory:
`autounmask-in-loop-complete`).

## B. Spurious `use.force`/`use.mask` parens  ·  HIGH · ~13 probes  ·  **FIXED — `c883662`**

Root cause: real `UseManager.getUseMask`/`getUseForce` stack the four
sources (`use.mask`, `use.stable.mask`, `package.use.mask`,
`package.use.stable.mask`) **interleaved per profile level**, one
incremental `stack_lists`. `base/package.use.stable.mask` masks
`sysprof` for `dev-libs/glib`; `arch/amd64/use.mask` (a *later* chain
level) un-masks it globally with `-sysprof`. portuale flat-unioned the
four sources, so the per-package entry re-added `sysprof`
unconditionally → `(-sysprof)`.

Fixed: `portage_profile::Config::use_mask_force_levels` (per-chain-level
+ synthetic repo-level [0]); `portage_repo::resolved_use_mask_or_force`
replays the interleave; `effective_use_flags` +
`forced_or_masked_flags` use it. Fixture `dev-libs/crossmaskcancelpkg`,
dual-language, `test_later_level_global_use_mask_cancels_earlier_
package_use_stable_mask`.
