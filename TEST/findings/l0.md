## A. Autounmask required → exit code + merge-list disclosure  ·  HIGH · ~15 probes  ·  **exit code `c883662`; "terminated early" notice + comparator done**

**Exit-code half fixed** (`c883662`): real `action_build` returns 1
whenever `_have_autounmask_changes()` — before any merge, `--pretend`
included. portuale now exits 1 when any `autounmask_{keyword,mask,use,
license}_changes` is non-empty, except `--autounmask-only` / real
non-pretend `--autounmask-continue`.

**"backtracking has terminated early" notice** now emitted (dual-lang) —
real `_display_autounmask`'s tail, gated on
`_autounmask_backtrack_disabled` (autounmask changes + `--autounmask-
backtrack` off, the default; `--pretend` included). Cleared the
`[error] real-only message: * In order to avoid wasting time…` findings.
12 pinned autounmask contract tests re-pinned (`BACKTRACK_TERMINATED_
EARLY` constant).

**Merge-list-truncation half.** The *comparator* now detects real's
"terminated early" marker + a >2× Total gap and **suppresses the
merge-list set/order/totals comparison** (truncated-vs-complete is
noise, same as the `rrc != prc` bail), emitting one `truncated` finding
instead of ~500 `extra`. plasma-meta 484→1, podman 35→1: L0 `extra`
591→~72, UNEXPLAINED 682→~161.

**Exact trigger (diagnosed 2026-09-09, resolver fix deferred).** Across
all 12 autounmask probes: `real Total == portuale Total` for every one
that has autounmask changes **and no circular dependency** (firefox 156,
gedit 142, gnome-shell 453, …). Real truncates **only** when autounmask
changes coincide with an **unresolvable circular dependency** — exactly
`podman` (`go` self-cycle → 8) and `plasma-meta` (`go` → 4). Mechanism:
`select_files` sets `_success_without_autounmask` (→ `need_config_change`
→ `backtrack_depgraph` breaks, full list shown) **only when autounmask
is the sole problem** (`depgraph.py` ~5628). A circular dep is an "other
problem" → flag stays false → the backtracker exhausts its retries →
`get_best_run()` returns the DFS-deepest *partial* graph = the top-level
atom + the first fully-resolved subtree(s), stopping at the first
`want_restart_for_use_change` autounmask node.

Real's partial set = {cycle nodes} ∪ {DFS-visited-before-the-first-
autounmask-restart-node}. For plasma-meta that is exactly the reverse-
reachability closure of `go` (go←gocryptfs←plasma-vault←plasma-meta);
for podman it is that closure **plus** `conmon` (a C sibling DFS-visited
before `iptables[nftables]`). Reproducing it faithfully needs
DFS-ordered graph construction + the backtracker's `get_best_run`
(cluster I / deferred backtracking work). An *approximate* BFS-prefix
truncation is worse than the status quo: it would bring portuale's
Total close to real's, defeating the comparator's size-gap suppression
and fanning back out to per-package `missing`/`extra` findings.

Original notes:


`podman`, `plasma-meta`, `gtk:4`, `gtk+:3`, `gnome-shell`, `nautilus`,
`gedit`, `firefox`, `thunderbird`, `libreoffice`, `gimp`, `nginx`,
`wireshark`, `i3`, `systemd-utils`, `MULTI_emptytree-system`.

Real portage, when autounmask changes are needed: prints the changes,
prints `* … backtracking has terminated early due to the above
autounmask change(s)`, **withholds the full merge list**, exits **1**.
Portuale: applies the changes, prints the **complete** merge list, exits
**0**.

A script that checks `$?` after `emerge -p` would treat "you must edit
package.use first" as success. Portuale should exit non-zero when
autounmask changes are required and neither `--autounmask-write` nor
`--autounmask-continue` is given, and match real's decision to withhold
the merge list.

## B. Spurious `use.force`/`use.mask` parens  ·  HIGH · ~13 probes  ·  **FIXED — `c883662`**

Root cause: real `UseManager.getUseMask`/`getUseForce` stack the four
sources (`use.mask`, `use.stable.mask`, `package.use.mask`,
`package.use.stable.mask`) **interleaved per profile level**, one
incremental `stack_lists`. `base/package.use.stable.mask` masks
`sysprof` for `dev-libs/glib`; `arch/amd64/use.mask` (a *later* chain
level) un-masks it globally with `-sysprof`. portuale flat-unioned the
four sources, so the per-package entry re-added `sysprof`
unconditionally → `(-sysprof)`.

Fixed: `portage_profile::Config::use_mask_force_levels` (per-chain-level
+ synthetic repo-level [0]); `portage_repo::resolved_use_mask_or_force`
replays the interleave; `effective_use_flags` +
`forced_or_masked_flags` use it. Fixture `dev-libs/crossmaskcancelpkg`,
dual-language, `test_later_level_global_use_mask_cancels_earlier_
package_use_stable_mask`.

## D. `dev-lang/go-bootstrap` not pulled  ·  MEDIUM · 2 probes · **FIXED**

`dev-lang/go` (Total 1 vs real 2), `runc` (Total 3 vs 4).

go's `BDEPEND` is `|| ( >=dev-lang/go-<v> dev-lang/go-bootstrap )` with
nothing installed. The first branch's only tree match is `dev-lang/go`
itself (circular self-dep), so real `dep_zapdeps` falls through to the
`go-bootstrap` branch; portuale flat-ranked both as `Available` and took
the first, which then resolved to the package being built (self) → the
`||` contributed nothing.

**Fixed:** the `_disj_pref` / disjunctive `alternative_satisfiable`
closure (both the main `resolve_pretend_graph` walk and the
`_enqueue_dependencies` `--deep` recursion, dual-language) now treats an
atom whose `cat/pkg` is the entry's own and which nothing installed
satisfies as unavailable — so a self-only branch can't win. Fixture
`dev-lang/selfbootpkg` + 2 contract CASES. Verified in the L0 container:
`dev-lang/go` → Total 2, `runc` → Total 4 (both match real).

## L. installed dep lacks a `[flag]` use-dep → not autounmasked/reinstalled  ·  HIGH · many probes · **FIXED**

Root cause shared by the `nginx` exit finding, most of E, all of G, and
part of F/`kdecore-meta`/`gnome-shell`. A dependency atom `foo[bar]`
where `foo` is **installed without `bar`**: real portage reinstalls
`foo` with `bar` and, since `bar` needs `package.use`, autounmasks it
(`[ebuild R] … bar*`, exit 1, the `nghttp2`/… that `bar` pulls appear).
portuale treated the installed `foo` as satisfying `foo[bar]` and
returned `AlreadyInstalled` → exit 0, subtree missing.

**Fixed** (`e17c6e9` + follow-up): `resolve_pretend`'s
`candidate_is_installed(best)` branch forces a `Reinstall` (not
`AlreadyInstalled`) when the atom's `[flag]` use-deps aren't satisfied
by the installed **vdb-recorded** USE -- so the graph layer's own
child-flip block routes the entry, records an autounmask change *only*
when the resolved candidate's *effective* USE also can't satisfy it
(`mime-types[nginx]` -> rc 1), and otherwise just reinstalls
(`systemd[policykit]` -- `policykit` is a global flag `systemd`'s ebuild
now defaults on -> `[ebuild R] … policykit*`, rc 0). The first cut
checked the effective USE, which wrongly suppressed the reinstall for
those global-flag cases. Dual-language, fixture
`dev-libs/flipinstconsumer` + 2 contract CASES. Verified in the L0
container: `www-servers/nginx` `rc 0->1`; `sys-auth/polkit` /
`dev-lang/rust` (E) / `net-misc/networkmanager` (G) all now match real
exactly (24/15/67 packages).

The `:=` slot-op turned out not to strip the `[flag]`
(`net-misc/curl:=[http2,ssl]` parses with `use_deps` intact), and the
already-resolved-`other_outcomes` case did not actually apply here --
`curl`/`systemd` are reached first by their own `[flag]` atom.

## J. REQUIRED_USE hard-error  ·  MEDIUM · 2 probes · **BOTH FIXED** (neither was an autounmask gap)

`app-editors/neovim` (real rc 0, portuale rc 1): portuale
`REQUIRED_USE not satisfied … "^^ ( lua_single_target_luajit
lua_single_target_lua5-1 … )"`. **Root cause was NOT missing autounmask**
— real doesn't autounmask anything here, it resolves cleanly with
`LUA_SINGLE_TARGET="luajit"` because `profiles/base/package.use` sets
`app-editors/neovim lua_single_target_luajit -lua_single_target_lua5-1`.
portuale folded the profile-wide `LUA_SINGLE_TARGET="lua5-1"`
(`profiles/base/make.defaults`) once, last-wins, into the high-priority
`conf` USE tier — re-applied *after* that `package.use` — so BOTH single
flags ended up on and `^^` tripped. Real config.py (2849-2889) folds a
profile `make.defaults` USE_EXPAND value **per profile level**,
*prepended* before that level's own `USE=`, so the same level's
`package.use` still cancels it; the `defaults` configdict is then skipped
by the main USE_EXPAND re-fold (2964).

**Fixed** on `main`: `portage_profile::resolve_config` now folds each
level's own USE_EXPAND / USE_EXPAND_UNPREFIXED make.defaults values into
that layer's `make_defaults_use` (prepended); the global `conf`-tier fold
skips any var the profile chain settled and `make.conf`/env never
touched. Dual-language (`emerge_pretend_reference.py` mirror). Fixture
`dev-libs/singletargetpkg`, Rust unit
`profile_make_defaults_use_expand_is_folded_per_level_before_package_use`,
contract `test_profile_use_expand_default_is_folded_per_level`.

**J-libsdl2 also FIXED** (`a250943` + follow-up) — also NOT an
autounmask gap: `emerge -pv app-emulation/wine-vanilla` →
`media-libs/libsdl2[haptic,joystick,...]` REQUIRED_USE fails on **both**
resolvers. The divergence was pure error *rendering* — portuale printed
a one-liner `emerge: REQUIRED_USE not satisfied for … "<whole expr>"`
where real `_show_unsatisfied_dep` prints the `!!! The ebuild selected
to satisfy "<atom>" has unmet requirements.` block (candidate +
`pkg_use_display`, the minimal unsatisfied sub-expression
`wayland? ( gles2 )`, the complete expression, the `(dependency required
by … [ebuild/argument])` chain). Ported `portage_required_use::
unsatisfied_reduced` (real `_RequiredUseBranch` tree + `tounicode`) +
`human_readable`, `render_required_use_block` / `required_use_dep_chain`
in `portage-repo`, the caller's `!!!`-no-`emerge:`-prefix rule in
`pretend.rs`. Dual-language. **wine-vanilla now byte-identical to real
→ L0 clean 73→74, parity 0.617.** The 3 `requiredusebadpkg*` contract +
Rust unit tests were re-pinned to the block.

## M. "Version selection" (firefox/thunderbird)  ·  ~~22 `version` + 1 `use`~~  ·  **NOT A BUG — comparator artifact, FIXED**

All 22 `[version]` findings and the `[use] dev-lang/rust-bin LLVM_SLOT`
finding were the same comparator defect, not a resolver divergence.
`resolve-compare.py` keyed package identity by `(type, category/pn)`, so
a package installed in two slots at once — `llvm-core/llvm-21.1.8:21`
*and* `llvm-core/llvm-22.1.8:22`, both merged by both resolvers for
firefox — collapsed to one map entry (last row wins). Real lists llvm-22
before llvm-21; portuale lists llvm-21 before llvm-22; so the survivors
were `llvm:21` (real) vs `llvm:22` (portuale) — a phantom
`real 21.1.8 vs portuale 22.1.8`. Same for `clang`, `compiler-rt`,
`rust-bin`, the `-config`/`-symlinks` stubs, and `rust-bin`'s baked
`LLVM_SLOT`.

Fix: `split_cpv_slot()` parses the slot out of the merge-list token;
identity is now keyed by `(type, cp, slot)`; the merge-order multiset
comparison is slot-aware too. Firefox/thunderbird now show only their
real residue — cluster I merge order + one `[blocks B]` soft-blocker
line (see A's "Residual" note). Doctests on `split_cpv_slot`.
